# 技能发现与按需读取

2026-09-28。Codex 的[技能文档](https://learn.chatgpt.com/docs/build-skills)说明初始上下文包含名称、用途和路径，模型选中技能后读取完整 `SKILL.md`；`allow_implicit_invocation: false` 不参与隐式匹配，但仍可显式调用。当前固定版本的 Codex Core 适配器没有注册技能扩展，之前只有 ShipiOS 的显式引用上下文，因此不能将技能列表界面视为已经接入自动选择。

ShipiOS 现为基础聊天与 Codex Core 提供同一份按任务项目范围筛选的目录。目录包含标识、名称、用途、路径与来源，以 JSON 行编码元数据，不预先注入指令正文。已停用技能、已停用来源插件、其他项目技能及禁止隐式调用的技能不进入目录；同名技能保持独立来源。目录以 8,000 字符为上限，超出时保留完整条目的标识和路径并提示省略，没有按服务上下文窗口实现动态百分比预算或优先缩短描述。

基础聊天提供只读 `shipios_read_skill` 工具，模型只能按本轮目录的准确标识读取。读取前重新检查当前私有配置、所属任务项目、来源、启停和隐式策略；工具不能读取任意路径或执行脚本。工具调用与成功/失败结果保存在任务时间线，实际读取的技能另存为 `invoked_skills`；原有 MCP 调用仍沿用其审批流程。Codex Core 通过已有原生文件工具按目录路径读取，仍受该任务的只读、审批和沙箱设置约束。模型是否选用技能由名称和用途匹配决定，不保证每个相似请求都触发。

已有 Codex 会话的续接请求现携带当前系统指令和技能目录，修复之前仅首轮传入技能上下文的问题；目录为空时明确替换旧目录。模型历史中已读过的技能正文不会被物理删除，最新目录和用户要求仍决定本轮可用范围。

验证结果和当前验收边界见下方；原生双端页面与交互仍待完成。在线目录、依赖配置、系统作用域、符号链接技能、按上下文窗口动态预算及完整视觉/焦点配对继续待补齐。

103 项相关定向测试通过（95 项技能/工具回归及 8 项会话回归），覆盖元数据与正文分离、8,000 字符预算、启停/隐式策略、任务范围、旧目录读取拦截、只读技能工具计入原有 128 个工具上限、基础聊天无 MCP 的真实 HTTP 工具循环、Codex Core 实际文件读取，以及同一会话目录更新/清空。8 项原有会话回归覆盖计划、目标、模型/服务切换、图片、文件、任务窗口及审查后续接。应用经 `script/build_and_run.sh --build-app` 构建并通过严格签名检查。本轮未重跑全量测试，未使用用户真实独立服务验证模型选择效果。

本轮未启动原生应用：上一阶段获取并启动 ShipiOS 被自动审批拒绝，理由是 Mac 已锁定且无法自动解锁；仍在等待用户手动解锁，未绕过限制。完整双端页面验收保持 0/43。
