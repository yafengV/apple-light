# 网页新建与子窗口归属

2026-09-25。修复共享浏览器会话创建新页面时没有保留来源任务，导致分离网页的子页面进入主窗口其他任务的问题。

## 实现

浏览器会话的新页面入口传递来源网页 ID。共享工作区中的 WebKit 弹窗、右键打开链接和分离窗口 ⌘T 继承来源任务与面板位置。分离来源创建新的分离窗口，后台主任务的选择、面板和浏览器选择保持不变；当前任务的普通页面仍在其对应面板激活新标签。

保留 WebKit 提供的配置，子页面继续打开下一层页面时仍能追溯自己的任务。失效、已关闭或已删除任务的来源，以及应用退出阶段，不再创建新页面。主窗口和分离窗口共同消费待打开窗口队列，一次消费后清空，避免多个观察者重复处理，也允许主窗口不在工作区页面时由分离窗口打开子页面。

后台网页保存已提交网址和未提交地址编辑，应用退出前再次捕获；只更新已加载实例对应的保存项，不丢弃未访问任务的记录。脚本关闭页面会删除对应保存项和待打开窗口记录，避免重启后重新出现；关闭后台网页不再请求主窗口输入焦点。

## 自动化验证

新增 6 项 `BrowserChildWindowTests`，覆盖 ⌘T 命令创建、两层来源继承、WebKit 配置保留、普通面板继承、后台地址草稿保存和恢复、脚本关闭、失效来源与退出保护。

另新增真实 HTTP/WebKit 集成测试：A 打开弹窗时主窗口显示 B，验证弹窗属 A、B 选择与焦点不变、已提交网址和地址草稿分别保存，以及 `window.close()` 只移除弹窗。

相关浏览器、窗口命令、窗口恢复和标签回归共 80 项通过，0 失败。日志 `.cache/browser-child-window-tests.log`。构建通过 `script/build_and_run.sh`，严格签名和 `git diff --check` 通过。

## 原生验收

隔离工作区 A 为分离网页、B 为主窗口网页，页面由本机 HTTP 服务提供。初始布局由保存记录建立，不作为拖放证据。

1. B 网页输入 `B untouched`，主窗口最小化。A 中按 ⌘T 打开新的分离网页，地址栏自动获得焦点，无须额外点击即可输入 `/new` 并导航。
2. 新页面点击 `target="_blank"` 链接，独立弹窗加载 `/popup`。磁盘记录原页面、新页面及弹窗均属于 A，主工作区仍为 B。
3. 弹窗按钮调用 `window.close()` 后只移除该页面；原页面与 `/new` 页面继续存在。新页面的“聚焦聊天”正确返回 A；再切回 B，`B untouched` 仍保留。
4. 主窗口回到 B，在分离子页面填写未提交的 `unfinished child address` 后正常退出。仅为隔离进程传入 `-NSQuitAlwaysKeepsWindows YES` 并重启，子窗口自动恢复，地址草稿保留，实际加载的仍是 `/new`。网页可输入 `Restored child works`。
5. 重启时服务请求原页面、B 和 `/new`，没有请求已关闭的 `/popup`；磁盘记录也不含该弹窗。随后在恢复网页中右键选择“在新标签页中打开链接”，新窗口再次打开 `/popup`，归属仍为 A，主工作区保持 B。

验证结束关闭本机服务，恢复原数据目录及普通启动参数，确认原任务、原待发送草稿和输入焦点正常。测试网页、运行数据和日志不提交。
