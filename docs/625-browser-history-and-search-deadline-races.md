## 浏览器历史

页面加载结束、URL 和标题的 WebKit 通知原来都调用同一个“记录新访问”入口。保持打开的页面在清理后改变标题，会重新加入已清理的历史；普通标题变更也会刷新访问时间并把原记录移到第一项。

两项真实 WebKit 用例在修改前稳定复现：标题变更错误排序/时间，以及主窗口和额外会话清理后的历史复活。日志 `.cache/browser-history-race-before-625.log`，terminal exit 1，两个用例共六条失败记录，其中一条为错误等待后的 unexpected 收尾。保留失败，不改成通过。

| 场景 | 修正后的行为 | 验证范围 |
| --- | --- | --- |
| 同一已完成页面更新标题 | 只更新仍存在记录的标题，保留访问时间、ID 与顺序 | 真实两页 WebKit 用例 |
| 清理或删除之后的迟到标题/URL 通知 | 同一访问的更新不能重新创建记录 | 主会话及额外独立会话、内存与 workspace.json |
| 重新导航或刷新 | 实际新访问仍记录；已清理的记录获得新 ID | 同一地址真实 reload |
| 窗口归属 | 主、注册会话、独立任务窗口均传递新访问/已有访问更新语义 | 统一三类绑定及相关窗口/标签回归 |
| 关闭/失败 | 不再用关闭后的或失败页面通知记录访问 | 代码保护及相关浏览器回归；完整失败/返回/所有标签配对仍需继续 |

修改浏览器历史语义，不宣称浏览器全部页面、精确菜单、权限、跨重启登录或 Codex 双端交互完成。

## 文件搜索

原 deadline 只核验 query ID。同一 query 的部分结果会重置超时，但旧 sleep 已到期且等待主 actor 执行时，取消不能证明旧任务不会执行收尾。新增每次期限的独立身份，并在 sleep 返回后检查任务取消；只有当前 query 的当前期限可终止搜索。默认 20 秒保持不变，不延长超时掩盖失败。

新增用例使用实际 helper 输出和可控制 sleep：旧期限先等待，收到真实部分帧后创建下一期限，再恢复已就绪的旧任务。旧任务不得结束搜索，随后真实完成帧正常收尾。原 400 毫秒进度延长期、真正无进度超时、无效帧、进程退出、分块帧及旧 query ID 测试全部保留。

这个用例证明修复覆盖指定竞态，不能反推原全量那次超时一定由此引起；高负载下首帧/调度延迟及新全量仍需检验。
