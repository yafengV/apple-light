# 新任务托管工作树

2026-09-26。在 [托管工作树基础](224-managed-worktree-foundation.md) 上，Git 项目的新任务输入区增加“本地 / 工作树”选择。选择“工作树”后，首次发送会先验证独立 Codex Responses 服务和项目状态，再保存待创建任务 ID，建立该任务专用的 detached checkout，并把草稿和附件移到任务中。真实 Codex Core 会话在新目录执行，侧栏和归档列表仍将任务归在来源项目下；该目录不显示为永久项目。重启后任务与目录关联保留，重复创建会恢复或复用原检出。

每个托管检出只用于一个任务。在该目录尝试开启第二个任务会被拒绝；分叉入口暂时禁用，因为现有分叉流程不会建立新的独立检出。来源目录有未提交修改时，首次发送保留原草稿并提示先提交或改用本地任务，避免生成与用户期望不一致的工作树。该限制是当前实现边界，尚未实现 Codex 的修改传递与 `.worktreeinclude`。分支选择、归档后的安全清理与快照恢复、Handoff 也仍待接入。

验证：42 项工作树、归档、侧栏与分叉相关测试通过；2 项真实本地模型服务和 Codex Core 集成测试通过，覆盖检出目录中的会话、来源项目归属、重启、归档筛选、一任务一检出保护及脏来源草稿保留。`script/build_and_run.sh --build-app` 构建结果另见本次提交记录。当前机器锁屏时无法完成新输入区的原生点击和与用户 Codex 版本的视觉/行为配对，因此不计为 43 个完整验收面中的任何一个。
