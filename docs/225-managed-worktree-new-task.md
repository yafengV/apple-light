# 新任务托管工作树

2026-09-26。在 [托管工作树基础](224-managed-worktree-foundation.md) 上，Git 项目的新任务输入区增加“本地 / 工作树”与起始分支选择。选择“工作树”后，首次发送会先验证独立 Codex Responses 服务和项目状态，再保存待创建任务 ID，从当前提交或所选分支建立该任务专用的 detached checkout，并把草稿和附件移到任务中。发送时重新检查所选分支的提交；分支已更新时保留草稿并要求刷新。真实 Codex Core 会话在新目录执行，侧栏和归档列表仍将任务归在来源项目下；该目录不显示为永久项目。重启后任务与目录关联保留，重复创建会恢复或复用原检出。

每个托管检出只用于一个任务。在该目录尝试开启第二个任务会被拒绝；分叉入口暂时禁用，因为现有分叉流程不会建立新的独立检出。选择当前分支时，已跟踪文件的已暂存与未暂存修改通过 Git stash 对象复制到新检出，来源目录保持原样；应用中断后可按快照校验并恢复应用步骤。选择其他分支时从其提交创建，不携带来源当前分支的修改。当前分支含未跟踪文件时保留草稿并提示先提交或使用本地任务，以免静默丢失文件。`.worktreeinclude` 忽略文件传递、归档后的安全清理与快照恢复、Handoff 仍待接入。

验证：42 项工作树、归档、侧栏与分叉相关测试通过；本轮 13 项 `WorktreeTests` 及 2 项真实本地模型服务和 Codex Core 集成测试通过，覆盖所选分支检出目录中的会话、来源项目归属、重启、归档筛选、一任务一检出保护、未跟踪文件拒绝、当前分支已暂存和未暂存状态同时传递，以及 Git 已应用后工作区标记未保存时的重试。`script/build_and_run.sh --build-app` 构建通过。当前机器锁屏时无法完成新输入区的原生点击和与用户 Codex 版本的视觉/行为配对，因此不计为 43 个完整验收面中的任何一个。
