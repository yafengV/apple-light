# 新任务托管工作树

2026-09-26。在 [托管工作树基础](224-managed-worktree-foundation.md) 上，Git 项目的新任务输入区增加“本地 / 工作树”与起始分支选择。选择“工作树”后，首次发送会先验证独立 Codex Responses 服务和项目状态，再保存待创建任务 ID，从当前提交或所选分支建立该任务专用的 detached checkout，并把草稿和附件移到任务中。发送时重新检查所选分支的提交；分支已更新时保留草稿并要求刷新。真实 Codex Core 会话在新目录执行，侧栏和归档列表仍将任务归在来源项目下；该目录不显示为永久项目。重启后任务与目录关联保留，重复创建会恢复或复用原检出。

每个托管检出只用于一个任务。在该目录尝试开启第二个任务会被拒绝；分叉入口暂时禁用，因为现有分叉流程不会建立新的独立检出。选择当前分支时，已跟踪文件的已暂存与未暂存修改通过 Git stash 对象复制到新检出；未跟踪普通文件和 `.worktreeinclude` 匹配的忽略文件先保存到 ShipiOS 私有快照，再复制到新检出。被忽略的 `AGENTS.override.md` 自动纳入，其他忽略文件不复制；忽略文件的来源符号链接跳过。来源目录保持原样，已存在且内容不同的目标文件不会被覆盖。中断后可以使用快照重试复制。选择其他分支时从其提交创建，不携带来源当前分支的修改。干净检出的归档清理见[第 226 篇](226-clean-managed-worktree-archive.md)；脏工作树快照恢复和 Handoff 仍待接入。

验证：先前 42 项工作树、归档、侧栏与分叉相关测试通过；本轮 15 项 `WorktreeTests` 及 2 项真实本地模型服务和 Codex Core 集成测试通过，覆盖分支选择、来源归属、重启、已暂存和未暂存状态传递、未跟踪与指定忽略文件复制、非指定忽略文件排除、重复安装、权限保留、符号链接与路径越界拒绝。`script/build_and_run.sh --build-app` 构建通过。当前机器锁屏时无法完成新输入区的原生点击和与用户 Codex 版本的视觉/行为配对，因此不计为 43 个完整验收面中的任何一个。
