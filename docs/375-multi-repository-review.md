# 多仓库审查及仓库选择恢复

## 对照范围

## 页面和操作范围

审查页列出任务目录及关联目录中实际所属的 Git 仓库。同一仓库的多个子目录去重，最近的嵌套仓库和工作树保持各自身份；同名仓库使用完整路径区分。没有 Git 的文件夹不进入仓库菜单。元数据不可读与工作区索引损坏分别保留错误，切换其他可读仓库不受影响；修复后可以刷新恢复。

普通差异范围、文件与差异块暂存、撤销、提交、新分支及推送使用选择的仓库。仓库选择不改变任务的执行目录、聊天草稿、终端目录或历史分支的来源。提交说明草稿、比较提交、基准分支及文件折叠状态在本次工作区生命周期内按仓库保留。PR 入口仅在主仓库可用；实际创建函数也检查此范围，不能只依赖按钮禁用。工作树入口继续使用项目或任务的原有范围。

目录修改同步使 Git 读取、差异、弹层与操作授权失效。旧操作即使在同一仓库被移除又重新添加后也不能重新取得授权，旧完成回调不能覆盖新上下文的草稿或错误；忙碌状态仍由原操作结束时释放。正在修改仓库或生成提交说明时不能通过仓库菜单切换。

## 最近一轮、评论和模型审查

最近一轮保留原始完整助手快照，不按当前选择的单一仓库筛选。文件标题和行号使用该回合固定的路径基准；跨出原基准的文件只有仍在当前关联目录内才能打开，并复核符号链接真实目标。删除的来源、不可用文件和旧回调保留原错误及任务身份，不猜测其他仓库的同名文件。

普通审查评论记录实际仓库的路径基准，添加及发送时都检查关联范围。已移除仓库的评论保留，但发送要求重新核对。模型审查快照只包含选择仓库的差异；两种协议的请求保留原任务目录、显式审查仓库和当轮关联目录。审查回复的文件链接使用保存的范围，关联目录后来移除不会将旧回复重新解释为主仓库的同名文件；没有原始范围记录时不扩大访问。

主窗口、独立任务窗口和分离审查布局保存仓库选择。恢复路径只是提示，需要当前关联目录实际确认仓库；失效或相对路径回到默认仓库。后台恢复刷新不覆盖调用方正在执行的手动刷新，旧版本布局没有仓库字段时仍可解码。
