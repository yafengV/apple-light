# 文件标签、定位与原生焦点

## 行为依据和设置复核

[官方快捷键文档](https://learn.chatgpt.com/docs/reference/commands)明确列出关闭当前标签或窗口、前后任务或标签，以及随焦点变化的行定位/浏览器地址操作。本文实现文件预览中的 ⌘W、Ctrl+Tab、Ctrl+Shift+Tab 和 ⌘L。前后标签沿用用户配置的前后任务快捷键；官方列出的其他备用组合尚未全部接入。

本轮在原数据启动的 ShipiOS 中实际按 ⌘,，原任务窗口转为“设置”，没有第二个设置窗口；源码也仅声明主 WindowGroup。随后使用隔离数据从文件预览进入设置，切换个性化页，在指令文本框按 Esc 返回；任务草稿、两个文件标签、当前文件选区和滚动位置保留。

CUA 尝试读取 Codex 本身时明确拒绝 `com.openai.codex`，因此没有使用其他技术绕过，也没有获得当前用户版本的设置布局或文件页面配对证据。

## 实现

- 文件选择和关闭同步更新标签状态；读取在后台执行，以请求编号、项目、选中文件及标签是否仍打开校验结果。关闭、快速切换和更换项目后，旧请求不能覆盖新内容或重新打开标签。
- 关闭选中标签选择相邻标签，关闭后台标签不影响当前内容。关闭最后一个文件保留文件树和主窗口，将输入交回任务草稿。
- 文件列表错误、文件读取错误、Git 审查错误分开；读取显示加载状态，失败后可重试。
- 使用只读 NSTextView 提供文本选择、复制、横纵滚动和行定位；在同一文件面板实例内保存每个打开文件的选区与滚动位置。
- 文件区域拥有实际键盘焦点时，⌘W 关闭文件，前后任务快捷键切换文件。设置、其他面板、全局弹层和快捷键录制不会收到这些文件操作。
- ⌘L 打开行号输入，Return 定位并选中该行；无效/越界行号保留输入并提示，Esc 取消且恢复文件焦点。行号偏移兼容 Unicode、CRLF 和末尾空行。
- 文件搜索确认后恢复到目标文件；取消搜索仍按原逻辑返回输入区。切换项目或打开设置后，旧弹层的关闭不能给旧文件抢焦点。
- 原生文件视图获得焦点时同步解除 SwiftUI 输入框焦点状态，防止最后标签关闭后无法恢复输入。

## 原生验收

隔离目录 `/private/tmp/shipios-git-ui-t2l492o2/Data`；项目 `BranchFixture`。新建的 NativeTabA.txt 含 120 行中文、emoji 和组合字符，NativeTabB.txt 含三行文字。没有请求外部模型服务。

实际操作确认：

1. ⌘P、Return 打开 A，焦点进入文件内容。
2. ⌘L 自动聚焦行号；999 提示越界；90 定位并选中第 90 行。
3. 搜索打开 B，Ctrl+Shift+Tab 回 A，选区与滚动位置保留；Ctrl+Tab 循环切换。
4. 点击标签也将焦点送入预览。⌘W 关闭当前文件后继续对相邻文件生效。
5. 最后一个文件关闭后主窗口仍在；直接键入测试标记进入任务输入框。随后恢复隔离草稿原文，没有发送。
6. 行号 Esc 取消后，再次 ⌘L 可重新聚焦输入。
7. 临时移动自建的 A 文件，重新打开显示缺失错误和重试；恢复源文件后点击重试，内容和焦点正常恢复。
8. 从文件进入主窗口设置，个性化文本框 Esc 返回，草稿、标签、选区、滚动位置仍在。

验收中发现并修复了行号框过早请求焦点，以及原生预览与 SwiftUI 输入框焦点不同步的问题。最后一次隔离启动 PID 51978，构建日志 `.cache/file-tabs-native-build.log`。
