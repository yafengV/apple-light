# 命令菜单与任务搜索窗口内弹层

2026-09-18。继文件搜索之后，移除命令菜单和任务搜索的原生 sheet，并整理共同的窗口边界。

## 依据与实现

公开静态资源 `app-initial` 的 `yAo` 为 root/chats/files 模式选择不同搜索提示，并共同使用 `$4.Dialog` 和 `global-command-menu-dialog`。本轮对齐该窗口内呈现关系，不宣称已实现官方统一搜索的所有模式和排序规则。

- `SearchDialog` 共用遮罩、窗口内尺寸约束、材质、辅助功能模态容器；命令/任务/文件搜索各自保留查询与结果。
- `SearchDialogKeyboardBridge` 共用窗口限定、输入焦点、方向键、Enter、Esc、⌘W 和 Tab；输入法组词与普通编辑快捷键保留给原生编辑器。
- 命令菜单使用稳定命令 ID 选择，键盘跳过不可用项，空结果显示提示；查询更新同步重置选择。
- 背景命令在搜索期间禁用。只有当前命令菜单的显式选择可通过 `executePaletteCommand` 执行；过期选择、不可用命令不执行。去掉关闭 sheet 后等待 0.2 秒的调度，直接关闭并执行或切换到下一弹层。
- 任务搜索沿用全项目/归档任务/消息/分支检索、异步结果和过期查询保护，结果打开后聚焦对应任务草稿；重试入口同样纳入焦点循环。
- 三种搜索保留原页面。取消时返回工作区草稿/原文件；非工作区页面保存原生控件的弱引用，等页面恢复可交互后返回该控件。保存文本框本体，避免保存被查询框复用的系统 field editor。
- 命令菜单切到任务/文件搜索时同时保留原页面控件与文件焦点；主动执行导航命令则交给目标页面管理焦点。

## 验证

- 最终 93 项相关测试通过，覆盖搜索、命令、AppKit field editor 归属、文件焦点、快捷键、页面导航、设置交互、注意事项导航、图片预览、个性化和终端。日志 `.cache/search-dialog-tests.log`。
- 扩大回归时发现旧导航测试仍假定“设置命令可穿透文件搜索”，已改为先验证被阻止、关闭弹层后再验证正常导航；新增专门测试确认命令菜单的显式选择仍能正常执行。
- 原生 `⌘K` 显示同一标准窗口内 `command-search-dialog`，查询“设置”后立即 Down/Enter 打开主窗口设置，未新增窗口或 sheet。
- 命令菜单查询“搜索任务”并执行，立即替换成 `task-search-dialog`，查询框聚焦。选择跨项目任务后正确切换任务并保留对应草稿。
- 无项目任务下不可用的“搜索文件”按 Enter 不执行、弹层保持。命令空结果、Tab 聚焦取消、Enter 返回草稿均通过。
- 从设置搜索字段进入命令菜单，初版取消丢失焦点；修复后原搜索文字保留且可直接编辑。设置→命令→任务搜索→⌘W 也返回原设置搜索框，不关闭窗口。
- 侧栏任务搜索检索 `later reply` 展示 4 条带高亮的回答摘录，连续 Down 选择 ProjectB 任务后打开正确草稿。空结果 Enter 不打开旧结果，⌘, 不穿透到设置。
- 文件搜索回归打开 Beta 并聚焦源码；命令菜单取消返回原源码。发现命令→任务搜索→取消曾返回聊天输入框，保留跨模式文件目标后最终原生复验确实返回 Beta 源码。
- 隔离数据的 A/B 草稿保持，未发送模型请求。最终项目脚本恢复原工作区，确认原任务与待发送草稿可交互；严格签名校验通过。测试数据、缓存、日志不提交。
