## 实现

`TaskPullRequestDetailView` 移除两个 `.sheet` 和旧 SwiftUI 弹窗，接入 `PullRequestDiscussionDialogPresenter`。新 `WindowDialogHost` 将遮罩及表单直接放在实际所属 `NSWindow.contentView`；窄 PR 面板不会限制对话框宽度，不创建独立窗口。

- 审查表单使用原生单选按钮和 `NSTextView`，标题、字段、宽度、边距、按钮结构按参考组件调整。只把当前选中的单选项纳入 Tab 顺序，方向键循环选择；初始焦点进入评论框，Tab/Shift-Tab 在表单内部循环。
- 保留原生选区、换行、撤销/重做；草稿同步观察原生 UndoManager，中文 marked text 期间不覆盖编辑器，也不拦截 Enter/Tab/Esc 用作表单命令。
- 空提交通过 `validateReviewSubmission` 显示不同评论/要求修改错误，未发出写入；批准无需正文。服务仍重新核对账户、权限和 head，并使用捕获的决策、正文与提交。
- 删除确认没有评论预览，使用危险按钮；失败经任务所属通知中心反馈。通知按当前对话框身份及错误去重，过期回调不会作用于替换后的评论。
- 共用窗口内模态作用域保护背景命令与焦点；编辑菜单允许当前表单文本的原生撤销，禁止落到背景编辑器。Esc/⌘W 和遮罩点击取消，忙碌时拒绝；挂载点离窗时清理作用域。
- 关闭后恢复仍存活的来源控件；同窗口替换对话框仍保留最初来源。旧控件的取消、提交与延迟通知回调均重新校验身份，卸载不会清除后来安装的其他模态。
- 文本框可纵向调整，限制按当前标题、换行单选区及错误高度计算；显示错误后再次限制，避免窄窗口或大输入框把表单按钮推出窗口。
- 对响应丢失且结果未确认的审查保留既有“重新读取操作结果”入口，仅执行只读确认。这是独立服务的写入保护边界，不能视为与参考端所有错误行为完全相同。
