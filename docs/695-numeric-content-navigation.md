# 数字标签选择的布局范围与方向

日期：2026-10-09。原始范围仍为 47 个页面入口和 29 项核心功能；本阶段推进 M14 内容标签和 S13 快捷键，不以测试数量换算页面完成率。

## 参考依据

当前安装的参考应用版本为 `26.930.51102`、build `13100`。只读公开打包资源 `app-initial-f9b16fbf8fc7.js` 的 SHA-256 为 `22f3ea455585cfc0508e3d3627eac161c80c849c0aace3d76d09fdebaa0aeca3`。实际数字选择函数 `swa` 按布局决定候选集合，数字越界时返回 false，并按 locale 方向逆序定位。公开任务内容组件 `Nu` 将命令的数字索引交给该函数；它与相邻标签命令使用同一选择函数的不同分支，不要求当前内容已有键盘焦点。

`script/extract_numeric_content_navigation.cjs` 校验来源摘要后，仅在显式状态和惰性焦点回调中执行该函数，不初始化参考应用或原生桥接。生成的 `numeric_content_navigation_reference_695.json` 含 **336 组实际函数结果**：full／split、LTR／RTL、0／1／3／11 个内容、聊天／最后内容作为当前项，以及 -1 至 10 的索引。范围为普通聊天主区且启用聊天标签；primary workspace 和未启用聊天标签的状态仍单独待实现／验收。

## 实现与对应行为

| 状态／动作 | 当前实现 |
| --- | --- |
| 普通 split 数字选择 | 只编号主内容集合，不把聊天作为数字 1；选择保留 split，显示对应侧栏并转移内容焦点 |
| full 数字选择 | 聊天和全部主内容共用顺序；选择聊天保留 full，内容重新选择不改变保存位置 |
| 主内容范围 | 原 left／right 位置合并；底部、分离窗口和其他任务不计入主窗口编号；独立任务窗口只使用自身内容 |
| 编号方向 | 当前实际 SwiftUI 布局方向为 RTL 时反转显示顺序，恢复 LTR 后立即使用原顺序；不把方向写入任务布局 |
| 命令可用性 | 主／独立任务窗口都按同一候选集合启用数字命令；空 full 有聊天数字 1，空 split 没有可执行数字命令 |
| 越界 | 原始选择函数返回 false 且保持当前焦点；产品命令仅接受 1—9，第 9 项精确定位，不表示最后一项；即使有更多内容，第 10 命令也不能执行 |
| 当前排序 | 每次从现有主内容顺序计算；排序后下一次数字选择立即使用新位置，隐藏 split 内容也能直接显示 |
| 原生路由 | 独立任务窗口的数字命令纳入统一 `TaskWindowTabs.commandEnabled`／`perform`，移除页面中重复维护的数量和选择分支 |

移除两个未在产品中调用的旧循环方法；原测试转而验证已用于产品的相邻内容导航，底部单标签不能通过相邻切换进入主内容。相邻标签顺序仍由自己的导航规则管理，不因本阶段数字定位的 RTL 处理而改变。

下一项关闭行为已有只读源码依据：同一公开资源的 `oe` 先考虑当前标签的配对伙伴，再调用 `IBn`；`IBn` 先使用仍有效的 opener 家族，最后以右邻／左邻回退。手动选择、移动／排序和删除会改变家族的 generation／有效性，不能仅把“关闭后选首项”改成固定相邻项就宣称完整对齐。本阶段没有修改这些关闭路径；需要继续覆盖其创建、选择、移动、关闭确认和焦点生命周期。
