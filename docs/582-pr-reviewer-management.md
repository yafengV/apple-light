# PR 审查者列表与请求管理

2026-10-04 核对当前安装参考包的公开资源，版本仍为 `26.930.21537`、build `12776`。`pull-request-detail-query-da2fa14a2b60.js` 与本机缓存逐字节一致；同时读取其当前依赖的 `pull-request-detail-model-67e2525aa6e1.js` 和 `pull-request-actions-392878e39ce6.js`。没有读取个人配置、认证或会话。参考组件仅在开放 PR 的作者范围显示管理入口：无审查者时为“请求”，已有审查者时为加号；候选多选后提交，关闭或 Esc 清空临时选择；已请求用户/团队可直接移除，已提交的审查保留并显示说明。

ShipiOS 的概览现有审查者行、用户/团队头像、等待/批准/要求修改状态与请求入口。主窗口、紧凑摘要及独立 PR 窗口复用同一详情组件。锚定弹层支持姓名或用户名搜索、250 毫秒防抖、候选多选、勾选状态、方向键定位、Return 选择、Esc 关闭与搜索失败重试。临时选择只在点击“请求”时提交；候选头像不显示概览中的审查状态圆点。已有审查者和临时选择先显示，再按用户名大小写去重合并搜索结果。团队可移除现有请求，新增候选为仓库协作者用户。

服务通过 GitHub CLI 使用当前用户账户，显式限定 GitHub、仓库与 PR。审查请求和每人的最新审查各自分页，验证分页总数、重复结果、游标及每页账户/PR 身份。请求中的 Bot 与 Mannequin 同样显示，不能使整组列表失败。团队显示名称用于界面、slug 用于实际移除；已提交的审查不能从待审查请求入口删除。

接口字段已核对 [GitHub 官方 GraphQL schema](https://raw.githubusercontent.com/octokit/graphql-schema/master/schema.graphql)：`collaborators` 支持姓名/登录名查询，`latestReviews` 为每人的最新非待提交审查，`RequestedReviewer` 包含 User、Team、Bot 和 Mannequin。请求/移除使用 [GitHub 审查请求 REST API](https://docs.github.com/en/rest/pulls/review-requests)，用户 login 与团队 slug 分开写入 JSON。输入临时目录 0700、文件 0600，并在结束/取消时清理。

所有写操作前重新读取作者、开放状态与当前账户，再核对应用有效范围和最新只读设置。多窗口共用既有 PR 操作协调器，避免和标题编辑/合并等写操作并发。成功后通过应用私有数据根目录和 PR 范围的更新事件使其他窗口重新读取；手动刷新与应用重新激活也会读取。列表首次加载独立于长评论读取。关闭详情取消所属操作和迟到发布。

CLI 提交响应丢失后先重新读取，匹配实际结果时确认成功，不重复发送；新增审查者在刷新前已提交审查也可确认。操作后状态无法确认时先要求刷新，再开放新的写入口。请求由用户点击触发，测试只使用临时本地 CLI 夹具，没有向真实用户发出审查通知。
