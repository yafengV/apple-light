# 逐任务模型选择与独立窗口入口

2026-09-18。本阶段将模型和推理强度保存到任务，独立任务窗口复用模型选择弹层。

## 实现

- 已有任务的选择独立保存；全局模型配置继续作为无覆盖任务和新任务的默认值。分叉继承来源任务选择，旧任务数据仍可解码。
- 覆盖绑定服务地址；切换服务后使用新服务默认配置，避免将旧服务的模型 ID 用于另一服务。
- 发送时捕获本轮配置；处理中修改选择只影响后续请求，准备请求期间也不覆盖较新的选择。保存失败不替换已生效的任务配置。
- 主窗口与独立窗口显示各自任务的模型。独立窗口按钮、模型快捷键和斜杠命令打开本窗口弹层；选择或 Esc 关闭后返回原草稿。

依据前期对 Codex 公开静态资源中任务设置和下一轮更新路径的检查进行行为修正；这不是当前 Codex 界面的完整视觉配对证据。

## 验证

- 64 项模型选择、HTTP 传输、分叉、独立窗口和命令相关测试通过，日志 `.cache/task-model-selection-final-tests.log`。
- 新增测试覆盖任务选择持久化、服务切换、保存失败、旧数据兼容、分叉继承，以及本地 HTTP 请求中本轮配置快照与下一轮新配置。
- 通过项目脚本构建并启动隔离工作区。独立任务 B 的 ⌃⇧M 和模型按钮均打开本窗口弹层，搜索框获得焦点；选择服务返回的模型后关闭并回到 B 的原草稿。再次打开后选择高推理强度，Esc 返回草稿。
- 检查隔离数据确认仅 B 保存了 `fixture-model/high`，A 没有覆盖，全局仍为 `default-native/low`。原生验证使用本地 HTTP 夹具，没有调用外部模型服务。
- 严格签名校验通过。最后通过脚本恢复原工作区，关闭恢复出的测试任务残留窗口，确认原任务和未发送草稿保留、输入框可聚焦；本地夹具已停止。
