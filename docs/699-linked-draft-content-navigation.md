# 关联草稿的目录、内容返回与重启恢复

日期：2026-10-09。继续推进 M01、M02、M14 与 S13；原始范围仍为 47 个页面入口和 29 项核心功能。此阶段修复新任务深链接产生的未发送草稿与内容标签之间的归属，不宣称完整页面已经对齐。

## 问题与依据

第 326 篇已实现新任务深链接独立草稿。其内容 owner 采用 `new:<项目>:link:<UUID>`，无项目使用 `new:none:link:<UUID>`。原文件／独立审查／终端和内容返回入口直接去掉 `new:` 前缀，因而把 `:link:<UUID>` 一起作为目录；搜索或独立窗口返回还会调用普通 `newTask()`，清除 UUID。结果是文件目录错误、无法返回原关联草稿，或标签仍保存却无法从固定项重新打开。

本阶段属于已有公开深链接能力的完整性修复，参考范围沿用第 326 篇及第 698 篇已固定的内容选择／布局规则。未从静态资源推断 Codex 私有草稿存储格式，也未将 ShipiOS 的 UUID 格式称为 Codex 的格式。当前参考分发仍为 `26.930.51102`；Codex 前台访问限制未绕过。

## 实现与验证范围

| 入口／状态 | 现在的行为与证据 |
| --- | --- |
| 草稿身份 | `WorkspaceDraftIdentity` 分离项目与关联 UUID，保留已有序列化格式；拒绝空 `new:`、相对目录与 NUL；配置中确实含 `:link:<UUID>` 的目录优先作为完整项目名解析 |
| 项目目录 | 用项目稳定归属查找配置的主目录；关联 UUID 不参与文件系统路径。无项目草稿没有文件／终端目录 |
| 文件与独立审查 | 关联项目草稿能在真实目录读取文件，独立审查使用同一实际目录；隐藏原生文件视图验证异步加载后的实际文本 |
| 终端 | 优先沿用已有终端实际 scope；没有实例时以解析后的真实根目录恢复，验证冷恢复终端进程启动和 conversation 归属 |
| 浏览器搜索返回 | 从另一任务返回指定关联草稿，保留普通草稿与另一任务草稿、浏览器对象、侧栏选择及 split 模式 |
| 独立窗口返回聊天 | 选择原关联草稿，内容仍在独立窗口，主窗口回到聊天输入焦点请求；不创建普通草稿替代来源 |
| 固定内容 | 固定项可以从其他任务／项目返回已有关联草稿，并保留内容来源 ID；实际深链接链路验证文件在原 split 中激活 |
| 前进／后退 | `TaskLocation` 记录草稿 owner，区分同一项目内的普通与关联草稿；返回关联草稿恢复其布局，再前进恢复普通草稿 |
| 创建下一份关联草稿 | 变更 UUID 前先捕获旧布局，避免上一份标签写进下一份归属；普通入口仍取回普通草稿 |
| 保存／重启 | 真实 helper 创建两项目、多份链接草稿、固定文件和浏览器，跨项目返回后关闭并新建 store 恢复；原 UUID、文本、split、文件选择和实际文件内容均保留 |

异步返回入口在打开作用域后再次核对调用方的内容或固定项、身份、主目录、取消与关闭状态。没有新增网络服务或触碰用户 API 凭证。新建普通草稿和选择已有草稿共用状态应用过程；仍保留现有跨项目导航的失败语义，不把它称为完整导航事务。
