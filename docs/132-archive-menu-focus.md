# 归档项目菜单的原生焦点与键盘交互

2026-09-18。本轮消除 [第 131 篇](131-confirmation-return-focus.md) 中项目菜单取消确认后只能回到设置搜索框的差异。

## 实现

项目组的省略号入口使用小型 `SettingsActionMenu` AppKit 桥接，复用已有的 `SettingsMenuControl` 原生菜单与键盘处理。SwiftUI 页面仍负责选定任务 ID、打开确认框和判断返回目标。

关闭确认后，如果项目组仍存在且可见，则向对应原生菜单发送一次焦点请求；项目已消失时回到设置搜索框。普通重绘不会重复获取焦点；禁用、隐藏及卸载控件不能执行动作，失效的异步焦点请求不能在重新启用后抢焦点。菜单使用原生辅助功能名称和焦点框。

- 21 项相关测试通过，日志 `.cache/archive-menu-focus-tests.log`。新增 4 项覆盖原生焦点请求、普通更新不重复聚焦、禁用/隐藏/卸载保护、失效回调，以及实际归档页面取消确认后返回菜单、项目移除后回到搜索框。
- 项目脚本构建运行及严格签名检查通过。原生测试使用 `/tmp/shipios-archive-menu-native-validation` 新建数据。
- 原生检查确认：鼠标打开省略号菜单并进入确认；Esc 取消后原菜单获得焦点且焦点框可见；空格和 Enter 均能重新打开菜单；方向键和 Enter 选择操作后进入确认框，默认焦点仍在取消按钮。两次确认均取消，没有执行永久删除。
- 原生检查切到记忆页后按 Tab，焦点进入当前侧栏的下一项，旧项目菜单未抢焦点。
- 第一处位于桌面的隔离样本触发 macOS 桌面文件夹权限等待。进程采样定位到快捷键配置读取，系统日志证实权限提示；未通过其他工具操作权限界面。改用新建临时样本完成独立验证。
- 最后通过项目脚本恢复原工作区，原任务与草稿保留，输入框实际获得焦点；日志 `.cache/archive-menu-focus-restore.log`。
