# 独立任务窗口的浏览器实际验收

日期：2026-10-10。源码基线 `d6e06046`，本轮没有修改产品、测试或构建脚本；补 R5／R7 的可见交互证据，不代表整组完成。

## 已验证的实际交互

通过 `script/build_and_run.sh --app --data-root …` 启动隔离数据，在已有自建工作树任务中打开独立窗口。主窗口仍停留在另一个本地任务；工作区短暂恢复提示消失，输入和内容控件可操作。网页使用仅监听 `127.0.0.1:18739` 的两页夹具，未使用用户 API 或认证。

- Cmd-T 新建浏览器并聚焦地址，输入网址后实际加载页面 A；完整视图 Cmd-1 返回聊天，无需点击输入框即可直接粘贴中文到正确任务，原草稿保留。Cmd-2 返回页面 A。
- 网页输入中文后，Cmd-L 修改未提交地址，再按 Esc，恢复原网址、网页输入及其焦点。链接到页面 B、Cmd-左／右后退前进均加载正确页面；同一进程内后退保留网页文字。
- 页面 A 的新标签链接在同一任务窗口打开 B；Cmd-W 关闭子标签后回到父页面及原网页焦点。Cmd-Shift-T 重新打开 B，另核对 HTML 内容和截图确认完成加载，而非只检查标签标题。
- Cmd-Shift-F 切到分屏，Cmd-1 选择内容页 A；分屏数字槽位不包含聊天。网页输入区在 full／split 切换后仍接收直接粘贴，聊天输入区不会抢占其焦点。点击聊天输入后能够编辑本任务草稿。
- Cmd-Shift-C 复制当前网址：无选区时粘贴得到正确网址。有选中文本时首次粘贴将选区包成 Markdown 链接；核对 `ComposerTextEditor` 的富文本逻辑及保存草稿，属于现有行为，未将它误记为复制失败或纯网址替换。验收后恢复原任务草稿。
- 标签菜单“移到主内容区”进入完整视图并保持所选页面。关闭独立窗口后主窗口仍为原本地任务；从“在新窗口中打开”再次打开同一任务，共享聊天草稿保留。

最后一次“在新窗口中打开”创建了新的窗口身份和空内容区。此入口按现有实现生成新窗口，不能把它当作原窗口的冷恢复验收。本轮没有证明退出重启后恢复同一独立窗口的浏览器标签，也没有证明跨进程保留网页 DOM 表单。

两次分屏标题间拖动没有改变顺序；一次完整视图拖动出现“移到右侧”提示，Esc 后未立即消失，随后点击内容标签恢复操作并移除提示。另用同一坐标点击确认起点确实对应可选择的标签标题。

目前未确定这是原生拖放生命周期、目标投递还是验收工具事件时序的问题，没有修改源码，也没有把菜单迁移、模型层重排测试或取消后的恢复当作实际拖放成功。后续需记录拖放源／目标／完成回调，定位并复验；R7 的拖放条件仍保留为未完成。
