# 任务内容标签与主窗口布局

2026-09-17。本轮从本机当前 Codex 应用包的命令定义、标签控制器和本地化资源还原任务标签条语义，并将 ShipiOS 原先只存在于右侧检查器的浏览器与审查页面接入主窗口内容标签层。

## 已核对的 Codex 行为

- 聊天是任务标签条最左侧的首标签；浏览器和审查属于其后的可关闭内容标签。
- `⌘T` 打开浏览器内容标签，`⌃⇧G` 打开审查内容标签。
- `⌃1` 到 `⌃9` 按任务标签条从左到右聚焦，首位包含聊天标签。
- `⌘W` 关闭当前可关闭内容标签；聊天首标签不会被该命令关闭。
- 标签菜单包含“关闭”“关闭其他标签页”“关闭右侧标签页”。
- `⌘⇧F` 在完整内容页和聊天加右侧分栏之间切换；`⌘⇧B` 显示或隐藏内容标签。

这些结论来自静态应用资源。CUA 的安全策略禁止读取 Codex 自身窗口，因此本轮没有把静态语义和 ShipiOS 原生验收写成逐像素一致。

## ShipiOS 实现

- 主内容顶部新增统一标签条，聊天为不可关闭首标签，浏览器和审查为任务所属内容标签。
- 浏览器的每个 `WKWebView` 保持独立身份、地址草稿、页面状态和关闭恢复栈；顶部标签切换不会重建页面。
- 内容标签按任务隔离。切换任务时显示该任务自己的标签；从新任务首次发送后，已有内容标签迁移到新建任务身份。
- 标签支持直接选择、按实际标签宽度拖动排序、关闭当前、关闭其他和关闭右侧。
- 浏览器与审查标签可在主内容区和右侧面板之间移动；两个区域各自维护标签顺序与激活项，“关闭其他”和“关闭右侧”只作用于当前面板。
- 终端接入同一控制器，并额外支持 Codex 静态注册声明中的底部目标。同一任务可创建多个真实 PTY 标签；主区、右侧、底部和独立窗口之间移动时保留同一个进程、输出缓冲和终端标题。
- 标签使用系统拖放数据在同区目标标签前后重排，并可放到主区、右侧或底部面板；浏览器与审查会拒绝底部目标。落点进入时显示强调色虚线边框。
- 侧栏实现 Codex 的另外三个拖放目标：放到“已置顶”固定同一标签引用；放到已有任务将标签所有者转给该聊天并立即切换；放到“新任务”创建无项目聊天草稿并转交标签。浏览器保留同一 `WKWebView`，终端会话单独迁移并保留同一 PTY，审查标签同步迁移布局、焦点和固定引用。
- 拖动期间显示与 Codex 静态资源一致的目标提示语义：固定标签页、移到聊天、移到新聊天、移到左侧/右侧/底部和在新窗口中打开。固定区为空时也会临时显示可释放目标。
- 拖动内容标签时显示“松开放到新窗口”目标；释放后独立窗口复用同一个内容标签、`WKWebView` 或 PTY 实例，提供“聚焦聊天”和“置于顶层”，关闭窗口后标签回到主内容区。内容标签菜单不提供“在新窗口中打开”；该文案只属于整个任务的窗口命令。
- 关闭后按 `⌘⇧T` 恢复最近内容标签。浏览器恢复原地址状态，审查标签恢复到原任务。
- `⌘⇧F` 在主内容区与右侧面板之间移动当前内容标签，页面状态保持；设置继续覆盖同一个 `ID: main` 主窗口。
- 布局菜单提供“打开/退出完整视图”“显示/隐藏标签页”和“交换左侧和右侧面板”；交换只改变物理位置，不重建内容标签。
- 标签条 `+` 打开分组启动器，包含“推荐”“最近工作”“插件和 MCP”“更多工具”；底部面板的 `+` 提供“打开底部终端”和“终端选项”。
- 旧右侧浏览器/审查入口已收敛到同一内容标签控制器，不再同时挂载第二个 `BrowserPanel`，因此不会让一个 `WKWebView` 被两个容器争用。

## 验证

`WorkspaceTabTests` 覆盖聊天/浏览器/审查顺序、位置快捷键、拖排、关闭右侧、关闭其他、关闭恢复、任务隔离、设置往返、新任务身份迁移、固定内容标签的关闭恢复，以及主区/右侧/独立窗口移动时浏览器对象身份不变。新增覆盖拖放目标生命周期、同一任务多终端、精确会话选择、主区/右侧/底部/独立窗口往返、标签显隐、完整/分栏视图、左右交换、启动器指定面板打开、浏览器与审查拒绝底部目标、单会话关闭/重启、草稿任务全部终端转交、浏览器转交到已有/新聊天时的 WebView 身份，以及终端跨聊天转交时的 PTY 身份。最终完整回归为 385 项 Swift、12 项 Rust、fmt/Clippy 与真实 IPC 冒烟全部通过。

签名应用使用独立数据目录完成原生操作：

- 连续按两次 `⌘T` 后，任务标签条显示聊天与两个浏览器标签，第二个标签激活。
- `⌃1` 返回聊天，`⌃2` 精确聚焦第一个浏览器标签；`⌘W` 只关闭该内容标签，主窗口保持。
- `⌘⇧T` 恢复关闭的浏览器标签；标签右键菜单显示三项关闭操作，关闭右侧实际移除后续标签。
- `⌘,` 进入标题为“设置”的同一 `ID: main` 窗口，Esc 返回后两个浏览器标签及激活项保持。
- 示例项目中 `⌃⇧G` 打开顶部“审查”标签；`⌘⇧F` 返回聊天并在右侧显示同一审查内容。
- 浏览器标签菜单显示“移到右侧面板”，不显示任务级的“在新窗口中打开”；移到右侧后主区继续显示聊天，右侧显示同一浏览器标签。
- 弹出窗口显示同一浏览器及“聚焦聊天”“置于顶层”。关闭后标签回到主内容区，右侧恢复执行详情，没有第二个浏览器宿主。
- 右侧详情的“浏览器”按钮会移动已有标签到右侧，而非创建旧式面板副本。
- 移动与弹窗闭环后，`⌘,` 仍在标题为“设置”的同一 `ID: main` 窗口显示；Esc 返回后标签保留。
- 底部 `+` 连续创建两个 zsh 标签；切换后两个终端拥有独立输出缓冲，第一个显示 `FIRST_TERMINAL` 时第二个保持空缓冲。
- 第二个终端从底部菜单移到右侧后仍能输入 `SECOND_TERMINAL`；右侧终端不显示只适用于底部面板的“隐藏终端”按钮。
- 同一终端弹出独立窗口后继续显示此前输出并接受 `DETACHED_TERMINAL`；窗口包含“聚焦聊天”和“置于顶层”，关闭后同一会话回到主内容区。
- 终端标签在底部时菜单提供主区和右侧，在右侧时提供主区和底部；拖到窗口目标后进入独立窗口，名称与当前 Codex 静态资源一致。
- 多终端仍显示时进入设置，辅助功能树只有标题为“设置”的标准窗口 `ID: main`，没有独立设置窗口。
- 隔离签名应用的 `+` 显示“推荐 / 最近工作 / 插件和 MCP / 更多工具”，选择浏览器后创建同一任务的内容标签；内容标签右键菜单只有固定、面板移动和关闭操作，没有内容级“在新窗口中打开”。
- 最新隔离签名应用实际显示内容标签的系统拖动预览与“松开放到新窗口”提示；原生固定命令将同一浏览器标签加入“已置顶”，随后设置仍在同一 `ID: main` 窗口显示，Esc 返回后浏览器标签保留。
- 布局菜单实际隐藏并恢复标签条；浏览器移到右侧形成聊天加内容分栏，执行“交换左侧和右侧面板”后同一浏览器移动到左侧、聊天移动到右侧。
- 最终签名应用使用原数据目录启动后，标准窗口仍为 `ID: main`，任务“验证新输入框的真实构建”和草稿“这是一条待发送草稿，重跑后应保留”均保持；`⌘,` 将同一窗口切换为“设置”，返回后任务、选中标签和草稿不变。

内容标签菜单还支持“固定到侧栏 / 从侧栏取消固定”。固定项进入侧栏“已置顶”区，保存任务归属、标签种类、标题和浏览器恢复地址；关闭来源或重启后可从同一固定项恢复，不会被当成任务或项目置顶。固定项可在已置顶区排序，不能误移入普通分组。

## 仍需推进

主区、右侧、底部、新窗口、固定、已有聊天和新聊天的系统拖放及视觉落点已经接入。CUA 的合成拖动不能稳定完成 macOS 系统拖放所需的长按、移动与释放阶段，所以跨聊天释放以真实状态迁移测试、原生拖动预览和对象身份覆盖，不冒充人工释放验收。标签跨应用重启恢复和当前 Codex 的逐像素标签动画仍需后续配对。
