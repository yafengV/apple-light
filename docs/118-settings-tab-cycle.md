# 设置导航的 Tab 循环与焦点分区

2026-09-18。接续 [隐藏编辑器隔离](117-settings-hidden-editor-focus.md)，修复设置搜索、导航与表单文本字段之间的键盘循环。本轮没有改动系统的键盘导航偏好。

## 实现

- 22 个导航项完整参与布局，侧栏与右侧内容划分 SwiftUI 焦点分区，避免懒加载分组没有进入焦点顺序。
- 返回按钮、导航项和搜索结果可以聚焦，并通过空格或 Enter 激活。Tab 移动焦点时不改变当前页面；上下方向键继续切页，首尾不循环，修饰键不触发切页。
- 原生搜索框将 Tab/Shift-Tab 交给侧栏时，先结束自己的编辑响应，再由 SwiftUI 聚焦导航、搜索结果或返回按钮。无结果时保留原生 Tab 行为，仍可进入右侧文本字段。
- 从侧栏末尾继续沿原生顺序遍历表单；回到侧栏时先进入返回按钮与搜索，避免绕过顶部入口。第一项的 Shift-Tab 返回搜索。
- 不再需要零尺寸的 `SettingsNavigationKeyboardTarget`。导航实际按钮承担焦点、方向键和激活行为。
- 搜索交接保留输入法组合输入保护，禁用、隐藏和卸载后的搜索控件不发布旧输入或发起焦点跳转；排队的导航请求可失效。

使用公开的 SwiftUI 焦点接口，参考 Apple 的 [焦点交互文档](https://developer.apple.com/documentation/swiftui/view/focusable(_:interactions:)) 和 [焦点分区说明](https://developer.apple.com/videos/play/wwdc2023/10162/)。

## 验证

39 项设置、导航、布局与文本编辑回归通过，日志 `.cache/settings-focus-cycle-tests.log`。搜索 Tab 测试覆盖正反向交接、查询不变、组合输入、禁用、隐藏、卸载回调，以及未处理 Tab 时不提前取消原生编辑器。

通过 `script/build_and_run.sh --app` 运行最终构建，日志 `.cache/settings-focus-cycle-build.log`。原生 UI 核验：

- 正向：搜索 → 22 个导航项 → 个人资料的显示名称/用户名 → 返回应用 → 搜索 → 通用。
- 反向：通用 → 搜索 → 返回应用 → 用户名 → 显示名称 → 运行时 → 已归档任务。
- Tab 到通知时通用内容保持不变，空格激活后切换到通知；上下键切页，首项 Up 保持原页，Shift-Down 不切页。
- `browser` 搜索后 Tab 到首结果，Enter 跳到对应快捷键设置。Cmd-F 全选后输入可替换原查询。
- 空结果时 Tab 可以进入右侧快捷键搜索框；单条 `sleep` 搜索结果能够进入表单并回到返回入口，激活通用设置后也没有困在单条结果上。
- Esc 清空搜索，空搜索时继续留在设置；导航/结果上的 Esc 和返回按钮的空格激活均回到原任务。
- 任务 `验证新输入框的真实构建` 及原待发送草稿在重启和验收后保持不变。

## 剩余验收范围

本轮证明的是导航与表单文本字段的焦点衔接。各页的全部按钮、开关、弹出菜单，以及系统键盘导航开启/关闭两种模式，尚未逐项配对验收；当前默认模式下部分系统控件仍不参与 Tab。所有设置页和全产品 UI 仍不能标为与 Codex 完全对齐。
