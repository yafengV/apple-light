# 文件草稿保存失败时的窗口关闭与退出保护

日期：2026-10-09。继续推进 C15、M02、M14，补齐第 702 篇留下的关闭／退出写盘失败路径。原范围保持 47 类页面入口与 29 项核心功能，完整双端页面验收仍为 0/47。

## 已复现的问题

原生主窗口、任务窗口的关闭按钮没有等待文件草稿持久化结果。任务资源释放时，即使捕获失败，也会重置编辑器、停止终端；应用退出同样无条件继续拆除服务。先前“编辑器仍存活时可重试”的测试不能证明窗口关闭后的文本保留。

修正测试夹具的私有属性访问后，四个真实临时文件／隐藏原生窗口用例复现 13 条失败断言、0 unexpected，exit 1（`.cache/file-recovery-close-fixture-repaired-red-703.log`）。第一轮夹具编译失败单独保留（`.cache/file-recovery-close-red-703.log`），不当作行为失败。

## 实现与交互覆盖

| 动作／状态 | 实现与验证 |
| --- | --- |
| 主窗口原生关闭 | 先持久化主文件树和仍属于主窗口的文件编辑器；失败保留窗口及文本，显示错误；修复数据目录后再次关闭可成功 |
| 任务窗口原生关闭 | 同一窗口包括当前／后台任务的文件树及文件标签一起提交；失败不拆除编辑器、浏览器或正在运行的终端 |
| 分离文件窗口关闭 | 只校验该标签持有的编辑器；使用实际完整分离窗口验证失败阻止关闭和修复后重试 |
| 页面内关闭命令 | 任务页面返回主会话、窗口关闭命令、恢复失败页关闭、归档后的关闭以及分离窗口命令菜单，先调用同一保存校验 |
| 无关的干净窗口关闭 | 另一窗口的失败草稿不会阻止干净任务／浏览器窗口；主窗口不因分离文件窗口的失败草稿被误阻止 |
| 已捕获内容随后无法写盘 | 关闭校验强制确认持久化成功，不仅以候选记录等于内存记录判断已保存 |
| `NSWindow.close()` 强制路径 | 该调用绕过 `windowShouldClose`；在 `windowWillClose` 尝试捕获，失败则由 store 强持有编辑器模型，窗口资源仍可清理；数据目录修复后重试保存暂存文本 |
| 放弃版本后清理失败 | 保留具体版本的待清理标记；即使编辑器被释放，下一次捕获也先清理该版本，再合并当前编辑，避免丢弃内容复活 |
| 退出应用 | 一次候选事务捕获主／任务／分离与暂存编辑器；失败返回 false，不设置退出状态、不执行服务拆除回调。AppDelegate 回复取消退出，允许重试并显示主窗口错误 |
| 异步退出期间的编辑 | 成功捕获后设置可观察的退出状态，页面禁用交互；模型入口同时拒绝新的编辑／放弃／覆盖操作，防止备份后新增未捕获文本 |
| SwiftUI 窗口代理 | 集中代理桥保留原关闭否决，转发其他可选方法，并在卸载时恢复原代理；不覆盖后来安装的其他代理 |

没有新增恢复管理页面、系统权限或文件范围。未修改独立 API 配置或用户凭证。强制关闭后的备用保留是本次运行的内存暂存；磁盘持续不可写时，任意强杀进程／断电仍无法保证恢复，正常退出会被保存校验阻止。
