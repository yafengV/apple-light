# Codex 项目写入与审批回传

2026-09-26。此前 ShipiOS 的 Codex Core 会话固定为只读，无法完成项目内文件修改；即使 Core 发出命令或补丁审批事件，界面也没有回传选择的通道。

现在固定版 Core 使用 `workspace_write` 与 `OnRequest`。项目内普通命令写入按工作区权限执行；需要额外权限的命令会在任务时间线显示审批卡片，用户可允许本次或拒绝。Swift 经私有 Agent RPC 把选择送回同一 Codex 线程。补丁审批、补丁开始及结束事件也进入时间线；拒绝状态会保留。卡片共用现有工具审批的焦点、快捷键及任务待处理标记，Codex 卡片只提供本次允许或拒绝。

验证：本地假 Responses 服务驱动四轮 Agent RPC，分别覆盖文字回复、批准提权命令、拒绝命令、无需审批的项目内写入；批准后及普通写入均生成预期文件，拒绝时不生成文件。Swift 集成测试确认命令在卡片待处理时未执行，允许后执行且工具记录持久化。40 项模型传输回归、2 项时间线单元测试、7 项 Agent/IPC 测试、应用构建与签名校验通过。原生页面因桌面自动化接口超时仍未完成当前 Codex Mac 的逐项配对。

仍待完成：补丁审批的真实模型端到端回归；审批选项与上游 `available_decisions` 的逐项映射；命令输出增量、更多工具类型、结构化提问、运行中事件重放、完整页面与键盘/焦点/拖放验收。当前改动不能证明全产品 UI 对齐。
