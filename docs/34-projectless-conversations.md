# 无项目新任务与会话恢复

2026-09-17。依据：[OpenAI Projects and chats](https://learn.chatgpt.com/docs/projects#start-without-a-project) 的桌面部分明确允许不选项目开始会话。此前 ShipiOS 的发送按钮会打开文件夹选择器，模型请求也要求本地 Agent 已连接；这与无项目会话流程不一致。

## 实现

- 全局“新任务”及其快捷键进入无项目新任务；项目菜单里的新任务仍属于该项目。项目运行期间禁止切换作用域，避免丢失当前任务。
- 无项目输入可直接发送独立 API 模型请求。模型会话的运行条件与本地 Agent 分离，不创建虚假的目录，不自动把当前 shell 目录或用户主目录当成项目。
- 侧栏新增默认“任务”区域，展示未归档、未置顶且未移入自定义分组的无项目任务；置顶、分组、重命名、搜索、归档恢复复用同一任务组织方式。
- 会话支持流式回复、停止、追加消息队列、失败/取消保留队列、重新执行、分叉、查找与报告导出。队列自动续发的上下文仍属于原任务。
- 进入设置及返回保持任务和草稿。通知点击可定位无项目任务，不把空的项目标识转换成文件 URL。
- 项目与无项目页面之间的前进/后退保留各自历史和草稿；重启恢复上次所在作用域和所选任务，包括明确停留在未发送新任务的状态。
- 没有项目时，诊断、构建、终端、文件和审查操作不获得本地目录。模型回复中的网页链接可打开，文件链接要求真实项目根目录。

## 数据与兼容

`WorkspaceLibrary.lastWorkspace` 是可选字段：旧记录缺少字段时仍按之前最近访问的项目恢复；空字符串明确代表无项目页面。已有 `WorkspaceTask.project` 和 `AgentRun.project` 使用空字符串表达无项目所有权，所有将该字段转换成目录的入口都需要显式判断。无项目任务不会出现在 `projects` 文件夹列表中。

`projectSelections[""]` 记录无项目任务选择，`new:none` 保留原有无项目新草稿键。独立 API、密钥和模型配置沿用用户选择的 ShipiOS 设置，不读取用户 Codex 认证。

模型请求与本地 Agent 分开后，额外修正项目切换保护：即便 `connected == false`，仍在进行的模型请求也不能被切换项目清空。断开的本地 Agent 仍允许原有重新连接流程。

## 验证范围

新增 8 项无项目/作用域测试与 2 项真实 HTTP 流式测试，覆盖：

- 无项目历史、草稿与重启恢复，旧项目列表不被误打开；
- 新任务与已有任务草稿隔离；无项目模式不执行项目命令；
- 置顶、归档恢复、分叉及通知路由；
- 网页链接与文件链接边界；
- 模型在运行、Agent 未连接时的项目切换保护；
- 真实 Rust Agent 的项目 → 无项目 → 后退/前进 → 重启恢复；
- 真实流式请求及完整历史上下文、队列自动续发；
- 停止后保留部分回复及未发送队列。

针对性相关测试 42 项通过。最终 `./script/test.sh` 全部通过：183 项 Swift、12 项 Rust、fmt/Clippy 和真实 Agent IPC 冒烟，无失败或跳过。全量日志：`.cache/projectless-full-tests.log`，其中包含真实 Agent 往返用例。网络测试仅使用 `127.0.0.1` 临时 fixture，无需用户密钥，不访问外部 API；集成测试配置关闭系统通知。

原生应用已重新构建、签名并使用原开发数据目录 `.shipios-local/desktop` 启动，进程验证 PID 68199。日志：`.cache/projectless-launch.log`。

原生界面验证仍受 Mac 锁屏影响，未验证此次新增侧栏区域的视觉、焦点和鼠标行为。仍未实现多任务同时生成、Codex Core 自主工具循环、附件及完整插件/自动化等流程，不能将本轮无项目会话标为全产品交互一致。
