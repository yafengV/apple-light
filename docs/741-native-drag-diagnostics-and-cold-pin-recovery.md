## 原生拖放证据

临时在 `ContentTabDragSource.SourceView` 记录鼠标事件、窗口是否存在、系统按键状态及会话开始／结束，不记录标题、网址或令牌。首轮诊断构建因在多语句函数中漏加 `return` 失败，修正后标准构建启动通过，Swift 构建 15.90 秒；这个编译错误不归类为产品回归。

在实际主窗口中，将网页 B 的标题拖到 A 前：

- `mouseDown` 和跨阈值 `mouseDragged` 均到达，源视图仍属于窗口，创建了 `NSDraggingSession`，调用了源操作类型回调。
- 两个事件时 `NSEvent.pressedMouseButtons` 均为 **0**。观察期间没有正常释放完成回调，也没有重排；工具返回后出现拖放提示。
- 按 Esc 后收到 `endedAt`，操作为 **0（取消）**，完成对象存在；随后的实际辅助功能状态确认提示已清理。

这证明源入口及取消收尾执行，但不能证明目标接收或成功重排，也不能仅凭系统按钮值认定产品没有缺陷。工具事件时序是待排查因素，没有为了让自动工具通过而改写正常 AppKit 拖放。已提出真实鼠标尝试的可选反馈请求，尚未收到结果；第 740 篇的拖放条件仍为未通过。

临时源码及筛选后的六条事件保存在 `.cache/tab-drag-and-pin-741/{diagnostic-source.swift,native-events.json}`，原日志 `.cache/tab-drag-native-trace-741.jsonl`。结束时逐字核对产品源文件与 `git show HEAD:…` 一致，日志代码没有保留在产品或提交中。

## 页面错误与固定项恢复

本轮隔离实例先于自建回环服务启动，两个网页出现连接失败。启动服务后实际点击各页“重试”，两页均加载正确 HTML，错误页消失。这是本机服务错误恢复证据，不是用户 API 断流或服务错误验收。

在独立工作树窗口打开 A，将其固定到侧栏，再从网页链接打开 B；保存记录包含同一窗口身份、两页及 full 选择。正常 Cmd-Q 后标准冷启动，原独立窗口没有自动重开；点击固定 A 在主窗口的正确工作树任务重建网页，网址和原聊天草稿保留。保存记录确认固定项转为主窗口来源，原独立窗口布局仍存在。该行为与 `openPinnedWorkspaceTab` 的关闭来源重建分支一致，不能表述为恢复原独立窗口全部标签。

另建独立窗口，保存两个网页、选中 B 和 split 布局，再通过标准脚本 TERM 重启。主窗口恢复可见，但随后读取系统 Window 菜单时，工具持续报告控件索引失效、截图不可用；重连及重置工具未能恢复该次菜单操作。没有完成对原独立窗口是否恢复的可靠核对，也没有将之前第 738 篇另一次成功恢复当成本次通过。原窗口身份及布局留存只证明保存，不证明它已显示。没有修改系统窗口恢复选项或归因于锁屏。
