实际输入是 `type=text` 单行控件，初始值为空，placeholder 为当前变体分享文本，自动聚焦且关闭拼写检查。`ua` 没有 form、输入 onSubmit 或 onKeyDown，所以输入框内 Return 不直接提交；激活已聚焦的按钮仍提交或取消。Tab/Shift-Tab 按输入、取消、有效时的导入、关闭按钮循环。共享 Radix modal 的焦点循环和 Escape 关闭可从分发实现核对。

另一个容易误推的细节：`ua` 没有 DialogTrigger，实际 `Tui` 关闭处理 preventDefault 后只尝试 triggerRef，而此处没有目标。因此没有增加自动返回“导入”按钮的逻辑。Cmd-W 也没有新建导入框专属处理；系统窗口关闭行为仍需实机配对。原生输入法组合状态下先交给文本系统处理 Escape/Return，不能将隐藏窗口测试当作完整输入法实机验收。

## 实现

短期 `AppearanceThemeImportSession` 只保存变体、身份与草稿，不持久保存输入，也不保存原生窗口或控件。任何关闭都会清空草稿；切页、离开设置或主题模式隐藏所属变体时结束会话。回调按当前身份、页面、加载/恢复状态和所属窗口重新检查，旧弹层不能修改或关闭新弹层。

弹层由 `AppContentView` 最外层呈现，背景禁用点击、导航命令与辅助功能访问；没有创建新窗口或 sheet。原生桥只负责单行输入、按钮、键盘循环和窗口内装饰。输入撤销、选区与横向编辑沿用原生文本系统；UI 字号控制输入的 13 基准字号，代码字体只提供 family/face，代码字号不改变输入字号。

无效分享文本禁用提交；保存失败保持输入、选区、焦点和当前主题，显示“无法导入 浅色/深色 主题”通知。成功仅修改指定变体，清空并关闭弹层，显示“已导入 浅色/深色 主题”。错误不会额外覆盖设置页的原有错误。任务草稿保持不变。主题复制成功显示实际中文文案；没有在测试中写入用户的系统剪贴板。

辅助功能中的 dialog 框使用居中卡片范围，实际交互遮罩仍覆盖主窗口。按钮和输入独立可访问；标题通过 dialog 标签提供。
