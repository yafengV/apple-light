# 主窗口连接设置与 SSH 主机发现

2026-09-17。依据 [OpenAI 远程连接文档](https://learn.chatgpt.com/docs/remote-connections) 增加“连接”设置分类。官方流程在“设置 > 连接”中区分控制本机、控制其他设备和 SSH，并从 OpenSSH 配置发现显式主机。ShipiOS 的设置继续作为主窗口页面显示。

## 当前实现

- 设置侧栏新增“连接”，页面包含“控制此 Mac / 控制其他设备 / SSH”三个分区。进入和离开分类不会创建第二个标准窗口，Esc 返回进入设置前的任务、插件或自动化页面。
- “控制此 Mac”显示当前本地运行时与数据驻留边界；“控制其他设备”明确显示账户安全中继尚未接入。
- 只有用户实际打开“连接”分类时才读取 `~/.ssh/config`。解析器列出不含通配符、否定符或选项前缀的显式 `Host` 别名，去重并保持配置顺序。
- 每个别名通过 `/usr/bin/ssh -G -- <alias>` 交给系统 OpenSSH 解析，页面显示有效的用户、主机和端口。ShipiOS 不读取私钥内容，也不复制 SSH 凭据到自身数据目录。
- “测试连接”使用 `BatchMode=yes`、5 秒连接超时和一次连接尝试，执行固定的无副作用输出命令；不会弹密码输入或保存密码。结果限制为 500 个字符显示。
- SSH 配置超过 2 MiB 或不是 UTF-8 时拒绝读取，并在页面显示错误和重新扫描入口。

## 验证与边界

`ConnectionTests` 覆盖显式别名/通配符/否定项处理、顺序去重、OpenSSH 输出映射、缺失配置、2 MiB 上限，以及从自动化页面进入设置后返回原页面并保留草稿。

完整回归通过 322 项 Swift 测试、12 项 Rust 测试、Rust fmt/Clippy 和真实 Agent IPC 冒烟，日志记录在 `.cache/connections-full-tests.log`。

macOS 当前锁屏，无法用 CUA 检查新增分类的实际布局、焦点顺序和 Esc。本轮没有对真实 SSH 主机发起连接，也没有修改用户的 SSH 配置。
