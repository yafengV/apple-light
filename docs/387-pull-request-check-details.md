# PR 检查详情

PR 页面新增独立、可折叠的检查区域。每个检查显示实际名称和状态，有有效详情链接时可以打开；读取失败和部分数据缺失分别显示错误或提示，不再把未知、缺失数据显示成成功或没有检查。

这是已安装版本的源码证据，不能替代原生页面和操作验收。Codex 的失败检查 Fix/Remove/Fix all 与自动修复入口也已发现，本阶段尚未接入该任务上下文链路，不将它们计为完成。

GitHub 数据读取依据 [检查运行 API](https://docs.github.com/en/rest/checks/runs#list-check-runs-for-a-git-reference)、[提交状态 API](https://docs.github.com/en/rest/commits/statuses#get-the-combined-status-for-a-specific-reference)及 [GitHub CLI 分页说明](https://cli.github.com/manual/gh_api)：读取最新检查运行与组合提交状态，每页 100、每源最多 20 页，并读取检查套件上限。组合提交状态保留 context 拼写，检查运行按 ID 区分；重复或总数漂移标记不完整，保留已验证的结果，不丢弃名称相同但身份不同的检查。

## 实现与边界

- 检查运行和旧式提交状态分别读取，同步后合并列表。两种来源都成功且页数/总数完整时才标记完整；一项失败保留另一项的有效数据，两项失败显示错误。缺少分页、损坏响应或错误提交数据不显示成“没有 CI 检查”。
- 请求绑定实际任务、工作目录、PR 和显示的头提交。先验证 PR，再读取该不可变提交的检查，最后复查头提交及两端分支。变化后的重试先刷新 PR 状态，旧任务、取消和迟到读取不能恢复旧页面结果。
- 详情链接使用现有所属任务的网页路由及应用内/系统浏览器偏好；无链接的行保持普通内容。非网页协议或包含凭据的 URL 不成为可点击链接。
- 检查状态与 PR 合并资格分开读取；本阶段没有替换第 385 篇的 GitHub 合并预检查及服务端提交匹配保护。
- 页面打开期间，开放 PR 的待完成、未知或不完整结果每 15 秒重新检查，普通结果每分钟刷新，读取错误每分钟重试；应用未激活时跳过，重新激活时刷新。关闭、切换任务或头提交改变取消旧读取；关闭/已合并 PR 跳过检查 API 并停止周期检查；检查读取发现 PR 状态变化时，另行刷新 PR 元数据，以更新页面状态和合并资格。完整 PR 发现、持续状态监控与自动修复仍未完成。
