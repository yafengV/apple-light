# 浏览器标签拖排与批量关闭

2026-09-17。本轮继续对照当前 Codex 应用包的静态命令资源，补齐浏览器标签的拖动排序和标签右键关闭动作。

## 已实现

- 标签可在同一个浏览器面板中直接横向拖动；跨过相邻标签阈值后按拖动方向和距离排序。
- 拖动阈值和跨越数量使用当前标签的真实宽度计算，短标题、长标题和连续跨越多个标签采用相同规则。
- 排序只移动标签身份，不重建 `WKWebView`，因此页面表单、滚动、历史、地址草稿及加载状态继续属于原标签。
- 排序期间当前选中标签和地址栏焦点目标保持同一个 UUID。
- 标签右键菜单提供“关闭标签页”“关闭其他标签页”“关闭右侧标签页”；不可执行的批量动作会禁用。
- 批量关闭通过既有 `BrowserTab.close()` 生命周期执行，清理下载、WebKit delegate、观察、菜单目标和窗口回调。

## 自动化验证

`BrowserTests.testTabDragOrderingAndBatchCloseKeepExactOwnership` 覆盖：

1. 小于拖动阈值时不排序，跨过阈值后可向左或向右排序。
2. 四标签跨越排序后的精确 UUID 顺序。
3. 选中项和地址栏焦点归属保持。
4. 自身/未知目标不产生排序。
5. 关闭右侧和关闭其他标签时的顺序、选中项及关闭生命周期。

浏览器定向测试现为 24 项，全部通过；签名 `.app` 的原生拖动、菜单可见性和设置返回状态也已完成验收。

## 原生验收

在签名后的 `ShipiOS.app` 和隔离数据目录中，使用本地 WebKit fixture 完成了以下真实交互：

1. 建立 `One`、`Two`、`Popup` 三个标签；末尾标签的“关闭右侧标签页”保持禁用，中间标签的同名动作可用。
2. 从 `Two` 执行“关闭右侧标签页”后只移除 `Popup`，并选中 `Two`，其 URL 与页面内容保持。
3. 真实鼠标把 `One` 向右拖过 `Two` 后，标签顺序从 `One, Two` 变为 `Two, One`；当前选中的 `Two`、地址和 `WKWebView` 内容没有变化。
4. `⌘,` 在同一个 `ID: main` 标准窗口中进入设置，`Esc` 返回后仍为 `Two, One`，选中页和地址保持。

原生验收还发现并修复了短标题标签无法落到右半侧的问题：固定 70pt 落点判断已替换为按真实标签宽度计算的直接横向拖动。
