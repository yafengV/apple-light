# PR 小号 Markdown 排版与实际六行裁剪

日期：2026-10-04。本阶段接续第 590、591 篇，把根评论的固定 120 点预览改为实际文字行位置，并修正评论/回复的小号 Markdown 排版。它不代表 PR 整页或全产品已经完成双端验收。

## 参考依据

参考版本 26.930.21537（12776）。只读取随应用分发的公开界面资源，没有读取个人配置、认证或历史。精简 CSS 规则、源哈希和浏览器测量事实保存在 `pr_comment_markdown_reference.json`，原资源及临时 HTML 留在忽略缓存。

`pull-request-comment-ae0822c719d2.js` 的实际根正文与线程回复渲染函数都传递 `textStyle: small`。沿共享 Markdown 组件确认使用当前匹配的 `app-initial-341eb5dd9ad5.css`，不是旧 CSS 模块。Electron 小号字号为 13；Markdown 行高为字号乘 1.625，间距单位为字号除以 4。小号 Markdown 使用 `text-sm`，不会随聊天字号同比放大，但保留选定内容字体。

`pull-request-readonly-comment-5934b5e08be0.js` 的富文本正文使用 `line-clamp-6`。其展开状态来自共享模块 `Tx` 导出的 `xTi`，通过 `CTi` 比较内容 `scrollHeight` 与外层继承行高乘 6 的向上取整值，容差为 1。它没有按 Markdown 块数决定是否提供按钮：恰好六个高标题也可能提供展开按钮，展开/收起时正文高度不变。外层高度判断与 CSS 实际裁剪是两套规则，不能合并成固定 120 点或“超过六个块”。

在仅监听 loopback 的本地 HTML 中加载公开 CSS 的相关规则，用语义段落、列表、引用和标题测量；这是样式夹具，不是 Codex 真实页面或账户数据。默认 13 点、宽 500 点的结果如下（不含展开按钮）：

| 内容 | 六行裁剪高度 | 完整高度 |
| --- | ---: | ---: |
| 一段内十行 | 126.75 | 211.25 |
| 十个独立段落 | 191.75 | 328.25 |
| 十个列表项 | 126.75 | 211.25 |
| 十行引用 | 139.75 | 224.25 |
| 六级标题各一行 | 172.25 | 172.25 |
| 一项含两个段落、其余八项 | 139.75 | 224.25 |
| 三层列表后接七项 | 126.75 | 211.25 |

三级列表的样式为 disc / circle / square，正文相对根起点分别为 26 / 52 / 78 点。引用正文用正常文字颜色，左边线映射 `border-strong` 的实际 `borderHeavy` 角色；上下留白各 6.5 点，左侧 19.5 点。

## 实现与验证

PR 小号段落、标题、列表和引用使用专用排版，按参考 CSS 合并相邻外边距。标题字号保留 19.5、16.25、14.625 等小数，行高分别为 26、22.75、22.75、19.5、21.125、21.125。列表取消额外项间距，补齐同一项内段落间距和嵌套标记。

原生只读 `NSTextView` 保留选择、链接、粗体/斜体/删除线和内联代码字体，报告实际排版后的行矩形；根评论按第六行所在位置裁剪，计入引用容器的留白。宽度变化重新测量；更换正文先清理旧测量，迟到的旧正文回调不影响新内容。回复及编辑/非空回复草稿保护的正文仍完整显示。展开按钮保留独立高度判断与 14 点字号、20 点行高、6 点顶部间距。普通会话继续使用原渲染器。
