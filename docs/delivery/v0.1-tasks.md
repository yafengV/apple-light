## 3. 每项任务的固定工作方式

1. **开始**：写本项目标、对应 A 编号、已有证据、具体差异、预计有效时间；只处理本项或阻断它的共用问题。
2. **开发**：做最小必要改动。没有缺口就直接验收，不为增加代码量重构；对无关 P2 记后续事项。
3. **自动验证**：选择实际受影响用例，记录命令、输入、执行数与终态；有失败先诊断，不能临时排除以取得通过。
4. **实际验收**：标准脚本启动正式包，在解锁 Mac 上操作本项页面；要求真实服务的项目另外保留真实 API 证据。
5. **交付**：更新同一验收表和证据索引，检查 diff 与磁盘，只提交本项已验证文件，及时 commit／push，记录 hash。
6. **下一项**：报告当前任务终态、通过的 A 编号、未解决问题和下一项；一次只有一项标为开发中。

有效工作时间与锁屏／等待配置时间分开记录。单项达到估算上限还未通过时，必须给出具体失败与修订估算，不静默越过或无限打磨。新功能改变范围时先让用户决定；原范围内修复和测试继续按已有授权推进。
