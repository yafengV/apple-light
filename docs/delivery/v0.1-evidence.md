## 23. T06 真实 Core 恢复集成自动验证

本组从 `d482887f` 开始，仅新增 `WorkspaceRecoveryIntegrationTests.swift`，没有产品源码修改。上一轮工具已明确报告锁屏，本轮没有收到新的解锁回复，因此没有尝试正式窗口或用隐藏窗口代替验收。独立临时数据根、原工程文件及无凭据 loopback 模型服务由每个测试创建并回收；使用真实 helper 和固定 Core。包装入口只记录自有 helper 的 PID、项目及数据根，然后 exec 同一 helper；SIGKILL 只作用此独立根内对应作用域的当前 helper，不全局查找／结束进程。

### 新增的三个用例

| 用例 | 必须满足且最终实际满足的结果 |
| --- | --- |
| 两个真实 Core 聊天 → 文件草稿 → shutdown → 新 store.restore | 聊天及 Core 线程 ID 不同；恢复到原项目／聊天，保留两条会话草稿、非当前聊天未读、文件标签和未写盘的中文草稿；任务／回合 ID 不变，源文件不变；冷恢复没有模型 POST，再次打开不重复标签，只有显式续聊产生一条新 POST，继续原 Core 线程 |
| 本地 Agent SIGKILL → 明确重连 → 冷恢复 | 有界结束连接等待并显示 Agent 退出，原工程／聊天／文件草稿不变；显式重连不重发回合；之后与上一用例相同的持久化和原线程续聊断言通过 |
| 流式 Core Agent SIGKILL → 失败 → 冷恢复 → 显式续聊 | 使用先发真实文本 delta、延迟完成的服务夹具，先断言回合仍 active 再结束对应 Core helper；5 秒内变为 failed，保留非空部分输出及错误，live 请求清零；会话／文件草稿和原文件保留；冷启动不自动重试，显式续聊复用原 task／Core thread，准确增加一次请求和回合 |

文件草稿使用产品现有的未保存关闭流程暂停 3 秒 autosave，保持未决操作；没有关闭产品保存逻辑或篡改磁盘基线。测试没有挂载 WorkspaceView，因此明确调用产品页面既有的文件作用域初始化和 selection 变化后的标签恢复方法，分别对应 `FileWorkspaceTabView.task`、`WorkspaceView.onChange(selection)`。不把这些模型操作当成真实窗口按钮／键盘操作。这里的 shutdown 是 store 生命周期调用，**不能替代 A10 的正式菜单退出／重启**。
