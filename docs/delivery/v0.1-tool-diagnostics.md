## A09：已确定的环节与尚未确定的原因

| 检查 | 结果与证据限度 |
| --- | --- |
| 应用标识 | NotificationCenter 为 `com.apple.notificationcenterui`，通知相关四个系统进程均存在，之前目标标识没有拼错 |
| 系统进程 | 一秒采样中 NotificationCenter 主线程持续在 AppKit／CFRunLoop 等待事件，未见忙循环；短时采样不能证明所有时刻都无挂起 |
| 普通应用通道 | ShipiOS 当前工作区可读取；正式包 strict deep 签名验证通过，未修改签名或系统权限 |
| 用户展开面板 | 用户说明回到聊天会收起面板，改为无需回复、展开后等待十秒读取；调用成功，但绑定的是天气组件窗口，没有 ShipiOS 通知节点 |
| 窗口枚举 | 展开后系统窗口清单仍超时并重置 REPL；没有得到能选择的正确通知窗口，工具未暴露进一步超时诊断接口 |
| 系统通知设置 | ShipiOS 已允许，桌面／通知中心／锁屏和声音开启；原提醒样式为临时，按用户已有临时验收授权改为持续，验收后必须恢复 |
| 屏幕共享 | 全局为镜像／共享时关闭通知，但用户明确回答当前没有共享或投屏；本轮不调整该全局设置，不能把它确定为实际抑制原因 |
| 后台任务 | 自有 t27-diagnostic-completion 成功，用户反馈未看到；原后台策略下由用户确认应用不在前台再释放 t27-background-control-completion，用户仍未看到 |
| 系统对照 | 应用内发送测试通知，系统接受，用户确认看到了；系统呈现至少有一条可用路径 |
| 时机对照 | 仅自有实例临时选择始终，t27-always-completion 通知用户看见并实际点击，工具随后确认正确任务／回合；返回 t27-other-ready 草稿完整，原后台选项已恢复 |

后续临时日志取得两个不同结果：t27-trace-completion 在 180 秒门闩上限到达时 `active=true`，被原后台策略在权限检查前过滤；用户“释放诊断”回复晚于该任务终态，不能将其视为已确认后台的试验。通过原生菜单“Hide ShipiOS”并实际点击系统设置“通用”后，t27-menu-background-completion 的日志为 `active=false`、权限 authorized、系统接受；用户确认看见并点击，实际窗口选中正确回合 `9CDA79CC-D9DD-4654-A766-1E412ED523C5`，返回来源聊天仍为 t27-preserved-draft。后台模式已有真实可见／点击证据；不能继续写成只有始终模式可见。

这确定了一个前台状态过滤案例和一个正常后台投递案例，尚不能解释所有较早未出现的通知，原负向反馈保留。系统面板读取／窗口选择的工具限制也未解除，没有据此修改通知业务规则。临时诊断日志已撤回，2477 个绑定输入全部与已通过候选相等；通过标准入口重新构建 exit 0、strict deep 签名验证通过。ShipiOS 系统提醒已实际恢复为“临时”，允许／桌面／通知中心／锁屏／声音保持，全局共享等设置未改。

正式无插桩构建使用原后台策略再次完成 t27-clean-background-completion（`2DB33AEC-30EF-4D56-85F4-288E156EF3F4`），仅服务端释放后不再读取／激活 ShipiOS；用户明确看见并点击，工具核对正确选中回合和完整回复，返回来源草稿完整。这次绑定正式构建与原临时横幅样式，不把临时插桩产物冒称同一工件。六个本轮受控请求均 completed，自有服务及日志采集已按完整命令核实后停止；原用户实例已通过标准入口恢复、实际点击输入框焦点可用，七类保护字段、九回合及模型文件哈希保持。2477 输入相等，严格签名和预算通过，A09 本项通过。系统读取限制与旧未出现反馈作为已知诊断限度保留，不称所有原因解决，不再重复生成对照通知。
