# 分离窗口搜索的跨项目导航与置前时序

2026-09-26。接续 [第 180 篇](180-detached-window-search.md) 的未验收项。原生操作发现：从 A 的分离网页搜索选择 A 任务时，主窗口虽然切换到 A，前台却可能落到同任务的另一个分离网页。

## 修复

跨项目任务选择新增可等待的入口。它在目标项目连接、任务重新校验和任务选择完成后才返回；分离窗口搜索此时再请求主窗口置前。主窗口请求先交给 SwiftUI 创建或恢复，随后在主线程下一轮解除最小化并设为键窗口，避免同一轮恢复的其他内容窗口覆盖它。同项目选择仍直接执行，普通侧栏任务选择继续使用原入口。

## 验证

新增真实双项目 Agent 测试：A 分离网页、B 当前项目，选择 A 后观察主窗口回调，确认回调发生时项目和任务均已切至 A，原分离标签归属不变。分离搜索、项目导航、命令搜索与网页子窗口相关共 26 项通过，0 失败；日志保存在忽略的 `.cache/detached-search-cross-project-tests.log`。通过 `script/build_and_run.sh` 构建运行。

原生隔离工作区中，以本机 HTTP 页面建立 A 的 Alpha/Delta 分离窗口和 B 的 Beta 主窗口网页：

1. Delta 的命令搜索输入 `Alpha` 并回车，前台切到已有 Alpha 窗口。
2. Alpha 命令菜单切到本窗口任务搜索，选择 B，主窗口显示 B 网页。再次从 Delta 搜索选择 A，修复后前台为 `ID: main` 的 A 聊天页，原 `A 审查草稿` 仍在。
3. B 网页输入 `B stays while switching`，从 Delta 命令菜单搜索 `Beta` 并回车，主窗口回到 B 的原标签，网页输入值保持。

这证明本轮的任务结果和附着/分离网页结果路由已经完成对应原生检查。终端与审查窗口组合、完整拖放、所有键盘/输入法边界和当前 Codex 全页面配对仍待继续。
