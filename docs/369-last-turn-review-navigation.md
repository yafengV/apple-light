# 最近一轮审查的快照入口

## 对照与已有差异

[官方审查文档](https://developers.openai.com/codex/app/review)将 Last turn 定义为最近一次助手回合的变更，并说明多目录项目的此范围汇总已附加仓库。之前 ShipiOS 只有未暂存、已暂存、提交和分支四个范围；Core 的精确回合差异仅可从聊天卡片查看。

本阶段接入最近一轮的浏览、逐文件统计、评论和路径归属，不将当前 Git 工作树差异当成助手改动。项目的多目录/多仓库选择、Last turn 的当前 Codex 暂存与撤销行为，以及完整原生页面配对仍需继续，不能将本阶段称为 Last turn 的全部交互已对齐。

## 实现

审查范围与默认范围可选「最近一轮」，按当前任务的回合顺序读取最近模型会话。无差异的最新回合显示空状态，不回退到较早有变更的回合；整理上下文的记录不覆盖最近助手回合。主窗口使用当前选中任务，独立任务与分离审查固定原所有者，分叉历史沿用现有任务历史读取。

使用私有完整快照及字节数/SHA-256 校验，按文件解析、统计和显示差异。完整读取和逐行解析在后台完成，浏览不会受到当前文件或索引变化影响。流式差异更新和空差异更新会改变观察身份并重载，失败保留实际错误和刷新入口，不使用截断预览冒充完整差异。

新回合差异首次进入记录时保存路径基准，后续更新保持原基准。固定 Core 当前以最近 Git 元数据的祖先目录为基准，无 Git 标记时使用回合工作目录，代码依据为锁定来源的 `session/turn.rs::turn_diff_display_roots`。文件打开使用该快照的路径，评论保存原回合标识、原路径基准和文件快照指纹；后续发送检查任务归属与快照，不把移交后的任务目录当作旧差异基准。

旧快照没有保存路径基准时继续展示精确内容，但不按当前 Git 标记或任务目录猜测原基准，文件打开与行内评论禁用。文件打开前同时检查已显示快照与当前任务来源，避免任务已切换而视图尚未更新时打开旧文件；评论还校验具体代码行及行号。

历史快照目前使用现有历史范围的写入禁用策略；当前工作区的暂存与撤销仍从未暂存/已暂存范围执行。是否符合当前 Codex Last turn 的实际动作、状态和键盘语义尚未取得双端证据，继续保留为缺口。

最近一轮范围独立于 Git 索引读取；切回普通范围时重新读取仓库状态。请求带有工作区代次、请求标识和来源身份，任务或项目变化时旧读取结果不能恢复旧快照。草稿、文件预览和任务执行目录保持原归属。范围在已有主窗口、任务窗口和分离审查的布局持久化中保存。

## 验证记录

首次编译因 Models 与 Stores 内两个 `LastTurnReview.swift` 文件生成相同对象名失败，见 `.cache/last-turn-review-compile.log`。存储动作文件改为 `LastTurnReviewActions.swift` 后继续验证；没有并行修改编译中的源文件。

初次 85 项相关回归全部通过，日志 `.cache/last-turn-review-related.log`。进一步收紧旧数据路径基准、来源切换期间文件打开以及评论具体行校验后，新增集合包含 11 项最近一轮用例；最终 144 项相关回归全部通过、无跳过，覆盖审查、读取恢复、仓库初始化、批量动作、评论、主/任务/分离窗口及标签恢复，日志 `.cache/last-turn-review-final.log`。

实际 Core 补丁测试额外验证路径基准、最近一轮完整快照与重启恢复，1 项通过，日志 `.cache/last-turn-review-core-final.log`，合计 145 项不同测试。第一次扩展断言误用不存在的 `developer` 属性，编译失败记录在 `.cache/last-turn-review-core.log`；确认终态后修正为已有 `workspace` 并重跑通过。

通过 `./script/build_and_run.sh --build-app` 构建应用，日志 `.cache/last-turn-review-app-build.log`；`codesign --verify --deep --strict --verbose=2 dist/ShipiOS.app` 及 `git diff --check` 通过。本阶段没有启动验证，不把构建与签名通过描述为工作区可交互。

本阶段没有取得当前 Codex 与 ShipiOS 的双端原生截图、点击、焦点及快捷键验收；完整配对仍为 0/45。
