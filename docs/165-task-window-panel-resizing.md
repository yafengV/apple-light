# 独立窗口面板尺寸与左右交换方向

2026-09-19。

## 问题与改动

主窗口已有可调整分割线，独立窗口却使用固定比例侧宽和固定范围终端高度，缺少同类交互。另一个实际问题是：主窗口把内容面板交换到左侧后，分割线仍按右侧面板计算鼠标和方向键增减。

- 独立任务窗口的文件、浏览器和审查侧面板共用可调整宽度，底部终端支持调整高度。使用现有原生 `PanelResizeHandle`，支持鼠标拖动、方向键、辅助功能数值调整及双击恢复默认。
- 主窗口和独立窗口均根据内容面板实际所在侧计算拖动及方向键方向；辅助功能“增加/减少”仍表示增加或减少尺寸，不随物理位置反转。
- 独立窗口尺寸由该窗口逐任务持有，任务往返和面板显隐保留，其他窗口和主窗口项目尺寸不受影响。沿用主窗口尺寸约束，缩小窗口只限制显示值，不覆盖用户设定。
- 调整尺寸不重建浏览器或终端资源。独立窗口尺寸尚未跨应用重启持久化，该项随通用布局恢复继续推进。

新增 6 项真实 AppKit 事件与模型测试，覆盖左右两侧拖动方向、拖动累计误差、方向键与辅助功能含义、底部高度与边界、双击复位后不会遗留拖动、按窗口和任务隔离、真实终端身份及非有限尺寸保护。

专项 11 项通过；最终 `PanelResizeInteraction|PanelLayout|TaskWindow|WorkspaceTab|TerminalHostFocus|TerminalSession` 范围 95 项测试通过，0 失败。日志 `.cache/task-window-resize-tests.log` 与 `.cache/task-window-resize-final-tests.log`。

## 原生 macOS 验收

使用项目脚本构建隔离工作区，实际操作确认：

1. 独立窗口侧面板初始宽度 380，左方向键增加到 400，鼠标向右拖动缩至 350，双击恢复 380。
2. 交换左右后，右方向键增加到 400，鼠标向右拖动增加到 420；画面确认文件面板位于左侧。
3. 底部终端初始高度 235，上方向键增加到 255，向上拖动增加到 295，双击恢复 235。再次调整到 275。
4. 通过命令搜索切到任务 A，再后退回任务 B，侧宽 420、高度 275、左右位置及草稿保持。终端输出 `AFTER:kept`，调整及导航前后 shell PID 均为 `82709`。
5. 关闭独立窗口后 PID `82709` 已退出。主窗口交换左右后，右方向键将宽度从 433.5 增至 453.5，鼠标向右拖动增至约 484，方向与实际分割线移动一致。

这些是 ShipiOS 原生行为证据，不代表当前 Codex 版本的精确尺寸、动画或全部布局配对通过。
