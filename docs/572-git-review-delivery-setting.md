# Git 设置中的审查结果呈现方式

当前 Codex 的 Git 设置包含 Review delivery：Inline 优先在当前聊天运行审查，无法使用时创建独立审查任务；Detached 始终创建独立审查任务。ShipiOS 已有对应的 `ReviewDelivery` 偏好与 `startCodeReview` 分流逻辑，但 Git 设置页没有入口，设置搜索原先还将“审查结果呈现方式”错误指向通用页。

现在 Git 设置页提供“内联／单独”原生菜单。选择后经现有 Git 偏好保存路径写入工作区配置，并直接影响下一次审查的任务归属；设置搜索会跳到 Git 页并定位控件。保存错误显示在同一设置分区。

原生隐藏窗口测试操作了实际菜单，验证选项、写入、重载持久化以及搜索导航；设置与导航相关 **43 项测试通过**。另外，内联当前任务和独立只读审查两项模型夹具测试通过，合计 45 项。`script/build_and_run.sh --build-app` 构建和严格深度签名通过。当前 Mac 桌面控制接口超时，未取得前台可交互工作区或 Codex 与 ShipiOS 双端点击、焦点、视觉配对证据。主工作区 21 项、设置页 26 项完整配对仍为 **0/47**；该数字表示待验收面，非确认缺陷数。Git 设置中的 PR 监控与自动修复等参考功能仍需单独实现和验证。
