# 全局快捷键在批量恢复中的原子交接

日期：2026-10-09。接续第 686 篇共享命令映射，范围为 S02 语音、S13 快捷键与宠物／弹出窗口的系统级组合登记。

## 缺口与依据

第 686 篇已确认语音页和通用页使用共享命令映射；已核验的通用页批量恢复操作为 `reset-codex-command-keybindings`。这些参考仅证明共享映射和恢复入口，不证明 Codex 内部使用 Carbon 或采取与本项目相同的事务实现；新版通用整页仍待配对。

本项目逐个准备新登记，会把同批次中即将由其他命令释放的组合当作外部占用。新增两项红测试分别交换语音绑定、宠物／弹出窗口绑定，均出现真实 Carbon 占用错误，日志 `.cache/global-hotkey-transfer-red-687.log`。因此“恢复全部默认”虽然能一次写入设置，仍可能无法将语音占用的组合交还给恢复后的宠物默认值。

## 实现

- `AppGlobalHotKey.prepareRegistrations` 先检查同批次重复命令／重复组合，再复用批次内现有的原生登记；其他应用或批次外命令的占用仍拒绝。两项交换及三项循环不提前注销旧组合，也不通过先清空再登记制造失败窗口。
- Carbon 事件路由随登记独立存活，提交后转交给新命令。旧命令对象释放不会注销已交接的组合；清除新命令只释放它目前持有的组合。交接与新组合并存时使用不同事件标识，避免不同命令共用路由。
- 候选登记、全部原登记和事件归属在保存之前保持；磁盘保存或后续候选失败时只释放新候选。保存成功后统一更新所有权及注册代次，再释放未使用的旧登记。重复提交不会重复释放，保留已提交事务对象也不会继续占用已清除的组合。
- 宠物、弹出窗口和三种语音模式共用一个保存计划。“恢复全部默认”使用候选通用快照验证语音绑定；批次内从语音交还给宠物、从宠物交给语音或弹出窗口均能复用现有登记。工作区只写入一次，成功后才发布快照；原独立配置对象仍保留原存储流程。
- 按住过程中转移组合，重复按下不能启动新命令，对应松开仍交给原动作／录制会话。已排队但尚未执行的旧输入由注册代次保护；下次完整按下进入新命令或当前录制框。保存错误及外部占用仍归属实际失败行。
