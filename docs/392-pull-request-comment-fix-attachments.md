# PR 审查线程 Fix、修复说明与消息附件

PR Activity 新增单线程 Fix 与整体 Fix all/Remove。附加未解决且具有有效代码位置的审查线程，包括原评论和全部回复；可以逐线程添加可选修复说明、移除或全部移除。点击只准备所属任务的草稿，不自动发送、不执行 Git 写入。

## 实现及边界

- 仅未解决、有相对文件路径、正行号和 LEFT/RIGHT 代码侧的代码审查线程可附加。无行号/代码侧、已解决或非代码评论不会进入修复集合；过时但仍有位置的线程可附加，提示要求先核对当前文件和状态。保存原位置、起始位置、差异、作者、原文、全部回复和可选说明。
- 单项 Fix 附加该线程；整体 Fix all 补齐当前可修复线程，全部已附加后整体按钮变为 Remove。移除不依赖添加资格，按当前 PR 范围处理。已附加的线程保留折叠浏览和说明表单，新的评论操作入口隐藏；既有编辑/回复草稿保留。
- 评论 Fix 保持 PR 页面焦点。默认提示只填入空输入或替换此前自动生成的提示；手写正文保持原样。最后线程移除后仅清除未修改的评论自动提示，其他评论附件或手写内容仍保留。检查 Fix 沿用自身提示和聚焦规则。
- 主窗口与独立任务窗口的输入区都有可展开的评论附件列表、可选说明和移除按钮。说明仅在内容变化后保存并去除首尾空白；Enter 保存、Esc 恢复，保存按钮对未改变的内容禁用。实际原生键盘投递和焦点尚未验收。
- 同任务/同 PR 的线程与失败检查可共存，按各自身份去重，重复添加不清除说明。切换到另一 PR 的 Fix 替换两类 PR 附件；其他任务保持独立。添加前重新检查当前分支；异步读取期间页面、范围、草稿或附件变化，以及取消，均不能覆盖新输入。
- 只读审查偏好允许准备模型消息，实际代码操作继续受原有会话权限控制。关闭 PR、错误分支、缺失任务、归档、移交或工作区不匹配不能附加。保存失败不部分安装附件、说明或删除结果。
- 主/独立任务窗口发送、冻结队列、队列编辑与派发、运行中 Core 引导均携带完整线程上下文。旧排队消息不能消耗新草稿；配置或保存失败保留未发送内容。两种模型协议都会收到正文、回复、位置和说明；记录与后续会话历史保留这些上下文。
- 沿用原 `PullRequestCheckDraft` 存储容器及 `pull_request_checks` 请求字段，扩展评论集合，避免旧队列/工作区迁移丢失。旧数据没有评论及自动提示字段时按空值恢复；内部自动提示标记不重复加入模型正文。
- GitHub 解决/重新打开线程的有效回执，在后续刷新失败时仍保留所有位置字段；本地解决成功后移除对应附件。既有普通评论、线程回复和审查流程保持独立。
