# 语音快捷键注册与保存事务

日期：2026-10-08，接续第 681 篇。范围仍为全部 47 类页面／交互和 29 类核心功能；本篇不代表语音整页或全部对齐完成。

## 证据与问题

沿用第 680 篇固定公开 Codex 26.930.51102／build 13100 的实际 `Pn`／`an` 失败回调夹具：结束录制后保存，失败保留原 accelerator，错误属于对应行，重新录制清除该行错误。该夹具不证明 Codex 原生后端的 Carbon 或持久化实现，本篇没有据此前端代码推断其后端事务。

本项目旧 `AppGlobalHotKey.register` 先注销原组合，再解码／注册新组合；设置先保存新值，再通知注册。新增真实 Carbon 测试在旧实现上得到 **3 项、2 失败、0 跳过、0.888 秒**（`.cache/voice-hotkey-registration-before-682.log`）：占用冲突和不支持的按键均使原组合释放，第三个原生注册对象能够抢占它。没有通过注入全局按键、麦克风或新系统授权制造失败。

## 实现

`AppGlobalHotKey` 先验证并预注册候选组合，原注册一直保留。提交时切换引用并注销原注册；丢弃预备对象只注销候选。相同绑定不重新注册，清除也等到提交后才注销。初始化事件处理器失败会明确报错。此修改同时保护其他使用该类的宠物／弹出窗口快捷键的原注册；它们各自设置的持久化事务仍不属于本篇。

`VoiceHotkeyRegistrationTransaction` 在同一次同步 MainActor 操作中，只准备本次修改模式的注册、保存工作区，再提交候选；某一修改模式准备失败或保存抛错会丢弃已准备候选。生产 AppDelegate 将实际三个 Carbon 对象接入此路径，保存成功后才刷新缓存、按住听写状态和裸修饰键监视器。失败不再清空已登记的原绑定缓存。未修改但启动注册不可用的另一行不会阻止本行保存；不支持一次无清除操作交换两个已占用组合，页面本身也要求先清除冲突组合。

设置存储只在注册和保存都通过后发布候选值，注册及保存错误按修改模式显示在原生语音页；重新录制只清该行错误，离页清理临时错误。保留原有通用设置保存错误状态。当前注册与文件保存为同步调用，没有增加虚假的异步 pending 动画。真实异步服务来源、裸修饰键权限／全局监视器安装的完整事务、启动恢复失败后录入同值的显式重试仍需另外验证和补齐。
