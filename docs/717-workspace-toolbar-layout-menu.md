## 实现内容

| 条件／操作 | 当前行为 |
| --- | --- |
| 内容已经显示 | 工具栏保留直接切换布局按钮，不打开悬停菜单 |
| 内容隐藏且存在保留标签 | 鼠标进入打开保留标签列表；按钮直接点击仍切换布局；辅助激活或键盘向下打开列表 |
| 新任务空工作区 | 显示两个新建菜单项；直接点击创建 split；键盘／菜单可选择 full |
| 已有任务且没有内容 | 使用普通切换按钮，避免误展示新任务菜单 |
| 保留标签行 | 标题按钮打开 split；行悬停或内部获得焦点时显示独立 full 动作 |
| 菜单范围 | 排除聊天、底部内容、分离窗口和其他任务；分别使用主窗口与任务窗口自己的标签集合 |
| 菜单打开期间标题／列表变化 | 更新显示并保留同一动作焦点；移除目标的旧回调不能执行；切换归属或菜单类型时关闭 |
| 悬停打开 | 同一窗口内容层内呈现，不创建独立窗口、不转移输入器 first responder |
| 指针离开 | 100ms 延迟；向菜单／触发器移动的三角走廊延长延迟；同窗追踪区域接收工具栏间隙的移动事件，不依赖指针光标偏好，进入目的地取消，移出走廊关闭 |
| 键盘接管 | 取消指针计时；触发器向上选择最后动作；保留列表按 Tab 访问每行两种动作，新建菜单按上下键导航 |
| Esc／外部点击／失焦／缩放／销毁 | 清理菜单、观察者和计时器；键盘 Esc 返回触发器，悬停关闭保留输入焦点；销毁后的回调无效 |

`WorkspaceLayoutMenu` 只描述菜单策略和当前可执行动作；布局、选择、浏览器资源继续由现有窗口标签模型持有。`WorkspaceLayoutMenuButton` 的 AppKit 边界负责工具栏、同窗覆盖层、焦点和事件，不引入第二套标签状态。主窗口和独立任务窗口均已接入；额外泛用布局菜单和右面板完整视图按钮的精确呈现仍未在本篇完成。
