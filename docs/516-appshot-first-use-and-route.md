# Appshot 首次启用与发送路由

参考端首次截取 Appshot 前展示“启用智能快照”说明，取消不会开始截图；启用后继续原请求，并在以后跳过说明。ShipiOS 现将该流程放在主窗口内，所有截图入口共用：输入区菜单、命令以及全局快捷键。首次请求保存草稿归属、选中的外部窗口、原窗口和截图回调；取消清理请求，启用后保存选择并继续。截图数达到上限时不会先打开说明。返回应用时，输入区的外部窗口目标也会刷新。

参考端只在当前工作区可接受 Appshot 时沿用当前路由；设置等页面接到全局快捷键时走新聊天。ShipiOS 现在按该条件分流，避免把截图附到设置背后的旧任务。

验证：23 项 Appshot／设置导航定向回归、1 项原窗口动画归属回归通过；`script/build_and_run.sh --build-app` 正式构建和严格签名通过。回归中发现截图注入闭包曾被 Swift 匹配到新回调参数，已改为显式 `capture:` 调用并重测通过。桌面控制确认 Mac 仍锁屏，故应用包的可交互工作区和真实页面行为未验收。

这一阶段的边界：首用弹层使用系统图标，尚未取得参考端插图；原生跨应用按键、权限弹窗、焦点与动画、音效和 Codex 双端逐交互对照仍需在解锁后的桌面验收。完整配对清单仍为 0/46，数字代表验收面而不是未实现项。
