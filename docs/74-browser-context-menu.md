# 浏览器右键菜单与点击目标

2026-09-17。本轮从本机当前 Codex 应用包的静态界面资源核对了浏览器右键命令，并补齐 ShipiOS 浏览器面板此前缺失的点击目标菜单。此检查只读取应用包内的静态资源，不读取个人 Codex 配置、认证或会话。

## 已实现

- `BrowserWebView` 在真实右击位置解析页面元素；链接菜单使用实际链接地址，页面动作使用当前页面地址。
- 菜单提供复制链接地址、后退、前进、重新加载、在外部浏览器打开、在新标签页打开链接、检查和使用 Codex 评论。
- 后退和前进根据当前 `WKBackForwardList` 状态禁用；新标签页进入 ShipiOS 自己的标签集合，并继续使用隔离的浏览器数据存储。
- “使用 Codex 评论”直接生成右击元素的结构化引用，保留选择器、文本、辅助功能标签、角色和页面矩形，不触发链接导航。
- WebKit 检查器已启用。存在原生点击节点检查动作时复用该动作；否则打开当前网页的 WebKit 检查器。
- 关闭标签会清理菜单目标和回调；设置入口仍通过单例 `ID: main` 的主窗口页面路由，没有新增 Settings Scene 或设置窗口。

## 自动化验证

`BrowserTests.testContextMenuResolvesClickedLinkAndMatchesCodexActions` 在真实 `WKWebView` 与本机回环 HTTP 夹具上完成以下检查：

1. 从 `#next` 的真实页面坐标解析 `/two` 链接和元素引用。
2. 核对链接右键菜单的可见动作及初始后退/前进状态。
3. 使用独立剪贴板验证复制的是链接地址。
4. 验证评论动作选择的是右击元素。
5. 验证“在新标签页中打开链接”创建受 ShipiOS 管理的标签，并真实加载目标页面。

浏览器定向测试现为 23 项。完整回归通过：363 项 Swift 测试、12 项 Rust 测试、Rustfmt、Clippy 和真实 IPC 冒烟均无失败。

## 原生窗口验收

使用 `/private/tmp/shipios-context-native-20260917` 隔离数据目录启动签名后的 `.app`，并在右侧浏览器加载本机回环页面。第一次原生右击揭示 `WKWebView.isFlipped` 与测试坐标假设不一致：链接被误判为页面空白。实现随后改为按视图坐标方向换算，测试也改为显式断言 WebKit 的翻转语义。

修正后的原生复验确认：

- 右击 `Next` 链接同时显示复制链接地址、新标签页打开及其余六个动作。
- “在新标签页中打开链接”真实创建第二个受管标签并加载 `/two`。
- “使用 Codex 评论”生成标题为 `Next`、选择器为 `#next` 的评论编辑区。
- 从浏览器进入设置后，窗口仍是同一个 `ID: main` 标准窗口；Esc 返回保留两个浏览器标签和未提交的评论编辑状态。

验收结束后已停止隔离实例和回环服务，重新启动原数据目录。任务“验证新输入框的真实构建”和草稿“这是一条待发送草稿，重跑后应保留”均已复核恢复。
