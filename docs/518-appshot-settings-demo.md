# Appshot 设置布局与演示

根据本机 Codex 客户端的 Appshots 设置资源，页面采用顶部说明、左侧设置卡与右侧竖向循环演示的结构。ShipiOS 已把 Appshot 设置整理成主窗口内的同类布局：快捷键、辅助功能提示、发送目标和音效留在左侧，右侧展示自制 SwiftUI 演示；窄窗口时上下排列。参考端的音效开关没有第二行说明，ShipiOS 现也采用单行标签与开关，同时保留辅助功能标签。演示用示例 Xcode 窗口、双修饰键和 ShipiOS 聊天卡片说明操作，不使用 Codex 的视频文件。

独立演示的纵横比按参考素材的 901:1095 设置，并在减少动态效果时停留在静态说明画面。离屏渲染已检查完整页面和演示画面；原先通过 `ImageRenderer` 生成的 ScrollView 截图为空白，改用离屏 `NSHostingView` 后加入非空像素断言，确认测试不是只检查图片尺寸。Appshot 设置、导航与偏好相关 32 项测试、`script/build_and_run.sh --build-app` 正式构建以及严格签名检查通过。

Mac 仍锁屏，无法在真实前台窗口中检查动画、弹出菜单、焦点、窗口宽度变化以及 Codex 与 ShipiOS 的逐项操作。完整双端配对仍是 **0/46**：主工作区 21 项、设置 25 项。这是待验收的交互面数量，不代表 46 个已确认缺陷。

单行音效开关更新后，Appshot 设置、导航与偏好相关 25 项回归通过；完整页面离屏图像已人工检查。此结果仍不替代前台双端验收。
