# 自动化复用任务会话

自动化运行现在按“模型与 API”中选择的协议进入普通任务会话路径。选择 Codex Core · Responses 时，可在自动化所属项目运行 Core 工具并使用现有审批、插件上下文、时间线和会话续接；选择 Chat Completions 时沿用原有服务配置，并可使用普通会话已启用的 MCP 工具。每次运行仍关联一个可打开、可审查的任务，后续运行继续该任务的上下文。运行记录保留 `automation_id`，完成后更新未读和下次运行时间。

自动化与当前打开的项目分开路由。首次运行先建立所属项目任务，再提交回合；运行中即可从自动化菜单打开任务处理审批。配置错误导致无法启动时移除空任务并推进日程，避免每次轮询重复失败。工作区暂时忙碌或项目移交中则保留到期时间，下一次轮询重试。标记上次结果已审查不会吞掉到期日程。当前项目的运行列表不再插入其他项目的回合。

验证：7 项自动化存储/页面/调度测试；本地假服务上的 Chat Completions 结果任务回归；Codex Core 工具端到端回归，确认 `apply_patch` 只在自动化指定的另一个项目生成文件；75 项模型会话回归。原生应用构建与签名检查见本次提交记录。

此阶段没有实现退出应用后的后台调度、错过日程的批量补跑、自定义日程或 Codex Mac 双端视觉/交互验收。工具审批使用现有任务审批流程，后台无人值守时仍需要用户处理等待中的批准。
