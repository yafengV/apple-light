# 通用设置权限模式与输入区菜单

2026-10-01。按当前[官方权限模式说明](https://learn.chatgpt.com/docs/permission-modes)，可用模式在通用设置中管理；开启仅让模式出现在输入区菜单，不会替现有任务选择它。ShipiOS 原先把完全访问显示开关放在 Agent 页，并始终展示自动审查候选。现在通用设置新增“默认权限 / 自动审查 / 完全访问”：默认权限显示可用的成套模式，自动审查和完全访问分别控制主工作区、独立任务窗口及弹出首页的同一候选列表。完全访问继续在显示选项前提示其作用范围，取消不改变状态。Agent 页保留审批者、策略、文件和网络等细项。

新安装默认只展示“按需请求批准”。关闭自动审查或完全访问时，使用该模式的全局默认值、弹出首页及未发送草稿恢复为按需请求批准；已创建任务的权限快照保留。旧任务若没有独立快照，在更改全局默认值前先保存原权限，避免继承新值。旧数据中已选自动审查的默认值会迁移为可见，以免升级后选项消失。设置搜索可定位通用页的新控件和 Agent 页的细项。命名权限档案仍只在运行时接通，尚无界面编辑及选择入口，见[第 468 篇](468-private-named-permission-runtime.md)。

验证：`WorkspaceLibraryTests` 22 项、`SettingsNavigationTests` 连同相关路由 15 项、`SettingsInteractionTests` 8 项，以及真实本地 Core 自动审查批准/拒绝、已有任务下一轮切换 3 项，合计 48 项通过。最终修改后 `script/build_and_run.sh --verify --data-root /private/tmp/shipios-general-permissions-20261001` 重建、签名并启动，严格深度签名检查通过。原生辅助功能操作确认“新任务”工作区可编辑；通用设置在同一 `main` 窗口，默认权限菜单在自动审查关闭时仅有按需请求批准，开启后增加自动审查批准，关闭又移除；完全访问提示可以取消且开关保持关闭。隔离实例切到无凭据、不可达的本地 Responses 测试地址后，输入区权限菜单也随开关显示/隐藏自动审查，最终构建重启后仍保持所选可用性；未向真实模型服务发送请求。Codex 参考端仍无法通过当前计算机使用接口访问，完整双端逐页配对保持 **0/45**。
