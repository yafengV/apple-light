# 独立任务窗口的返回与前进

2026-09-18。延续窗口内分叉，接入窗口专属任务导航历史。

## 行为依据

公开静态资源 `app-initial` 的 `navigateBack` / `navigateForward` 命令定义使用 `CmdOrCtrl+[` / `CmdOrCtrl+]`，消息处理通过当前路由的 `i(-1)` / `i(1)` 进行前后导航。特殊浮层窗口另外限制这些动作。本阶段对齐普通独立任务窗口的键盘与菜单路径；不把静态资源检查写成当前 Codex 原生配对验收。

## 实现

- `TaskWindowSceneView` 持有独立历史，分叉、来源链接和重命名撤销使用同一导航入口。返回/前进只更新当前窗口路由，不调用主窗口任务选择。
- 成功的新导航记录当前位置并清空前进分支；重复位置、已不存在的目标不产生新记录。前后导航跳过已删除任务，也不把已删除的当前位置重新加入另一侧历史。
- 原有任务菜单和窗口键盘桥按历史可用性启用返回/前进，支持用户自定义绑定。图片、文件、模型、目标和重命名弹层期间沿用窗口命令禁用规则。
- 切换任务后输入框重新获得焦点；草稿来自对应任务的持久化数据。任务专属面板随任务重新建立，窗口级重命名历史保留。

## 验证

- 18 项导航、窗口命令、分叉和重命名历史回归通过，日志 `.cache/task-window-navigation-tests.log`。新增导航测试覆盖多级往返、前进分支替换、重复/失效目标、删除记录跳过及窗口历史隔离。
- 随后扩展并单独重跑快捷键测试，确认默认绑定、自定义返回绑定和移除前进绑定，日志 `.cache/task-window-navigation-bindings-test.log`。
- 原生隔离工作区：主窗口停留 A，B 独立窗口从首回复分叉；填写新任务草稿后 `⌘[` 返回 B，任务菜单显示返回禁用、前进可用；点击前进回到分叉任务，草稿恢复。
- 图片预览打开时 `⌘[` 不切换任务。关闭后点击来源链接，再用返回/前进完成往返，焦点回到对应输入框。
- 在存在前进记录时新建下一层分叉，菜单前进禁用，菜单返回恢复之前任务及草稿。
- 关闭独立窗口后主窗口仍选中 A；持久化检查确认主选择为 `main-A-run`，A、B 和分叉草稿均保持。未发送模型请求。
- 项目脚本恢复原工作区，构建与严格签名检查通过；原任务及草稿保持、输入框可聚焦。切换测试数据目录后仍可能恢复无效测试任务窗口，本轮关闭该窗口后验证主窗口；此场景恢复问题尚待修复。缓存和合成测试数据不提交。
