# Codex MCP URL 验证请求

2026-09-26。Codex Core 转发 MCP 服务的 URL `elicitation_request` 时，ShipiOS 现在在任务时间线显示验证卡片。用户可在系统浏览器打开验证地址，完成后点“已完成验证，继续”，或点“取消”。两种选择分别回传 Core 的 `Accept` 和 `Cancel`，避免回合停在等待状态。

验证地址只在请求存活期间保存在内存；工作区记录仅保留服务名、提示、主机名与处理状态，不保存可能含一次性令牌的完整 URL。本地模型与 STDIO MCP 假服务的集成测试覆盖服务发起 `elicitation/create`、完成、取消、回合继续与持久记录脱敏。

原生页面的点击位置、浏览器切换、焦点、键盘和当前 Codex Mac 的视觉配对尚未验收；macOS 锁屏时不能把构建或测试通过当作原生交互通过。设备验证模式仍待接入。
