# Codex Core 同回合引导

2026-09-26。ShipiOS 的 Codex Responses 普通会话在“引导当前运行”设置下，现使用固定版 Core 的 `steer_turn` 和预期回合 ID 提交运行中消息。Core 接受时不取消当前回合，也不新建 ShipiOS 运行记录；消息、图片和文本/PDF 附件按原顺序保存为同一时间线中的用户消息，附件保留引用。主窗口与独立任务窗口均可在运行中发送。任务内查找、任务搜索和分叉上下文包含已接收的引导消息。

若回合已结束或预期回合 ID 不匹配，Core 不接收输入，ShipiOS 保留待发送队列；正在等待引导结果的消息会阻止后续队列消息越序发送。“等待下一轮”设置仍使用新回合。非 Codex API 的现有取消后继续行为保持原有语义。

本地假模型端到端测试验证主窗口与独立任务窗口同回合提交、文本附件、单运行记录及历史持久化；Agent RPC 冒烟验证错误 ID 拒绝和正确 ID 接收；搜索、分叉、任务窗口与模型传输相关的 79 项 Swift 回归、Rust 测试通过。Codex Mac 的按钮布局、焦点、键盘和运行卡片顺序仍未完成原生配对；真实用户 API 服务需在用户填写后验证。
