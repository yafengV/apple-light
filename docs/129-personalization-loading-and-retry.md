# 个性化编辑器加载与重试

2026-09-18。接续 [自定义指令保存交互](128-personalization-save-interaction.md)，区分指令读取失败和编辑后的保存失败。

## 参考与实现

公开分发资源 `personalization-settings-2428288d0130.js` 的 Codex 指令编辑器在内容区域显示加载状态，初次读取失败时改为错误与 Retry，读取成功后才提供文本编辑器。

ShipiOS 按此结构在自定义指令区块内切换加载、读取失败和可编辑状态。读取失败不再留下空白的禁用编辑器；错误和重试位于原编辑器位置。重新加载会清除过期错误，重复点击由已有加载状态保护。保存失败保留当前编辑器、草稿和具体错误，仍可修正后保存。设置搜索定位覆盖同一个内容区域，在编辑器未出现时也保留定位目标。

## 验证

- 20 项个性化、编辑器、布局相关测试通过，日志 `.cache/personalization-editor-states-tests.log`。
- 新增真实 NSHostingView 测试：加载/读取失败时无文本编辑器，修复文件并重新加载后出现可编辑内容；保存失败保留同一编辑器和全部草稿，修正保存后错误清除。已检查加载、读取失败和保存失败三张离屏截图。
- 项目脚本构建运行并通过严格签名检查，使用新建的 `.shipios-local/personalization-retry-validation` 隔离目录和不可读 UTF-8 指令样本。原生页面显示错误及重试，保存和其他偏好控件禁用。
- 文件仍损坏时实机重试回到错误状态，没有持续加载。将仅用于测试的样本修复后，再次点击重试，无需重启便出现正确文本并恢复控件。追加文字后 ⌘S 保存成功，读取测试文件确认内容完全一致。
- 使用项目脚本恢复原工作区，原任务和输入草稿保留，实际聚焦输入框确认可交互。构建及恢复日志分别为 `.cache/personalization-retry-build.log`、`.cache/personalization-retry-restore.log`。

加载状态的视觉证据来自受控离屏测试；真实文件读取很快，本轮不宣称录制到完整加载动画。按钮颜色、整体页面视觉、VoiceOver 和完整产品配对仍未完成，真实模型请求未执行。
