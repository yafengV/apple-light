## 实现

PR 详情读取实际 head revision 和 merge state，再读取 GraphQL 的当前登录身份、作者、仓库支持的两种策略及自动合并状态。两次读取的 PR、仓库、状态、草稿、源/目标分支和提交必须一致；部分 GraphQL 错误不启用操作。

当前作者的未合并 PR 提供合并与自动合并操作。确认显示当前完整头提交、仓库允许的方法和明确确认按钮，运行期间不能重复提交或关闭确认。Git 设置在主窗口内保存默认方式，并进入设置搜索；旧配置和未知方式回退为 merge。单次选择不修改全局偏好；仓库限制导致的 squash 回退只在操作成功后保存，保存失败单独报告。

执行前重新读取远端 PR，校验头提交、源/目标分支、作者、检查及仓库策略，最后再次校验任务身份和写入权限。普通合并与启用自动合并显式传入 PR 编号、仓库及头提交匹配参数。停用自动合并也使用明确 PR 和仓库。不同窗口共用 PR 操作锁；任务/目录失效、窗口退出及取消后的迟到结果不能更新旧视图或错误归属。

本阶段沿用 ShipiOS 现有只读审查偏好，禁止其 PR 写入。远端合并不切换本地分支、修改索引或工作文件；没有管理员绕过、自动删除分支和自动重试。远端成功后按实际刷新状态更新任务记录。连接中断但已确认合并可恢复为成功；刷新失败明确结果待确认，清除写入资格；排队且仍开放时保留真实状态并提示等待，不能虚构合并完成。
