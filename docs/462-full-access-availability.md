# Agent 完全访问选项的显示确认

当前 Codex Mac 分发资源的 Agent 权限页有“Show Full access in the composer”开关；开启前显示“Make Full Access available?”确认，并说明确认只把选项加入输入区权限菜单，不会立即选择完全访问。ShipiOS 原先在 Agent 默认文件访问和弹出任务权限菜单中始终列出“完全访问”，缺少这一步。

ShipiOS 现将显示状态保存在独立工作区数据中，新配置默认关闭。Agent 设置页打开开关时先显示风险和“仅显示选项”的确认，取消不保存；弹出任务输入区的权限菜单和 Agent 默认文件访问下拉只在开启后列出完全访问。直接保存完全访问默认值也受该状态约束。既有数据若已经将全局或弹出任务默认值设为完全访问，迁移后会保持选项可见；即使持久数据出现“关闭显示但仍选择完全访问”的矛盾状态，加载时也优先显示当前选择，避免掩盖实际权限。

关闭显示会在一次持久化中把全局及弹出任务的新任务默认文件权限恢复为“工作区写入”，并关闭对应的工作区网络开关；已创建任务的权限快照不会修改。开启显示本身不会更改沙箱、审批策略或已有任务。写入失败会保持原状态。

`WorkspaceLibraryTests`、`GeneralSettingsParityTests` 和 `SettingsNavigationTests` 共 53 项通过，覆盖选项过滤、旧数据迁移、未确认状态不可选、关闭后的未来默认值、已有任务快照、失败回滚与设置搜索。`script/build_and_run.sh --verify` 使用隔离数据目录构建并启动签名应用，`codesign --verify --strict --deep dist/ShipiOS.app` 通过。

桌面控制报告 Mac 锁屏，设置开关、确认弹窗和弹出菜单的前台操作尚未验收。主工作区和独立任务窗口仍没有对应的输入区权限菜单；Codex 参考页的完整布局、文案、焦点与交互也未完成双端配对。此阶段不构成 Agent 页面或全产品完全对齐，完整验收保持 **0/45**。
