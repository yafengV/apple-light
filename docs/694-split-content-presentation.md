## 已实现与验证的行为

| 入口／状态 | 本阶段结果 |
| --- | --- |
| split 内容标签集合 | 主窗口与独立任务窗口共用该任务全部原左／右内容；底部、分离标签及其他任务不混入 |
| 选择原左侧内容 | 保持 split，聊天留在主区，选中内容在侧栏显示；保留原物理位置作为打开／恢复元数据 |
| 明确切换布局／打开内容 | 移到左侧进入 full 并隐藏内容侧栏，移到右侧进入 split；普通选择已有标签不再隐式切换布局 |
| 标签栏与实际挂载 | split 主区不再重复展示内容标签栏；侧栏显示全部主内容标签；两个实际视图各只挂载被选中的一个网页 |
| 返回聊天／输入框焦点 | split 内容继续显示；清除内容命令焦点，相邻内容导航不再占用聊天导航；原生输入框焦点交接有覆盖 |
| 相邻导航 | split 在主内容集合中循环，不经过聊天；单标签不处理；底部继续使用自身集合 |
| 保存与恢复 | split 的侧栏选择可以引用原左侧标签；恢复模式、选择与焦点；旧无模式布局继续用有效旧主选择推断 |
| 关闭／排序／隐藏 | 按实际显示集合执行跨原左右位置排序和关闭右侧／其他标签；隐藏后释放内容焦点，关闭选中侧栏内容可选择存活内容 |
| 文件／浏览器／终端入口 | 内容内新建文件或网页使用当前显示表面；侧栏终端复用不局限于旧物理右侧；隐藏内容不接收命令 |
| 分离窗口回收 | 非当前任务的分离内容回到主区时同时保存 full 模式，避免之后恢复时被旧 split 状态吞掉 |

隐藏原生窗口还验证了左右交换会改变同一 WKWebView 的显示位置，保持宽度和实例；主窗口与独立任务窗口的网页宽度均小于 600 点，聊天仍存在。此验证针对 ordinary split，不能当作 primary workspace home／辅助聊天的完整主次交换。
