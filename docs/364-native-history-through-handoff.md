# 任务移交保持原生会话历史

## 复现与修复

第 363 阶段后继续使用真实 Agent / Codex Core 和本地模型夹具核对移交。原实现按当前执行目录选择私有历史目录；本地任务移交到托管工作树后找不到原引用，因此创建新 Core 线程，并回放文字上下文。原生线程 ID、历史文件位置随之改变，工具历史无法保证连续。历史回合仍保留真实原执行目录，但分叉只允许当前任务目录，因此旧回合入口被禁用。

现在分别保存执行目录与历史命名空间：Swift 续接请求携带同一任务已记录的工作区和原生线程 ID；Agent 在 ShipiOS 私有 Projects 根目录内解析该任务引用，并验证实际线程身份与 rollout 范围。Core 使用原私有历史目录续接，工作目录使用移交后的当前项目。历史目录损坏、身份不符或引用越界会明确失败，不改为新线程文字回放。旧物理检出已清理时仍能读取私有历史，不重新创建旧工作树。

分叉历史允许已记录托管检出的来源和目标目录，并保留每个执行回合的实际位置。主窗口与独立窗口都读取任务完整历史，避免重启后只按当前项目记录判断可用性。子任务复制的固定回合可以按自身保存的分叉记录继续嵌套分叉，即使本地子任务不关联来源工作树；其他目录或修改后的复制回合仍拒绝。
