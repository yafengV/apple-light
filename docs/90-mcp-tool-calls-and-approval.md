# 会话 MCP 调用与任务内审批

2026-09-18。将已连接 MCP 的工具接入真实模型请求，在任务时间线内显示审批、执行状态与结果。

## 对照依据

Codex 本地静态界面 `mcp-tool-item-content-7382fa98d0b0.js` 包含折叠工具行、结果状态和原始输出对话框；`app-initial-4d7ea7f81c2d.js` 有批准/拒绝请求的命令定义和 MCP 审批内容。本轮实现任务内可执行审批流程及输出查看，但尚未复刻所有定制审批卡片、默认快捷键与富内容结果。

协议参考 [OpenAI function calling](https://developers.openai.com/api/docs/guides/function-calling) 以及 [MCP tools](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)。独立 API 服务须支持 Chat Completions 的工具声明和流式 `tool_calls`。

## 当前行为

- 普通/目标会话发送时快照当前已连接且启用的工具，以独立函数名称映射服务器和工具。计划与代码审查回合暂不提供工具。
- 支持分片工具调用参数、多次模型请求和一次回复中的多个调用。参数须为完整 JSON 对象；截断、非法标识或不完整调用不执行。
- 主窗口与独立任务窗口共享工具卡片：服务器/工具名、参数、等待批准/执行/完成/失败/拒绝/取消状态。结果可展开并打开完整原始输出。
- 用户可允许本次、拒绝，或在当前任务中允许同一工具。任务授权仅在内存中生效，并绑定当前连接身份；其他任务、重连或应用重启不会继承。
- 批准前不发送 `tools/call`。批准后再次检查服务器启用状态、连接身份和工具定义，防止旧审批被用于已更改的服务。
- 拒绝回传明确的拒绝结果；完成后把工具调用和响应按对应标识交回模型，继续生成同一回合的回答。工具错误保留为失败记录并交回模型。
- 待审批任务在侧栏显示提示标志，并进入“下一个需关注任务”。清除未读不会消除尚未处理的审批。
- 停止回合会结束待审批等待，向已发送请求发出 MCP 取消通知；取消不保证撤销服务器已经产生的副作用。断开/停用服务器会解除其尚未处理的审批。
- 执行记录与结构化工具消息保存在该回合中。重启不重放待审批或执行中的调用；中断记录显示取消。工具后的部分回答也随历史保留，后续请求不会出现缺少工具响应的消息对。
- 单轮最多 16 次模型请求，工具目录最多 128 项，单批工具参数最多 1 MiB。用量累加服务实际报告的多次请求值。
