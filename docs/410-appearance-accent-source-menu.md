# 强调色来源菜单与自定义颜色输入

外观页浅深两侧的强调色现在使用同窗口来源菜单和已有的十六进制输入。八个账户选项按参考顺序显示颜色圆点，第九项为“自定义”；深色模式下账户“黑色”显示为“白色”。没有 ChatGPT 账户时，八个账户项禁用，自定义项可选择。

用户选择独立 API 服务认证，当前 ShipiOS 没有 ChatGPT 账户设置桥接，因此实现参考的无账户分支。没有把账户颜色变成本地假账户选项，也没有读取用户个人 Codex 登录状态。真实账户登录、账户主题读取与更新仍缺，不能将此阶段写成完整账户流程对齐。

## 选择与保存行为

来源只有 `chatgpt` 时显示账户主题；账户缺失显示“默认”。未指定来源与 `custom` 均显示“自定义”和颜色输入。因此默认外观页有六个颜色输入，而非仅背景／前景的四个。选择 `codex` 预设会恢复 `chatgpt` 来源并隐藏该侧自定义输入；再选择自定义只更改该侧来源与当前强调色，保留代码预设、背景／前景、字体及另一侧主题。

自定义输入复用第 409 篇的同窗口颜色面板、立即保存和部分草稿规则。可访问标签采用实际中文翻译：“浅色模式下的自定义强调色”与“深色自定义强调色”。没有额外系统颜色窗口或重置按钮。重复选择不重新写入相同配置；保存失败关闭来源菜单，保留原来源、标题、颜色及草稿，并显示现有错误。

打开及提交均即时读取工作区可用状态，不能因 `libraryLoaded` 不触发 Observation 更新而使用旧可用值。键盘只访问启用项，账户项不可通过悬停、方向键、文字匹配或直接旧回调选中；文字匹配缓存一秒，Space 在活动匹配中参与匹配，过期后执行选择。Tab 保持菜单打开；Esc 关闭并恢复调用按钮焦点。字体、主题与颜色浮层在同窗口内互斥，其他窗口独立。

## 尺寸和原生验证边界

按钮 144×28、文字默认 13；菜单宽 220、边距 4，圆点 12，圆点至文字间隔 8，行内容与尾部图标间隔 6。禁用行透明度为 0.5，未高亮的勾选图标为 0.75。菜单共享既有末端对齐、碰撞裁剪及窗口关闭处理；原生材料和阴影仍不能声明与 Electron 精确一致。

参考 CSS 在 Electron 根元素将 `text-sm` 改为 13。body 自身的纵向行边距为 5，并不被之后 root 的 4 覆盖；横向为 8。计算行高为 `13 × (1.25 / 0.875) + 10 = 28.5714…`，九行加菜单内边距为 265.1429…。原生尺寸使用此公式并跟随现有界面字体缩放。

离线、不附着窗口的 WKWebView 加载实际 CSS 规则子集，核对计算字体、行高和边距；WebKit 此处将文字行框取整为 18，实际行元素高度为 28。测试分别保留计算值与实际 WebKit 结果，不把其作为 Chromium 的渲染结果，不据此降低原生尺寸或放宽误差。完整 Codex 可见布局、滚动和点击范围仍待配对。
