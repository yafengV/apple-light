# 计划任务无人值守权限

[OpenAI 官方 Scheduled tasks 文档](https://learn.chatgpt.com/docs/automations?surface=app)说明计划任务无人值守运行，沿用用户的沙箱设置，并在允许时使用 `approval_policy = "never"`；本地项目的计划任务要求电脑开机且桌面应用保持运行。

ShipiOS 现在仅为 Codex Core 计划任务的新会话使用 `never` 审批策略，保留用户已选的沙箱和网络范围。普通交互会话仍使用设置中的审批策略。如果需要交互批准的命令或 MCP 请求仍到达应用层，计划任务立即拒绝并在工具记录中说明原因；基础 Chat Completions 的 MCP 工具采用同样的无人值守拒绝。无法自动回答的结构化提问会使该次运行失败，问题和失败结果留在任务历史中供审查。MCP 表单在 Core 已自动处理时不会生成待处理卡；若传到应用层则自动拒绝或取消。

验证：3 项真实本地夹具测试覆盖计划任务的提权命令、结构化提问、MCP 表单和基础协议 MCP 工具，均未留下待处理审批；普通会话手动批准、拒绝、提问和表单的 16 项回归与 22 项自动化日程测试通过。应用构建与签名检查通过。原生页面仍因 Mac 锁屏无法逐项验收。

仍待对照：当前 Codex Mac 的审批卡、结果状态及管理策略限制下的行为；完整 RRULE、计划任务环境选择与其他页面交互仍未完成。
