## 行为与实现

- 开启和合并来自 PR 元数据；批准、要求修改来自审查状态。审查优先使用 `submittedAt`，缺失时回退 `createdAt`，事件先于相同时间的审查正文。其他审查状态只显示非空正文。
- 空白普通评论、审查正文和线程根正文不进入活动列表；原始审查和正文仍在快照中保留，用于权限、编辑、结果确认及其他操作。
- 日期按实际瞬间排序，兼容时区和小数秒。相同瞬间保持参考输入顺序：开启、提交、普通评论、审查事件及正文、代码线程、合并。无法解析的日期稳定排在最后。
- 排序后仅合并相邻提交，评论、审查事件及线程会分隔分组。分组身份由首个提交确定，摘要日期使用最后一个提交的日期；活动数统计分组及其他条目，不累计分组内提交数。
- 单提交直接显示标题、七位 ID、作者头像或姓名首字母及相对日期。有效 GitHub 提交链接沿用所属任务的打开方式。多提交摘要整行可展开/收起，默认收起，展开显示分隔线和全部提交；摘要和提交链接支持 Return，原生按钮保留 Space 激活；箭头在悬停或摘要/内部链接的键盘焦点时显示，减少动态效果偏好关闭旋转动画。
- 评论、事件和提交使用相对日期并定时更新，完整日期进入帮助文字和辅助功能标签。具体日期用语、窗口字体、颜色和布局仍需双端原生配对。
- 当前 PR 的 `commits(last:100)` 只读取一次，保留主要作者和链接，缺失链接使用对应仓库提交地址。强推前的历史 timeline commit 不再混入当前提交集合。超过 100 条时保留最近 100 条并显示部分审查详情未载入提示。
- 普通评论、审查、代码线程和线程回复独立分页，继续检查重复、游标循环、数量漂移、账户、PR 和头提交。提交连接缺少分页信息或包含重复提交时，读取失败而不安装不完整快照。身份变化保持原来的重试保护。
- 新建/编辑审查的回执包含提交时间，刷新不可用时仍呈现已接受的决定事件；空白批准不会插入空正文卡片。旧评论数据没有 `submittedAt` 时按原创建时间恢复。
