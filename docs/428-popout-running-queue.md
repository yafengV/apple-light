# 弹出会话运行态与排队消息

弹出会话此前始终只显示发送按钮。运行中的任务没有停止入口；虽然发送草稿会进入任务队列，弹出窗口本身看不到队列。原有 `ComposerQueueView` 还依赖主窗口当前选中的任务，直接复用会显示错误会话，编辑队列消息也会因主窗口未选中该任务而静默失效。

弹出会话现按自身任务 ID 显示运行状态、停止按钮及有界高度的排队消息列表。发送按钮随任务可发送状态、附件导入和运行中追加行为启用，并提示“发送消息”或当前追加方式。队列沿用现有编辑、上移、下移、立即发送和删除操作，但筛选、发送资格及编辑草稿均按队列消息所属任务处理；编辑会把文字和附件恢复到弹出会话草稿，不改变主窗口当前任务、动作或焦点。现有草稿未清空时保留队列消息并在弹出窗口显示错误。运行中输入新消息沿用 `sendTaskWindowDraft` 的排队/引导逻辑。

固定 470×640 窗口的隐藏原生截图已检查运行状态、队列行、输入文字、停止及发送控件同时可见；截图只证明布局渲染，不能代替真实点击和焦点验收。运行中追加只进入当前任务队列、从该任务队列编辑、已有草稿保护等定向测试通过。相关回归 142 项中 141 项一次通过；既有归档流测试等待实际响应超时，单独复跑通过。`script/build_and_run.sh --verify` 构建并启动签名应用、严格深度签名及 29 个语法资源和七份许可证逐字节核对通过。启动后的工作区可交互检查因 Mac 锁屏无法完成；用户解锁后需继续检查。Codex 应用被当前 UI 工具限制读取，因此双端可见配对、真实模型停止/继续、鼠标和键盘操作尚未验收，完整配对仍为 **0/45**。
