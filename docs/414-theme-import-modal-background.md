# 主题导入弹层的背景外观、指针与焦点约束

主题导入现在通过所属窗口的临时交互范围拦截背景操作，保留背景控件原有的启用外观。打开弹层时关闭已有字体／主题菜单和 HSV 选色面板，取消它们的迟到选择及焦点恢复；弹层关闭后恢复背景控件本来的可用状态，原先不可用的控件不会被强行启用。

## 当前分发参考

核对 Codex 26.911.61220 / build 9647 的公开安装包资源，初始模块 SHA-256 为 `01c04b2e5a96e5dd4c97e02ffa183f571a55bef7a221abd99404246c430f2212`，与缓存逐字节相同。设置、CSS、按钮和中文资源也重新核对相同；没有读取个人账户、凭据、会话或工作区。

在隔离 Node VM 中执行实际 `fa`、`Tui`、`XMe`、`xa` 和 `oNe`，React hooks 与文档对象只提供其依赖的测试环境。实际 layer effect 把 body 指针设为 none，清理后恢复原值，没有改动背景控件的 disabled 或 opacity。六种鼠标按钮／Control 组合来自实际 modal 回调：普通左键和中键的外部点击可关闭；右键和 Control-left 被阻止关闭。

实际焦点范围记录最后一个内部控件。外部 focusin／focusout 会调用 `xa` 返回该控件，输入恢复使用 select:true 与 preventScroll:true；返回按钮不会选择输入。实际 Tab 循环与事件监听清理也执行核对。普通外部指针经过 layer 与 modal 回调后触发关闭；这与只发生焦点逃逸时的恢复不同。

`oNe` 保留 dialog、外部 aria-live 区域和 script，不把通知区域隐藏。因此通知继续显示并可访问。通知自身有 pointer-events-auto，实际 provider 将它放在 dialog 外；点击通知也属于外部指针，应先关闭导入框，再执行通知原有操作。上述结果和源表达式哈希保存到 `appearance_modal_barrier_reference.json`；这些是实际代码在隔离依赖中的行为证据，不是 Chromium 或可见桌面验收。

## 原生实现

`WindowModalInteraction` 只在自有 NSWindow 上保存弱作用域。外观 radio、字号、颜色、主题／字体按钮、滑杆、设置搜索和代码预览按所属窗口检查焦点与操作资格；SwiftUI 根内容仍阻止命中并隐藏背景辅助功能。启用状态和绘制参数不用于表达 modal 的临时阻挡。

作用域随 native surface 的挂载／卸载安装和清理，旧作用域的清理不能移除新作用域，也不会阻挡其他窗口。菜单及选色面板属于内容视图的独立上层子视图，所以挂载时明确关闭它们，并禁止恢复背景焦点。

标题操作把启用外观与即时操作资格分开，按最新确认状态检查焦点和回调；弹层状态已打开但原生作用域尚未挂载时也不接受旧操作。完整主窗口测试在等待渲染之前核对这个边界，没有调用用户系统剪贴板。

窗口事件只处理所属 key window；窗口更新／重新成为 key 时检查内部焦点，鼠标投递后再检查一次。输入恢复时全选，普通外观更新保持原选区。焦点记录和事件回调使用弱引用，关闭、换页、旧会话及 attached sheet 时不会抢夺焦点。

外部通知的原生命中使用 contentView 的父坐标系，避免 NSHostingView 翻转坐标产生误判。通知点击关闭 modal 后仍投递给通知；遮罩事件留给原 Surface 处理，避免提前移除遮罩让同一次点击触发背景控件。右键和 Control-left 外部点击保留弹层，中键外部点击关闭。
