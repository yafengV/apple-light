# 主窗口记忆设置与模型上下文

2026-09-17。继续补齐 Codex 设置能力，新增可实际使用的本地记忆页；这项实现不代表当前 Codex 的视觉布局已经完成逐项配对。

## 对照依据

[OpenAI 的 Codex plan 帮助文档](https://help.openai.com/en/articles/11369540-using-codex-with-your-chatgpt-plan) 将 Memories 列为 Codex 用于保留上下文的功能之一。[Codex customization 概览](https://learn.chatgpt.com/docs/customization/overview) 将 memories 与 `AGENTS.md`、skills 和 MCP 区分为不同的定制层。

上述资料支持“记忆是独立持久上下文”的功能方向，但不证明当前用户版本的分类位置、行高、文案、动画或自动提取规则。ShipiOS 当前只实现可解释、可管理的显式记忆，不伪造服务端自动记忆。

## 当前实现

- 设置侧栏新增“记忆”，仍在同一主窗口内。页面包含“启用记忆”、添加区、空状态、已保存列表、编辑、逐条删除和清空全部。
- 开启时，保存的记忆组成独立 system 上下文，随下一次请求发送给用户配置的 API 服务。当前请求与记忆冲突时，system 文案明确要求优先当前请求。
- 关闭只停止向模型发送，不删除内容。重新开启后原内容继续生效。
- 添加和编辑会去除首尾空白，拒绝空内容、重复内容、重复 ID 和超限数据。当前限制为 100 条、单条 4 KiB、合计 64 KiB。
- 记忆保存在当前 ShipiOS 数据根目录的 `memories.json`，文件权限为 0600。不同数据根目录相互隔离，不读取用户 Codex 的记忆或配置。
- 文件损坏或校验失败时保留原文件、页面显示错误并提供重新加载。模型请求会停止并保留草稿，避免静默忽略用户原有记忆。
- 删除单条和清空全部均有确认对话框。自动从会话发现、合并或更新记忆尚未实现；当前所有新增和编辑均由用户明确操作。

## 验证

5 项记忆存储测试覆盖默认迁移、0600 权限、独立目录、添加/编辑/删除/启停持久化、重复与大小限制、损坏文件保护。页面导航测试覆盖新增分类在设置、弹层和运行任务中的状态保留。

本机 HTTP fixture 验证同一条记忆在开启时确实出现在收到的 system message 中，关闭后不再出现；没有调用外部或收费服务。

完整回归通过 295 项 Swift 测试、12 项 Rust 测试、Rust fmt/Clippy 和真实 Agent IPC 冒烟。日志：`.cache/memory-settings-full-tests.log`。

原生验收使用隔离目录 `.shipios-local/memory-validation`：在主窗口设置打开“记忆”，确认默认空状态；添加“优先使用 SwiftUI，并先运行完整测试。”，编辑为“优先使用 SwiftUI，并在修改后运行完整测试。”；关闭和重新开启后条目仍在；应用重启后条目与启用状态均恢复。逐条删除和清空没有在 CUA 中执行，相关数据变化由自动测试验证。

验收结束后应用已恢复到原数据目录 `.shipios-local/desktop`，PID 4408；窗口重新选中“验证新输入框的真实构建”，并保留“这是一条待发送草稿，重跑后应保留”。

## 剩余边界

尚缺当前 Codex 的同页截图/录屏配对、自动记忆发现和摘要、来源追踪、从会话纠正记忆、项目级与账户级范围规则、临时会话，以及与 Codex Core 的原生 memory 生命周期。账户、插件/集成、定时任务、远程和其他设置页面也仍未完整实现。
