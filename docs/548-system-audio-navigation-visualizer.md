# 系统音频驱动的会话导航轨道

本机 Codex 应用的通用设置“玩具”中有“Audio visualizer”：开启时先尝试系统音频录制，成功才保存偏好；用户消息导航轨道的标记按播放频段伸缩。参考组件只在至少 4 条用户消息时出现，且在减少动态效果或窗口不可见时不订阅音频。

ShipiOS 现把轨道显示门槛改为 4 条。设置页新增“音频可视化”和搜索入口。开启时用 [Apple Core Audio tap](https://developer.apple.com/documentation/coreaudio/capturing-system-audio-with-core-audio-taps) 创建私有、不中断播放的系统音频输入；同一应用的多个轨道共享它。音频只在内存中计算 64 个频段，标记按其对应频段的最大值改变长度；250 毫秒没有新样本就归零。关闭偏好、减少动态效果、窗口消失或应用失焦时停止采集。macOS 14.0–14.1 不提供此开关。应用包新增 `NSAudioCaptureUsageDescription`；不读取麦克风或屏幕画面，也不保存、上传原始音频。

合成静音及 1 kHz 音频、频段到标记分配、共享采集生命周期、失败反馈、旧配置、设置搜索和轨道离屏绘制有自动化测试。桌面控制当前超时，尚未验证真实系统音频权限弹窗、音乐播放时的实际动效、多个前台窗口及 Codex 双端配对；完整配对仍为 **0/47**，该数字是验收面数量，不是确定缺陷数量。
