# 最近一轮范围的仓库检查与入口恢复

## 对照与范围纠正

本轮实际检索并打开[官方审查文档](https://learn.chatgpt.com/docs/code-review?surface=app)。文档要求项目在 Git 仓库中才能使用审查面板，没有仓库时提示创建；Last turn 显示最近助手回合。暂存/撤销的说明覆盖整个差异、文件和差异块，但没有逐范围说明全部动作都可用。

进一步追踪已有 Codex 26.908.70816/build9275 的 `.cache/settings-reference-app-initial.js`：`ZBa` 仅接受 staged/unstaged；`F$a` 的本地/工作树差异修改资格要求此条件，Last turn 不读取普通 Git 差异，而使用记录差异。因此此前把「最近一轮没有暂存/撤销」直接当作待实现功能不准确。保留历史范围的差异修改禁用，与此版本模型资格一致；本条件不能证明提交/推送/PR 等其他按钮的显示资格，它们仍需各自对照。是否符合当前版本原生按钮、菜单和键盘仍待配对。这是旧版本参考资源证据，不是当前 Codex 双端验收。

## 问题与实现

第 369 篇的 `refreshGit` 在最近一轮范围提前返回，只加载回合快照：恢复此范围时不能发现已有仓库；仓库被移除或索引损坏时，继续保留旧 Git 可用状态。视图又特许最近一轮绕过 `gitAvailable`，使无仓库项目缺少官方要求的创建入口。新增两个真实 Git 用例实际复现 8 个失败断言，日志 `.cache/last-turn-repository-gate-baseline.log`。

刷新现在先检查项目所属仓库，再加载所选范围；最近一轮的显示内容仍来自保存的助手快照，不改为当前工作区差异。主窗口、独立任务与分离审查共用现有仓库可用、读取失败、创建和重试入口。没有仓库时允许正常创建，创建成功进入未暂存范围；损坏仓库禁用创建，并可修复后在原最近一轮范围重试。

刷新或检查失败会失效旧回合读取请求、清除旧快照，后到达的结果不能恢复旧内容。Git 检查期间显示读取状态，避免在检查过程中误显示无回合变更。最近一轮的路径说明取其保存的原基准，避免移交后的当前仓库路径冒充旧回合基准。
