# 统一任务归档与窗口确认

2026-09-28。第 353 阶段补齐 Activity 单条归档，但普通侧栏、主窗口任务工具栏/归档命令和独立窗口仍禁用活动任务。本阶段统一这些用户入口的归档语义，并把确认归属明确到发起窗口。

## 对照依据与入口

此前提取的官方桌面资源中，共享任务行 `e8t` 对运行中的任务进入 `hU` 的停止并归档确认；普通任务菜单 `h6t` 通过统一回调归档，而非因运行中直接移除入口。空闲任务直接归档，活动任务先确认，再停止并归档。静态资源是行为依据，仍不构成当前用户版本的原生双端配对证据。

普通侧栏右键、主窗口任务工具栏、命令菜单/归档快捷键、独立任务窗口菜单/命令及 Activity 单条入口现共用固定身份的归档流程。运行中仍可进入确认，取消保留工作；空闲时直接执行。确认后复用已经验证的停止、终态检查、保存失败保护、部分输出/队列保留以及工作树清理机制。已持久化的空任务可以归档，临时侧聊和未提交的弹出草稿保持既有约束。

原有低层归档/恢复接口仍用于已知空闲状态和项目操作。项目批量归档当前仍只处理空闲任务，不把本阶段单条入口统一描述成项目批量流程也已对齐。

## 窗口、对象与焦点

单条确认固定任务 ID、请求 ID 和发起窗口 ID；主窗口使用默认归属，独立窗口只显示自身请求。主窗口的设置确认状态不再包含另一个任务窗口的归档确认，因此后台主窗口原有页面/图片预览保留。其他窗口的确认或取消回调不能执行此请求；同一窗口取消后建立新请求时，旧确认框回调也不能确认或关闭新对象。

独立窗口确认显示在本窗口覆盖层，任务内容不可点击，原内容对辅助功能隐藏，普通命令和 MCP 批准快捷键暂时停止分发。窗口内历史导航及固定内容的回显入口不能在归档确认期间替换任务。关闭发起窗口会取消尚未确认的请求；已经确认且正在执行的归档继续等待终态并报告结果。

独立窗口取消或失败后请求恢复原生响应者，缺少原控件时回到聊天输入；成功归档沿用原有关闭此独立任务窗口的行为。焦点恢复校验窗口仍为当前键窗口、原视图仍附着且无其他本窗口弹层。覆盖层拆为单独视图属性，避免在原有长 SwiftUI 表达式上触发编译器类型检查超时。实际窗口数量、响应者、Tab/Return/Esc、审批键优先级及关闭操作仍待原生配对验收。

归档停止期间，模型及本地构建/诊断入口都不能重新启动目标任务；其他任务仍可运行。普通入口的失败也写入主窗口错误/通知，不能只有 Activity 才能看到原因。
