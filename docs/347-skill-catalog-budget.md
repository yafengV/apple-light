# 技能目录预算与本轮可用性

2026-09-28。此前 ShipiOS 按目录顺序放入完整用途描述，达到固定 8,000 字符预算后跳过后面的技能。界面仍能显示这些技能，但模型可能完全看不到其名称和路径。另一个问题是在读取本轮已提供的技能时重新应用默认预算；发送后新增其他技能，可能让原来有效的条目被挤出目录并错误地拒绝读取。

本阶段依据本地 Codex 源码快照 `50d7795` 中 `ext/skills/src/render.rs` 的分配规则修正这两个差异：先保留标识和完整位置，预算不足时缩短描述并公平分配空间；所有最小条目仍放不下时才省略条目。上游的模型上下文百分比、可配置 token 预算和共享路径别名仍是后续对齐项，本阶段使用当前产品的字符预算，不将其描述为完整动态预算。

目录渲染现在先计算完整描述的成本。如果无法全部放下，但所有最小条目能放下，则保留全部 `id`、名称、路径和来源，并轮流增加每个描述的字符，避免首个长描述占满剩余空间。单项描述在目录中最多使用 1,024 个字符，完整技能指令仍由按需读取提供。只有连全部最小条目也放不下时，才使用无描述的最小条目及省略提示；不截断标识或路径，也不输出半段 JSON。

JSON 转义、引号、换行、中文、组合字符和 Emoji 的实际序列化成本进入字符预算。正常描述无需缩短时保持完整。描述平均缩短超过 100 个字符时，会话显示明确提示：模型仍可看到全部技能，但部分描述较短；省略条目时显示数量和可停用无用技能/插件的建议。提示进入同一任务时间线，主窗口及独立任务窗口沿用现有提示卡，重启后保留。

本轮技能读取现在先检查该条目确实曾提供给当前任务，再读取当前来源的启用状态、隐式调用政策、项目范围和实际目标；重新校验不再受新目录预算影响。停用、移除、改变链接目标或范围的条目仍拒绝读取；新增其他技能不会使已提供的有效技能突然不可用。

新增回归覆盖描述压缩后保留全部身份、不同条目的公平分配、完整 JSON 和原样路径、转义与 Unicode、恰好能容纳最小目录的预算、零/负预算及发送后目录增长。两种协议经临时 HTTP 模型服务验证：16 个较长描述的私有技能与项目技能共同存在时，全部 17 个条目仍提供给模型，目录尾部的项目技能通过真实读取获得完整指令；预算提示随任务持久化。基础聊天使用技能读取工具，Codex Core 使用原生文件工具。

132 项相关定向回归通过，日志为 `.cache/skill-catalog-budget-regression.log`；本阶段没有重跑全量产品回归。`script/build_and_run.sh --build-app` 构建及严格签名检查通过。
