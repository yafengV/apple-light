## 依据及代码进展

[官方审查说明](https://learn.chatgpt.com/docs/code-review)描述了点击文件名打开文件、点击标题背景展开/折叠、悬停行的加号添加反馈，以及填写后续消息提交评论的流程。该文档不能证明当前版本的像素布局。

- 审查页改为逐文件差异，文件标题显示新增/删除行数；标题背景和箭头控制折叠。不同范围保存独立折叠状态，刷新保留折叠选择。
- 文件名通过系统默认应用打开当前工作区文件；已删除文件保留历史差异并提供错误提示。自定义编辑器设置与 Cmd+行跳转尚未完成。
- 差异解析显示旧/新行号、新增/删除背景及 hunk 标题。支持多 hunk、首次添加、全部删除、无末尾换行提示，以及文件内容以 `+`/`-` 开头的行。
- 未跟踪文本文件也有差异行和新增统计；二进制/不可读文件显示说明，不编造行号。
- 行悬停出现加号，也可从行右键菜单添加评论。支持保存、编辑、取消、移除，编辑框 Escape 取消。
- 评论与编辑中的文本保存到任务草稿对应的工作区记录。记录包含项目、路径、比较范围、引用、旧/新行号、代码行和 diff 指纹。
- 刷新后代码变化时，旧反馈不强行挂到新的代码行；输入区仍可查看和编辑保存的反馈。
- 输入区显示待发送评论数量和可展开列表。用户填写明确的后续消息后，评论作为上下文进入当前模型会话或它的消息队列；其他任务的评论保持不变。
- 未保存的评论、空后续消息、错误配置、项目不一致等情况不会清掉反馈。开始会话后若服务返回错误，提交的反馈仍保留在该次消息记录中，可使用原有重跑路径。

当前独立 API 仍是文本会话，不是 Codex Core 工具执行循环。评论进入模型上下文不等于自动修改代码，不代表模型已执行审查或修复。
