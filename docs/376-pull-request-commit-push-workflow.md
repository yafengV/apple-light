# PR 弹层中的提交、推送与创建流程

## 参考证据

2026-09-28 检查当前安装的 `/Applications/ChatGPT.app` 公共应用包，版本 `26.911.61220`。包内 Codex 工作区资源 `create-pull-request-modal-content-33cfaee2b7e2.js` 显示“Commit and push local changes”复选框；`git-action-new-branch-field-d7fd686030a3.js` 的 `on`、`yn` 和 `pi` 函数分别确定下一步、禁用原因及实际执行顺序。勾选时可按状态提交并推送后创建、先推送后创建或直接创建；取消勾选时直接使用已发布分支。生成内容在仓库修改前完成，手填字段保留。

这是公共分发代码的行为证据，不是两个原生应用的逐页配对验收；没有读取用户个人 Codex 的认证、配置或历史。

## 已接入的交互

主窗口、任务窗口和分离审查入口继续复用同一个 PR 弹层。弹层提供“提交并推送本地变更”选项、增删行统计、现有标题/描述与目标分支，并显示准备、生成、提交、推送及创建的当前阶段。创建草稿的偏好保持生效，生成阶段可取消，操作期间表单和关闭受保护。

勾选时，已暂存、未暂存和未跟踪内容组成固定的本地选择；没有本地内容时不会创建空提交，尚未发布的分支可以直接推送。缺失的提交说明、标题和描述通过独立 API 生成；提交指令只用于本地提交说明，PR 指令用于整个 PR，已有手填字段保持不变。

取消勾选时不暂存、提交或推送，即使本地还有未推送的提交也只在已发布的源分支上创建 PR。生成描述只包含已发布的提交和差异，本地草稿及未跟踪文件不会混入。源分支尚未发布时，界面提示勾选该选项或先推送。

## 快照、失败与继续操作

读取和生成使用私有临时索引，不修改实际索引。操作固定仓库、远端地址、源分支、目标分支提交及所选文件签名；生成期间文件、索引、分支、远端或目标提交变化会要求重新检查。手动改变 PR 内容或提交说明不能让旧操作继续发布。

实际暂存、提交、推送和创建前分别重新检查审查权限与工作区身份。提交后核对文件树和父提交，Git 钩子改写内容会保留已成功的提交，并停止后续推送。强制推送沿用捕获的 `force-with-lease`，不以新的跟踪引用悄悄扩大租约。

提交失败保留提交说明和 PR 输入；推送失败保留已经成功的提交，重新读取当前 HEAD，重试从推送继续，不重复提交。创建结果不确定时保持标题、描述及重新检查入口，确认已有 PR 后不再重复创建。PR 记录仍按任务物理目录保存，不归入其他任务。
