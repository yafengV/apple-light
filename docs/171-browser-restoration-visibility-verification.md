## 更正空白观察的结论

本地服务收到成功请求，网页标题与 URL 正确；原生视图尺寸正常，父视图未隐藏，但 JavaScript 返回 `document.visibilityState == "hidden"`。诊断同时记录窗口 `occlusionState.rawValue == 8192`。本机 AppKit SDK 的 `NSWindow.h` 定义可见位为 `NSWindowOcclusionStateVisible = 1UL << 1`；8192 不包含该位，不能把 `window.isVisible == true` 当作窗口内容未被遮挡的证明。

WebKit 的[原生可见性判断实现](https://github.com/WebKit/WebKit/blob/main/Source/WebKit/UIProcess/mac/PageClientImplMac.mm)也检查窗口遮挡状态。该源码用于解释诊断方向；实际结论以本机原生复验为准。

恢复到 `b408aa7` 的未修改产品代码并重新启动后，先观察到同样的后台空白；实际点击窗口标题栏激活窗口后，正文和 HTML 辅助功能树出现，没有刷新网页、调整尺寸或切换标签。网页输入框可输入 `restored-page-interactive`。因此，第 170 篇把这次后台观察直接归为已确认的产品渲染缺陷，证据不足；当前前台路径没有复现持续空白。

这不等于所有网页恢复路径都已验收。后续原生检查应在每次重启后重新取得应用对象、实际激活窗口，再判断页面正文、输入和导航；不要用后台窗口截图独自判定加载或渲染失败。
