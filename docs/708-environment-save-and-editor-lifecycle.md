# 环境保存快照及编辑器关闭／重开

日期：2026-10-09。接续第 707 篇的环境读取身份，核对保存等待、目录补读与编辑器生命周期。

## 问题与行为

原保存代码在回复到达时把当前表单设为已保存基准，导致等待期间的新编辑被误标为已保存。保存未使早先读取失效；A→B→A 后，旧保存或保存后的目录回复仍可能写入当前页面。设置编辑器关闭等待旧 Agent 停止时，新的打开已经完成，旧关闭仍会清空新项目路径和目录。

| 场景 | 本阶段行为及覆盖 |
| --- | --- |
| 工作区保存期间继续编辑 | 仅以提交时表单更新已保存基准；新名称／cleanup 留在当前表单且保持未保存，保存使用的 JSON 仍是提交内容 |
| 设置编辑器保存期间继续编辑 | 相同行为，保存结束后新草稿仍可继续保存；状态明确提示提交内容已保存但当前仍有修改 |
| 保存 RPC 等待中的 A→B→A | 成功／失败回复须匹配连接代数／会话、文件与操作身份；旧回复不替换新 revision、表单、加载基准和错误／冲突状态 |
| 保存后的目录请求等待中的 A→B→A | 目录成功或失败都不再把旧操作视为当前保存成功；旧目录不写入新页面 |
| 先读取、后保存 | 保存开始使更早读取失效；旧读取结束不覆盖已保存表单、版本或状态文字 |
| 旧编辑器关闭等待期间重开另一项目 | 关闭尾部须匹配自己的连接代数；旧 Agent 停止后不清空新项目、目录、表单或 loading |
| 旧保存清理期间新编辑器开始保存 | 保存标志按连接代数清理；旧保存／关闭结束不提前清除新操作的 saving，也不阻止新连接保存 |
| 工作区切换／无项目／关闭 | 更换连接会话时释放原保存标志；旧操作的 defer 不改新连接的标志，准备或关闭期间禁止启动保存 |

保存与读取／选择／新建共用操作身份。只有当前上下文的保存结果可触发后续界面动作。操作失效并不撤销已经发送给 Agent 的磁盘写入；这里隔离 UI 回复，没有实现或声称回滚已完成的写入。

保留名字／操作校验和 `expectedRevision` 外部修改冲突要求；没有放宽冲突校验、使用真实 API、改变凭证或重置系统权限。
