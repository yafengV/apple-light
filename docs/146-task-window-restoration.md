# 任务窗口恢复与数据目录归属

2026-09-18。修复第 144、145 篇原生验收中反复出现的失效恢复窗口，并区分恢复加载、读取失败和已删除任务。

## 实现

- 独立任务窗口路由保存规范化数据目录。即使两个目录存在相同任务 ID，也不会把前一个目录的窗口绑定到后一个目录的任务。
- 所有新开窗口、分叉及返回/前进导航写入目录归属；旧版仅含任务 ID 的路由仍可解码。旧任务存在时补充当前目录，任务不存在时关闭失效恢复窗口。旧路由本身无法证明原目录，不宣称消除了旧数据同 ID 的歧义。
- SwiftUI 尚未注入路由，或 Store 尚未完成恢复时显示任务恢复状态，不提前判为已删除。
- 工作区读取失败保留窗口并显示错误、重试和关闭按钮。修复文件后可以在同一窗口重试，原路由与草稿不丢失，也不覆盖损坏文件。
- 首次恢复时已不存在的任务自动关闭；任务已经展示后再被删除，保留既有不可用页面及窗口导航，允许用户返回历史或关闭。
- 加载/错误页面将任务命令留在当前窗口，避免发送、重命名等动作回落到后台主任务。日志只记录恢复阶段的布尔状态，不记录标题、正文、凭据或目录。

## 验证

- 21 项窗口恢复、导航、分叉、命令和主工作区恢复回归通过，日志 `.cache/task-window-restoration-final-tests.log`。新增 5 项测试包括 Codable 兼容、目录身份、符号链接归一化、同 ID 目录冲突、暂未注入路由、加载与删除区别、真实损坏文件修复重试。
- 使用项目脚本构建真实 macOS App。普通退出在当前系统环境下没有恢复新打开的任务窗口，不能作为恢复通过的证据；后续仅给隔离测试进程添加 `-NSQuitAlwaysKeepsWindows YES`，没有写入系统全局偏好。
- 同目录正常退出后重启：系统实际创建任务窗口，日志经过加载到就绪；两回合历史、图片、工具结果及 `窗口恢复草稿 first` 均恢复，输入框获得焦点。
- 退出后将隔离 `workspace.json` 备份并替换为无效 JSON，再启动显示“无法恢复任务窗口”及重试入口。确认应用没有覆盖无效文件，恢复备份并点击重试后，同一窗口恢复 B 的历史和草稿。
- 从 first 目录保留窗口退出，再启动包含相同任务 ID 的 second 目录：日志确认旧窗口执行关闭分支，原生界面只显示 second 的主任务 A。状态日志 `.cache/task-window-restoration-native.log`。
- 最后恢复原数据目录及普通启动参数，严格签名检查通过；缓存、运行数据、日志和备份均不提交。

## 剩余范围

本阶段修复的是任务窗口恢复故障，尚未对齐独立标签页的恢复、跨进程导航历史及滚动/面板位置。是否恢复窗口继续遵循 macOS 的退出/恢复设置；没有强制开启全局窗口恢复。当前 Codex 全页面视觉和交互配对仍未完成。
