# 分离审查窗口的项目与评论归属

2026-09-25。分离审查窗口使用原任务的独立审查工作区，避免主窗口切换项目后，差异展示和 Git 操作跟随到其他仓库。

## 实现

新增 `DetachedReviewSession` 和 `DetachedReviewView`，按标签归属解析项目并加载差异。审查范围保存到原任务布局，不覆盖主窗口其他任务的范围。原任务删除或项目改变时清理旧差异与操作状态；窗口关闭时释放工作区。

评论显式绑定原任务或新任务草稿的项目。指定任务不存在、已删除或没有项目时，不再回退到主窗口当前项目。评论后续消息与“聚焦聊天”共用原任务跳转逻辑。

## 自动化验证

新增 6 项 `DetachedReviewTests`，覆盖跨项目切换、评论隔离、范围持久化、失效任务、草稿归属、项目变化清理，以及两个真实 Git 仓库的暂存隔离。

分离审查、审查评论、Git 审查、分离标签和终端重启共 33 项相关测试通过，0 失败。日志为 `.cache/detached-review-final-tests.log`。通过 `script/build_and_run.sh` 构建运行，严格签名检查和 `git diff --check` 通过。

## 原生验收

通过隔离工作区中已保存的分离审查布局验证，不视为完整拖放验收：

- A 的分离审查显示 `review-a` 分支和 `A.swift`。主窗口切到 B 项目并最小化后，审查窗口仍显示 A 的差异。
- 点击“全部暂存”后，A 的暂存区包含 `A.swift`，B 的暂存区仍为空。
- 切换到“已暂存”后仍显示 A 的差异。退出后的磁盘布局记录 A 为 `staged`、B 为 `unstaged`。
- 最后通过构建运行脚本恢复原工作区，原任务及待发送草稿保留，输入框可实际聚焦。
