# PR 状态菜单及状态切换

2026-10-04 核对参考应用版本 `26.930.21537`、build `12776`，读取当前分发的 `pull-request-detail-actions-2a146b8f0011.js` 和 `pull-request-detail-model-67e2525aa6e1.js`。没有读取个人配置、认证或任务历史。参考 `Ae` 只给作者和未合并 PR 提供状态操作；状态位置允许已关闭 PR。`De` 固定列出 Draft、Ready for review、Closed，当前项勾选且禁用，关闭时禁用草稿。`h` 将关闭的普通 PR 映射为 reopen，将关闭的草稿映射为 reopen-ready。

ShipiOS 在概览状态行接入无边框原生菜单“草稿／可供审查／已关闭”，主详情与紧凑摘要共用。作者的未合并 PR 显示菜单；非作者和已合并 PR 保持文本。当前状态勾选且不可重复选择，关闭后不能直接选择草稿；只读、读取中或同一 PR 正在执行其他写操作时禁用。操作中保留已确认文案并显示进度，菜单选中后关闭。正式前台菜单外观与键盘焦点仍需双端配对。

服务读取明确仓库与 PR 的详情、GraphQL 节点 ID、当前账户及作者权限，在写入前重新核对身份和最新任务写权限。使用 [GitHub GraphQL schema](https://raw.githubusercontent.com/octokit/graphql-schema/master/schema.graphql) 中的 `convertPullRequestToDraft`、`markPullRequestReadyForReview`、`closePullRequest` 和 `reopenPullRequest`，各输入都绑定 `pullRequestId`。关闭的草稿先重新打开，再重新读取、核对权限并标记就绪；已关闭的普通 PR 只需重新打开。没有调用合并来替代状态切换，也不修改本地检出。

每一步写入后重新读取实际状态。丢失响应时只核对结果，不自动重复写入；部分成功保留实际已重新打开的草稿并反馈后续失败。无法确认结果时阻止后续状态和合并操作，成功刷新后恢复；编辑器旧元数据不能解除此保护。已知失败且元数据可确认时保留评论及检查读数，不把操作错误当作元数据读取失败。错误同时进入现有通知浮层。多窗口共用 PR 写操作协调器；离页/失效后的迟到结果不会改写任务，其他窗口通过既有 PR 更新通道刷新。
