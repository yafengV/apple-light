## 已复现的问题

项目主目录从 A 改为 B 后，主窗口保留 A 的旧文件标签；草稿提升为任务后，独立任务窗口在 B 打开相对路径相同的文件，可能生成相同标签 ID。任务窗口原先通过主窗口的全局文件缓存取得编辑器，实际显示 A 的内容，查找、跳行与未保存编辑也共享；关闭任务窗口的文件还可能保存到 A。

修复前，三个原生专项方法出现 11 条失败断言、0 unexpected（`.cache/task-file-isolation-final-red-701.log`），覆盖实际文件显示、编辑器实例、写入目录、查找状态和固定／布局根目录。此前两个夹具版本存在查找 API 名称和闭包显式 self 编译错误，日志保留；不将夹具编译错误当作应用缺陷。

## 改动与交互覆盖

| 动作／状态 | 本阶段实现与证据 |
| --- | --- |
| 主窗口与独立任务窗口打开同名文件 | 每个任务窗口持有自己的文件编辑器集合，实际任务页面以执行目录打开文件；主窗口 A 的旧编辑与任务窗口 B 的编辑并存 |
| 独立窗口关闭文件 | 保存本窗口编辑器后再关闭；保存结果需要匹配原请求、任务标签集合与同一个编辑器实例，不能操作主窗口缓存 |
| 两个任务窗口 | 同任务、同文件标签也使用不同编辑器；完整隐藏任务页面的原生查找和跳行按键只操作来源窗口 |
| 任务执行目录改变 | 捕获旧目录未保存草稿并释放其编辑器，取消旧关闭请求；新目录同 ID 标签不被迟到结果关闭或写入 |
| 固定标签 | 记录窗口自己的文件根目录，按实际文件 URL 确认是否仍为原来源；同 ID 在新目录重用后，旧固定项不会被覆盖成新文件 |
| 固定项回到主窗口 | 原窗口来源失效后按保存根目录重开；与主窗口旧相对 ID 冲突时保持两个实际文件的不同身份 |
| 窗口关闭与冷恢复 | 关闭前捕获窗口文件草稿与布局；重新加载工作区记录并挂载完整任务页面后恢复 B 的未保存内容，主窗口保留 A 的文件根目录 |
| 恢复数据校验 | 保存的根目录必须有效且与任务执行目录一致；不同目录、相对目录、NUL 均被拒绝；无此可选字段的旧布局继续兼容 |
| 空文件浏览入口 | 固定项保留其窗口根目录，任务目录改变后不会误认成新目录的同 ID 浏览入口 |

文件资源由 `TaskWindowResources` 管理，跟随任务移除、目录切换及窗口关闭捕获恢复记录并释放。`FileWorkspaceTabView` 接受来源窗口的编辑器和目录；主窗口继续使用自己的文件身份规则。本阶段沿用已有文件范围校验与权限流程，没有增加系统授权，也未提取或声称复刻 Codex 的私有存储格式。
