## 实现

`PullRequestCommentComposerKind` 明确评论、编辑和回复的表面、占位与无障碍字段名称，评论正文适配器传入真实类型和作者。

- 普通评论使用现有主题派生的输入表面与边框；编辑和回复去掉外围表面、边框。输入及 footer 尺寸按 compact 布局调整，取消与提交使用 20 点圆形按钮和各自说明。
- footer 总是保留 24 点头像槽。已知当前 GitHub 登录名时加载 `.png?size=48`，空值或加载失败使用字母/空圆占位；helper 的 trim、拒绝内部空白和 URI 编码经实际参考结果核对。当前服务仍限 GitHub.com，不能视为其他托管主机已支持。
- 原生 `NSTextView` 绘制占位文字，沿用实际字体、28 点段落行高与主题文字颜色，并约束窄窗口文字宽度。编辑器的顶部 origin 和水平留白与文本测量一致。
- 外层输入区固定为内容所需高度，长文达到 192 点后滚动；不能把内部文本框的 38 点高度误当作外层也没有撑高。独立窗口宿主现同时检查完整输入区高度：空白为 74 点，长文为 228 点（含 footer）。
- 延迟自动聚焦、候选替换、原生输入、选择回调和草稿同步重新检查所属窗口内模态作用域；其他窗口不受影响，背景控件保持原有启用外观。被弹层阻止的聚焦请求不被错误标为已完成，可在弹层解除后再次请求；卸载后的回调失效。
- 普通评论/编辑/回复共用原生输入、撤销、中文组合输入和现有服务；提交、pending 锁、失败保留、输入清除所属错误与成功移除草稿均通过实际界面绑定和临时 fake CLI 路径验证。
