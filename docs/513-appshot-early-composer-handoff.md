# Appshot 早期输入区交接

此前 Appshot 必须等 ScreenCaptureKit 截图、辅助功能文字采集和附件落盘全部结束，才向输入区插入卡片并开始原生截图移动。参考端在最终附件完成前先显示占位并交接过渡，因此长时间的辅助功能采集会造成明显的空档。

现在截图编码完成即报告一份带窗口信息和应用图标的预览。所属草稿在主窗口、独立任务窗口及弹出窗口输入区预留同尺寸卡片，并可立即启动原生截图浮层。辅助功能文字继续采集；完成后用相同附件 ID 保存完整上下文，卡片直接接替占位。捕捉取消、出错或附件导入失败会移除临时卡片和对应浮层；应用退出也清除临时状态。减少动态效果、窗口不可见或最小化时直接显示预览，不启动移动动画。输入区在最终附件准备好前仍禁止发送，避免丢失辅助功能文字。

18 项 Appshot 定向测试及 24 项图片附件／任务窗口回归通过，覆盖预览早于最终结果、占位的原生视图尺寸、附件 ID 与文字元数据、取消及错误清理、窗口归属和减少动态效果。`script/build_and_run.sh --build-app`、严格深度签名及差异检查通过。当前 Mac 仍锁屏，真实跨应用动画、最终视觉细节与 Codex 双端逐项配对未能在前台验收；完整配对仍为 **0/45**。
