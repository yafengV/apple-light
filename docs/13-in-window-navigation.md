# 主窗口内页面导航修正

2026-09-16。用户明确指出：Codex 设置在主窗口内，要求每个页面的 UI 和交互对齐。此要求覆盖通用 macOS 原生独立设置窗口惯例。此前把 SwiftUI `Settings` Scene 作为产品设置入口是实现错误。

## 已修正

- 删除独立 `Settings` Scene 和 `SettingsLink`。齿轮、应用菜单“设置…”、⌘,、⌘/、⌃⇧M、输入区模型按钮、命令菜单中的设置动作统一进入主窗口内页面。
- `AppContentView` 管理工作区与设置的显示；`AppDestination` 表达工作区、项目、设置。设置左侧为返回与分类，右侧为内容，没有独立窗口或固定 760×550 的弹窗。
- 项目列表改成主窗口内容页，保留任务侧栏；设置从项目进入时返回项目页，从任务进入时返回原任务。
- 工作区视图保持挂载，但设置显示时禁用交互与辅助功能访问。设置期间不可向隐藏任务发送消息。运行中的任务保持运行。
- 六个现有设置子页在分类切换时保持各自视图状态，API 表单未保存草稿不会因切换分类丢失。离开设置不自动保存密钥或服务配置。
- 返回按钮与 Esc 绑定到当前可见页面。修复了隐藏项目搜索视图/原生焦点导致 Esc 不响应的问题。
- 设置页移除工作区侧栏开关和开发工具栏，保留原生窗口控件。移除侧栏默认工具项使用 Apple 文档所示的列内修饰位置：[toolbar(removing:)](https://developer.apple.com/documentation/swiftui/view/toolbar(removing:))。

## 实机检查

全部使用 ShipiOS 原生 macOS App。主窗口辅助功能 ID 始终以 `ShipiOS.AppContentView` 结尾的同一 `AppWindow-1`，进入设置后只改变标题，没有创建 `com_apple_SwiftUI_Settings_window`。

| 页面或入口 | 操作与结果 |
| --- | --- |
| 通用 | ⌘, 进入；设置主窗口显示发送偏好与追加消息说明 |
| 外观 | 左侧切换，在同一窗口显示系统/浅/深主题选择器 |
| 模型与 API | 输入测试用未保存地址，切到外观再返回，地址仍在；随后清空测试草稿，没有保存或发送请求 |
| 快捷键 | 左侧与 ⌘/ 均切换到同一主窗口内的快捷键页 |
| 已归档任务 | 左侧切换，当前空状态正确显示；未修改归档数据 |
| 运行时 | 左侧切换，显示原工作区的 Agent 状态和数据目录 |
| 项目页 | 从侧栏进入主窗口内容区；筛选 SlowHello → 设置 → Esc，仍返回筛选后的项目列表 |
| 任务返回 | 设置 → Esc，原任务、输入草稿与输入焦点保留 |
| 模型快捷入口 | ⌃⇧M 直接进入主窗口内“模型与 API” |
| 窗口工具栏 | 设置页没有工作区工具按钮或无效的侧栏开关；返回后恢复工作区工具栏 |

自动化：`./script/test.sh` 通过 Rust fmt/Clippy、12 项 Rust、22 项 Swift 和真实 Agent IPC 冒烟。新增 3 项导航测试覆盖所有设置分类进入/返回、活动任务与草稿保持、项目返回来源、重复进入设置、隐藏任务发送保护和临时搜索关闭。日志：`.cache/in-window-navigation-tests.log`。最后的 Esc 绑定与工具栏修正已重新构建并实机复验。
