# 文件关闭确认与实际窗口恢复验收

日期：2026-10-10。开发基线 `bdddd7b5`。本篇补 R3／R6／R7 的部分实际交互和一个文件保存缺陷；R1–R8 的交付范围不变。

## 缺陷与修复

实际独立任务窗口中，编辑文件后立即按 Cmd-W，会出现“保存此文件的更改？”确认。但原先的 3 秒自动保存仍在运行：用户尚未选择保存或放弃，编辑内容便写入磁盘，“放弃更改并关闭”无法保留原文件。

现在进入关闭确认时取消该文件待执行的自动保存；自动保存的排队和执行入口均检查待关闭文件身份，监控／冲突刷新也不能重新启动它。其他文件的自动保存不受影响。选择“继续编辑”或取消确认时重新排队自动保存；显式保存仍可执行，放弃仍清除该文件的编辑与恢复记录。已经开始写入的保存沿用原有等待和禁用放弃规则，本次不宣称撤回在途写入。

新增两个磁盘回归：保持确认超过自动保存期限，检查待关闭文件未被写入、其他文件正常保存、放弃后原文件不变；取消关闭后不增加新输入即可自动保存，随后显式保存并关闭仍可用。

## 实际窗口验收

在独立数据目录和自建 Git 工作树中，通过原生点击、粘贴及按键完成下列操作。没有填写用户 API，也没有读取个人 Codex 认证。

- 恢复归档任务后，在通知有效期内点击“查看”：退出主窗口内设置，打开正确的本地子任务并聚焦输入框。第 737 篇的过期点击失败记录保留，本篇另记成功。
- 从未选中的工作树任务菜单打开独立窗口：标题／来源正确，主窗口仍为本地子任务。实际 PTY 输入 `pwd` 返回该工作树目录；隐藏终端后返回任务输入框。文件面板双击能打开该工作树的文件。
- 文件编辑与关闭：确认框保持打开，另观察 **3.405 秒**不输入，磁盘 SHA 与原文件一致；选择放弃后文件关闭、磁盘仍为原内容。选择保存后文件关闭并写入指定内容；选择继续编辑后保留文字、编辑器和焦点，无新输入也恢复自动保存。最初非即时关闭前自动保存已完成的操作，只证明已保存文件可关闭，不当作脏文件确认通过。
- 独立窗口关闭／重开：输入草稿完整保留，主窗口未切到工作树任务。含未保存文件时关闭窗口，草稿先保存在工作区恢复记录，项目文件保持原内容；手动重开文件恢复正确文字和“未保存”状态。最后通过 UI 保存原文，核对原文件 SHA 恢复且相应恢复记录已清除。
- 正常 Cmd-Q 后标准重启：主窗口恢复正确本地任务，短暂恢复提示消失，控件可操作；手动重开工作树窗口恢复其输入草稿。本次正常退出后没有自动重开独立窗口，故不将该项记为成功。另一次标准脚本 TERM 重启后，系统恢复的独立窗口从短暂“正在恢复任务”进入正确任务、恢复输入草稿和文件面板；两种启动结果分别记录，没有修改系统窗口恢复设置。

实际页面与按键结果保存在本次工具记录；补充包哈希、磁盘状态、草稿及恢复记录在 `.cache/interactive-navigation-738/`，入口为 `final-ui-evidence.json`。构建／启动／IPC／签名记录为 `.cache/file-close-{package,fixed-launch,default-launch,ipc,signature}-738.log`，这些缓存和夹具不进入提交。
