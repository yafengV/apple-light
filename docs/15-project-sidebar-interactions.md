# 多项目侧栏与项目菜单

2026-09-16。上一轮设置页改造属于有效进展；本轮继续处理基线 B01、B04、B06、B08、B10 的已知差异，未把目标缩小为这些项目。

参考：[官方项目与任务说明](https://learn.chatgpt.com/docs/projects#organize-projects-and-chats)。置顶项目/任务、项目菜单批量归档、项目页搜索有官方行为依据。缺少当前安装版本的逐页参考画面，仍不能声称像素、悬停、动画和所有导航语义一致。

## 实现

- 所有已保存项目分别显示任务列表，每个项目独立展开/收起，状态保存在 ShipiOS 工作区记录中。无需先切换 Agent 才能看到其他项目已有任务。
- 置顶任务跨项目显示，附项目名称；普通任务保留在所属项目下。项目置顶同时影响侧栏和项目页排序。
- 侧栏和项目页共用项目菜单：新建任务、打开项目、置顶、重命名、归档项目内任务、Finder 打开。任务菜单增加标记已读操作。
- 项目别名只改变显示名称，不移动目录或改变任务所属项目。名称同步到侧栏、项目页、任务搜索、工具栏和归档上下文。
- 项目记住上次选择的任务或新任务草稿位置，切换回来恢复该选择。已归档、丢失或属于其他项目的选择不会误恢复。
- 点击其他项目的任务只记录一次原任务位置。打开已有项目保持现有会话；运行中禁用需要切换单个 Agent 进程的跨项目入口。
- 将侧栏、项目分组、任务行和任务搜索拆分为独立视图，避免继续扩大同一 SwiftUI 文件。
- 修复实机发现的重复重命名表单偶尔未预填名称问题：在呈现前同步设置输入草稿，取消不会残留到下一目标。

## 后续：未读导航与全局命令

2026-09-17。本节补充后续实现；前文“未完成”保留历史状态，最新范围以第 37 篇为准。

依据[官方命令表](https://learn.chatgpt.com/docs/reference/commands)，增加 ⌘⌥A“下一个需关注的任务”和 ⇧Esc“清除全部未读标记”。菜单、命令面板和可自定义快捷键共用命令路由。当前需关注范围是已登记的未读任务；工具审批/待输入状态尚未实现，不能据此宣称完整的 Codex attention 状态等价。

导航从当前任务之后开始按任务列表顺序查找并回绕，跳过归档、空任务和当前不可打开的跨项目任务。成功打开才消费未读状态，并返回主窗口工作区、展开归属项目/分组、保留原草稿与导航历史。存在运行中的任务时，允许查看同项目其他任务，禁止切断 Agent 的跨项目跳转。失败后保留未读，可以再次尝试；修复了“目录相同但 Agent 未连接”被误认为已打开的情况。

模型回答与本地执行共用完成事件更新未读：任务在后台、设置页/弹层背后或其他会话中完成时标记；正在前台查看的任务不新增标记。历史回放与重复完成事件不会重复加回已清除的标记，取消不作为完成提醒。手动标记、清除全部采用先持久化后更新状态，写入失败不会让界面假装成功。

Shift-Esc 使用真正的 Escape 键值；快捷键录制中普通 Esc 取消，带修饰键的 Escape 可录制。新增默认快捷键会让位于已有自定义绑定，避免升级后抢占用户的按键。

验证：55 项导航、通知、快捷键、无项目及终端回归通过（`.cache/attention-tests.log`）；浏览器回归另跑（`.cache/attention-browser-tests.log`）。新增测试覆盖循环导航、归档/不可用任务过滤、草稿保留、跨作用域、重复失败、未读去重、原子保存和已有自定义键冲突。最终原工作区启动 PID 38559，日志 `.cache/attention-launch.log`。Mac 仍锁定，新命令的原生按键分发、设置页内操作和 Codex 排序/视觉配对均未验收；不能用前文早期侧栏截图替代。

## 解锁后的未读命令复测

原生验证 ⌘⌥A 从设置跳到未读的无项目任务，并聚焦输入区。首次实际测试发现 SwiftUI 菜单的 ⇧Esc 没有清除未读；现增加仅属于当前主窗口的 AppKit 按键桥接，解析用户现有绑定，并避开弹层、恢复中状态及快捷键录制。

修复后在设置按 ⇧Esc，设置保持打开，持久化未读列表变为空。在“按组合键搜索”录制时，⇧Esc 仅匹配“清除全部未读标记”，未清除测试任务的未读状态；普通 Esc 取消录制，随后非录制状态的 ⇧Esc 可以清除，普通 Esc 返回工作区。此时持久化草稿及归档状态保持。

新增回归覆盖录制、全局弹层、模型/分支弹层、恢复保护、空列表及自定义绑定；连同导航、浏览器、工作树等 41 项通过，日志 `.cache/navigation-native-tests.log`。这些是 ShipiOS 原生验证，尚非 Codex 逐项配对。
