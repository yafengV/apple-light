# 永久工作树与主窗口设置

2026-09-17。接入项目菜单 → 创建永久工作树 → 独立项目 → 多个任务的实际流程。

## 对齐依据

[OpenAI 工作树文档](https://learn.chatgpt.com/docs/environments/git-worktrees#codex-managed-and-permanent-worktrees) 明确区分托管工作树和永久工作树：永久工作树从侧栏项目三点菜单创建，成为自己的项目，可以创建多个任务，且不会自动删除。同页说明可在 Settings > Worktrees 修改工作树根目录。

本轮实现永久工作树和根目录设置。随新任务提交自动创建的托管工作树、未提交修改转移、Handoff、环境脚本、`.worktreeinclude`、自动清理和快照恢复仍未接入。这里的“恢复登记”是永久工作树创建中断后的项目登记，不是已删除托管工作树的快照恢复。

## 页面与操作

1. 侧栏和项目页共用的项目菜单增加“创建永久工作树…”。创建面板属于主窗口。
2. 输入项目名称，选择当前提交或本地/已缓存远程分支作为起点。列表刷新后重新选择起点，提交前复核引用，过期时显示错误。
3. 明确说明原项目的未提交修改留在原处；该流程从选定提交创建一个 detached HEAD 检出，不占用新的分支名。
4. 点击“创建并打开”执行真实 `git worktree add`。成功后侧栏出现新项目，打开该目录的 Agent、文件、终端和审查环境。原项目仍可返回。
5. 工作树是持久的独立项目，可创建多个任务；现有分支选择器可从其 detached HEAD 创建分支。归档任务不会删除工作树。
6. 主窗口设置新增“工作树”分类：选择/恢复默认根目录、查看永久工作树、打开项目、在 Finder 中显示、继续中断的创建或恢复项目登记。

默认根目录是 ShipiOS 独立数据目录下的 `worktrees`。修改根目录只影响之后的创建，不移动已有工作树。名称用于项目显示，磁盘目录使用 UUID，名称不拼接成 Shell 或任意路径。侧栏和项目列表用分支图标标识已登记的永久工作树。

## 持久化与失败处理

`PermanentWorktree` 记录来源仓库、Git 公共目录、目标路径、起始提交、显示名称、时间及是否完成登记。实际 Git 创建前先原子保存待完成记录；这一步失败不会创建工作树。

创建成功后再把工作树加入项目列表并保存。第二次保存失败时，已落盘的待完成记录保留目标路径，可以从设置继续登记。恢复前核对工作树是否由原仓库登记，检查公共目录和有效 HEAD；既有检出不被重置，用户在其中新增的修改不会丢失。

创建面板发生部分失败后，按钮切换为“继续创建并打开”，锁定原来的名称与起点并复用待完成记录，避免重试生成第二份目录；关闭面板后仍可从设置恢复。

普通已有目录、被替换的仓库、Git 元数据内的目标目录，以及计划后被替换为符号链接的根目录都会被拒绝。不执行强制覆盖、删除、自动清理或网络拉取。旧工作区缺少新字段时，按默认目录和空工作树清单加载。
