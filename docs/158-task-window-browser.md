# 独立任务窗口浏览器

2026-09-19。

## 问题与实现

第 157 篇接管了独立窗口搜索，但浏览器命令仍不可用；回复链接、新建/关闭标签、截图、评论等路径依赖主窗口选择。本轮复用第 40、70—75、151 篇已有的 WebKit 面板、网页动作及搜索规则，接入明确的窗口与任务归属。没有新增 Codex 独立窗口的原生配对观察，因此这是已知功能缺口的实现与隔离验证，不代表整个独立窗口已经完全对齐。

- 独立窗口增加浏览器入口，支持地址编辑/取消、前进后退、刷新、复制网址、多标签、关闭/恢复、拖排和批量关闭，以及分栏/全宽显示。⌘T、⌘W、⌘⇧T、数字标签快捷键由当前窗口处理；网页编辑快捷键实时检查原生焦点，避免抢占草稿编辑。
- 同一窗口按任务保留 BrowserSession；通过任务搜索或返回/前进离开后，原有 WKWebView 继续保留。关闭窗口或退出应用时释放所有所属页面及下载。不同窗口不会复用同一个 WKWebView。
- 命令菜单搜索当前独立窗口的网页，选择其他任务所属的结果时在同窗口导航；不读取主窗口浏览器标签。关闭的搜索结果再次执行会被拒绝。
- 回复普通链接、显式“应用内打开”和带修饰键的打开方式通过窗口路由进入本地浏览器；保留外部浏览器偏好、文件打开和下载路径。重复同页或锚点复用页面，新标签手势创建独立页面，后台标签不抢输入焦点。
- 网页截图、元素引用和评论使用明确的任务 ID。WebKit 异步截图开始前固定草稿归属；评论标记和输入区评论列表读取该任务的数据。
- 浏览器历史、下载设置和下载记录仍由应用统一管理，通过弱引用注册窗口会话，让全局下载取消、清除网站数据和应用退出能够覆盖独立窗口。设置入口继续在主窗口内打开。
- 全宽浏览器中打开任务查找、模型选择、计划输入或终端时恢复分栏，使目标控件可见；被隐藏的会话不会继续接收审批快捷键。

## 验证

- 74 项浏览器、回复链接、命令路由与搜索相关 Swift 测试通过。真实测试网页仅监听本机回环地址。首轮沙箱限制导致 fixture 不能监听端口；获准的原生环境运行后通过。日志 `.cache/task-window-browser-tests.log`。
- 新增 WebKit 测试覆盖跨任务页面与 JavaScript 状态保留、锚点复用、历史记录、已关闭搜索结果、关闭恢复、窗口释放、后台标签焦点、全局下载取消、不同窗口分离以及明确任务的引用/评论归属。新增编辑快捷键测试确认实时焦点变化及显式菜单动作彼此独立。
- 原生隔离工作区保持主窗口任务 A、独立窗口任务 B。B 加载本地 One/Two 网页，网页链接及 ⌘← 后退有效；截图只出现在 B 草稿，网页评论只随 B 的下一条消息附带。返回主窗口后，A 草稿、附件和任务选择均保持原状。
- 原生全宽、⌘T 新标签、⌘W 关闭、⌘⇧T 恢复及 ⌘2 选中首个网页通过。网页输入 `Window B page state` 后切换到任务 A，再在菜单搜索网页 URL，返回 B 时原输入仍保留，验证未销毁/重载页面。
- 最终版本原生点击合成回复中的链接，在该独立窗口打开 One；跳转到 Two 后聚焦草稿按 ⌘←，网页保持 Two、草稿保持原文。全宽浏览器点击任务查找后恢复分栏并聚焦查找栏。
- 最终通过项目脚本恢复原工作区，保留原未发送草稿；严格应用签名检查通过。测试网页、截图、评论和缓存均不提交。
