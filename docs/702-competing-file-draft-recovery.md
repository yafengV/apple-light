# 同一文件多窗口竞争草稿的恢复与清理

日期：2026-10-09。继续推进 C15、M02、M14，处理第 701 篇留下的同一实际文件多窗口未保存版本问题。原范围保持 47 类页面入口、29 项核心功能，完整双端页面验收仍为 0/47。

## 已复现的问题

文件恢复原先仅按实际文件路径保存一份 `baseText`／`text`。两个独立任务窗口分别编辑同一文件并关闭后，后关闭窗口覆盖前者，冷恢复两个窗口会显示同一份内容。放弃恢复草稿或普通编辑器保存时，还会直接清除该路径整份记录，误删另一窗口尚未解决的版本。

另外，任务文件树在切换执行目录时先重置工作区，再绑定恢复数据，旧编辑尚未被写入恢复记录。首轮四个方法复现 **9 条失败断言、0 unexpected**，exit 1（`.cache/competing-file-recovery-red-702.log`），包含两个完整隐藏任务页面的实际编辑器内容。

## 实现与交互覆盖

| 动作／状态 | 本阶段实现与验证 |
| --- | --- |
| 同一文件的两个任务窗口 | 在一个实际路径记录下保存来源不同的并存版本；按稳定窗口 ID、任务和文件标签来源恢复各自的编辑与原始比较文本 |
| 主窗口与任务窗口 | 主文件标签、主文件树、任务文件标签、任务文件树使用不同来源，避免同一路径互相覆盖 |
| 保存一个恢复版本 | 只清理本编辑器实际选择或捕获的版本；另一份仍可恢复，并继续使用原 `baseText` 检查磁盘冲突，不静默覆盖已保存文本 |
| 放弃一个恢复版本 | 清理选中版本，保留另一窗口的记录；现有放弃／保留磁盘／使用本地编辑入口继续工作 |
| 未恢复草稿的普通保存 | 没有恢复选择记录时不删除别的窗口版本；另一窗口恢复后仍能看到原草稿和实际磁盘冲突 |
| 原来源窗口不再存在 | 新窗口沿用现有文件打开入口，恢复最近捕获版本；解决该版本后，另一新窗口还能恢复剩余版本，不要求原窗口存活 |
| 刷新恢复绑定 | 更新可供未来打开的恢复数据，不改写当前编辑文本或当前恢复选择；迟到清理不会转向后来捕获的其他来源版本 |
| 项目／任务目录切换 | 文件树先捕获旧目录的未保存编辑，再配置新目录；第 701 篇文件内容窗口的独立资源释放规则继续有效 |
| 草稿提升／内容归属变化 | 迁移已有编辑器缓存时同步更新来源；后续捕获替换本编辑器旧归属版本，冷恢复以新任务身份读取，不制造一份旧来源重复记录 |
| 持久化失败 | 捕获使用候选记录，写盘成功才更新恢复选择；清理失败保留内存记录与原选择，编辑器仍存活时可重试且只解决当前版本，其他版本不变 |
| Unicode 字节 | 恢复内容比较使用 UTF-8 字节，避免 Swift 字符串规范等价判断漏掉同一来源的实际字节变化 |
| 旧格式 | 原 `baseText`／`text` 保持可读；来源和其他版本为可选字段。继续编辑旧草稿后替换原无来源版本，不留一份过时副本 |

来源使用结构化的种类、窗口 ID、owner 和文件路径，避免自行拼接分隔符产生歧义。实际文件仍使用既有绝对路径外层键；同一来源持续编辑时替换自己的旧版本，不累积每次按键的历史。没有新增恢复页面或修改文件范围／系统权限，也不声称此本地记录格式来自 Codex。

原窗口优先匹配自己的来源；没有匹配来源时保留原有“最近捕获草稿”回退语义。保存、放弃、监控确认磁盘已等于编辑内容、关闭清理等既有回调，统一通过所选择的来源及完整文本版本清理，不按路径整批删除。
