# 托管工作树初始化脚本

2026-09-26。Codex 的[本地环境说明](https://learn.chatgpt.com/docs/environments/local-environment)规定：创建新工作树后，在任务开始前运行 setup 脚本。ShipiOS 现在允许在主窗口的“设置 → 环境”中为当前项目保存初始化脚本，并在新托管工作树接收来源修改后、首轮模型请求前执行。运行中输入区显示“正在初始化工作树…”。

脚本在新工作树目录中用登录 zsh 执行，最多运行十分钟。非零退出会保留工作树和原草稿，界面显示退出码与有限输出；用户修正脚本后可重试。成功状态写入托管工作树记录，重复调用不会重新运行已完成的脚本。旧项目构建配置缺少脚本字段时按空脚本读取。

本阶段只接通托管工作树的默认 macOS setup。Codex 的可共享 `.codex` 环境文件、跨平台脚本、cleanup、顶部快捷 action 和云环境仍未实现。代码测试与 App 构建不等于当前 Codex Mac 页面配对。

四项针对性测试通过：旧配置解码、脚本失败后修正重试、成功后不重复执行、托管工作树预留和恢复。`script/build_and_run.sh --build-app` 及严格签名校验通过。扩展工作树测试运行到既有脏 Handoff 用例时长时间无输出，已中止该次全组运行；该用例不在上述四项通过的范围内。Mac 仍锁屏，无法检查窗口实际交互。
