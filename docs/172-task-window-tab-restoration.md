# 独立任务窗口标签与布局恢复

2026-09-25。补齐独立任务窗口的布局持久化；本轮验证的是重启后手动重开窗口的内容恢复，不代表全部窗口自动重开或完整 Codex UI 对齐。

## 实现范围

- 路由保存稳定窗口 ID，窗口内切换任务时保持原窗口归属；按窗口、任务分别缓存布局，与主窗口互不覆盖。
- 保存浏览器、终端、审查标签的顺序、位置、选中项、面板显隐、左右方向、面板尺寸和文件面板显隐。网页已提交 URL 与未提交地址编辑分别保存。
- 终端恢复稳定标签 ID，但启动新 shell，不重放命令或旧环境。任务项目改变时跳过旧终端、审查和文件面板恢复。
- 延迟保存布局变更，在切换及关闭窗口、应用退出时先保存再释放资源。尚未访问的任务缓存不会被空状态覆盖；删除任务同步清理对应缓存。
- 固定网页可唤回原窗口；该窗口内尚未访问的已保存任务按需恢复。重复或无效标签被过滤，隐藏面板不会因旧焦点重新打开。损坏的可选布局缓存不会阻止任务和草稿加载。

## 原生交互验证

在隔离工作区中建立左侧审查、右侧网页、底部终端三个标签，并将网页固定到侧栏；右侧宽度设为 400、底部高度设为 255。网页加载本地 HTTP 页面后，地址栏保留未提交编辑。

正常退出并重启应用，手动重开同一任务窗口后，三个标签的位置、面板尺寸、地址编辑和聊天草稿均保留。网页正文可见，输入框可继续输入。终端重启前输出 `BEFORE:before:16727`，重启后输出 `AFTER:unset:17481`，确认 PID 更新且旧环境变量未恢复。从主窗口点击固定网页可返回原独立窗口，网页输入仍在。

最终通过构建脚本恢复原工作区，确认原任务显示正常、既有待发送草稿保留，点击输入框后实际获得焦点。隔离运行数据和日志不提交。
