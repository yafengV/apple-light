# PR 失败检查附件与 Fix

PR 检查列表新增单项 Fix/Remove 和整体 Fix all/Remove。Fix 把所选失败检查附加到所属任务，填入修复提示并聚焦输入区；用户发送后才进入模型会话。检查附件可以在输入区展开、逐项移除或全部移除，并随草稿保存和恢复。

## 实现

- `PullRequestCheckDraft` 保存所属目录、PR、添加时的头提交和所选检查。不同任务各自保存；同一任务切换到另一 PR 的 Fix 替换旧集合。分页检查仍使用 API ID，附件使用参考 UI 的链接/工作流名称身份，避免重复附加同一失败。
- 单项已附加时显示 Remove；未全部附加时 Fix all 补齐当前可见失败检查，全部附加后整体 Remove 删除这些检查。通过、进行中、未知等行没有修复按钮。移除不清空提示词。
- Fix 填入检查最新 PR、运行、注释、GitHub Actions 或外部 CI 日志的提示，要求日志和访问能力不足时说明阻碍，并在修复后验证、提交和推送。点击本身没有调用模型、切换分支或执行 Git 写入。
- 页面使用实际 PR 分支资料；添加前重新读取所属目录的检出分支。异步读取期间草稿被修改、附件被替换、任务/PR 被移除、页面失效或取消时，不覆盖新的输入。只读审查偏好不妨碍准备消息附件，实际代码操作仍由模型会话原有权限控制。
- 主窗口聚焦当前聊天；独立任务窗口使用该窗口任务，不修改主窗口选择。分离 PR 窗口聚焦已有所属任务窗口，缺少窗口时新建所属任务窗口，保留主窗口任务和草稿。窗口实际焦点仍待原生验收。
- 主窗口和独立任务窗口的发送、排队与运行中引导均携带结构化检查快照。队列编辑恢复原提示和附件，移除后不再发送这些检查；排队后新添加的草稿与检查不被旧消息消耗。保存失败、配置失败或失效的工作区保留未发送的数据。
- Chat Completions 与 Codex Responses 的真实请求均添加检查上下文，会话记录保存展开后的上下文和结构化元数据，后续历史不会遗漏所选失败检查。`/init` 不混入这些附件，存在附件时不能 `/compact`；删除任务和清理未发送弹出任务会清理对应记录。旧工作区和旧队列没有新增字段时按空值迁移。
