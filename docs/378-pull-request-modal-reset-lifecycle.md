# PR 弹层关闭与操作结束后的表单重置

## 参考证据

2026-09-29 再次读取 `/Applications/ChatGPT.app` 的公开分发资源，版本 `26.911.61220`、构建 `9647`。`local-conversation-git-actions-61fd0d6dad47.js` 与 `git-action-new-branch-field-d7fd686030a3.js` 和已有参考副本逐字节相同。未读取个人配置、认证或历史。

外层 PR 弹层的关闭回调在没有运行操作时调用重置，已有 PR 的打开入口也关闭并重置。创建操作先关闭弹层，再执行后台 mutation；`onSettled` 使用 `n||q()`，即浏览器创建保留表单，普通创建和草稿创建无论成功或失败都调用重置。重置函数 `jn` 清空标题和描述，并将本地变更勾选恢复为 true。

重置属于弹层外层生命周期，不属于内层 Git 工作流。因此模型生成、提交、推送及错误恢复继续保持实际结果，界面入口另按操作类型处理表单。分发代码不是原生双端页面验收证据。

## 实现

新增 `GitPullRequestModalScope`，将每次弹层的草稿、仓库、工作区代次和审查范围固定下来。普通关闭取消尚未结束的读取并重置三个输入，保留目标分支、已确认 PR、错误及 Git 结果。操作选择后立即关闭，交接标记防止关闭回调提前清除后台使用的输入；同一个正在关闭的弹层不能再次开始操作。

所有 UI 操作通过 `WorkspaceStore.beginPullRequestAction` 同步取得操作身份，再启动后台任务。重复激活在调度前被拒绝，失败的启动资格检查保持原输入。接受的普通创建、草稿创建及已有 PR 打开在结束时清空表单；成功、推送失败、取消和模型配置失败都遵循同一规则。浏览器创建成功和失败均保留标题、描述及勾选。

已有 PR 打开使用已校验地址，在只读审查下也可用；系统浏览器打开失败同样关闭并重置，错误在审查页保留，不伪造新增 PR 记录。真实创建仍记录已确认的 PR。推送失败后保留实际成功的提交，重新填写表单并重试不会重复提交。

迟到的关闭或任务结束不会重置被替换的草稿、变更后的仓库或新工作区。每个弹层保有自己的交接状态，旧浏览器弹层的迟到关闭也不会清除同工作区重新打开的表单；旧操作身份不能解除新操作的占用。

内层 `createPullRequest` 和 `GitHubPRDraft.create` 保留生成及失败输入的既有行为，表单重置由 UI 外层负责。通用错误文字不再声称 UI 会保留标题和描述，浏览器失败仍明确保留输入。

## 验证

测试使用临时 Git 仓库、真实 Git 提交和本地推送拒绝钩子，GitHub CLI 由进程夹具返回已知状态，系统浏览器打开由闭包替代。不创建实际 GitHub PR、不打开用户浏览器、不读取真实模型凭据。

通过 `script/build_and_run.sh --build-app` 构建正式 macOS 应用包，Swift 构建耗时 28.24 秒；随后严格深度签名校验通过。日志 `.cache/pr-modal-reset-app-build.log`、`.cache/pr-modal-reset-signature.log`。仅构建，没有启动新应用或证明原生工作区可交互。
