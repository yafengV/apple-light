# 项目准备期间的运行状态与通知补读

日期：2026-10-09。接续第 705 篇，修复跨项目打开／历史导航等待环境文件时，新页面使用过期运行状态的问题。

## 问题与行为

旧流程先读取 `run.list` 与本地模型会话，再等待环境列表和内容；准备期间的运行事件与事件缺口直接忽略。若任务在等待期间结束，目标页面仍可显示运行中，新增模型会话也可能缺失。仅把列表读取移到最后仍不够：列表已生成但回复尚未应用时到达的通知，可能比快照更新。

| 场景 | 本阶段行为及覆盖 |
| --- | --- |
| 环境列表／内容等待期间任务完成 | 环境候选完成后再读取最终运行列表，直接打开及历史导航均使用新终态；原页面、草稿与两侧历史仍在提交前保留 |
| 后台模型会话完成／新增／分叉 | 最后一次 Agent 列表回复后合并当前本地会话，避免使用进入环境读取前的副本；重新协调会话所属任务 |
| 最终快照读取期间的运行通知 | 记录运行 ID，在 scope 提交后读取最新运行；更早的通知由最终快照覆盖，不额外逐条读取 |
| 最终快照读取期间的事件缺口 | 记录缺口，在 scope 提交后重新读取列表；不把缺口当成没有更新 |
| 补读／刷新期间再次切换项目 | 请求及回复校验连接会话与准备状态；旧列表、错误和运行回复不修改正在准备的新 scope |
| 最后一次列表读取被取消或历史改变 | 保留源项目、源环境表单、源草稿及当时历史栈；不会提交已经失效的目标 |

保留运行中本地构建禁止跨项目导航的既有规则。没有新设置、真实 API 调用、凭证改动或权限重置。
