# 主窗口自动化与审查队列

2026-09-17。依据 [Codex app 发布说明](https://openai.com/index/introducing-the-codex-app/) 中“指令 + 可选技能 + 日程 + 审查队列”的自动化模型，新增 ShipiOS 本地自动化页面。自动化和设置都继续替换主窗口内容，没有增加独立窗口或 `Settings` Scene。

## 当前实现

- 主窗口侧栏、“工作区”菜单、命令菜单和 `/automations` 都打开同一个自动化页面；返回、Esc 和设置往返恢复原工作区与草稿。
- 页面提供“全部 / 运行中 / 已暂停”筛选、搜索、新建、编辑、启停、删除、立即运行、上次结果和下一次运行时间。
- 编辑器支持无项目或已保存项目、每小时/每天/每周日程、星期、时间和最长 20,000 字节的指令。指令可显式使用已启用插件的 `@标识` Skill 上下文。
- `automations.json` 只写入 ShipiOS 当前数据根目录，权限为 0600；损坏或无效数据不会静默覆盖。
- 主窗口挂载期间每 30 秒检查到期项，同一自动化不会并发重复运行。配置或凭据缺失时显示错误并推进到下一次日程，避免高频重试。
- 运行使用用户在 ShipiOS 设置中填写的独立 API 服务，不读取个人 Codex 配置。结果写入正常任务与会话记录，并标记为未读；自动化页的“等待审查”打开该任务后才清除待审状态。
- 删除自动化只删除日程，已经生成的任务和结果保留。

## 验证

`AutomationTests` 覆盖小时/日/周日程、0600 持久化、无效数据保护、启停删除、失败后的日程推进、主窗口路由、设置返回及 `/automations`。模型传输集成测试通过本机 fixture 服务验证实际请求、运行元数据、结果任务、待审状态和打开结果。

完整回归通过 318 项 Swift 测试、12 项 Rust 测试、Rust fmt/Clippy 和真实 Agent IPC 冒烟，日志记录在 `.cache/automations-full-tests.log`。

原生验收已使用隔离目录 `.shipios-local/automations-validation` 构建并启动；随后 macOS 锁屏阻止 CUA 读取窗口，因此本轮没有把页面可见性、表单焦点、弹层和重启交互标为已通过。解锁后仍需补做同一标准窗口、创建/编辑、设置往返、Esc、暂停和跨重启恢复的原生检查。

## 尚未对齐

当前调度器只在 ShipiOS 主窗口进程运行时检查日程；还没有登录项/LaunchAgent，因此关机、退出应用或休眠期间不会补跑。尚缺自然语言日程、一次性和自定义 RRULE、多个日程附着同一会话、运行历史列表、完成条件、动态调整频率、系统通知联动、审批暂停，以及 Codex Core 的工具执行和后台沙箱。

CUA 安全策略仍禁止读取本机 Codex 应用。本页依据官方功能说明实现真实本地闭环，不声称布局、动画、焦点顺序和所有调度语义已经与当前 Codex 逐像素一致。
