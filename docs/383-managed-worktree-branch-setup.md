## 实现

新增托管工作树专用“创建分支”命令及“在这里工作”弹层。命令、原生菜单、用户配置的快捷键和审查工具栏使用当前窗口所属任务与工作区；普通项目不显示此专用命令。托管工作树的命名默认分支使用独立创建入口，分离 HEAD 保留已有提交和 PR 操作。

弹层提供名称建议、手动编辑、200 毫秒校验、Enter 创建、关闭和重新检查。空名称、无效名称、已有分支、远程/标签引用及未完成首次提交均阻止创建。保留单个 `refs/heads/` 前缀的规范化，拒绝规范化后仍指向 heads/remotes/tags 的名称，同时拒绝 Git 的 `@{-1}` 展开；其他符合 Git 格式的普通名称不额外禁止。

接受创建时固定任务、托管检出身份、项目目录、仓库根目录及工作区代次。写入前核对真实 linked worktree 的 Git 目录、common directory 和登记路径；目录、任务、权限、审查范围或来源 HEAD 变化均不能继续旧操作。子目录任务在实际仓库根目录创建分支，任务执行目录不改变。

先从固定源提交创建分支，再保存引用与树对象，最后检出并保存当前任务分支。记录存入 ShipiOS 独立工作区资料，不读写个人 Codex 的 synced branch 配置。创建不暂存、不提交、不推送，本地暂存、未暂存和未跟踪内容保持。历史运行分支、真实 Core 线程身份及共享检出的其他任务记录保持。

成功后关闭准备弹层，等待关闭回调才恢复原操作，保留原任务与单次草稿选择；取消关闭丢弃待继续操作。默认分支只有推送内容的提交命令先准备分支，有可提交内容时直接打开原提交弹层。单独创建不打开提交或 PR。

分支创建、记录保存或检出失败均结束工作状态，并保留已经成功的 Git 结果。检出钩子失败不会自动删除分支；检出成功后任务资料保存失败明确提示实际分支已检出，不声称 Git 回滚。工作区重置或任务切换使迟到结果失效，不能在新窗口任务继续旧流程。
