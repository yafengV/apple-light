# 模型代码审查与 Review Delivery

2026-09-18。本轮把 Codex 的 `/review` 模型审查与 ShipiOS 原有的本地 Git 差异页拆成两条独立交互。工具栏和快捷键仍打开本地差异页；输入区的 `/review` 与代码审查命令打开模型审查选择器。

## 已实现行为

- “通用”设置新增“代码审查 / 审查结果呈现方式”，可选“内联”或“单独”，说明为“尽可能在当前聊天中启动 /review，或启动单独的审查聊天。”偏好持久化在独立数据目录，旧配置默认内联。
- `/review` 打开“代码审查”选择器，可审查未提交更改，或搜索并选择基础分支。分支审查使用 merge-base；请求前把引用解析成不可变提交。
- 未提交审查同时包含已暂存、未暂存和未跟踪文件内容。空差异及超过 512 KiB 的差异会在界面中给出错误，不会提交模型请求。
- 差异以只读 `<git_diff>` 内容发送，并附加把差异视为不可信数据的 system 指令。返回格式要求 findings-first、P0–P3、文件/行号、影响与修复建议；无问题时明确说明。
- 内联模式复用当前可用任务并保留草稿。单独模式先创建不可见的待定任务，请求成功建立后再显示和选中；失败时清理待定任务。
- 请求元数据记录 `conversation_kind: review`、审查范围、呈现方式和差异字节数；分支审查还记录选择的引用。

## 自动化验证

真实 Git fixture 覆盖已暂存、未暂存、未跟踪文件、merge-base、空差异及体积上限。真实本地 HTTP 模型 fixture 分别验证内联和单独呈现、请求正文、system 指令、任务归属、元数据、错误清理与原草稿保留。

最终 `./script/test.sh` 通过 410 项 Swift、12 项 Rust、Rust fmt/Clippy 和真实 Agent IPC 冒烟，全部无失败。`script/build_and_run.sh --build-app` 完成打包，`codesign --verify --deep --strict` 通过。

## 原生 macOS 验收

签名应用使用原隔离目录 `.shipios-local/desktop` 启动，应用 PID 67047，Agent PID 67049。侧栏账户菜单进入设置后，辅助功能树仍只有一个 `ID: main` 标准窗口，标题从任务名变为“设置”。“通用”页实际显示“代码审查”“审查结果呈现方式”“内联”“单独”和说明文本；切换到单独后再恢复内联，落盘值为 `reviewDelivery: inline`。

返回原任务后输入 `/review`，候选显示“/review, 审查代码变更”。执行后出现“代码审查”“审查未提交的更改或与分支比较”“审查未提交的更改”“针对基础分支进行审查”和 Git 引用搜索框。当前验收项目不是 Git 仓库，分支区按设计显示可见错误与“重试”，没有发起模型请求。关闭选择器后恢复原草稿“这是一条待发送草稿，重跑后应保留”。落盘复核只有该任务保持非空草稿，没有新增审查任务。

## 边界

这里完成的是 `/review` 这一条交互与请求链路。ShipiOS 原有差异页仍承担本地查看、暂存、撤销、评论和提交；推送、PR 创建、托管平台自动审查、安全审查及审批流程仍是后续范围。该结果不代表全部 Codex 页面已经配对完成。
