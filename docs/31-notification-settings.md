# 通知设置与任务跳转

2026-09-17。继续补齐设置页。依据此前读取的 [官方 Settings 文档](https://learn.chatgpt.com/docs/reference/settings#notifications)，通知页需要控制回合结束通知时机，以及是否询问通知权限。该文档没有完整规定当前 Codex 版本的选项、默认值和布局；这些细节继续待配对核验。

## 当前实现

- 主窗口设置新增“通知”，目前共八个分类。提供后台时、始终、从不三种任务结束通知策略，以及“需要通知时询问系统权限”。
- 默认后台提醒、关闭自动询问权限。页面读取系统授权状态，用户可主动允许通知、打开系统设置、刷新状态或发送测试通知；拒绝后引导到系统设置，不循环询问。
- 使用 macOS `UNUserNotificationCenter`，不是应用内静态提示。权限读取和投递实现可注入，自动化测试不会弹系统权限框，也不发送真实通知。
- 模型回复与本地诊断/构建都接入完成事件。成功与失败提醒，主动取消或中断不提醒。初始化时的历史、分叉快照、重复或迟到事件不产生重复通知。
- 权限请求返回后重新检查通知偏好和前后台状态，避免等待期间改为“从不”后仍投递。
- 通知只显示完成状态与任务标题；关联数据根目录、项目、任务和回合。通知 ID 同时包含数据目录作用域与回合 ID。
- 点击通知验证归属后打开对应任务，并请求定位到该回合。冷启动先恢复工作区再处理目标。跨项目跳转若被正在运行的任务阻止，会明确说明，不终止当前运行。
- 设置按 ShipiOS 数据目录保存；系统授权仍由 macOS 按应用管理。应用内设置未加载完成或保存失败时，不用默认空工作区覆盖已有文件，也不假装偏好已保存。
- 测试通知由用户明确点击发出，不受“从不”策略限制，但仍要求系统已授权；应用显示“已交给系统”，不宣称横幅一定可见。

## 待实机验收

本轮 CUA 再次报告 Mac 锁屏。未请求真实系统授权或发送测试通知。解锁后需要检查：

1. 通知页布局与主窗口返回；允许、拒绝、系统设置修改后的状态刷新。
2. 前台/后台/关闭三种策略，系统横幅与通知中心，以及专注模式影响。
3. 模型与本地执行成功、失败和取消，事件重放时不重复提醒。
4. 点击通知定位到目标回合；正在查找时的滚动、跨项目返回历史、冷启动、归档任务和旧数据目录通知。
5. 正在运行时跨项目通知的阻止反馈，以及解除运行后再次打开。

目前的通知实现与测试不能证明 Codex 的全部通知交互一致。其他设置页、工作树和此前锁屏期间未验收的功能继续保留待办。
