# 浏览器元素引用与任务提示历史

2026-09-17。内置浏览器现在支持选择网页元素并把结构化引用加入当前输入区；独立任务窗口也补齐空输入按 `↑` 恢复本任务上一条提示的行为。

浏览器地址栏右侧新增“选择网页元素”。进入后，网页中的悬停元素显示临时轮廓，单击会阻止原网页动作并捕获当前页面 URL、标题、稳定 CSS 选择器、标签、角色、可访问名称和受长度限制的可见文本。结果先显示在浏览器面板中，由用户明确点击“添加到输入区”后才写入当前草稿；它不会写入其他任务草稿。选择模式支持工具栏取消、网页内 Esc 和窗口级 Esc，页面导航、关闭标签或 WebView 销毁也会结束选择并清理临时样式。

元素引用以可读文本写入草稿，便于独立 API 会话理解用户指向的页面位置。网页仍是未受信任内容；选择只读取用户单击元素的有限元数据，不执行页面给出的指令，也不自动发送模型请求。浏览器仍使用内存中的非持久 WebKit 数据存储，不读取系统浏览器或个人 Codex 数据。

后续第 72 篇已在此选择器基础上加入拖选区域、可保存的多条评论、编号标记和任务消息上下文；本篇保留单次引用与提示历史阶段的验收记录。

提示历史按任务 ID 查找运行顺序中最近一条非空提示。主窗口继续支持空输入按 `↑`；独立任务窗口现在使用同一规则，并且不会读取主窗口当前选择或其他任务内容，也不会覆盖已有草稿。附件不会被历史恢复隐式复制。

15 项浏览器定向测试使用回环 HTTP 服务和真实 `WKWebView`，覆盖元素捕获、阻止链接导航、取消、结构化引用与任务草稿隔离。7 项任务窗口测试覆盖精确任务恢复、跳过空提示、缺失任务和已有草稿保护。原生隔离实例中，选择 `Next` 链接后面板显示 `#next`，页面保持 `/one`；点击“添加到输入区”得到 URL、标题、选择器、标签和文本。首次测试发现工具栏焦点下 Esc 未到达网页脚本，增加窗口级快捷键后重新构建验证通过。另一个隔离实例创建“任务窗口上条提示验收”，在独立任务窗口空输入按 `↑` 后准确恢复同名上一条提示。

完整回归为 355 项 Swift、12 项 Rust、fmt/Clippy 和真实 IPC 冒烟全部通过，日志 `.cache/browser-element-history-full-tests.log`。验收结束后以原数据目录重建启动为 PID 80338；原任务“验证新输入框的真实构建”和草稿“这是一条待发送草稿，重跑后应保留”保持不变。设置再次显示在 `ID: main` 主窗口，Esc 返回原任务。
