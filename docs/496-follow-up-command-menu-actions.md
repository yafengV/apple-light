# 运行中消息的命令菜单发送方式

当前 Codex macOS 客户端的命令目录包含 `composer.steer` 与 `composer.queue`；其输入区命令处理会把“引导”或“排队”作为本次提交动作传入，而不是修改默认偏好。ShipiOS 此前已有两种实际发送路径，但只能按设置页保存的全局偏好选择，命令菜单无法逐条指定。

现在“会话”命令组和原生任务菜单提供“引导当前运行”与“加入队列”。主窗口和独立任务窗口仅在所属聊天有活动回合且输入区有可发送内容时启用；独立任务窗口始终以该窗口的任务 ID 提交。发送函数接受一次性覆盖，原有设置保持不变；Codex Responses 活动回合的非标准模式仍按现有约束禁用。

验证：命令及任务窗口 28 项、快捷键／弹层／输入区与队列 26 项回归通过；两项真实本地 Codex Core 测试验证默认“排队”下单次“引导”确实进入运行中的任务并保留默认设置。正式应用构建、严格深度签名及 `git diff --check` 通过。Mac 锁屏阻挡前台菜单、焦点和 Codex 双端操作验收；完整配对保持 **0/45**。
