# 专用弹出窗口与全局快捷键

当前 Codex 主进程的弹出窗口使用首页与会话两个独立 panel，而不是普通任务窗口。参考 `main-DS3FMq4P.js`（SHA-256 `9f4ce005ae6422a85758fe1d8e8f26e049f85026dc65618f6901fa65b0be35c0`）：首页初始 470×290、无边框且不可手动调整大小；会话初始 470×640、无边框且可调整大小，最小 400×400。隐藏时记住上次显示的表面和会话路由；全局快捷键再次触发时恢复它。通用设置快捷键的文案依据 `general-settings-ed7ca2006cd3.js`（SHA-256 `3a2ff568faaa71fa98cde8ca59a04d525baf13ce81a470ea8ae72c5283800753`）及中文包 `zh-CN-523d79e20e0e.js`（SHA-256 `43e8401d13c6b4a2554c2263406a2bc67a5106ec6b277aea2f19d3ce978553c6`）。

ShipiOS 现在由单独的 `PopoutWindowController` 持有两个 panel，热键在隐藏／上次表面之间切换；关闭按钮隐藏窗口，首页与会话互相切换，用户拖动过的窗口位置和会话输入在隐藏后保留。首页只有发送时才创建真实弹出任务，所选独立聊天范围不改写全局默认；会话复用真实任务运行、回复与附件能力。任务被删除后，热键恢复首页而不是显示失效会话。浮窗使用项目已有的原生输入控件，遵守发送快捷键和输入法组合状态。

通用设置增加“弹出窗口快捷键”录制／清除入口，默认关闭。注册使用独立于宠物热键的 Carbon 标识，设置搜索与快捷键页共用持久化绑定；系统占用等注册错误显示在设置中。菜单栏和应用菜单也能打开／切换浮窗。

设置搜索的目标行新增原生滚动锚点：对通用设置中的弹出窗口快捷键进行离屏测试时，先确认表单位于顶部，再确认搜索后滚动超过 400pt，截图可见目标行。这修正了搜索状态已更新、但实际 `Form` 仍停在顶部的问题。弹出窗口两种尺寸也以隐藏原生窗口渲染核对；相关快捷键、设置、恢复、任务与模型流的 134 项回归通过。`script/build_and_run.sh --build-app` 构建通过，严格深度签名通过；正式包的 29 个语法资源和七份许可证与源文件逐字节一致。该构建命令没有前台启动应用，故不算可见交互验收。
