# 已归档任务的永久删除

2026-09-17。本轮补齐主窗口设置“已归档任务”中的单条和批量删除。设置仍由 `AppContentView` 路由，不创建独立窗口。

## 对照依据

OpenAI 当前帮助文档 [How to archive and delete Codex chats in the ChatGPT app](https://help.openai.com/en/articles/20001333-how-to-archive-and-delete-codex-chats-in-the-chatgpt-app) 描述的桌面流程是：先归档任务，再进入 Settings > Archived chats；单条删除使用行上的垃圾桶并确认，页面也提供删除全部归档任务。

## 已实现

- 保留原有跨项目搜索、项目名称、归档时间和恢复入口。
- 每行增加永久删除按钮，操作前显示任务名称和不可恢复说明。
- 页面顶部增加“全部删除”，显示实际归档数量并在执行前再次确认。
- 删除会原子移除任务、会话快照、草稿、队列、未读状态、侧栏位置、分支记录、评论及附件引用。
- 最后一个引用删除后，ShipiOS 私有目录中的文件和图片副本一并删除。
- 本地 Agent 的执行审计记录保持不可变；持久化 tombstone 阻止已删除执行在重启或项目重新扫描后返回桌面历史。
- 工作区文件保存失败时，不改变内存中的任务和附件引用，并在设置页显示错误。

## 验证

15 项定向测试通过，包括：

- 单条删除只影响目标归档任务，活动任务保留；
- 私有文件和图片副本实际删除；
- 删除状态跨重启保存，Agent 旧执行不会重新生成任务；
- 工作区不可写时完整回滚；旧归档记录即使没有 run ID 也能删除；
- 全部设置分类仍在同一主窗口保留活动工作区、草稿和返回目标。

随后执行完整回归：283 项 Swift 测试、12 项 Rust 测试、Rust fmt/Clippy 与真实 IPC 冒烟全部通过。日志保存在 `.cache/archived-delete-full-tests.log`。

macOS 当前处于锁屏状态，垃圾桶悬停、两个确认框、取消和焦点恢复的原生可见验收仍等待解锁。测试没有触碰用户原数据目录中的归档任务。

## 仍待配对

当前实现针对 ShipiOS 本地数据。OpenAI 云端的 30 天删除语义不适用于独立 ShipiOS 运行时；本地 Agent 的审计数据库也不作为可恢复任务暴露。行高、按钮显隐、悬停、键盘焦点、确认框文案和动画仍需与用户当前 Codex 版本配对。
