# 环境设置保存后的返回与同步保护

日期：2026-10-09。接续第 708 篇，检查 `LocalEnvironmentSettingsView` 实际保存按钮使用的页面流程，而不只检查底层保存状态。

## 问题与行为

原设置按钮保存结束后无条件返回环境概览，即使保存期间又输入新内容，或保存后的工作区同步失败。同步等待期间切换环境后，旧同步失败还会写入新选择。工作区同步内部在刷新等待后没有再次检查连接会话，可能在下一项目准备期间改变源环境选择和版本。

| 场景 | 本阶段行为及证据 |
| --- | --- |
| 保存等待期间输入新草稿 | 保存提交内容并同步工作区，返回决策为留在编辑页；新草稿、未保存标志和再次保存能力保留 |
| 保存后同步等待期间继续输入 | 同样留在编辑页，状态提示当前还有未保存修改，不自动离开 |
| 同步等待期间 A→B→A | 只匹配当前连接代数、操作身份、项目和文件的回复可更新状态或触发返回；旧失败不覆盖最新环境状态 |
| 当前同步失败 | 留在编辑页显示既有“已保存，但无法选中”信息，不把错误藏在自动返回的概览后面 |
| 已有／新建环境干净保存 | 正确传递项目、文件及 created；同步成功且无新修改时可返回概览 |
| 下一项目准备期间收到旧工作区同步 | 刷新及选择之后再次校验会话、路径、连接与准备状态；旧同步不改变源文件选择、revision 或表单 |

保存返回决策集中到 `EnvironmentSettingsSession.saveFromSettings`，实际设置按钮已调用该流程。页面调用前后还检查仍在编辑页、设置仍为环境页；已取消的流程不自动导航。上述为源码接入及共享流程测试证据，尚未完成实际窗口点击验收。

没有更改磁盘保存协议、外部修改冲突要求或首次授权，没有使用真实 API 或用户凭证。
