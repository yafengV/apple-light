# 固定标签恢复竞态与关闭恢复验收

2026-09-19。

## 原生发现与修复

补验第 162 篇的关闭恢复路径时发现：关闭独立窗口，在主窗口切到无项目任务 A，再快速双击项目 B 的网页固定项，会产生两个同名网页标签。两个异步调用在项目连接期间交错执行，先后使用同一份旧恢复记录创建内容。

现在同一固定项恢复期间只允许一个调用执行，退出时释放恢复状态。项目范围加载完成后，再检查固定项是否仍存在以及请求是否已取消，避免用户在加载期间取消固定后留下孤立标签。

## 自动化回归

新增测试通过一个有界、受文件信号控制的启动包装脚本调用真实 `shipios-agent`，精确暂停在初始化阶段，构造重复打开和取消固定的交错时序，不依赖随机延迟猜测竞态。

- 修复前，重复恢复得到 2 个网页标签而非 1 个；取消固定后仍有网页和内容标签。2 项回归共 4 个失败断言，日志 `.cache/pin-restore-race-before.log`。
- 修复后同样回归通过，并增加终端重复恢复只创建一个会话、后续打开复用会话、取消恢复后可重试。
- 最终 `PinnedTabRestoreRace|TaskWindowPin|WorkspaceTab|Sidebar|TerminalSession|TerminalHostFocus` 范围 58 项测试通过，0 失败，日志 `.cache/pin-restore-final-tests.log`。

## 原生 macOS 验收

使用隔离工作区和仅监听 loopback 的 HTTP 页面：

1. 独立窗口打开 Two 网页并固定；创建真实终端、记录变量和 PID，再固定终端。关闭整个独立窗口后，两项仍在侧栏。
2. 修复前从另一任务双击网页固定项，辅助功能树实际出现两个“关闭标签：Two”。修复后在相同跨项目路径双击，仅出现一个；再次双击仍只有一个，地址及页面正常。
3. 网页与终端恢复后仍沿用各自原固定记录 ID，来源内容 ID 更新并转为主窗口归属。固定数量从恢复前到恢复后保持 7，未追加重复固定项。
4. 旧终端 PID 为 `83481`；恢复后新 shell PID 为 `84336`，直接输入输出 `RESTORED:unset`，证明旧 shell 变量未被假装恢复。
5. 从侧栏取消终端固定后，终端标签仍在，命令输出 `UNPIN_ALIVE`，PID 保持 `84336`。取消网页固定后，网页标签、地址和页面仍可打开。持久化文件确认这两个固定 ID 已移除，固定数量由 7 降至 5。

跨应用重启的普通标签布局、跨窗口拖放及完整 Codex 配对仍未完成。本次不将固定引用的恢复等同于全部网页、终端运行状态的恢复。

最终构建和严格签名检查通过，原工作区、受保护草稿及点击输入框后的焦点已恢复。两个测试终端 PID 均已退出，临时 HTTP 服务器已停止。运行数据、脚本包装器、缓存和日志不提交。
