> 2026-09-17 更新：设备已解锁，后续实测范围与未覆盖项见 [原生审查、撤销与导航验收](23-native-review-validation.md)。下文保留本篇实现时的记录。

2026-09-16。延续逐文件审查与行内反馈，补齐文件打开偏好和行定位，并修复重命名文件只记录新路径的问题。

## 已实现

- 主窗口内“设置 → 通用”增加默认编辑器选择，提供系统默认应用、Xcode、Visual Studio Code，显示安装检测状态并允许重新检测。
- 偏好保存在 ShipiOS 独立工作区记录，旧记录默认使用系统应用；未知的未来枚举值回退到系统应用，不导致整个工作区读取失败。
- 审查页文件名、文件面板“打开”统一使用该偏好。
- Cmd 点击差异代码文本，以及行右键菜单“在编辑器打开此行”，请求编辑器打开对应工作区文件和行号。
- 删除行映射到当前 hunk 中附近的现有行。历史差异仍打开当前工作区文件，不宣称其内容与历史版本相同；已删除的文件不会被重新创建。
- 系统默认应用若是支持的 Xcode/VS Code，会使用对应行定位接口；其他默认应用无法定位行时提供设置提示。未安装编辑器不自动下载或安装。
- Cmd 点击使用局部 AppKit 命中区域，只拦截带 Cmd 的左键事件，普通选择和右键保留给原视图。没有全局事件监听器。

Git 修复：

- 状态解析保留重命名旧路径，以及重命名位于暂存区还是工作区的信息。
- 历史范围使用 NUL 分隔的 name-status 记录，保留重命名来源；纯重命名不会显示成整文件新增。
- 暂存区差异以旧、新两条字面路径比较。取消暂存重命名时恢复两侧；暂存重命名后的额外修改时只更新当前工作区路径。
- 写操作前重新读取 Git 状态，避免仅依赖界面缓存决定路径。评论上下文可记录旧文件路径。

## 接口依据

- [Codex 开发者设置](https://learn.chatgpt.com/docs/developer-settings)：桌面端可选择文件打开位置。
- [Codex 审查页](https://learn.chatgpt.com/docs/code-review)：文件名与 Cmd+代码行的编辑器打开行为。
- [VS Code 官方命令行接口文档](https://code.visualstudio.com/docs/configure/command-line)：`vscode://file/…:line:column`。代码使用 URLComponents 编码路径，并将 URL 明确交给 VS Code 应用。
- 当前机器 `/usr/bin/xcrun xed --help` 确认 `--line <number>` 支持。代码将绝对文件路径和行号作为独立进程参数传递，不拼接 shell 命令。

当前支持的编辑器集合不是对用户安装版本 Codex 全部选项的完整复刻。
