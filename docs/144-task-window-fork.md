# 独立任务窗口内分叉

2026-09-18。补齐独立任务窗口的分叉入口、当前窗口导航和失败重试。

## 行为依据

公开静态资源 `app-primary` 的分叉调用传入来源任务与工作区，并在成功后导航到新任务。斜杠命令还提供原目录和新工作树分叉选项。本阶段实现原目录分叉；新工作树分叉仍待实现，不能据此认定完整对齐。

## 实现

- 独立窗口支持任务菜单分叉、从指定回复分叉和 `/fork`；发送按钮及发送快捷键同样识别该命令。
- 成功后在当前独立窗口展示新任务，来源按钮也在当前窗口返回。主窗口的任务选择、项目和导航历史保持独立。
- 复制指定回合及之前的完整历史、附件、工具结果和任务模型选择；默认分叉停止在进行中的回合之前。缺失历史、错误项目和进行中的明确分叉点会被拒绝。
- 保存成功才清除来源 `/fork` 草稿；失败不产生残留任务，保留命令、候选和输入焦点以便重试。其他任务草稿不变。
- 重命名历史由窗口场景持有，切换分叉任务不会丢失；撤销来源任务的改名后在同一窗口返回该任务。文件、终端等任务专属状态随任务重新建立。

## 验证

- 38 项分叉、任务窗口、窗口命令、模型选择和重命名历史测试通过，日志 `.cache/task-window-fork-final-tests.log`。
- 另一个本地 HTTP 集成测试确认请求仅发送复制的历史和新提示，通过日志 `.cache/task-window-fork-transport-test.log`；未调用外部模型服务。
- 原生隔离工作区：主窗口 A、独立窗口 B，从 B 第一条回复分叉仍使用同一窗口，只包含第一回合及图片、工具结果；持久化确认 A 的选择和两条原草稿保持。
- 返回来源任务后，模拟工作区文件写入失败，`/fork` 保留并重新获得焦点；恢复文件后 Enter 成功重试。另验收任务菜单及 ⌘Return 分叉。
- 独立窗口改名后再分叉，⌘Z 恢复来源名称并返回来源任务，输入框获得焦点。
- 使用项目脚本构建并恢复原工作区，严格签名检查通过；原任务和待发送草稿保持，输入框可交互。切换数据目录后 macOS 曾恢复一个测试任务窗口，因原工作区没有该任务而显示“任务不可用”，关闭后回到正常主窗口。缓存、运行数据和测试日志不提交。
