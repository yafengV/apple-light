## 当前判断

核心功能已有广泛实现和自动验证，目前剩余 **8 组交付工作**。这是按用户工作流合并后的待补齐／待验收组数，不是 8 个从零开发的功能，也不是精确缺陷数或开发完成百分比。同一缺陷归属一组，关联页面只作为验证入口，不重复计数。

现有证据包括真实本机 Core、HTTP、IPC、Git、PTY、WebKit 和部分原生窗口操作。真实用户 API 的完整开发闭环、全部常用页面的可见交互及部分焦点行为仍没有完整验收证据；不能用测试数量代替这些验收。

## 本轮不作为对齐门槛

- ChatGPT 账户、组织、订阅额度、邀请、云端历史及 HTTPS 分享服务。
- 官方插件市场、在线技能市场、账户同步及各服务 OAuth 的完整覆盖。
- SSH／远程 App Server、云环境、跨主机 Handoff 和账户中继。
- 语音通话、全局听写、宠物、跨应用截图／Computer Use 的完整官方能力。
- 退出应用后仍执行的自动化、完整日历规则、云组织调度、自动 PR 值守／修复／合并。
- 当前 Core 不支持的目标、子任务或其他版本专属请求及功能开关变体；已有可用路径保留，核心运行不被其错误拖住。
- 所有浏览器特殊媒体及高级开发协议、跨提交脏状态迁移、所有托管平台的逐项等价。

这些功能已有的实现不删除。已暴露的入口仍应正确禁用、说明能力或报错，不能假装支持、不响应点击或持续等待。影响核心流程的可选模块缺陷仍须处理。

## 版本差异处理

当前项目以 `vendor/codex-core` 嵌入 Core；清单中的部分 Codex 依赖固定为 `50d77959bf927293c4b5ddcca81d05331ae582ea`。现有桌面行为参考为已冻结的 Codex 26.930.51102／build 13100 公共资源，二者不应假定具有相同能力。

每项按当前 Core 和独立 API 的实际能力判断：共同支持的核心功能对齐行为；界面共用的导航／状态／焦点／快捷键按参考对齐；依赖官方后端或缺少 Core 接口的功能列为暂缓并正确展示可用性。不能仅凭“可能版本不一致”跳过已有接口支持的核心功能，也不为匹配某个版本的菜单强行实现官方专属后台。
