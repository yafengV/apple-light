# Codex Responses 图片输入

2026-09-26。主窗口和独立任务窗口原有的图片导入、粘贴、预览、草稿与任务归属继续使用 ShipiOS 的附件存储。显式选择 Codex Core · Responses 后，已连接项目的普通会话现在可发送文字及图片，也可只发送图片。Swift 在提交前重新校验附件内容，将随机图片 ID、扩展名和字节数通过私有 stdio 传给 Agent；图片字节不经过 64 KiB JSON-RPC 帧。Agent 从该项目所属的 ShipiOS 附件目录构造路径，限制 UUID、格式、数量、大小、普通文件和目录边界，再用上游 `UserInput::LocalImage` 交给 Codex Core。新任务与恢复后的旧任务均使用同一图片通道。

本地假 Responses 服务的 Rust 测试断言第三轮模型请求确实含有 `data:image/png;base64`，并检查不存在的图片 ID 不会提交模型回合。Swift 集成测试覆盖新建任务仅图片输入，以及应用重启后旧任务的图片回复和附件归属。Agent 7 项测试、相关 Swift 50 项测试、应用构建与签名检查通过；真实用户服务的多模态能力仍需用户在设置里填写服务后验证。

Responses 路径的文本/PDF 文件附件、工具审批、运行中回合重放和全部页面交互仍未接入或验收。Mac 当前锁屏，本轮无法完成原生拖入、粘贴、预览与焦点的逐项可见配对；此前 Chat Completions 路径的原生验收不能代替这条新通道的验收。
