# 通知滑动方向、速度与回弹

继续对照 Codex 26.911.61220 / build 9647 的公开分发资源。当前通知容器明确传入 `swipeDirections: ["right"]`；实际 toast 组件先在位移超过 1px 后锁定水平或垂直轴，下一次移动才按该轴计算位移。向右水平位移原样跟随指针；向左位移用 `1 / (1.5 + |x| / 20)` 衰减；垂直方向无允许的滑动方向。松开时，有效位移达到 45px，或有效位移除以经过毫秒数大于 0.11，就关闭通知；低于阈值时回到原位。虽然容器只配置向右，实际回调允许速度足够高的受阻尼左滑触发左侧关闭，这是当前分发代码的行为。

在隔离 Node VM 中直接运行实际 toast 组件，模拟八组按下、移动和松开事件，覆盖慢／快短滑、45px 边界、垂直轴、受阻尼反向慢／快滑、按钮起点和已有文字选择。结果与源哈希保存在 `apps/macos/Tests/ShipiOSTests/Fixtures/notice_swipe_reference.json`。这是组件回调证据，不是桌面指针或渲染截图证据。

`NoticeSwipeGesture` 将方向锁定、有效位移与距离／速度判定独立于 SwiftUI 呈现。卡片拖动时跟随有效位移，松开未达阈值时以 400ms 缓动回弹，达到阈值时以 200ms 滑出并淡出，然后按 generation 关闭；减少动态效果时立即关闭。操作按钮起点不会启动滑动；拖动中的按钮禁用，避免滑动同时触发操作。pending 通知仍不可滑动。通知寿命的交互暂停由上一阶段的共同状态控制。
