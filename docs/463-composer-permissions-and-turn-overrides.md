# 主工作区与任务窗口输入区权限

主工作区与独立任务窗口的 Codex Core 输入区现在各有权限菜单，包含“沿用全局设置”、审批策略、只读／工作区写入／完全访问及工作区网络选项。完全访问仅在 Agent 设置页确认显示后向新草稿提供；如果旧任务已经选择完全访问，即使后来关闭显示，该任务菜单仍展示当前选择，避免隐藏实际权限。Chat Completions 模式不显示不会生效的 Codex Core 权限菜单。

主工作区新任务的选择跟随草稿身份持久化，切项目或切换任务不串用。普通新任务在首轮提交时把选择固定到新任务并清除草稿选择；托管工作树创建时也把来源草稿选择转移到工作树任务。现有任务的选择按任务 ID 保存，主窗口与独立任务窗口读取同一份状态。选择“沿用全局设置”会移除当前草稿或任务的显式覆盖；关闭完全访问的显示设置时，新草稿中的完全访问回退为工作区写入，已有任务快照保留。

此前 Codex Core 只在线程启动时接收权限，因此续聊更改菜单不会改变执行权限。现在 Swift 在每次 `codex.turn.submit` 发送当前选择；Rust Agent 将该选择作为每轮 `ThreadSettingsOverrides` 的审批策略与权限配置传入 Codex Core。旧客户端不传本字段时仍沿用线程初始设置；计划／只读回合仍由 Core 限制为只读，不会因输入区选择而放宽。

验证包括 `WorkspaceLibraryTests` 的草稿／任务隔离及重启持久化、本地模型服务下普通新任务和工作树新任务的权限快照，以及真实 Codex Core 同一任务的两轮测试：只读回合尝试写入未产生文件，改为工作区写入后下一轮在项目目录成功写入。`shipios-codex` 11 项单元测试、Agent 协议兼容测试、Python 样例语法检查、Rust 格式检查、`script/build_and_run.sh --verify` 正式构建启动与严格深度签名均通过。回环模型服务测试需要系统权限；受限沙箱内服务无法绑定端口。

Mac 仍锁屏，桌面控制无法检查输入区菜单的实际点击、焦点、键盘及布局；Codex 参考应用的桌面读取也受限制。弹出任务、主工作区和独立任务窗口的三种菜单尚未完成双端逐项交互配对，完整验收保持 **0/45**。
