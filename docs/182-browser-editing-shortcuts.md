# 网页编辑区域与浏览器历史快捷键

2026-09-26。修复网页输入时 ⌘←/⌘→ 被浏览器历史快捷键抢走的问题。

## 问题与实现

原生复现：B 网页从 Beta 导航到 Gamma 后，在 Gamma 的输入框键入 `hello world`，按 ⌘← 直接退回 Beta，输入被打断。WebKit 的原生 first responder 对普通网页和网页输入框相同，原有命令路由只能看出网页获得焦点。

每个 WebKit 内容控制器现在只安装一次隔离内容世界的焦点脚本和消息处理器。它报告 input、textarea、contenteditable 的焦点变化；原生侧按网页实例和 frame 保存可编辑状态，并在页面导航、关闭时清空。共享控制器的多个网页继续共用一个处理器，关闭其中一个不会撤除另一个的监听。

主窗口、分离内容窗口和独立任务窗口在地址栏或网页可编辑区域获得焦点时，将浏览器后退/前进的键盘事件交回文本编辑；普通网页内容保持 ⌘←/⌘→ 历史导航。显式点击浏览器后退/前进按钮不受键盘焦点限制。

## 验证

真实 WebKit 页面测试覆盖 input、contenteditable、失焦和导航清理；共享控制器测试覆盖脚本不重复安装及关闭另一网页后继续上报。连同分离窗口命令、独立窗口命令和网页子窗口回归，共 20 项通过，0 失败，日志为忽略的 `.cache/browser-edit-keys-shared-tests.log`。`script/build_and_run.sh` 构建运行，签名校验和 diff 检查通过。

原生隔离数据目录中：

1. 修复前，主窗口 B 的 Gamma 输入框键入 `hello world` 后按 ⌘←，页面错误地退回 Beta。
2. 修复后，Gamma 输入框中的 ⌘← 把光标移到行首，随后输入显示为 `Xhello world`；地址栏中同样可在行首插入文本，页面仍为 Gamma。点击正文后 ⌘← 回到 Beta，⌘→ 再回 Gamma。
3. 最终构建中，A 的分离 Gamma 网页输入后按 ⌘←，文字仍在 Gamma 输入框行首插入；点击正文后 ⌘← 正确返回分离窗口的 Delta 页面。

这轮没有把嵌套 frame 的全部站点行为、输入法组合、自定义快捷键冲突和 Codex 当前版本配对判为完整验收。测试服务与隔离数据不提交。
