## 实现

普通评论、评论编辑及线程/引用回复输入接入 `@` 候选。基础查询读取前 100 位 PR 参与者；裸 `@` 可显示参与者，单字符在本地过滤，没有候选时关闭列表。至少两个字符延迟 500 毫秒后查询仓库前十项可提及用户，先合并匹配参与者，再合并仓库结果，按登录名忽略大小写去重并最多显示十项。账户、仓库与 PR 身份逐次检查；查询正文复用私有 JSON 文件传参及清理机制。

成功查询使用一分钟内存缓存，按项目目录、PR、账户、CLI 来源和查询隔离。多个输入区共享在途请求；关闭其中一个输入不取消其他输入仍需要的查询，最后一个等待者取消时清理请求。失败不自动重试、不缓存；过期后重新打开候选会更新基础参与者。旧上下文、旧查询和取消结果不能覆盖当前候选。

候选通过主窗口内容层呈现，脱离活动页滚动裁剪；优先显示在输入框上方，相隔 8 点，空间不足时换侧或限高，保留窗口边缘 6 点间距。候选不接收编辑焦点，滚动或改变窗口大小时重新定位；编辑器离开窗口、隐藏或失去焦点时清理候选。实际点击、遮挡和全部滚动时序仍须原生验收。

方向键及 macOS Ctrl+N/P 移动候选，Enter/Tab 插入当前用户名，Esc 关闭；Cmd/Ctrl+Enter 关闭候选后提交表单。输入法组合期间由原生文本系统处理按键。插入替换整个用户名，包括光标后尚未输入完的部分，只有位于正文末尾才添加空格；中文/emoji 前缀按 UTF-16 计算。原生 `insertText` 保留撤销/重做，异步插入前检查原文、选区、输入法和当前第一响应者，防止过期选择修改新输入。

评论正文按内容增长，使用 16 点文字、28 点行高及最高 192 点输入高度；标题和描述既有编辑规则保持各自范围。普通输入不主动聚焦，编辑/回复沿用显式焦点请求。取消和发送采用独立的紧凑图标与可访问名称，只有本输入区待提交时显示进度并锁定本输入。

错误按普通评论、每条编辑/回复、审查、删除目标、线程和活动读取分别保存。评论错误在对应输入区下方显示；编辑另一条评论、后台刷新或成功发布其他输入不会清除原错误。提交时其他输入仍可编辑，PR 写入继续共用互斥；结果待确认的输入保留正文和错误，只读确认成功后才清除，不重复发布。
