# 主窗口电脑使用设置

2026-09-17。依据 [官方 Computer Use 文档](https://learn.chatgpt.com/zh-Hans/docs/computer-use) 增加电脑使用设置页。官方页面将操作系统的屏幕录制/辅助功能权限与应用级批准分开；ShipiOS 沿用这一模型，并继续把设置放在主窗口中。

## 当前实现

- “控制”区提供“任意应用”策略开关，并显示内置浏览器连接状态；“管理”直接切到主窗口浏览器设置页。
- “macOS 系统访问”读取 `CGPreflightScreenCaptureAccess` 和 `AXIsProcessTrusted` 的真实状态。用户主动点击时可请求系统授权或打开对应的“隐私与安全性”页面；返回 ShipiOS 前台时自动重新检查。
- “始终允许的应用”可通过系统文件选择器添加 `.app`，保存显示名称、Bundle ID 和标准化路径，可逐项移除。策略位于当前数据根目录 `computer-use.json`，权限为 0600，不读取个人 Codex 配置。
- 配置加载失败不会覆盖原文件；页面显示错误和重新加载入口。应用列表去重，设置及原工作区状态在分类切换和重启时保留。
- “锁定状态下使用”按官方页面保留对应区块，但明确禁用。该能力需要 Apple 授权的系统插件，当前 ShipiOS 构建没有安装或冒充这一插件。

## 自动化与原生验收

`ComputerUseTests` 覆盖任意应用策略、始终允许应用、去重、0600 权限、删除和完整重启恢复。页面导航测试自动覆盖新增设置分类，完整回归通过 306 项 Swift 测试、12 项 Rust 测试、Rust fmt/Clippy 与真实 Agent IPC 冒烟，日志为 `.cache/pets-computer-use-full-tests.log`。随后只调整“管理”行的 SwiftUI 辅助功能分组，2 项 ComputerUse 定向测试再次通过。

原生验收确认“电脑使用”出现在同一主窗口的设置侧栏；页面显示当前机器的屏幕录制和辅助功能状态、重新检查、请求访问、打开系统设置、空的始终允许列表及锁定状态说明。“任意应用”从关闭切换为开启后，完整重启应用仍为开启。“管理”按钮在辅助功能树中独立暴露并实际切到主窗口“浏览器”分类。测试没有点击系统授权按钮或更改 macOS 隐私设置。

隔离验收结束后，应用已切回 `.shipios-local/desktop`（PID 19008），原任务和待发送草稿均由原生辅助功能树确认保留。

## 尚未对齐

当前页面管理真实系统权限状态和本地应用策略，但 ShipiOS 尚未接入可查看/操作任意桌面应用的 Computer Use MCP/技能运行时，始终允许列表也尚未被该运行时消费。浏览器扩展、Excel/PowerPoint 插件、每次应用控制的批准弹窗、Appshots、锁定状态系统插件和管理员托管策略仍缺失。

CUA 出于安全限制拒绝读取正在承载本任务的 Codex 应用，因此本轮只能对照官方文档和 ShipiOS 原生结果，不能声称当前用户版本 Codex 的像素、焦点和动画已完成一一配对。
