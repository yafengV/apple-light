# 环境读取期间的新输入与放弃修改返回保护

日期：2026-10-09。接续第 709 篇，修复工作区与设置编辑器在异步读取环境时覆盖新输入的问题。

## 行为

| 场景 | 修复后的行为 |
| --- | --- |
| 同文件重新读取期间继续输入 | 工作区与设置编辑器均保留当前完整表单、原已加载基准及 revision；迟到成功回复不覆盖新内容 |
| 读取期间继续输入，随后收到错误 | 保留新表单及既有版本，显示保留编辑提示；旧错误不清空内容或禁用原本可保存的编辑器 |
| 目录列表或随后文件内容刷新期间输入 | 两个等待阶段分别比较开始时的完整表单，发现新修改即停止应用旧回复；保留原选择及版本 |
| 设置页确认放弃后，在重读期间又输入 | 实际确认按钮调用 `reloadFromSettings`，返回决策为留在编辑页，新草稿保持未保存 |
| 确认放弃后的读取失败 | 留在编辑页显示错误，不无条件返回概览 |
| 确认放弃后无新输入且读取成功 | 原已授权放弃的草稿被磁盘内容替换，干净状态允许返回概览 |

完整表单包括名称、通用／平台初始化、通用／平台清理和 actions。发现新输入后使当前读取操作身份失效，防止选择流程的后续步骤把已丢弃回复视为成功。本阶段不将未展示的磁盘内容或 revision 合并进新草稿；保留原 revision，使后续保存仍经过既有外部修改冲突校验。没有改变保存协议或首次授权要求。

设置确认按钮在等待前后还检查当前仍为环境设置编辑页。该接入与共享返回流程已检查，但完整页面离开再返回的生命周期、全部确认组合、焦点及前台实际点击仍待验收。
