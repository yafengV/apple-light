# 主窗口计划模式

2026-09-17。输入区增加一次性计划模式，使独立 API 会话可以先产出可审查的实施计划，再进入普通执行交流。该模式位于现有主窗口输入区，不创建独立窗口或设置窗口。

## 交互

- 在斜杠候选中选择 `/plan`，或从输入区模式菜单选择“计划模式”。输入区模式标签变为“计划”，旁边提供明确的退出按钮。
- `/plan` 只切换模式并保持输入焦点；`/plan 具体需求` 会去掉命令前缀并直接把后续文字作为计划请求发送。
- 计划模式是一次性的。请求成功创建、或在运行中进入等待/引导队列后，当前输入区恢复标准模式；请求在创建前失败时保持计划模式，便于修正配置后重试。
- 切换任务或新建任务会恢复标准模式，避免把计划状态意外带到另一个会话。
- 计划消息进入等待队列时保留模式，编辑队列消息时恢复对应模式；旧数据缺少模式字段时兼容为标准消息。
- 重试历史计划回合时保留计划模式。运行标题显示“计划 · 模型”，运行请求元数据保存 `mode: plan`。
- 成功的计划回复下方显示“按计划继续”。该操作在输入区为空时预填标准模式执行提示并恢复焦点；已有草稿或附件时拒绝覆盖。

## 模型行为

计划回合在现有个性化、记忆与插件/技能上下文之间加入独立 system 指令，要求模型输出有序步骤、关键文件或系统边界、验证方法、必要假设和主要风险，并禁止声称已完成尚未执行的工作。用户消息保持原文，仍使用用户在设置中配置的独立 API 服务。

## 验证

命令测试覆盖 `/plan` 候选、菜单选择、带参数命令、任务切换重置、旧队列迁移和“按计划继续”的草稿保护。模型传输集成测试通过本机 HTTP fixture 验证计划指令进入真实请求、user message 不被改写、运行元数据与标题正确，并在创建回合后恢复标准模式。

完整回归为 331 项 Swift、12 项 Rust、fmt/Clippy 与 IPC 冒烟通过，结果记录在 `.cache/plan-mode-full-tests.log`。macOS 会话仍处于锁屏状态，本轮不能对模式菜单、退出按钮、焦点、队列标签和“按计划继续”卡片做原生可见验收。

计划模式当前只生成可审查文本，不包含 Codex Core 的结构化目标状态、工具执行、审批或计划步骤自动更新；这些仍属于后续运行时差距。
