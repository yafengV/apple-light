# Hook 声明的完整类型展示

Hooks 设置页此前只列出 `command`，使同一插件内的 `mcp_tool`、`prompt` 和 `agent` 声明不可见。现在四类处理器均列出，并显示事件、命令或 MCP 目标、匹配条件、状态文字、超时和配置来源。空配置保持正常空状态；损坏的 `hooks` 结构显示读取错误，不再伪装为没有声明。

状态说明参考项目固定 Codex Core `50d77959` 的 Hook 发现逻辑：空命令、缺少 MCP 目标、未知事件、`SessionEnd` 的 MCP Hook 会被跳过；此版本尚不支持 Prompt 和 Agent Hook。ShipiOS 目前仍只做声明检查，尚未将插件 Hook 加入任务运行时，也未提供逐定义信任及执行审计。因此即使命令或 MCP Hook 结构有效，页面仍显示当前不会执行。

验证：Hook 声明专项测试、现有插件回归、原生应用构建与签名检查。桌面锁屏阻止了设置页点击和 Codex 双端视觉、焦点配对。
