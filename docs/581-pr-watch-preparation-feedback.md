# PR 监控工作树准备状态与完成通知

第 580 篇改为按需创建修复工作树后，检查模型回合结束会提前发送“任务已完成”，随后真实工作树初始化仍在进行；修复任务转入另一项目后，结束通知又可能因主窗口仍在来源项目而漏发。本阶段修正这两处时机，未将模型检查和修复改为单个回合。

只有当前调度器确实正在执行、任务和监控归属一致、最近成功的检查回合持久保存了修复请求时，才显示“正在准备修复工作树”。仅有磁盘请求不能表示操作仍在运行。主会话、独立任务窗口和右侧进度面板共用此状态，准备期间输入仍可编辑，但不能提前发送普通回合；拒绝发送时草稿保留。模型主动暂停且尚未开始准备时不显示虚假加载；已在运行的初始化则保留真实执行状态至其返回。

真实准备操作以应用拥有的工具记录保存运行中、成功、失败或取消，输出包含实际准备结果或错误。初始化失败在原进度入口提供错误提示，保留未完成的日程供恢复，至少五分钟后再重试，避免每次轮询重复初始化。重启会取消未确认的准备记录，保留已成功的模型检查状态，后续监控继续核对和恢复同一检出。

准备后还要修复的中间检查结果不发布完成通知，也不提前标为未读。最终修复结束从完整会话库获取结果，主窗口留在来源项目也可通知，并按实际任务路径和回合定位。无需修复或模型已暂停的单阶段检查仍只通知一次；通知去重不会重放中间结果。
