# 原生子会话持久历史、详情与输入

接续[子任务概览](614-native-subagent-monitor-and-overview.md)。本阶段把主窗口、独立任务窗口及分离内容标签中的概览行接到子会话详情。目标仍是全部页面和核心功能对齐，不能把本阶段当作子任务或整个应用完整验收。

## 参考及实现

参考本机版本 26.930.21537 的公开组件 `subagent-panel-ddcf64e588b9.js` 和 `local-conversation-subagents-panel-tab-7e63a07a2817.js`：概览行可选择，详情标题包含返回、24 点头像、名称及模型信息。本阶段修正标题 8 点间距、16 点水平内边距、名称中等字重。没有取得 Codex 自身前台证据；默认人像还不是参考的确定性头像。

| 行为 | 当前实现及边界 |
| --- | --- |
| 点击与返回 | 行进入同一右侧标签内的子详情，返回列表；状态与草稿属于该窗口，主/任务/分离窗口不共享选择；所属父线程变更会退出详情 |
| 标题 | 显示子任务名称、模型与推理强度；返回有名称和稳定标识。精确截断比例、所有键盘焦点和主题仍需前台配对 |
| 历史来源 | task-private 原生 ThreadManager 子树校验后，通过 ThreadStore.load_history 读取完整持久记录；加载线程先 flush，不抢占父/子事件消费者；冷子历史不会被重新加载或执行 |
| 历史范围 | 保留整理上下文之前的持久记录，不把模型的压缩上下文当成完整会话；摘要最多 1,024 字符的旧 preview 不用于代替详情 |
| 历史传输 | 每次读取取得独立不可变快照，48 KiB UTF-8 分块，根/子身份、偏移、总字节数、UUID、终态和 SHA-256 校验；全部组装成功后才更新页面，没有按行数或消息长度截断历史 |
| 并发读取 | 快照归父线程 handle，多个窗口各自完成自己的读取；活动缓存按最后访问清理，根关闭后释放，不写入用户任务 JSON |
| 呈现 | 用户/助手文字、Markdown、公开思考摘要、原始工具调用与输出、部分原生 TurnItem、上下文整理标记；私有开发者/系统消息、加密内容和原始思考不作为呈现记录传给界面 |
| 加载与错误 | 空状态、加载提示、原历史保留、错误和重新加载；旧选择的迟到结果不能覆盖新选择；取消释放忙碌状态 |
| 续聊 | 只向当前已加载且属于该父任务的子线程原子 start_turn_if_idle；父回复保持不变，使用子线程本来的模型和权限 |
| 引导 | 工作中的子线程必须有实际回合 ID，原生 steer_turn 验证 ID；忙碌、不匹配、冷线程及无关根/同 manager 的 peer 都拒绝，不转成新的父任务回合 |
| 草稿 | 失败保留草稿，成功只清除提交时仍相同的文本；迟到的旧提交不能清除新选择或新编辑的草稿 |
| 刷新 | 子状态变化或手动重试重新读取；实际工作中的子会话每秒刷新持久记录，稳定完成/错误停止轮询。这不是逐 delta 流式呈现 |

原生历史记录本身受 Core 的持久化策略影响。暂态审批、未完成 delta 等未持久记录没有因上述分页自动获得；不能将“完整持久记录”写成“所有原生 UI 时间线事件已完整呈现”。父线程重启后尚未连接时会报可恢复错误，目前没有离线读取未恢复父线程的完整子历史。
