# 固定浏览器来源分叉菜单

日期：2026-10-09。

## 参考和实现

沿用已冻结的 Codex 26.930.51102／build 13100 公共资源。执行实际 `ewa/eYr/tYr`，核对分叉子菜单位于复制标签页之后、复制 URL 之前；子项使用来源 conversation ID 和 workspace root，成功后导航到返回的新聊天。工作树来源显示相同工作树，项目外来源只提供本地。子项采用实际中文资源中的“创建聊天分支”“在同一工作树中创建聊天分支”“在新工作树中创建聊天分支”；提取器核验中文资源摘要，测试与实际翻译相比较。参考提取明确模拟 `fCa/pCa` 的运行时返回值，不把 JavaScript 菜单验证称为真实 Core 或工作树执行验证。

新增 `PinnedBrowserForking.swift`，从固定标签保存的 owner 解析任务，复用本地／相同工作树分叉和新工作树生命周期。主窗口后台来源与独立任务窗口来源都从原任务历史创建新任务，然后打开保存的新任务；不把当前显示的无关聊天当成来源。调用前验证原 pin、generation、项目、面板、session 和 page 实例，拒绝关闭、取消固定、模态、归档及已经分叉的来源。

本地路径保留原生 `codexForkOrigin` 和固定回合边界，Core 在第一次续聊时创建原生子会话；新工作树路径保留 Git 索引、工作区修改、已完成历史和恢复检查点。失败保存不发布幽灵任务，保留原页面并允许重试。来源的草稿及运行中回合不被分叉消耗。

## 尚未完成

Codex 的新工作树菜单会立即打开 pending client thread；目前 ShipiOS 在已有工作树创建流程完成后打开任务。Core 本地分叉的实际创建仍在首次续聊时执行，尚未与参考的菜单立即创建／失败提示时机完全一致。新任务标题仍采用现有的“· 分叉”标记，参考的本地分叉保留原标题，准备中工作树则有临时标题，后续需同步。空历史来源的分叉、运行时等待提示及异步取消也需继续核对；参考资源的 continue 功能开关变体也尚未验收。

本阶段不替代真实前台菜单、窗口焦点及双端配对验收。音频静音、完整浏览器历史克隆、特殊媒体、iframe/CDP/WebMCP 和页面视觉仍待完成。完整范围保持 47 页面、29 核心项，完整双端配对仍为 0/47。
