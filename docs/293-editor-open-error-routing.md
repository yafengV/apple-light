# 外部编辑器打开失败归属

2026-09-27。Codex 桌面应用的[官方介绍](https://openai.com/index/introducing-the-codex-app/)描述了在应用中审查差异，再交给外部编辑器手动修改。ShipiOS 已有只读文件预览、审查差异中的文件与行打开，以及可选的系统默认应用、Xcode 和 VS Code；因此维持只读预览，修正这条现有交互。

先前独立任务窗口中的文件打开失败会写入主窗口的 Git 错误状态，当前任务窗口可能看不到。现在文件面板与审查差异都将失败写入所属 `DeveloperWorkspace`，在对应面板显示；更换文件或项目会清除旧错误，较慢的旧打开请求也不能覆盖新上下文。文件面板的按钮明确标为“在编辑器中打开”，悬停提示显示当前所选编辑器。

26 项相关测试通过，覆盖独立工作区错误归属、切换清理、现有文件预览和审查回归；`script/build_and_run.sh --build-app` 与 `codesign --verify --deep --strict` 通过。Mac 仍锁屏，外部编辑器实际启动、页面显示和 Codex 双端交互未验收；43 个验收面仍无完整配对验收。
