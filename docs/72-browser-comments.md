# 浏览器多元素与区域评论

2026-09-17。内置浏览器批注已从单个元素引用扩展为可保存的多条评论。实现依据 [OpenAI 浏览器文档](https://learn.chatgpt.com/ko-KR/docs/browser)：开启批注模式后可点击元素或拖动选择区域，填写并保存评论，再在聊天中要求处理；页面应显示带编号的评论标记。

批注模式现在支持两种锚点。单击元素保存页面 URL、标题、CSS 选择器、标签、可访问名称、有限可见文本和当时边界；拖动则额外保存文档坐标区域。选择会阻止原页面点击动作，Esc、工具栏取消、导航和关闭标签均结束模式并清理临时样式。

保存后的评论按任务 ID 写入独立 `workspace.json`。当前页面会绘制蓝色边框和编号，元素锚点随当前 DOM 位置重新计算，区域锚点保留选择时坐标。浏览器面板列出评论内容与页面，主输入区和独立任务窗口显示“将随消息发送”的评论数量。任务切换、其他窗口和其他任务的评论不会混入。

发送模型消息时，评论以结构化 JSON 附在用户提示之后，包含页面、选择器、区域与反馈正文。空提示、非模型操作和无效 URL 会被拒绝。评论只有在消息成功排队或模型回合已写入任务后才清除；配置失败或保存失败会保留。删除任务时同步清理该任务评论。

19 项浏览器定向测试使用真实 `WKWebView`，覆盖元素选择、拖动区域、编号标记、链接动作阻止、取消、任务隔离、编码持久化以及运行中消息队列的真实评论内容。完整回归为 359 项 Swift、12 项 Rust、fmt/Clippy 和真实 IPC 冒烟全部通过，日志 `.cache/browser-comments-full-tests.log`。

原生隔离实例加载 `http://127.0.0.1:55267/one`，选择 `Next` 后页面仍停留在 `/one`。输入“这个链接在窄屏时必须保持单行”并保存，浏览器与主输入区都显示 1 条待发送评论，页面目标出现蓝色编号 `1` 标记。以相同隔离数据目录完整重启后，主输入区仍显示这条待发送评论。

验收后以原数据目录重启为 PID 89536。主窗口仍选中“验证新输入框的真实构建”，草稿“这是一条待发送草稿，重跑后应保留”保持不变；`⌘,` 继续在同一个 `ID: main` 窗口显示设置，Esc 返回原任务。

当前尚未实现官方文档中的字体、文字、间距、颜色等样式调整预览。模型主动控制浏览器、站点授权弹窗、完整 CDP 与持久浏览器资料仍是后续对齐项；下载设置已在第 73 篇补齐。
