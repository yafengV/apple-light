# 提交或推送弹层与强制推送偏好

2026-09-18。本轮补齐审查页的提交/推送操作及主窗口 Git 设置的推送偏好。此前的提交指令生成见 [第 95 篇](95-git-commit-instructions.md)。

## 对照证据

本机 Codex 静态 UI 包中的 `git-branch-picker-dropdown-content-17fc53789202.js` 包含“Commit or push”弹层、提交说明输入、留空自动生成、Commit / Commit and push / Push 选项。`git-action-new-branch-field-824effe030d6.js` 定义推送进度、成功和失败、无新提交及分支不可用状态。`git-settings-be89d122415f.js` 中的 Always force push 明确使用 `--force-with-lease`。

这是静态流程证据，不代表已经完成原生逐项配对。

## 实现

- 审查页原来的内联提交栏改为“提交或推送…”入口，在所属窗口内呈现弹层。主窗口与独立任务窗口共用组件；设置仍在主窗口中。
- 多行提交说明、生成及取消生成、留空自动生成、提交、提交并推送、单独推送、阶段进度、失败信息与成功状态。
- 从真实仓库读取远端和本地分支，按 branch.pushRemote / remote.pushDefault / upstream / origin 选择默认远端；可指定远端分支。没有本地提交时允许先提交再推送。
- 推送状态加载时禁用按钮；基于本地跟踪引用检查是否有新提交，不做隐式 fetch。读取失败可重试。
- Git 设置增加“始终强制推送”，保存后实际采用明确目标引用和期望 OID 的 `--force-with-lease`。默认关闭；保存失败不覆盖旧偏好。设置搜索可定位此项。
- 推送前复核本地分支、提交、推送 URL 和跟踪引用；推送不可变提交 OID。只推送所选分支，不跟随标签、不递归推送子模块，不沿用远端 mirror / 多 refspec 扩大范围。
- 首次成功推送后设置上游；已有上游和三角工作流保持原样。多个 push URL、分离 HEAD、无远端、无效分支等情形显示原因。
- 提交成功但推送失败时保留“已提交”状态；可单独重试推送，不重复创建提交。失败不清除未提交的说明；切换项目后的旧操作结果不会写到新项目。
