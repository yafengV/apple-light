# 设置表单按钮的键盘操作

2026-09-18。接续 [设置开关](119-settings-switch-controls.md)，补齐设置表单中的默认操作按钮。

## 已实现

`SettingsActionButtonStyle` 保留 SwiftUI 原按钮的标签、角色、动作和原生鼠标行为，让启用的按钮参与 Tab 顺序，并支持空格和 Enter 激活。焦点具有可见边框；禁用或隐藏页面的按钮不可聚焦。带修饰键的激活按键保留原有命令路由。

参考依据为本机 Codex 26.908.70816（9275）的公开随包按钮资源：原生 HTML button、禁用状态及 focus-visible 边框。此次主要修复键盘行为；保留 ShipiOS 当前按钮外形，不能据此认定视觉已完全一致。使用自定义 buttonStyle 的控件仍需要各自核验。

## 验证

- 通过 `script/build_and_run.sh --app` 在原数据目录重建运行，日志 `.cache/settings-buttons-build.log`。
- 设置布局、交互、通用偏好、导航与文本编辑器共 48 项回归通过，日志 `.cache/settings-buttons-regression-tests.log`；严格签名检查通过。
- 原生通用页：搜索 → 22 个导航项 → 重新检测 → 开关 → 更改…。Enter 和空格分别打开文件夹选择器，Esc 取消后焦点均回到“更改…”，没有修改目录；Shift-Enter 不打开选择器。
- “更改…”之后 Tab 跳过禁用的“恢复默认”，Shift-Tab 返回“更改…”。
- 原生资料页：导航末项 → 显示名称 → 用户名 → 选择头像 → 保存资料卡 → 返回应用。禁用的“保存资料”和隐藏页面控件未混入。
- 重启后原任务“验证新输入框的真实构建”和待发送草稿保持不变，主窗口可交互。

## 仍待修复与验收

- 原生下拉菜单和分段选择器在当前系统键盘偏好下仍被 Tab 跳过。
- 资料页从“个人资料”侧栏按钮起，连续 Tab 24 次到“返回应用”，此时 Shift-Tab 实际跳到“外观”，应回到“保存资料卡”。通过 Cmd-F → Shift-Tab → Shift-Tab 进入同一入口时可以正确回到资料卡，说明完整循环后的焦点交接仍有问题。此项修正了第 118 篇对反向循环的验收范围，不能把局部路径通过推广为所有路径通过。
- 延迟重定向、重置 firstResponder、单独原生返回按钮均未解决上面的完整循环问题；移除焦点分区导致顺序交错。这些实验均未保留。
