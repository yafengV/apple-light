# 记忆列表搜索、排序与操作焦点

2026-09-18。参考公开分发资源 `personalization-settings-2428288d0130.js` 中的 saved-memory manager：搜索框、最新/最早排序、更多菜单、紧凑分隔列表，以及加载、读取失败和搜索空结果。此处只对照公开资源中的管理器交互，不将 ShipiOS 本地记忆等同于账户云端记忆。

## 实现

记忆设置使用主窗口内的单一页面滚动布局。保存列表置于添加编辑器之前；行内容可选取，删除放入危险色更多菜单，日期转为提示。保留 ShipiOS 已有的手动添加和编辑能力。

搜索支持文本片段、大小写/音调/全角归一化及拼写误差；采用位置无关的子串编辑距离，容错比例为 0.4。最新与最早均按更新时间排序，同时间以标识稳定排序。排序在原生平铺菜单中独立勾选，支持 Tab、空格/Enter 和方向键。搜索和排序只改变呈现，不修改存储；“删除全部”始终确认完整集合的快照。

加载期间不展示过期行，读取失败提供原位重试，空集合与搜索无匹配分别呈现；写入失败仍保留列表和编辑内容。菜单取消后回到原入口；被删除或不再匹配的行回退到搜索框。编辑器使用一次性原生焦点请求，隐藏、禁用或卸载后的回调不会抢焦点；取消/保存在按钮重新挂载后返回原行，筛选结果消失则返回搜索框。

## 验证

- 33 项相关测试通过，覆盖记忆存储与删除、列表状态与匹配、更新时间排序、菜单作用域与焦点、读取失败后恢复、共享下拉菜单及文本编辑器生命周期。日志：`.cache/memory-list-final-tests.log`。
- 使用项目脚本构建、启动并严格校验签名。原生验证使用 `/tmp/shipios-memory-list-validation` 的三条合成记忆，无用户 API 凭证。
- 确认初始最新优先，Tab + 空格打开排序菜单，键盘选择最早优先后实际行顺序改变。
- 搜索 `stagng` 找到 `staging`；无匹配时呈现包含查询的提示且操作区保留。仅一条搜索结果时，“删除全部”确认仍显示三条；Esc 取消后查询、排序及原菜单焦点保留。未在原生界面执行永久删除。
- 修改测试记忆并保存，筛选结果消失后回到搜索框；磁盘验证三条记录仍在且修改已持久化。
- 合成损坏 JSON 不被覆盖、不出现无限恢复；设置显示读取错误且禁用修改。修复该测试文件后点击重试，在同一页面恢复三条记忆。
- 最终构建验证编辑器自动聚焦、取消回到原行按钮、空格重新编辑。
- 使用项目脚本恢复原数据目录，原任务“验证新输入框的真实构建”和待发送草稿完整保留，输入框可实际聚焦。恢复日志：`.cache/memory-list-restore.log`。
- 测试宿主仍输出 AttributeGraph cycle 警告：本轮 87 条，归档基线日志 38 条；新增记忆宿主测试也触发该警告。断言与原生交互通过，但警告原因尚未定位，不视为已解决。
