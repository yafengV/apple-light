# 提交范围与新分支目标

2026-09-18。在 [提交或推送弹层](96-git-commit-push.md) 中接入新分支目标和包含未暂存变更。

## 对照证据

本机 Codex 静态 UI 包 `git-branch-picker-dropdown-content-17fc53789202.js` 的提交弹层提供 Commit to / New branch、分支名校验、Include unstaged changes 和所选变更摘要。`git-action-new-branch-field-824effe030d6.js` 中 `git-action-include-unstaged-changes` 持久状态默认开启；提交说明生成和正式提交都读取同一选择。

## 实现

- “提交到”可选择当前分支或新分支；新分支输入框采用 Git 设置中的前缀，停止输入 200 ms 后检查名称和重名，正式操作前再次校验。
- “包含未暂存变更”默认开启并保存选择，关闭时只提交真实索引中的内容。显示所选文件数；只读审查仍禁止提交操作。
- 生成提交说明时遵循同一范围。包含未暂存内容时，在私有临时目录复制真实 Git 索引，保留稀疏检出标记并展开分离索引，只在临时索引中暂存当前工作区。不会改变真实暂存区，也不会创建分支或提交；忽略文件不进入请求。
- 正式提交前捕获分支、HEAD、索引和选中工作区内容。生成过程中发生变化时，拒绝使用旧选择继续提交。
- 新分支在正式操作阶段创建；随后按范围暂存并提交。当前分支原有提交不前移，支持尚无首次提交的仓库。
- 提交钩子失败时保留说明、新分支和已暂存内容；弹层识别已创建的目标分支，允许直接重试，而不是重复创建。错误信息在刷新 Git 状态后继续显示。
- 取消自动生成时不创建新分支、不修改真实索引、不创建提交。切换项目后的旧操作不覆盖新项目状态。
