# 独立任务窗口 Git 审查

2026-09-17。项目任务的独立窗口现在直接承载 Git 审查面板。工具栏“任务审查”在任务所属项目上创建窗口专属 `DeveloperWorkspace`，不依赖主窗口当前项目、所选任务或审查范围。

面板显示任务项目的当前分支，并支持未暂存、已暂存、提交和分支比较范围；文件展开、逐行差异、整文件与差异块暂存/取消暂存、未暂存撤销、提交说明和提交操作复用主窗口的真实 Git 服务。任务窗口把分支作为只读项目身份显示，避免误用主窗口的分支切换弹层。

行内审查评论按任务 ID 隔离。评论的新增、编辑、保存、取消和移除只读取当前任务集合；主窗口切换任务或项目不会移动评论。任务窗口发送消息时，会将当前任务的评论序列化到实际请求，只在新回合成功建立后清除；请求失败时保留评论和草稿。面板的“撰写后续消息”把焦点送回同一任务窗口输入区。

原生隔离实例在真实 Git 仓库中完成了可见验收：任务窗口显示 `main`、1 个未暂存文件、`App.swift` 的 `+2 −1` 差异、文件与差异块操作；通过代码行上下文菜单添加并保存评论后，底部显示“1 条待发送评论”，草稿“审查评论发送草稿”保持不变。随后完成整文件暂存、切换到“已暂存”查看同一差异，再取消暂存恢复 fixture。任务窗口设置按钮仍将单例 `ID: main` 主窗口切到设置页，设置不是独立窗口；Esc 返回原任务后，评论和草稿仍保留。

自动化覆盖任务评论集合隔离、项目锚点校验、任务窗口提交实际 HTTP 内容、成功后精确清理和失败保留。完整回归为 351 项 Swift、12 项 Rust、fmt/Clippy 和真实 IPC 冒烟全部通过，日志 `.cache/task-window-review-full-tests.log`。验收结束后以原数据目录重建启动为 PID 76021；原任务“验证新输入框的真实构建”和草稿“这是一条待发送草稿，重跑后应保留”保持不变，设置再次确认位于 `ID: main` 主窗口并可用 Esc 返回。
