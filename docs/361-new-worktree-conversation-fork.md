# 会话分叉到新工作树

后续来源检出清理后的首次 Core 续聊修复与真实验证见[第 362 篇](362-core-fork-after-source-pruning.md)。下文保留本阶段当时的验证及边界。

日期：2026-09-28。普通侧栏与 Activity 的共享分叉菜单、主会话菜单和独立任务窗口新增「分叉到新工作树」。普通同目录分叉及真实 Core 历史分叉沿用第 359、360 篇；托管相同检出分叉仍未实现。

## 参考与实现

旧 Codex 26.908.70816/build 9275 缓存资源中的 `o3t` 先检查 Git 来源，解析来源项目的环境选择，以 `startingState: {type: working-tree}` 和 `launchMode: fork-conversation` 创建待处理工作树。`c3t` 校验项目环境并解析配置路径。这是静态实现参考，本阶段仍没有当前用户版本 Codex 的双端原生页面配对。

新入口固定点击时来源的已结束历史边界，保留当前暂存区、工作区修改、普通未跟踪文件和既有 `.worktreeinclude`/`AGENTS.override.md` 规则允许的文件。通过 `stash create` 和保护引用保存已跟踪内容，不移动、清空或停止来源；Git HEAD/分支、暂存区、工作区和本地文件在保存前重新校验。来源正在运行的后缀不进入分叉。

新任务、复制回合、原生 Core 来源、环境快照和待创建检出通过同一次工作区保存登记，之后才执行 `git worktree add --detach`。历史回合换为子项目归属，原始来源映射、附件和工具历史保留。Git 创建、来源内容应用、环境 setup 和最终完成状态依次持久化。没有保存成功时，不创建 Git 工作树，并释放私有文件快照和保护引用。

创建或 setup 失败后，固定任务 ID、历史、检出路径和环境继续保留。侧栏、会话菜单、独立窗口和工作树设置可继续创建；从侧栏跨项目打开待完成任务也先恢复。未完成的子任务不能发送模型回合或移交到本地，自动数量清理与归档清理不会删除它。重试不重新分叉或复制已经改变的来源；不覆盖未经登记的现有目录、另一仓库或准备前改变的目标提交。成功 setup 不重复执行；若脚本已创建 Git 提交且完成状态已保存，最终登记恢复保留该提交，不再错误地要求初始 HEAD。

在托管任务中继续分叉时，新工作树的 Git 生命周期指向稳定的原始来源仓库，文件快照与 setup 的 `CODEX_SOURCE_TREE_PATH` 使用实际来源检出。因此来源托管目录随后被清理，子工作树仍可归档恢复。源托管任务选择的环境，包括明确的「无环境」，随子任务继承。项目默认环境只使用实际存在的配置，编辑器默认 `environment.toml` 占位值不会被误当成已选择文件；显式选中的缺失文件仍报错。

主窗口入口在完成后进入子任务，打开失败保留可重试的已保存任务。独立任务窗口入口留在自己的窗口导航，不替换主窗口当前工作区。来源运行在准备期间完成时，释放临时启动保护后恢复其排队输入或仍有效的目标续轮；已取消、归档、被删除、正在运行或已经开启下一轮的任务不再次启动。
