## 实现范围

- PR 内容页接入可折叠 Activity、普通评论、审查状态、代码线程与回复、八种事件及单独提交记录。已解决线程及机器人评论默认折叠，编辑/回复草稿阻止收起。其他事件明确提示尚未显示，没有宣称活动全部覆盖。
- 评论具有作者头像及回退、正文 Markdown、GitHub 链接、权限菜单；编辑替换正文，引用逐行添加 `> `，普通引用发布普通评论，代码引用/回复进入原线程。每条评论保持各自的视图草稿，普通评论输入独立。
- 空评论、空编辑和空回复不可提交；普通发布和回复去除首尾空白，编辑保留原始换行及 Markdown。复用原生文本系统的输入法、选区、撤销/重做和 Cmd/Ctrl+Enter；普通 Return 换行。普通输入不自动聚焦，编辑及回复有独立焦点请求。
- 删除弹层固定目标，说明永久删除，失败保留弹层；审查本体不提供删除菜单。线程解决/重新打开由服务器返回的对应权限决定。
- 非作者的开放 PR 可提交评论、批准或要求修改；批准允许空说明，其余要求说明。取消保留正文及选择，成功重置并关闭，提交期间禁用取消和关闭。显示头提交保存在弹层，写入前再次检查开放状态、作者与头提交。
- GraphQL 请求使用 0700 临时目录中的 0600 JSON 文件，完整原文不进入 CLI 参数，正常结束及取消清理。显式限定仓库与 PR，修改目标必须出现在当前 PR 的已读数据中；写入前复查账户、目标与权限。
- 时间线、线程列表及每个线程回复分别分页。验证总数、重复 ID、空页、游标循环和读取上限；完整读取前后检查 PR、账户、状态与头提交，拒绝跨页混合结果。读失败保留草稿并提供重试。已有数据的后台刷新保持编辑控件；迟到及取消结果不能覆盖原快照。
- 评论、审查、标题/描述及合并共用 PR 修改互斥；成功更新通知按独立资料目录与 PR 隔离，其他窗口重新读取活动和元数据。输入不写入磁盘，不跨窗口共用评论草稿。
- 写入响应丢失时先读取结果；唯一匹配的新评论/回复/审查可确认成功。未能确认时保留输入，提供只读结果确认，阻止重复发帖；明确的服务器拒绝允许修复后重试。有效写入回执在活动读取失败时仍更新已接受的评论、审查或线程状态，并显示刷新提示。
