# 背景／前景颜色输入与窗口内选色面板

浅深两侧的背景色和前景色现在使用 136×28 十六进制输入。点击 14 点色点打开同窗口的饱和度／亮度与色相面板，不再调用系统 ColorPicker。完整有效输入立即保存；部分输入保留草稿，失焦或关闭选色面板恢复当前保存值。删除原背景／前景行上的额外重置按钮；强调色账户来源菜单仍未对齐。

## 输入与绘制

输入先转大写、移除非十六进制字符与所有井号，最多保留六位，再加一个前缀井号；六位有效值立即提交小写请求，由独立存储规范化保存。未完成的输入只影响文本，不改变色点和背景。外部主题变化更新实际颜色，同时保留未完成草稿；失焦恢复最新值。输入法组合期间不进行过滤和保存，Enter 不额外提交部分输入。

控件底色是被编辑的原始颜色，而不是页面的派生正文色；默认深色前景输入显示 `#FFFFFF`，即使默认页面正文角色为 `#dfdfdf`。控件文字按参考的加权通道亮度 0.62 阈值选择 `#101010` 或白色，色点边框混合 18% 对比文字。此算法独立于强调色文字亮度算法。

组件注入的未分层 CSS 覆盖了外观页分层的 `h-34/w-34` 工具类。在无窗口、非持久、离线 WKWebView 中加载两者的实际规则，结果为 200×200；饱和度容器 176 高、有效调整区 164 高，底部黑色间隔 12，色相区域 24 高。没有只按工具类推测为 136×136。面板保留 12 点内边距，224×224，靠色点末端对齐，间隔 8，碰撞边距 6。

RGB 转 HSV 使用参考整数舍入；拖动过程保留浮点 HSV，色相方向键每次 18 度，饱和度／亮度每次 5%，边界截断。灰色和黑色中不会因为自己的相同 hex 回写而丢失当前色相。指针颜色使用参考的取整 HSL，方向键及两个可聚焦 slider 均接入原生可访问性；名称保持组件的 `Color`／`Hue`。

原生测试发现 AppKit 的目标颜色空间逐层混合会改变饱和度区域颜色。现先在明确的 sRGB 缓冲生成整个渐变，再做显示空间转换，并缓存同色相／大小的图像。保留黑色间隔、色相渐变及指针；像素测试读取显式 sRGB，色相样本直接与参考 CSS 色阶的离线浏览器实际绘制比较，保持每通道 3/255 精度。中间像素不等于精确的颜色停止点，不能把理想青色当作采样结果。

## 窗口与失败处理

面板挂载到调用窗口内容层，沿用已有浮层互斥与设置 Esc 返回保护。打开不自动聚焦选色 slider；鼠标选色后焦点进入相应 slider。Esc 关闭并返回色点，外部点击透传，窗口失焦／关闭、隐藏、卸载和工作区不可用时关闭或拒绝操作。Tab 保留原生焦点行为，不走菜单文字匹配或菜单 Tab 循环。

工作区加载状态使用即时读取闭包验证，防止未触发页面刷新时旧回调仍打开面板。保存失败保持原色、原编辑控件、焦点与任务草稿；关闭后的旧选色回调不能继续修改。主题、字体与颜色浮层只在同一窗口内互斥，其他窗口仍独立。
