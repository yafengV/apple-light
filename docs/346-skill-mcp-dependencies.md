# 技能工具依赖与安装选择

2026-09-28。此前 ShipiOS 读取技能的界面元数据时忽略 `agents/openai.yaml` 的 `dependencies.tools`，显式调用需要 MCP 的技能也没有安装入口。本阶段接入声明查看和发送前的安装选择。

行为依据是本地 OpenAI Codex 源码快照 `50d7795` 中的 `core/src/mcp_skill_dependencies.rs`、`skills/src/model.rs` 和 `ext/skills/src/loader/metadata.rs`，以及官方[技能文档](https://learn.chatgpt.com/docs/build-skills)。上游在显式提及技能时询问是否安装缺失的 MCP，允许继续而不安装，并按传输方式与地址或启动命令识别已有服务。上游此功能有第一方客户端和功能开关限制；ShipiOS 在自身私有运行时中实现对应产品行为，不修改用户个人 Codex 配置。

技能预览现在显示工具名称、用途和实际配置/连接状态。未安装服务可进入主窗口内 MCP 设置的预填编辑器；已有服务可进入其管理页。打开预览只读取配置，进入编辑器不会保存或发起连接；返回仍保留原技能页和任务草稿。重新载入从实际技能来源读取新依赖，链接来源保留实际目标快照。

显式 `$技能` 或 `@插件` 调用所包含的技能，若声明缺失的可支持 MCP 服务，会在模型请求之前显示同一任务时间线中的安装提问卡，列出 HTTP 地址或 STDIO 启动命令。选择“安装并启用”后才保存到 ShipiOS 私有 `mcp-servers.json` 并在本轮接入；选择“继续而不安装”不写入配置，同一任务会话不重复询问相同传输和地址/命令。仅列入隐式技能目录不触发安装提问。无人值守计划任务和临时侧聊不安装缺失依赖，记录明确提示。

支持 `type: mcp`、默认或显式 `streamable_http`，以及 `stdio`。STDIO 的 `command` 是可执行程序，不作 shell 拆分。与现有服务匹配时使用传输和去除首尾空白后的地址/命令，可复用不同名称的配置；停用服务仍保持停用。已有同名但不同地址/命令的服务不会被覆盖，依赖名称与现有 MCP 表单共用校验。

等待选择期间外部文件或设置可能变化，因此安装再次读取私有 MCP 配置及当前技能来源、启用状态、目标和依赖声明。来源或声明改变则拒绝旧请求；一批依赖存在冲突时不部分保存。取消等待会清理提问和继续执行句柄，不安装服务。模型获得的是本轮真实工具和依赖状态，配置存在不被描述成连接成功。

基础聊天等待需要的已启用服务握手并重新计算工具列表；Codex Core 从当前私有配置启动相应服务。两种协议均通过临时 HTTP 模型与 MCP 服务验证：缺失服务先提问，跳过和同任务后续调用不安装，新任务可重新选择安装，新服务工具出现在同一轮请求，提问状态随工作区恢复。测试使用临时数据，不使用用户密钥或外部模型服务。

128 项相关定向回归通过，其中新增 9 项依赖测试，覆盖元数据、别名及停用配置、跳过、安装、取消、无人值守、配置冲突、确认期间声明更改、批量原子保存及主窗口编辑导航；现有技能、插件、MCP 和真实 Core 提问回归同时通过。日志为 `.cache/skill-dependency-regression.log`。本阶段未重跑全量产品回归。
