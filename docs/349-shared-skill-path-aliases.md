# 技能目录共享路径别名

> 本阶段记录的 Core 含引号目录沙箱与启动失败卡片缺陷，后续修复和回归见[第 350 篇](350-core-sandbox-paths-and-command-failures.md)。以下保留本阶段的验收边界。

2026-09-28。本阶段补齐技能目录的共享路径别名，以减少重复的绝对目录前缀占用，使预算更优先用于技能身份及用途说明。

依据本地 Codex 源码快照 `50d7795` 的 `ext/skills/src/aliases.rs`、`host_aliases.rs` 和 `render.rs`：目录分别生成绝对路径与别名方案，先比较已保留技能数量，再比较被缩短的描述字符数，最后选择元数据成本更低的方案。别名根目录表和额外展开指令计入原有字符或近似 token 预算；不因可以生成别名就强制使用。

私有技能、项目 `.agents/skills` 及已安装插件由各自经过校验的来源加载器提供根目录。根目录去重并按当前目录顺序分配 `r0`、`r1` 等别名，嵌套根目录使用最长路径组件前缀，不能将 `skills-extra` 误认为 `skills` 的子目录。单技能本地插件共享 ShipiOS 的 `Plugins` 安装根目录；多技能插件保留包根目录，对应上游单技能市场包共用市场根目录的规则。名称和目录变化可重新分配别名，每一回合明确替换此前目录及别名表。

根目录以 JSON 字符串转义后列出，支持中文、引号、换行与组合字符。没有验证来源根目录的引用保持绝对路径，不推断共同的系统目录，也不读取用户个人 Codex 路径。macOS 目录枚举可能使用 `/private/var` 而来源作用域使用 `/var`；项目加载器现在沿用枚举文件的根目录拼写，根目录匹配也检查声明根的解析形式，不将符号链接技能的外部目标当作目录根。

路径别名仅用于发送给模型的目录。技能 ID、项目作用域、逻辑文件 URL、符号链接目标快照、编辑与卸载语义均保持原样。基础协议仍按完整 ID 调用只读技能工具；Core 按本轮根目录表展开路径后读取文件，相对资源从展开后的技能目录访问。新目录没有别名表时不沿用旧别名。预算不足时继续先保留完整身份，再公平缩短描述，仅在最小条目放不下时省略。

新增四项回归覆盖方案选择顺序、表与指令的完整预算成本、极小预算、昂贵别名表回退、路径组件边界、最长根目录、非法别名展开、插件共享根及停用来源。集成回归对两种真实协议发送 21 项私有/项目目录，从实际请求解析根目录表，逐项核对展开后的路径和原始 ID，再读取链接到外部文件夹的完整技能指令。基础协议验证含双引号的工作路径；Core 验证中文长目录及目标含引号的符号链接读取。完整指令未预先注入目录。

158 项技能、模型选择、插件、MCP 及 Core 提问相关定向回归通过，日志 `.cache/skill-path-alias-regression.log`。`script/build_and_run.sh --build-app` 构建及严格签名检查通过。本阶段未重跑全量产品回归，也未取得新的原生页面或双端配对证据。

## 新发现的独立待修缺陷

将 Core 工作目录本身设置为包含双引号的路径时，实际 `exec_command` 返回退出码 65，Seatbelt 提示 `sandbox-exec: unbound variable`，位置在受保护 `.git` 路径规则。本机固定版本的沙箱策略生成存在转义问题；同一会话仍返回最终回复，且 Swift 时间线没有记录该次启动失败为命令卡片。失败证据在 `.cache/skill-path-alias-diagnostic-3.log`，源码待检查位置为上游 `codex-rs/sandboxing/src/seatbelt.rs` 的受保护元数据 regex 生成及 ShipiOS 的失败事件处理。

该缺陷未修复，不将 Core 含引号工作目录记为通过；不通过更换沙箱权限掩盖失败。后续需要修复并回归目录转义及失败呈现。共享路径别名完成不代表完整工具循环或 UI 对齐完成。在线技能/插件目录、系统作用域、OAuth 和各页原生双端配对仍缺；完整配对保持 0/45。此前桌面锁定导致自动审批拒绝打开 ShipiOS，仍待手动解锁，未绕过限制。
