# 独立任务窗口的命令归属与查找焦点

2026-09-18。延续图片预览的多窗口检查，修复应用菜单对独立任务窗口仍使用主窗口选择的问题。

## 问题与修复

原先 `WorkspaceCommands` 的发送、停止、置顶、查找等菜单一律调用主 Store 当前选择。独立窗口虽已有部分工具栏快捷键，但自定义绑定及菜单点击可能操作主窗口；主窗口打开图片预览又会全局禁用这些命令。

现在独立窗口通过 `FocusedSceneValue` 发布 `TaskWindowCommandContext`。菜单验证和执行优先使用当前任务窗口的能力与动作；窗口本地键盘桥同样读取快捷键配置，限制在自身 key window，跳过 sheet、模态窗口、输入法组合文字和本窗口覆盖层。新桥卸载时移除事件监听。

已接入的命令包括发送、停止、查找与前后匹配、置顶、未读、归档、关闭窗口，以及任务项目文件树、审查、终端和源码行定位。发送与停止传递窗口 taskID；查找与面板使用窗口本地状态。尚未接入独立窗口的任务命令显示为不可用，不能回落到后台主任务；应用级入口继续沿用主窗口路由。独立窗口的 ⌘W 关闭当前窗口，图片预览打开时仍优先只关闭预览。

查找及发送移除重复硬编码快捷键，按用户配置执行。查找栏在布局完成后请求焦点，重复查找命令会重新聚焦现有输入框；Esc 关闭并返回草稿。按钮说明也反映自定义绑定。

## 验证

- 59 项命令、快捷键、页面、附件、审批及独立窗口相关测试通过，日志 `.cache/task-window-command-tests.log`。
- 新增 4 项测试：拒绝禁用或非任务动作、自定义与移除快捷键、后台主窗口图片预览不决定本地任务能力、任务/应用命令范围。
- 另外 2 项真实本地 HTTP 夹具回归通过：不同任务并行流式返回、停止一个任务不取消另一个请求。首次过滤器使用了文件名对应类，匹配 0 项；修正为实际 `ModelTransportTests` 后确实执行 2 项。日志 `.cache/task-window-command-parallel-tests.log`。这覆盖任务发送/停止的数据隔离，不替代原生菜单发送完整验收。
- 原生工作区使用主任务 A 与独立任务 B 的合成数据。主窗口 A 保持第二张图片预览，切到 B 后通过自定义 ⌃⌥F 打开 B 的查找，通过 ⌘⌥P 置顶 B；读取持久化结果确认 A 未置顶、主选择仍为 A、两条草稿完整。
- 通过 B 的菜单取消置顶，再用 ⌘W 关闭 B，返回后 A 的原图片预览仍在。验证菜单与快捷键两条分发路径。
- 最后构建中验证查找直接键入命中 B、Esc 返回原草稿、旧 ⌘F 无效、再次查找保留查询并聚焦，以及从草稿回到已打开的查找框。
- B 自身打开图片预览时自定义查找不触发，⌘W 只关闭预览，焦点回到原缩略图，独立窗口保持打开。
- 通过项目脚本恢复原工作区，签名严格校验通过；原任务与未发送草稿保留，输入框可聚焦。恢复日志 `.cache/task-window-command-restore.log`。

## 后续范围

独立窗口的重命名、分叉、模型选择、文件搜索、任务/标签导航等还需接入对应窗口流程，当前不会借用后台主任务执行。新增面板快捷键、菜单发送和归档尚未完成逐项原生验收；应用级全局命令与后台覆盖层的完整路由仍需继续对齐。本阶段证明了具体多窗口归属修复，没有取得 Codex 全页面配对证据，整体目标仍未完成。
