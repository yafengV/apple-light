# 文件路径模糊检索与文件名排序

2026-09-18。将文件搜索从现有文件列表的连续子串筛选，改为独立路径检索与文件名二次排序。

## 参考证据

- 已安装客户端公开静态资源 `app-primary-4af6ed7f68d1.js`：`Bbt/Hbt/Wbt` 接收后端候选，过滤指定目录组件，再按文件名模糊得分降序、文件名 UTF-16 顺序及原始位置排序。仅路径命中的候选不会因文件名得分为零而被移除。
- `Zbt/DSr`：空查询提示输入后搜索；结果包含文件和目录，标题显示文件名，说明显示相对父目录。文件打开走当前任务的侧面板路径，目录可走系统文件管理器。
- 本地上游源码快照 `50d77959bf927293c4b5ddcca81d05331ae582ea` 的 `codex-rs/file-search` 与 `app-server/src/fuzzy_file_search.rs`：nucleo 使用路径配置、忽略大小写、Smart normalization，候选上限 50。Nucleo 先按得分及路径长度选择候选，服务再按得分及路径排序。
- 上游锁定的 nucleo revision 为 `4253de9faabb4e5c6d81d946a5e35a90f87347ee`，本项目使用相同 revision 的 matcher；没有将客户端打包源码加入仓库。

## 实现

- `shipios-agent search-files --query …` 使用独立只读入口，不加载模型配置、不创建认证或数据库状态。目录扫描遵循 git ignore 上下文，包含隐藏条目和目录；结果传回相对路径、类型及分数。
- Swift 搜索目录与请求属于发起窗口。75 ms 输入防抖后启动 helper，取消查询会终止旧子进程；已有 20 秒命令超时仍生效。请求身份与版本保护阻止旧查询、已取消查询和旧项目结果覆盖当前界面。
- 界面复用已验证的文件名词首匹配器做二次排序，按参考顺序过滤 `.git`、`.hg`、`.next`、`.pnpm-store`、`.svn`、`.turbo`、`.yarn`、`build`、`coverage`、`dist`、`node_modules` 组件。
- 空查询不扫描、不列出整个项目。查询时显示搜索状态，失败可以重试；结果行分别显示文件名、目录和文件/文件夹图标。
- 文件继续在原窗口内预览并聚焦；目录验证存在且位于项目内后在访达打开，失败保留搜索弹层并提示。原有项目边界检查保留。
- 新增依赖的许可证及源码地址随应用打包到 `Resources/Licenses`。
