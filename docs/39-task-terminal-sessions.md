# 任务终端归属、退出与焦点

2026-09-17。原实现按项目路径缓存一个 PTY，同一项目中的所有任务共享 Shell 状态。本轮改为按“工作目录 + 任务”保留终端。

## 依据与范围

[官方终端文档](https://learn.chatgpt.com/docs/integrated-terminal) 描述每个任务包含以当前项目或工作树为目录的终端，以及工具栏和 Ctrl+反引号入口。本轮按此任务归属实现会话隔离；具体缓存寿命及不同任务之间是否存在额外共享机制仍需用户版本的实机配对。

本机当前 Codex 应用包静态声明终端标签可落到 `left`、`right` 和 `bottom`，并提供“Move to left pane / right pane / bottom pane”。ShipiOS 现按该声明实现多终端和跨面板身份保留；静态资源仍不能替代逐像素配对。

## 已实现

- 同项目的不同任务使用不同 Shell。切换到另一个项目或工作树时，使用该目录及任务对应的会话。
- 隐藏面板、进入设置或切换任务保留内存中的终端进程、环境变量和输出；返回原任务时复用该会话。
- 未发送的新任务可以先打开终端。首次模型消息或本地 Agent 操作创建任务后，把该会话转交给新任务；后续回合继续使用同一会话。再次新建任务得到新的 Shell。
- 归属转交不会覆盖已有任务会话，也不能跨工作目录转交。
- Shell 自然退出后显示退出码或信号，保留输出，不自动清屏或重新启动。
- 明确的“结束会话”和“重新打开”操作；结束时处理 PTY 的前台进程组及 Shell，并回收退出的子进程。已经退出的 Shell 不再按旧 PID 发送信号。
- 终端标题响应进程发出的标题控制序列，过滤控制字符并限制显示长度。
- 工具栏、Ctrl+反引号和底部面板命令共用打开/隐藏逻辑。打开或重启请求终端焦点；隐藏后恢复输入区焦点。延迟的 AppKit 焦点操作核对原任务、请求标识和当前页面，不能抢占设置或全局弹层。
- 同一任务可以创建多个终端标签，每个标签拥有独立 `TerminalSession` 和真实 PTY；切换标签不会共享环境变量或输出缓冲。
- 终端可在主内容区、右侧面板、底部面板和独立窗口之间移动，移动与弹窗不重建进程。每个区域分别维护激活标签，只有底部终端显示“隐藏终端”。
- 终端标签支持固定到侧栏、关闭/关闭其他/关闭右侧、关闭后重新打开，以及单标签结束和重启。关闭或重启只作用于精确会话，不影响同任务的其他终端。
- 草稿首次提交为任务时，会一次转交该草稿的全部终端；标签 ID、面板位置、当前选择、固定引用、Shell 进程和输出都保持。

终端进程只在用户打开面板或测试显式创建时启动。退出应用时停止全部会话；本轮没有保存或重放 Shell 命令来模拟跨应用重启的终端恢复。

## 验证

真实 PTY 测试验证独立环境变量、实际工作目录、标题控制序列、自然退出码、输出保留、显式重启、结束前台 `sleep`、Shell 回收和另一任务继续运行。目录验证读取临时目录内的 `PWD` 记录，并解析 macOS 路径别名，避免把 `/var` 与 `/private/var` 误判成不同目录。

此外覆盖：新任务终端转交、返回原任务复用、同名任务但不同工作目录隔离、无项目时不提供终端，以及焦点请求在进入设置、打开弹层、切换任务后失效。真实 HTTP 模型会话和真实 Agent 提交路径分别验证首次提交实际转交会话，不只单测一个未接线的辅助方法。

隔离签名应用已原生验证两个底部 zsh 标签的切换和独立输出、右侧终端 first responder、独立窗口继续输入、关闭窗口回到主区，以及终端存在时设置仍使用同一 `ID: main` 主窗口。文本选择、复制、缩放、滚动和当前 Codex 的精确焦点矩阵仍需配对。

最新全量 `./script/test.sh` 通过 385 项 Swift、12 项 Rust、fmt/Clippy 和真实 Agent IPC 冒烟，无失败或跳过。终端标签转交到其他聊天时迁移同一会话对象及 PTY，不按目标聊天重启 shell。

应用已通过原工作区 `.shipios-local/desktop` 重新构建、签名、启动，进程验证 PID 83959；日志：`.cache/terminal-scope-launch.log`。

## 保留的差异

- 模型读取终端输出、可复用环境动作以及跨应用重启恢复仍未接入。
- 终端拆分和跨应用重启恢复仍未实现；拖动终端标签时已经提供“松开放到新窗口”的直接落点，标签菜单不再混入任务级的新窗口命令。
- 快捷键文档存在冲突：[命令表](https://learn.chatgpt.com/docs/reference/commands) 将聚焦终端时的 Cmd+K 列为清屏，而终端专页明确说 Cmd+K 打开命令面板、Ctrl+L 清屏。当前保留命令面板入口，等待用户版本实机证据，不将此项标为已一致。
