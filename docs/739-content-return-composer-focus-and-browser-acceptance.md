# 内容返回输入焦点与浏览器实际验收

日期：2026-10-10。开发基线 `4fa9c9ef`。本篇补 R5／R7 的主窗口内容导航和焦点；R1–R8 的范围不变。

## 实际缺陷与修复

在完整网页视图中按 Cmd-1 返回聊天，聊天和输入区出现，但关键窗口的 first responder 仍为窗口，直接粘贴没有进入草稿。`ComposerView` 在网页视图中被卸载，返回时重新挂载；原来的 `onChange(focusComposer)` 只响应挂载之后的变化，漏掉导航动作已发出的请求。

现在挂载时也处理当前请求，但仅在没有内容标签持有命令焦点时将输入区标记为聚焦，保留原有原生窗口／可编辑／弹层检查。首次无条件初始化曾使分屏输入区提前标记为已聚焦，后续用户点击无法正确清除网页的命令焦点；最终加入同现有自动焦点许可一致的内容身份检查，没有修改原失败断言。

新增真实原生回归：同一个实际关键窗口先显示完整浏览器，确认输入区确实卸载；两次返回聊天，检查新挂载的原生输入框成为 first responder、full 模式保留，编辑草稿再次返回后保持原值。测试调用实际视图所用的导航动作，不将它等同于物理快捷键测试；实际 Cmd-1 和不点击输入框的粘贴另在标准应用中验证。前台宿主明确选择和要求执行 **4 项**，仍检查 0 失败／异常／跳过及冻结输入。

## 实际页面与键盘

使用独立数据目录、自建任务及仅监听回环地址的两页 HTTP 夹具，不访问用户服务、不填写认证。基础 Cmd-T 打开及地址初次焦点在基线包中通过；最终标准包复验以下流程：

- 冷启动恢复两个网页标签与聊天选择；完整网页按 Cmd-1 返回聊天，不点击输入框即可粘贴中文，文字进入正确任务。
- 地址输入、Esc 取消、页面链接导航、Cmd-左／右箭头后退／前进可操作，后退恢复网页表单输入。最初尝试 Cmd-[ 没有响应，核对当前绑定后使用实际配置，不归类为后退缺陷。
- 完整视图包含聊天的数字槽位；普通分屏只编号内容标签，选择父／子网页保持布局。快捷键切换 full／split 后，最终包保留网页表单文字与原生焦点；分屏输入框不会抢网页焦点，点击输入区后可编辑且已保存布局的内容命令焦点为空。
- 从网页新建子标签；重启恢复后关闭子标签回到父标签。Cmd-Shift-T 重新打开关闭页，核对实际页面已加载，而非只检查标题。复制网址后粘贴到本任务输入区，结果为正确的回环网页 URL，随后清理夹具输入。

页面表单输入只验证同一进程内导航和布局切换，**没有宣称跨冷启动保留 DOM 表单**。最终夹具保存确认来源草稿未变、验收聊天文本已清理、内容焦点已释放。页面／按键结果在工具记录；包及 HTML 摘要、布局和范围记录在 `.cache/browser-visible-739/{baseline-focus-evidence,final-ui-evidence,signature}.json`。运行数据、服务器夹具和缓存不进入提交。
