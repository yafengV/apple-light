# 独立 API 实时语音聊天入口与会话链路

语音设置页现可填写独立服务的实时语音模型 ID、选择内置或自定义音色，并在主窗口内启动语音聊天。主输入区和独立任务窗口也有入口。会话浮层显示连接、聆听、思考、回复和失败状态，可静音、重试、进入设置或结束；启动听写时会结束语音聊天，避免两个功能争用麦克风。

会话使用 ShipiOS 模型配置的基础地址和同一服务专属 Keychain 凭据，连接该地址的 `/realtime` WebSocket。启动前检查麦克风授权与所选设备；录音 PCM 转为 24 kHz 单声道 16 位格式，语义 VAD 负责轮次划分。返回的音频在应用内播放，播放缓冲耗尽后才返回聆听状态。音频不写入最近听写录音，也不读取个人 Codex 配置。服务必须支持相应的实时语音协议和所填模型；普通文本聊天接口不足以启动此功能。

合成 PCM、CoreMedia 样本缓冲、连接地址、请求与事件解析、旧偏好迁移、设置搜索及浮层离屏渲染的 14 项测试通过。`script/build_and_run.sh --build-app` 完成正式 `.app` 构建，严格签名验证通过；设置页与会话浮层图片已目视检查。本机没有可枚举麦克风，用户的独立服务凭据也未配置，因此真实服务握手、录放音、静音、重试和多轮语音未实测。当前旧 ShipiOS 进程未重启，不能以构建成功代替可交互启动验收。

与 Codex 的逐页逐交互配对仍是 **0/47**（主工作区 21 项、设置 26 项）；这表示没有双端完整验收证据，并非 47 项全部缺失。语音聊天仍缺参考端的全局启动快捷键、完整音色选择交互与屏幕上下文；各页视觉尺寸、焦点、菜单、加载/错误/返回状态，以及云端、账户和远程能力也需继续逐项对照。Codex 参考客户端的直接 UI 读取不可用，本阶段只能据公开界面资源和协议文档实现，不能宣称已经完全对齐。
