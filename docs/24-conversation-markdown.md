# 会话 Markdown 与复制交互

日期：2026-09-17。本轮推进差异审计 D03、D04 的消息展示部分，不代表媒体、全部消息操作或整个会话页已与 Codex 等价。

## 实现

此前模型响应由单个 `Text(.init(response))` 显示。现在解析为原生块级视图：标题、段落、行内强调/代码/删除线、有序与无序列表、嵌套列表、任务列表、引用、表格、分隔线和代码块。

解析采用 [Swift Markdown](https://github.com/swiftlang/swift-markdown) 0.8.0，固定包版本及解析器依赖。该发布版要求 Swift 6.2 工具链；最低运行系统仍为 macOS 14。解析离开主线程，旧的异步结果不会覆盖更新的消息；未闭合围栏按代码块呈现。

- 代码块保持空行与缩进，长行横向滚动，复制仅包含代码，提供短暂成功反馈。
- 整条回复复制保留原 Markdown，也提供成功反馈。
- 表格支持列对齐与水平滚动，标题和任务状态提供辅助功能语义。
- 网页链接交给系统打开；项目内文件链接使用已有编辑器偏好，支持 `:行号`、`#L行号`。中文、空格、转义路径不会重复编码；拒绝越出项目的文件路径和不支持的协议。
- 模型提供的 HTML 只展示源文，不执行。图片语法目前显示可点击的替代文字，尚未实现内嵌图片显示。

主要代码：`MessageDocument`、`MessageLink`、`MessageMarkdownView`、`EditorPreferences`、`ConversationView`。

## 原生验收

使用 `.shipios-local/markdown-ui-native` 独立数据目录，将 [本地样例](../fixtures/markdown-response.md) 作为已有会话记录展示。页面明确标注样例身份；没有伪装成真实模型响应，没有配置或发送 API 请求。

| 操作 | 证据与结果 |
| --- | --- |
| 展示长回复 | 标题、代码块、嵌套列表、复选状态、引用、表格、分隔线均在 macOS 窗口显示 |
| 复制 Swift 代码块后粘贴到输入框 | 只有原代码，中文、空行与缩进保留；出现“已复制代码” |
| 复制整条回复后粘贴 | 保留 `#`、围栏、列表、表格与链接原文；出现“已复制回复” |
| 点击项目文件链接 | Xcode 窗口 URL 指向示例项目 `HelloShipiOSApp.swift`，正文与文件一致；未修改文件 |
| 点击不支持的协议 | 会话出现“不支持此链接类型”提示 |
| 打开右侧面板缩窄会话 | 发现并修复链接行宽度约束问题；修复后链接完整可见 |
| 窄表格水平滚动条 | 可滚到末列，数量 1、2 正常显示；触控板手势尚未单独证明 |
| 无 Git 仓库的审查面板 | 发现并修复空状态把标签栏推到中间的问题；标签栏现固定在顶部 |

验收期间没有修改用户原数据；结束后切回 `.shipios-local/desktop`。

当前 Codex 自身不能由 UI 工具读取，逐像素和逐手势配对仍缺直接证据；完整对齐目标保持未完成。
