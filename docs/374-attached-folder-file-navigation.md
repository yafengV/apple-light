# 关联目录的文件浏览与搜索

## 对照范围

实际打开[官方项目文档](https://learn.chatgpt.com/docs/projects?surface=app)，确认附加目录也用于文件搜索、读取和编辑。此前工具回合已经获得关联目录，但文件面板和文件搜索仍只读任务执行目录。本阶段接入文件列表、只读预览、搜索及外部编辑器打开；完整编辑能力、多仓库审查和当前 Codex 的原生呈现仍需后续实现或配对，不能将本阶段描述为全页面对齐。

## 页面和任务范围

多目录文件面板按文件夹分组，单目录保持原来的文件树。主目录文件仍使用原相对路径，其他目录文件使用绝对路径作为标签身份；两个目录中的同名文件不共享标签、文字、选择或定位。路径解析会检查当前关联目录及符号链接实际目标，目录外文件不能借助相对路径、旧搜索结果或链接进入预览和编辑器。

主窗口、独立任务窗口和分离审查工作区使用任务物理执行目录及当前关联文件夹。保存目录编辑时同步主窗口与独立任务窗口；已有任务的执行目录、终端和 Git 基准不变。移除目录关闭已失效的文件标签，清除外部打开状态并使旧读取失效，其他文件保留。目录不可读时文件列表保留其他目录结果并显示错误。

## 实际搜索

私有只读 Rust 搜索会话通过重复 `--additional-root` 参数创建一个跨目录索引，规范化目录去重，重叠目录中的同一入口也不重复。候选上限仍在后端统一应用，不在每个目录分别取上限。主目录结果维持旧协议，附加目录结果带 `rootPath`；前端按完整身份处理点击、鼠标选择、方向键和回车，并显示来源文件夹。macOS 与 Rust 的 `/var`、`/private/var` 路径表示统一规范化，路径中的 `..` 与相同文件入口不另建标签。索引和请求身份包含关联目录，目录修改或明确重试会关闭旧进程并创建新索引。

打开结果前再次检查当前范围；目录结果打开其真实来源位置，文本结果进入对应预览。搜索 helper 不读取 Agent 配置、认证或历史，也不创建运行数据。搜索根失效时报告失败并允许重试，不将失败描述成无匹配文件。

## 验证

真实 Rust CLI 已验证两个目录的同名文件、重复根、查询复用与 EOF 回收。新增 Swift 用例覆盖真实跨目录搜索、同名文件打开、路径身份、重叠目录去重、符号链接实际范围、目录不可读时的部分列表、读取期间移除目录、项目编辑同步独立窗口及分离审查来源。

首轮 55 项集合有 10 个断言失败，分别暴露自动/手动刷新竞争、临时目录路径表示和编辑夹具未关闭旧请求的问题；第二轮 86 项集合剩 1 项路径身份断言失败，不能描述为全通过。修复后的 86 项相关 Swift 回归全部通过，日志 `.cache/attached-files-verified-swift-tests.log`；最终分离窗口绑定与避免逐文件磁盘访问的分组实现另通过 22 项相关回归，日志 `.cache/attached-files-final-window-tests.log`。两组为 86 项不同用例，不相加为 108 项。

22 项 Rust 单元/IPC 回归、fmt、Clippy、`script/build_and_run.sh --build-app` 应用构建及严格签名校验通过；日志 `.cache/attached-files-final-rust-tests.log`、`.cache/attached-files-clippy.log`、`.cache/attached-files-app-build.log`。模型相关测试仅连接本地夹具，没有使用用户配置的 API 服务。
