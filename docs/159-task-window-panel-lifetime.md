# 独立任务窗口的文件与终端生命周期

2026-09-19。

## 差异与实现

第 145、157 篇引入了同一独立窗口内的任务导航，但文件/审查工作区和终端仍由会随任务 ID 重建的页面持有。切走任务会停止其 shell，返回会丢失文件标签和面板状态。此行为与第 77 篇已记录的任务内容资源保留方式不一致，也使第 158 篇浏览器保留与其他面板表现不一致。

- 新增窗口持有的 `TaskWindowPanelSessions`，每个任务保留独立的 `DeveloperWorkspace`、文件/审查/终端显隐及终端会话。任务导航不再调用终端停止，也不重置文件标签、筛选或审查输入。
- 隐藏终端保留同一 PTY、输出与退出状态。显式“重新打开终端”停止旧进程并创建新会话，同时把焦点交给新终端。
- 项目路径按规范化身份比较；路径别名不会重置资源，实际换项目时回收旧 shell 并清空旧项目面板。无项目任务不能创建终端。
- 删除任务时回收其资源；当前任务仍保留模型供“任务不可用”页面展示，离开后移除。关闭窗口回收它持有的全部任务资源；应用退出通过弱引用注册表统一回收，不会因为注册而延长窗口生命周期。
- 文件预览选区与滚动位置改由工作区保存，卸载前记录，重新挂载时恢复。不会重放旧跳行请求覆盖更新后的选区；加载中的空文本不会覆盖已保存位置。关闭文件标签立即删除对应位置，切换项目清空全部位置。
- 文件和终端的延迟聚焦需确认宿主窗口仍是当前窗口，避免后台任务夺取输入焦点。

## 验证

95 项任务窗口、窗口恢复/命令、真实终端、文件预览/工作区与浏览器相关 Swift 回归通过，日志 `.cache/task-window-panels-tests.log`。新增覆盖真实 shell 变量与 PID 保留、窗口隔离、自然退出与显式重启、换项目/删除/关闭窗口/应用退出、弱引用注册，以及真实 AppKit 预览卸载重挂载后的选区和滚动。XCTest 的聚焦测试显式控制测试窗口的 key 状态；真实前台窗口行为另作原生验收。

隔离工作区使用项目脚本构建运行，原生操作确认：

1. 独立窗口任务 B 启动 zsh，设置 `SHIPIOS_PANEL_QA=alive`。通过 ⌘K 进入 A，A 不显示 B 的终端且保留自己的草稿；系统进程检查确认 B 的 shell 仍活着。
2. ⌘[ 返回 B，终端自动恢复并接受输入，输出 `RETURNED:alive`；前后记录的 PID 都为 64823。
3. 文件搜索打开合成的 200 行 `PanelState.swift`，⌘L 跳到第 120 行，再用原生按键选中第 121 行。⌘] 去 A、⌘[ 回 B 后，文件标签、选中行及滚动条值 0.6163522012578616 均保留，没有被旧跳行请求覆盖。
4. 隐藏/重新显示终端后，原输出保留；显式重启获得 PID 65138，变量显示 `RESTARTED:unset`，旧 shell 已退出。
5. 在新 shell 启动前台 `sleep`，记录其 PID 65151 后关闭独立窗口。三个已记录的进程均不存在；主窗口继续显示原任务 B 和草稿，未被导航到 A。

最终通过项目脚本恢复原工作区，严格签名检查通过，原任务及未发送草稿保持。合成文件、运行数据、日志及缓存均不提交。

## 仍需对齐

本阶段是资源生命周期与恢复位置修复，没有新增 Codex 自身窗口的原生配对观察。独立窗口的统一内容标签、多终端标签、布局/跨窗口拖放和跨应用重启恢复仍未完成；审查页每个筛选与输入的原生往返、全部焦点优先级及视觉配对还需继续。不能据此宣称整个窗口或全产品已对齐。
