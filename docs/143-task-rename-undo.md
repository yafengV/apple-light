# 任务重命名的撤销与重做

2026-09-18。延续窗口内重命名，接入 Edit 菜单、⌘Z/⌘⇧Z 和结果反馈。

## 行为依据

公开静态资源 `app-initial` 中，重命名通过 `Lb` 注册旧名称与新名称的 undo/redo。通用记录默认有效期 60 秒，撤销后显示名称恢复反馈；`Wrn` 同时准备返回该操作所在位置的导航。命令定义使用 ⌘Z 与 ⌘⇧Z。

## 实现

- 每个任务窗口持有自己的重命名历史。成功改名才登记，未变化名称不产生记录，失败不清除已有重做记录。
- 记录在 60 秒后过期；成功撤销/重做更新对应记录期限，新改名清空重做栈。记录只在本次窗口生命周期保留。
- Edit 菜单及快捷键优先使用当前编辑器的文字撤销；浏览器、终端保留原生处理。没有可用文字撤销时才操作任务重命名历史，弹层期间不执行任务撤销。
- 主窗口撤销其他任务的改名后返回该任务；不允许切换时不执行。独立窗口不会借用主窗口历史。
- 写入成功后才移动撤销栈；失败保留名称和记录供重试。操作前确认任务存在且名称仍与记录相符，防止覆盖其他窗口的新名称。
- 撤销完整恢复旧名称，包括旧数据中超过当前输入长度限制的名称。成功显示短暂反馈，错误保留到手动关闭或重试成功。

## 验证

- 最终 26 项历史、重命名、任务窗口、命令和审批路由回归通过，日志 `.cache/task-rename-undo-final-tests.log`。新增加 6 项历史测试，包括连续撤销/重做、持久化、空操作、过期、分支失效、跨窗口新名称、任务删除、双向写入失败重试及旧名称完整恢复。
- 原生主窗口：改名后 ⌘Z 恢复名称、⌘⇧Z 重做；草稿新增文字后 ⌘Z 只撤销文字，任务名保持；Edit 菜单的任务撤销入口也成功。
- 原生独立窗口：改名后模拟隔离工作区写入失败，⌘Z 显示错误且名称保持。恢复文件后再次 ⌘Z 成功恢复名称，原草稿未改变。
- 最终构建中主窗口将 B 改名后切到 A，⌘Z 恢复 B 的原名称并回到 B，两个任务草稿均保留。
- 项目脚本恢复原工作区，签名严格校验通过；测试数据、缓存与日志不提交。

## 仍待核验

目前新增的是任务重命名历史，其他应用动作还未共用统一撤销栈。终端/网页编辑器、多项目跳转、各设置输入控件的原生撤销边界及当前 Codex 的全页面视觉配对仍需继续验收。
