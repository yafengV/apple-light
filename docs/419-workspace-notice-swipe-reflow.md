# 滑动退出时的通知叠放重排

当前 Codex 分发代码在滑动松开并判定关闭时，先从 toast 高度集合中移除目标，再将卡片保留约 200ms 完成向外滑出。其余卡片因此无需等待业务通知卸载，就开始按新的叠放顺序移动。上一阶段的 ShipiOS 虽然保留了 200ms 滑出，但业务通知直到动画结束才移除，其他卡片也因此延迟重排。

呈现时间线现在在滑动判定成立时记录目标卡片原有的位置、缩放和高度，并立即把它从叠放计算中排除。滑动中的卡片仍保留原视图身份和自身的水平位移动画；存活卡片同时按新顺序过渡。200ms 后业务通知按 generation 移除时，时间线清理该记录，不再重复播放普通关闭的退出动画。连续滑动、其他通知同时消失或新通知加入时，普通退出的位置以当时仍在叠放中的卡片为准。

模型用例验证滑动前后卡片集合与位置，隐藏 NSWindow 中的实际 SwiftUI 视图进一步验证：业务集合仍有两条通知时，滑动标记已使叠放高度缩小；后续移除滑动卡片不会出现第二张退出副本。键盘、弹层命中和通知关闭相关回归也已覆盖。这里仍没有可见鼠标／触控板操作或 Codex 双端动画配对，因此完整页面验收继续保持 **0/45**。
