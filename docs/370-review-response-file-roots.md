# 代码审查回复的文件路径基准

## 问题与复现

第 367 篇已将子目录项目的审查范围改为完整所属仓库，并在不可变审查快照中记录仓库根目录。然而聊天回复的文件链接与摘要输出列表仍使用任务工作目录；仓库根目录与子目录存在同名文件时，会打开子目录文件。新增用例实际复现 1 项测试、2 个断言失败，日志 `.cache/review-response-files-baseline.log`。

## 实现范围

新审查回合将 `review_repository_root` 存入自身请求元数据。主窗口和独立任务窗口的共用回复视图、摘要浮层及固定摘要均按该回合保存的路径基准解析文件引用。任务的工作目录、文件树和普通聊天的解析范围保持各自原任务目录。网页链接仍进入原有浏览器路由。

旧审查从私有原始快照读取已保存的仓库基准，成功读取的路径在应用内缓存，避免渲染回复时重复解析完整差异。读取失败仍可修复后重试；没有记录基准的更早快照保留回答内容和网页链接，但不能据此解析本地文件，不根据当前 Git 元数据或任务目录猜测旧基准。相对或与任务目录无关的根目录无效。

摘要文件位于项目子目录内时转换为本窗口文件预览的相对路径；仓库内其他文件沿用应用内 Quick Look 预览。点击时重新检查原引用的范围、当前项目范围、文件存在和符号链接，不能把仓库之外的文件放入项目文件面板。

## 验证与边界

首次相关集合编译失败，原因是新增测试试图修改 `AgentRun` 的不可变 `project`/`request` 字段，日志 `.cache/review-response-files-related.log`。确认测试进程已结束后，改为分别构造普通和无项目回合；没有修改运行中的编译源文件。

第一次可执行相关集合为 35 项，其中 34 项通过；实际模型审查夹具只设置子目录，未进行正常的仓库加载，审查没有启动并在取得模型任务时失败，日志 `.cache/review-response-files-final.log`。确认终态后补齐 `refreshGit` 与根目录断言，增加失败原因诊断。同时验证无效旧基准修复后可以重新读取，不将未通过范围检查的路径缓存为成功来源。

最终 35 项相关回归全部通过、无跳过，日志 `.cache/review-response-files-verified.log`。新增 8 项回归覆盖同名文件错误、保存基准、旧快照恢复/修复、无效路径、普通及无项目回合、摘要预览和链接行号；实际独立模型审查用例改为子目录项目，检查请求记录仓库基准而执行项目仍为子目录。
