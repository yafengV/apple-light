# 全局听写状态浮窗

Codex macOS 26.911.61220 的公开分发资源 `global-dictation-page-3d28a1fd7ea2.js`、`global-dictation-page-a20b6b6d9798.css` 与主进程 `main-DS3FMq4P.js` 显示：全局听写有一个 720×84 的无焦点、置顶浮窗，位于鼠标所在屏幕工作区底部上方 16 点；空闲状态是 40×8 的提示条，录音和转写状态显示 72×30 胶囊，正常状态透传鼠标，错误状态开放点按。ShipiOS 原先只在主窗口设置页和菜单栏显示听写状态，跨应用听写时用户看不到反馈。

现以原生非激活 `NSPanel` 实现空闲、授权准备、正在听写、整理转写及错误状态，随快捷键设置、语音会话和显示器变化更新。外部应用保持焦点；新会话会按当前鼠标所在屏幕重新定位。输入目标写回失败时浮窗显示错误和明确的“复制”恢复动作，只有用户点击才把听写文本写入剪贴板；关闭错误后回到空闲提示。监听器和浮窗在应用退出时移除。

22 项全局听写、语音和状态相关回归通过，包含实际 `NSPanel` 的可见性、层级、无焦点、鼠标透传、错误交互和快捷键关闭；错误状态离屏图像、正式应用构建和严格签名通过。当前机器没有可枚举麦克风，新包前台、真实跨应用听写和 Codex 双端点击仍未验收。实时音量波形、录音保存／恢复／重试及完整错误交互仍缺；完整配对保持 **0/47**。
