状态：整理建议。以下按阶段交付，不代表已经承诺工期或已经完成。90 天安排是容量规划参考，P0 结果可改变后续排期。

2026-09-16 实施更新：已完成本地 Agent、配置来源、SQLite 状态/事件、Xcode 构建、取消/超时和 Swift IPC 原型；已固定并审计 Codex 源码，尚未内嵌编译。P0 整体未通过，逐项进度见 [本地原型报告](08-local-prototype.md)。

## 1. 开始实现前的顺序

先证明运行时可集成且可隔离，再验证一条本地改码闭环，随后接入发布。商业访谈可以与技术验证同时进行，但不提前开发完整云平台。

| 阶段 | 参考时间 | 核心交付 | 退出条件 |
| --- | --- | --- | --- |
| P0 技术验证 | 第 1–2 周 | 固定源码版本的 Agent PoC、隔离报告、选型记录 | 运行会话、工具注册、取消和关键隔离用例可验证 |
| M1 本地闭环 | 第 3–6 周 | 薄 macOS 客户端、构建修复、一个冒烟场景、报告 | 完成真实改码→构建→验证→审查，失败可接管 |
| M2 发布试点 | 第 7–10 周 | Archive、TestFlight、材料草稿、发布检查点 | 试点项目可上传并确认处理状态，未知状态可恢复 |
| M3 商业验证 | 第 11–13 周 | 多项目试用记录、定价实验、分发包 | 有重复使用和真实付款证据，再确定扩展方向 |

## 5. 测试层次与证据

- **状态机与契约测试**：覆盖预算耗尽、重复事件、取消竞态、版本不兼容、过期证据和授权失效。
- **工具集成测试**：可构建 fixture、故意编译失败、断言失败、模拟器不可用、结果解析失败。
- **隔离测试**：使用临时目录和测试密钥执行隔离矩阵；禁止污染个人 Codex。
- **恢复测试**：步骤间崩溃、上传超时、重复恢复；验证不会丢失状态或重复产生外部副作用。
- **分发测试**：干净环境启动、缺 Xcode、helper 版本冲突、升级与卸载范围。

记录机器、系统/Xcode/runtime 版本、测试项目与代码树、输入、结果、证据路径。外部真实上传先用用户授权的测试 App 验证，不将模拟接口通过视为生产验证。

## 6. 关键风险与应对

| 风险 | 早期信号 | 应对 |
| --- | --- | --- |
| 上游接口与对话描述不一致 | crate/Contributor 不存在或不可用 | 固定版本验证，缩小适配面，评估备选 |
| 默认配置发现无法隔离 | 冲突配置或外部密钥污染 | 阻止产品化，定位 loader/认证/环境来源 |
| UI 验证误判 | 截图看似成功但断言失败 | 场景化、确定性断言、显式未覆盖 |
| 多项目兼容性失控 | 每个新项目需定制脚本 | 限定支持矩阵，记录接入工时 |
| 模型成本与修复时间失控 | 反复同类失败、无有效 diff | 预算、有限重试、人工接管 |
| 发布状态不可恢复 | 超时后无法判断是否已上传 | 持久化意图、远端 ID、查询去重 |
| 用户只尝鲜不付费 | 有安装无重复使用 | 提前访谈与付费试点，缩小痛点范围 |
