# 环境读取的请求身份与取消状态保留

日期：2026-10-09。接续第 706 篇，核对已打开项目和同窗口设置编辑器的并发环境读取。

## 问题与行为

工作区原先仅检查项目路径与文件名；设置编辑器检查连接代数与文件名。A→B→A 后，最早的 A 回复仍满足这些条件，可能覆盖后来载入的 A。目录刷新也可能在新建环境或选择另一份文件之后继续选择并载入，覆盖新草稿。

| 场景 | 本阶段行为及测试 |
| --- | --- |
| A→B→A 的乱序成功回复 | 工作区及设置编辑器每次读取有独立 UUID；最新 A 的表单、revision、存在状态和加载基准保持不变 |
| A→B→A 的旧错误 | 不清空最新表单，不改变当前状态文字或 readError，不把旧错误显示在新选择上 |
| 目录刷新之后选择另一环境 | 原目录请求失效，不再发起覆盖新选择的内容读取；新选择的未保存名称保留 |
| 目录刷新之后新建环境 | 新文件名、草稿、空 revision、存在状态和未保存提示保留，不回选默认文件 |
| 读取中切换项目 | 工作区读取还须匹配 Agent 连接会话、连接状态和准备标记；旧 Agent 停止造成的错误不清空尚在显示的源项目表单 |
| 已取消调用及读取中取消 | 不应用成功／失败回复；同文件重读保留读取前的完整表单、revision 和存在状态。已取消调用也不使其他读取失效 |
| 切换到另一文件 | 仍清除上一文件的版本身份；设置编辑器保留新文件的空表单语义，避免把旧文件版本用于新选择 |

目录刷新及随后内容读取共用一次请求身份；后来的选择、新建或重读可使整次旧刷新失效。只有当前请求可保存读取到的项目 profile。没有新产品开关、真实 API 调用、凭证改动或权限重置。

## 验证

新增 `EnvironmentReadConcurrencyTests.swift`：线程化 Python RPC 夹具在真实管道中返回乱序回复，按文件计数区分最早与最新请求，并用磁盘闸门控制完成顺序。

原实现四项测试产生 **29 条失败断言**（`.cache/environment-read-red-707.log`）。独立读取身份修复后四项复现与真实 helper 六项环境接口共 10 项通过。

进一步把取消测试的比较基准前移到读取开始前，复现两项测试共 **10 条失败断言**（`.cache/environment-read-cancel-state-red-707.log`）：忽略迟到回复仍会留下此前已清空的状态。因此同文件重读改为收到有效回复后更新；取消保留原表单与版本。切换不同文件的版本清理仍保留。
