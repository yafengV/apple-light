# Activity 数字快捷键与失败切换保护

2026-09-28。Activity 已替换主窗口侧栏，但此前侧栏数字命令仍取普通侧栏的任务顺序。本阶段改用当前 Activity 的任务槽，并修复验证中发现的跨项目失败切换问题。

## 参考与路由

此前缓存的官方桌面资源中，`UIn` 使用 `(U ? H : [...K, ...ee.flatMap(QIn)]).slice(0, 9)` 生成侧栏数字目标：显示优先区域时只取优先任务；隐藏后按置顶、近期顺序取九个。空优先区域或少于九项时不使用其他区域补位。`uAo` / `dAo` 注册的 `hG` 来自 `thread1` 至 `thread9`，与独立的六个 `recentThread` 命令不同。这是静态行为参考，不能替代当前用户版本的原生双端配对。

ShipiOS 的 `focus-chat-1…9` 现在取当前 Activity 优先列表，或隐藏优先后的置顶与近期列表。沿用计划任务过滤、独立置顶区域、七个日历日分组和保留已读优先条目的规则；不可选择的任务占据原槽位，不能挤移后续任务。九号是第九项，没有“最后一项”的别名；关闭 Activity 后恢复普通侧栏的展开顺序。

快捷键仍由现有偏好解析，保留数字键目标交换、自定义改绑与冲突处理。`recent-chat-1…6`、其默认 ⌘⌥1…6 和独立窗口的最近任务路由保持独立，不从 Activity 列表取目标。

数字命令在发起时捕获任务 ID 和 Activity 会话 ID，异步执行前检查会话、可见目标、设置、弹层和录制状态。关闭并重新打开 Activity、归档目标或出现确认后，旧请求不能打开另一任务；列表变化不会把捕获对象换成新槽位里的任务。点击与数字入口共用正在打开状态，成功后使用同一自动化结果审查流程。选中任务变化时，Activity 更新键盘定位并滚动到该行，不主动把焦点从输入区抢回列表；真实焦点和滚动仍需原生验收。

## 跨项目失败切换

新测试发现旧 `open` 在 Agent 初始化失败前就替换项目、任务选择和文件工作区。因此虽然 Activity 保留目标未读，原任务和草稿已不在屏幕上。

现在先完成初始化、项目检查、配置与运行列表读取，再更新项目、任务选择、文件工作区及环境状态。准备期间的 Agent 事件不能按原项目归属处理；完成后以最新运行列表作为初始状态。任一准备步骤失败时保留原任务、草稿、文件预览、面板和环境信息。跨项目导航仅在成功后记录，失败保留后退/前进历史。原本的本地 Agent 在切换准备时已经停止，因此失败后如实显示未连接，重新打开原项目可恢复连接；本阶段没有把停止的进程伪装成仍然可用。
