## 回归中发现并修复的真实问题

本轮首次关联集执行 213 项，有一项审批等待中 Stop 后立即续聊失败。单独重跑曾通过，随后连续压力运行在第 8 次再次复现，错误为“该任务已有 Codex 回合正在运行”。没有将它归为无害偶发。

原因是本地取消结束早于 Core 的终止通知，旧 stream 仍占据任务；取消处理器和 catch 还可能重复发送中断。现在每条 stream 持有独立 token，取消路径合并同一回合的中断，等待实际终止边界；迟到的旧 token 不作用于新回合。超过 10 秒没有终止通知则关闭不确定的线程，保留 rollout 供恢复，避免复用未知活动状态。启动取消仍走原独立初始化取消路径。

新增确定性 IPC 用例刻意将提交确认与终止通知分开 400ms，验证重复取消只产生一次 RPC、立即续聊成功、旧取消不能影响新回合。真实审批中断/续聊修复后连续 12 次通过。
