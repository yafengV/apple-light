ShipiOS 新建 PR 监控时现在从原任务已结束的历史分叉，保留会话上下文、模型选择和可用的 Core 分叉来源，关联同一 PR。监控及工作区写入失败会回滚新分叉；没有已完成历史时显示错误。刷新远端 PR 后重新检查来源任务，来源已归档或正在删除时不创建监控。恢复监控继续使用已有任务；定时轮次复用同一任务和工作树，原任务保持独立。

每轮读取最新 PR 分支和 Git 设置后，使用更新的持久记录发送提示，避免写回旧提示。已暂停的监控不读取 PR 或启动轮次；关联任务删除、归档或缺失时暂停，不自动重建空任务。工作树准备完成后再次检查任务和监控状态。准备失败按本轮实际自动化回合判断并推进日程，分叉继承的历史不再被误判为本轮已经运行。

PR 监控的新工作树从提交开始，不复制来源目录的未提交文件、未跟踪文件或本地快照；通用自动化和其他工作树任务保留原行为。这样 PR 修复不会混入用户当前检出的编辑内容。首次运行仍提前准备工作树，尚未实现参考端“需要改代码时才创建”的时机；旧工作树已有内容不会被重置。
