# MCP 工具持久授权

2026-10-01。MCP 工具详情页新增“始终允许此工具（自定义 API 会话）”开关。用户开启后，同一服务器配置和同一工具定义的自定义 API 会话调用可跨任务、跨应用重启使用该授权；关闭开关后后续调用重新请求批准。

授权记录只保存服务器 ID、工具名和配置/工具定义的 SHA-256 指纹。指纹包含服务器配置、工具标题与说明、输入 schema，以及当前从进程环境继承的相关变量值；工作区文件不保存这些环境变量原值。服务器配置变化时立即清除该服务器的授权；重连或刷新发现工具定义、继承的环境值变化时也清除旧授权，因此把配置改回原值不会恢复旧授权。调用前仍核验服务器启用、当前连接身份及工具定义。计划任务保持无人值守拒绝策略，即使该工具曾被持久授权。

Codex Core 的 MCP 审批事件目前没有提供可与设置页工具定义核对的完整快照，因此 Core 会话仍按现有审批流程逐次询问，界面开关只适用于 ShipiOS 自定义 API 会话。这一阶段没有完成当前 Codex Mac 的原生视觉和交互配对。

`MCPToolCallTests` 的 14 项定向测试及 `MCPServerSettingsTests` 的 8 项设置回归通过，包括重启后真实工具调用自动通过、服务器配置或工具 schema 变化后永久撤销授权，以及无人值守计划任务拒绝调用。测试日志在 `.cache/mcp-persistent-grants-tests.log` 和 `.cache/mcp-persistent-settings-tests.log`。`script/build_and_run.sh --verify` 构建、签名和进程启动通过，`codesign --verify --strict --deep` 通过。前台工具报告 Mac 锁屏，无法核验工作区可交互或与 Codex 原生页面逐项配对。
