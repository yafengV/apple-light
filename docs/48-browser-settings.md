# 浏览器设置、历史与数据清除

2026-09-17。本轮在主窗口设置中加入“浏览器”分类。它与其余设置共用 `AppContentView`，不会创建独立设置窗口；从菜单或 `⌘,` 进入后，返回按钮与 Esc 回到进入设置前的页面。

## 对照依据

OpenAI 当前帮助文档说明，桌面内置浏览器有自己的浏览状态，支持多标签与下载，设置中可以清除 Cookie、登录状态和浏览历史；网站允许/阻止规则也在桌面设置管理。另一个官方页面说明 `Settings > Browser` 中包含完整 CDP 访问开关。参考：

- [Using the built-in browser in the ChatGPT desktop app](https://help.openai.com/en/articles/20001277-using-the-built-in-browser-in-the-chatgpt-desktop-app)
- [Using Codex with your ChatGPT plan](https://help.openai.com/en/articles/11369540-using-codex-with-your-chatgpt-plan)

这些资料用于确定页面职责，不足以证明像素、焦点顺序和所有交互与当前用户安装版本一致；完整配对仍需要两侧相同前置数据的逐项原生记录。

## 已实现

- 设置侧栏增加“浏览器”，仍在同一个主窗口切换。
- WebKit 完成一次页面访问后记录标题、完整 URL 与时间；同 URL 再次访问更新原记录并移到最前，最多保存 500 条。
- 历史写入 ShipiOS 独立 `workspace.json`，旧数据自动迁移为空历史；应用不会读取个人 Codex 或系统浏览器历史。
- 设置页可按标题或 URL 搜索，可从历史在内置浏览器新标签重新打开，也可删除单条记录。
- “清除浏览数据…”先显示破坏性确认，可选择是否同时清除浏览历史；网站数据通过 `WKWebsiteDataStore` 清除 Cookie、缓存及站点存储。
- 页面明确提示完整 URL 可能包含查询参数，并说明目前浏览资料只在本次 App 运行期间保留。

2026-09-27 更新：第 [270 篇](270-persistent-browser-profile.md)已将正式应用改为独立持久 WebKit 资料；上句描述的是本篇实现时的状态。指定 `--data-root` 的隔离实例仍为临时资料。
- 浏览器工具栏可将当前标签的可见区域截图加入触发时的任务输入区；实现、失败边界与原生预览证据见第 71 篇。
- 页面支持点击元素或拖选区域后保存多条评论、显示编号标记并随下一条任务消息发送；见第 72 篇。
- “下载”子页支持系统默认或自定义目录、每次询问保存位置、下载记录与清除；浏览器面板显示真实进度、完成/失败/取消，并可打开文件或在 Finder 中显示，见第 73 篇。

## 验证

19 项定向回归覆盖浏览器与主窗口路由，其中 11 项浏览器测试使用真实 `WKWebView` 和本机 fixture，验证：

- 页面标题与 URL 记录、同 URL 去重、上限逻辑和重启后持久化；
- 从设置重新打开历史，且设置退出到工作区的浏览器面板；
- `Set-Cookie` 后实际清除 WebKit 网站数据；
- 关闭“同时清除浏览历史”时保留本地历史；
- 设置切换仍保留活动工作区，不产生第二个设置窗口。

随后执行完整回归：280 项 Swift 测试、12 项 Rust 测试、Rust fmt/Clippy 与真实 IPC 冒烟全部通过。日志保存在 `.cache/browser-settings-full-tests.log`。

原生主窗口验收已准备使用隔离数据根目录运行。当前 macOS 锁屏阻止 UI 自动化读取应用，因此搜索、重新打开和清除确认框仍标为等待解锁，不能用自动化状态测试冒充可见验收。
