# 主窗口设置与全局命令交互

2026-09-17。继续执行用户要求：设置是主窗口内页面，每个页面都需要按当前 Codex 版本逐项比对。本轮没有将现有八个设置分类等同于 Codex 的完整设置目录。

## 发现与修正

设置已经通过 `AppContentView` 显示在主窗口，应用没有独立 `Settings` Scene。本轮发现命令菜单、任务搜索和文件搜索的 sheet 仍挂在设置背后被禁用的 `WorkspaceView` 上。这种层级让全局弹层受到隐藏工作区的状态影响。现将三类弹层移到主窗口根视图，由单一 `WorkspaceOverlay` 状态控制。

- 设置页打开命令菜单或任务搜索，原设置分类和返回来源保留；取消弹层不会退出设置。
- 同时只允许一个全局弹层；旧弹层的布尔关闭回调不会误关新弹层。
- 工作区关闭弹层后恢复输入焦点；设置页关闭弹层不主动聚焦隐藏输入框。
- 命令调度入口再次检查可用条件，避免直接调用禁用动作修改隐藏任务。
- 切走工作区时关闭输入区构建选项和模型弹层，释放输入框焦点。

## 输入区候选

现有 `/` 命令补齐键盘选择：上下键选择可用项，回车/Tab 确认，Esc 收起并保留文本，修改文本后重新显示。列表最多显示约六行，可滚动到选中项；没有匹配项时不显示空框。

- `/chat`、`/doctor`、`/build` 只补全模式和空格，不立即启动任务。
- 文件、终端、审查与分叉命令按当前任务/项目状态禁用；不可用候选不会被回车当成普通消息发送。
- 无修饰键时才处理候选键；Shift+Enter 和发送快捷键保持各自用途。
- 原生文本输入客户端有 marked text 时不拦截这些按键。自动化测试覆盖该状态分支，真实中文输入法确认仍待解锁后验证。
