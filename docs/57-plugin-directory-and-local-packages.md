# 主窗口插件目录与本地包管理

2026-09-17。依据 [OpenAI 插件文档](https://learn.chatgpt.com/docs/plugins) 增加独立插件页面。官方目录将插件描述为技能、MCP 服务、浏览器扩展和钩子的组合，并提供发现、搜索、详情、已安装、启用/停用和卸载流程。ShipiOS 先实现可以在独立运行时中真实完成的本地部分。

## 当前实现

- 主窗口侧栏增加“插件”，`/plugins` 和命令菜单也可进入；页面替换主内容区，不创建独立窗口。
- 页面提供“发现 / 已安装”、搜索、本地导入、组件摘要、详情、启用/停用、Finder 定位和卸载确认。
- 设置侧栏提供独立的“MCP 服务器”“Hooks”“插件”“技能”分类。这些页面读取同一份安装状态，支持本地导入、重新加载和插件级启停；技能页同时显示可在输入区使用的 `$名称`。
- 本地导入要求 `.codex-plugin/plugin.json`，读取名称、标识、版本和说明，并识别 `skills/**/SKILL.md`、MCP 服务、浏览器扩展和钩子。
- 导入前拒绝无效标识、重复安装、符号链接、超过 2,000 个文件或 50 MiB 的包。插件复制到当前数据根目录 `Plugins/<id>/`，目录权限为 0700；状态写入 `plugins.json`，权限为 0600。
- 插件页进入设置后，设置继续在同一个标准窗口内显示；Esc 返回插件页，再返回任务时工作区和草稿保持挂载。
- 输入区识别以空白或行首开始的 `@插件标识`。键入部分标识时显示已启用插件的候选浮层，支持鼠标、上下方向键、Return、Tab 和 Esc；确认后只替换光标前的尾部引用，不会把电子邮件地址误判为插件。
- 输入区也支持 `$技能` 候选和单技能调用；同名技能自动使用 `$插件/技能` 消歧，只注入被选择的 `SKILL.md`。完整行为与边界见 [输入区技能选择与上下文调用](61-skill-mentions-and-context.md)。
- 发送时只解析当前消息中显式引用且已启用的插件。对应 `skills/**/SKILL.md` 以有界 system context 加入本次独立 API 请求，用户原始消息不改写；本地执行记录另存实际启用的插件标识。单个 Skill 限制 64 KiB、一次调用合计限制 128 KiB，并拒绝符号链接、非普通文件和非 UTF-8 内容。
- ShipiOS 不读取、覆盖或卸载用户个人 Codex 的插件目录。

## 自动化与原生验收

`PluginTests` 覆盖清单解析、组件识别、安装、重复和符号链接拒绝、0600 状态文件、启停、卸载、跨实例加载、插件页导航、设置返回、`/plugins`、`@` 候选过滤、引用替换和 Skill 上下文边界。模型传输集成测试通过本机 fixture 服务检查了真实请求体：system message 包含被点名插件的 Skill，user message 保持原样，执行记录包含插件标识。

完整回归通过 312 项 Swift 测试、12 项 Rust 测试、Rust fmt/Clippy 和真实 Agent IPC 冒烟，日志为 `.cache/plugin-invocation-full-tests.log`。

原生验收使用 `.shipios-local/plugins-validation`。辅助功能树和截图确认插件页位于唯一的 ShipiOS 标准窗口内；`/plugins` 经 `⌘↵` 打开页面。通过系统文件选择器导入 `Native Validation Plugin` 后，页面与详情都显示 1 个技能和 1 个 MCP 服务。从插件页进入设置并按 Esc，窗口返回插件页。

随后启用该插件，在输入区键入 `请使用 @nat`，候选浮层只显示 `Native Validation Plugin`；按 Return 后草稿变为 `请使用 @native-validation-plugin `，没有发送消息。完整重启后该草稿和启用状态都恢复，插件页仍在同一个标准主窗口中。

后续设置页验收使用签名后的原数据目录构建。侧栏滚动列表完整显示 MCP 服务器、Hooks、插件和技能；四页逐一打开后均保留 `ID: main`，空状态与导入、重新加载控件可见。Esc 返回后原任务和未发送草稿保持不变。`PageNavigationTests` 与 `PluginTests` 共 12 项通过。

GUI 验收没有点击卸载，因为该操作会删除本地文件；删除与失败回滚由隔离自动化测试完成。
