# 文件选区模型编辑

文件页在可编辑文本有非空选区时提供“编辑选区…”入口。用户输入修改要求后，ShipiOS 使用当前任务的独立模型配置生成仅含 `replacement` 的 JSON 建议；Chat Completions 使用独立 API 请求，Responses 使用只读、纯文本、无 MCP 工具的临时 Codex Core 回合，完成后销毁临时线程。单次选区上限 16 KiB，提示词上限 40 KiB，返回内容上限约 1.1 MiB，编辑后的文件仍受应用内 1 MiB 上限约束。

生成结果先显示原选区和建议替换文本。生成阶段不改草稿或磁盘；用户点击“接受修改”时才通过原生 `NSTextView` 应用替换，因此保留现有撤销与自动保存流程。“拒绝”或关闭面板不修改文件。接受前检查文件路径、完整文件字节、选区和编辑资格；文件或选区变化后旧建议无法应用。切换项目或文件时取消并清理选区编辑状态。

验证：`FileSelectionEditRequestTests` 和 `FilePreviewFocusTests` 的 10 项针对性测试通过，其中包含 UTF‑16 选区、无效/超大响应、建议阶段无写入、接受后的原生撤销，以及旧选区拒绝。相邻的文件和模型传输回归另有 109 项通过，正式应用构建及严格深度签名校验通过。Mac 锁屏阻挡前台鼠标焦点、窗口布局、可交互工作区以及 Codex 双端配对；真实服务端返回内容也尚未验收。本项不能计入 45 项完整页面交互验收。
