# 文字与工具交错时间线

2026-09-18。主窗口和独立任务窗口现在按生成顺序显示文字与 MCP 工具调用，避免把整轮工具卡片集中放在回答之前。

## 对照与实现

本机 Codex 静态界面的 `local-conversation-thread-turn-entries-31417db74667.js` 和 `split-items-into-render-groups-5c1e145454a2.js` 从回合内的消息与活动项生成渲染条目；这与 ShipiOS 原先独立渲染“全部工具 + 全部回答”的结构不同。本轮补齐顺序模型，尚不声称复刻官方全部活动分组与视觉样式。

回合结果新增独立 `response_items` 顺序记录。文字项持有稳定身份，后续文本分片追加到当前文字项；工具项引用对应执行记录，审批、执行、失败等状态更新不改变其位置。工具结束后的模型回复创建新的文字项。

工具执行记录和它的顺序条目一次保存，避免重启后出现只有引用、没有卡片的状态。主窗口与独立任务窗口共用 `ChatResponseView`。原有聚合回答和模型对话历史继续用于复制、分享和模型上下文。

会话查找按相同文字项解析 Markdown，并为段落、代码、引用、列表和表格添加所属文字项的定位前缀。工具两侧相同的关键词拥有各自定位身份，不会重复搜索聚合回答或跳转到另一段。

旧会话未记录时间顺序，继续按原方式显示；不根据时间戳猜测穿插位置。缺失工具引用或重复身份的损坏记录也回退显示完整回答及工具列表。

## 验证

首轮 40 项相关回归通过；新增顺序与搜索用例后 44 项定向测试通过，日志 `.cache/response-timeline-tests.log`。随后增加目标结束标志、部分回答停止与重启恢复检查，并运行完整 Swift 回归，日志 `.cache/response-timeline-full-tests.log`。

完整回归最终 479 项通过、0 失败，耗时约 173 秒。本轮新增 5 项测试，并扩展既有停止与恢复用例。构建日志 `.cache/response-timeline-build.log`。

应用构建与严格深度签名验证通过，原数据目录实例已重启为 PID 4705；受保护任务和待发送草稿均保留。

本地模型/MCP 联测覆盖“文字 → 批准工具 → 文字 → 拒绝工具 → 最终回答”，验证等待审批时的实时顺序、状态更新后的身份稳定、持久化恢复，以及三段文字的搜索定位。纯模型测试还覆盖 Unicode 分片、嵌套 Markdown 搜索和旧格式兼容。
