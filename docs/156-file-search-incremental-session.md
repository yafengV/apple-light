# 文件搜索增量会话与加载恢复

2026-09-19。替换第 155 篇中每次查询重新启动 helper、扫描整个目录的界面调用方式。

## 对照依据

客户端公开静态资源 `Ybt/Bbt/Zbt` 在同一根目录下复用搜索 session，并接收更新及完成通知；查询更新期间保留已经显示的结果，空查询清除结果，根目录变化或组件卸载停止 session。上游 `file-search` 使用 nucleo 的 Injector、增量 pattern、tick 和 snapshot，让目录扫描与匹配独立推进。

## 实现

- 新增只读 `search-files-session` stdio 入口，绕过模型配置、认证、数据库和主 Agent RPC。一个搜索窗口对应一个独立索引，输入 JSON 行携带查询编号，输出可包含多次部分结果及一次完成状态。
- 采用与前一阶段相同 revision 的 nucleo 高层引擎；扫描线程逐项注入，匹配线程处理查询变化，候选仍限制为 50 条，再交给现有文件名排序。索引完成且查询完成时阻塞等待输入，避免空闲轮询。
- Swift transport 顺序解码分片和多帧输出，忽略旧编号，限制单帧大小，覆盖进程退出、非法输出和 20 秒查询超时。失败关闭会话，“重试”重新建立索引。
- 同项目查询切换保留已显示的结果，直到新响应到达；迟到的旧响应不覆盖当前查询。空查询清空结果但保留索引，切换项目或显式重试重建索引，关闭搜索或打开结果释放进程。
- 部分结果在搜索完成前即可选择，标题旁显示搜索进度。选择状态改为文件路径，避免流式插入或排序变化时，仅因行号改变而打开另一文件。
- 保留原有一次性 CLI，便于独立使用和诊断；界面采用 session。

## 验证

- 18 项 Rust 工作区测试通过。新增确定性测试在扫描完成前注入第一项、观察部分结果，再注入第二项并完成扫描，验证完成状态和下一查询复用；真实 CLI 测试覆盖连续/快速查询、空查询、扫描后新增文件不进入旧索引，以及 stdin EOF 后退出。
- 24 项 Swift 相关测试通过。新增 session 测试覆盖部分结果显示、同项目复用与结果保留、切换目录、重试重建、关闭未完成查询、真实子进程分帧解码、旧编号过滤、进程退出、非法响应及超时。测试中只给超时场景使用短时限，协议错误场景留足进程启动时间。
- 在原生隔离工作区加入 5,000 个文件后，`AlphaBeta` 正常返回 50 条候选；切换为 `cpv` 后显示既有 4 条结果。系统进程检查确认两次查询复用同一 helper PID。
- 原生索引建立后创建一个测试文件，当前 session 查不到它；Esc 关闭后确认 helper 不再存在，再打开搜索即可查到该文件。这验证了实际索引复用及关闭重建。
- 主动终止已核对 PID 的测试 helper 后输入新查询，界面显示“文件搜索进程不可用，请重试。”；点击重试后恢复 `cpv` 结果，方向键与回车打开正确文件并聚焦内容。测试任务未发送草稿完整。
- 打开文件后再次检查 helper 已退出。测试日志为 `.cache/file-session-rust-tests.log`、`.cache/file-session-swift-tests.log`；本轮运行数据、合成文件和缓存不提交。
- 最终通过项目脚本构建并恢复原工作区，原未发送草稿及输入焦点完整；严格签名检查通过。

## 剩余范围

本轮完成单根本地搜索的会话生命周期，不代表多根目录、远端主机、超大仓库延迟、所有文件类型打开方式、所有视觉细节或整个产品已经对齐。5,000 文件原生验收不是与 Codex 客户端配对的性能基准；部分结果的确定性证据来自受控测试，不能替代所有真实机器上的逐帧验收。搜索窗口内不监听文件系统变化，关闭重开或显式重试会重新扫描。
