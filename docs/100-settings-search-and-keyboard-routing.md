# 设置主窗口、搜索和键盘路由复核

2026-09-18。用户再次指出设置不应是独立窗口，并要求逐页对齐。本次只记录确认并修复的差异，不把已有功能或测试数量作为全产品对齐证明。

## 对照依据

读取本机 Codex 应用包内的 `settings-page-1f095c82376f.js`：设置页传给导航的 `canCollapse` 为 false；搜索框的 `CmdOrCtrl+F` 聚焦并全选；搜索列表 Esc 清空查询；页面级 Esc 排除可编辑输入及已打开的对话框。原生 CUA 检查仍报告 Mac 锁屏，因此没有获得当前两应用的逐页截图或实际键盘投递证据。

## 修复

- 设置继续作为主窗口 `AppContentView` 的页面。没有 `Settings` Scene；菜单和独立任务窗口的设置入口唤起 `main`。
- 移除设置导航中自行加入的折叠按钮，保留分组、独立滚动、搜索及返回应用入口。
- 修复设置中 ⌘F 错误返回任务搜索的问题。22 个设置页均通过同一路由聚焦设置搜索，菜单和自定义查找绑定保持一致；切页与搜索不修改来源页面、任务或草稿。
- 使用仅用于设置搜索的 `NSSearchField` 桥接，聚焦时全选查询，方向键移动结果，Enter 打开高亮结果。原生清除按钮同步查询；鼠标悬停和键盘焦点同步高亮项。
- 搜索框 Esc 只清空查询，查询已空时仍留在设置。页面级 Esc 保护正在编辑的文本、输入法组合、快捷键录制与模态窗口；返回按钮仍能显式离开。
- 聚焦请求检查所属窗口、可见页面和输入法状态，卸载后作废，避免后台设置抢占其他输入。
