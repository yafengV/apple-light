# 托管工作树数量上限

2026-09-26。[OpenAI 官方工作树文档](https://learn.chatgpt.com/docs/environments/git-worktrees)说明 Codex 默认保留最近 15 个托管工作树，可在设置中修改上限或关闭自动删除；置顶、运行中和永久工作树不自动删除，删除前保存快照，重新打开任务时可恢复。ShipiOS 的设置 → 工作树现提供对应开关和正整数数量上限，旧工作区默认启用并保留 15 个。

创建托管工作树、修改设置或恢复工作区后会核对数量。超限时按任务最近更新时间和工作树创建时间依次尝试清理，只处理未置顶、无活动回合且未被任务窗口或当前项目使用的托管检出；永久工作树不计入。清理复用归档快照路径，保护 HEAD、暂存与未暂存修改、未跟踪及忽略文件。若可清理的候选不足，数量可暂时超过上限，不会强删受保护的目录。

用户在主窗口重新打开被清理的任务时，先在原路径恢复快照再打开项目；独立任务窗口在准备资源前恢复，失败时显示重试。工作树保留原任务关联，任务本身不被归档。真实 Git 回归覆盖超限清理、已暂存/未暂存/未跟踪文件恢复、重新选择任务后保持上限，以及关闭自动清理、置顶保护与设置重启持久化。当前 Codex Mac 原生布局和交互仍未配对；Handoff 尚未实现。
