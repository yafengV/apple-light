# Activity 优先任务批量归档

2026-09-28。第 351 阶段修正了 Activity 侧栏和显示选项，但缺少选项菜单的批量归档。本阶段接入该入口、运行中停止确认和结果反馈。

## 对照依据与范围

此前提取的官方桌面资源明确包含 Archive chats，确认框固定目标列表和数量，仅归档有对应归档能力的 Priority 条目，近期列表不在范围内。选中任务仍运行时，标题与按钮改为 Stop and archive；执行时显示 Archiving 并禁止关闭或重复确认，完成后关闭确认框，并区分成功数量和失败数量。正在查看的任务被归档后进入新会话。这些静态资源用来确认行为，不能代替用户当前版本的原生配对证据。

ShipiOS 的选项菜单现有“归档任务”，范围固定为打开确认框时可归档的优先条目，不因之后新任务到达或选项变化扩大范围。单独置顶、隐藏的计划任务及近期区域不进入该批操作。任务存在未完成工作树移交时遵守原有归档约束；确认后重新检查任务身份与状态。确认默认聚焦取消，Return、Tab、Esc 和关闭行为复用已有主窗口确认组件。实际菜单和键盘投递仍待原生验收。

## 停止、持久化与失败处理

模型请求先取消，等到运行记录进入终态且该请求句柄移除后才归档；无法找到实际请求或停止未完成时保留任务。本地 Agent 先请求取消，再查询真实运行状态，连接、项目或返回任务不匹配时保留任务。应用关闭或操作取消时也不将仍活动的任务改为归档。

归档期间，目标任务不能从独立窗口、队列或目标续轮再次启动模型请求；其他任务不受影响。已经归档的任务需要先恢复才能继续模型会话。队列、未发送草稿、部分回答与执行记录保留。

每个任务在停止后重新从最新工作区构造候选配置，先保存成功才更新内存；保存失败不会将任务误标为归档。多任务操作允许部分成功，失败的任务保留，确认框关闭后显示成功/失败数量，侧栏显示具体失败原因。已不存在的目标不会被替换为新到达的任务。当前任务归档后新建任务；活动侧栏保持打开。

已成功归档的托管工作树沿用已有串行清理、脏检出快照和恢复机制。新增真实 Git 回归通过批量入口归档含已跟踪修改和未跟踪文件的工作树，确认目录清理后仍可恢复原任务及两类文件内容。
