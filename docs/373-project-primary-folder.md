# 项目主目录切换与任务目录保留

## 对照与实现范围

实际打开并核对[官方项目文档](https://learn.chatgpt.com/docs/projects?surface=app)：Edit project 的 Make primary 改变新会话的默认工作目录，主目录承担默认 Git 及自动指令/技能发现；附加目录仍可读写。本阶段增加真实「设为主目录」，并保留已有任务的物理执行目录。旧任务目录保留有实际 Core 回归证据，当前 Codex 原生菜单、悬停呈现和所有边界仍待配对。

## 项目身份和用户入口

项目编辑中可将任一附加目录设为主目录，原主目录仍在文件夹列表中，可再切换回来或移除。取消不保存，名称/目录/主目录一次性提交，失败保留编辑内容和原配置。当前主目录不可直接移除，避免留下无有效目录的执行项目。

项目继续使用原稳定标识保存名称、置顶、侧栏分组及顺序；`projectPrimaryFolders` 仅记录新的默认物理目录，`projectScopeOwners` 保留以前使用过的主目录归属。切换后不创建另一个项目、不重写旧任务或运行的 `project`、不移动原私有 rollout。旧工作区缺少这些字段时保持原路径作为主目录。

项目列表和选择器显示新的主目录，并可搜索附加目录；侧栏仍在原分组中展示新旧任务。Finder 与项目工作树入口使用新主目录。项目未提交草稿和深链接草稿使用稳定项目标识，新目录不会使它们丢失；已提交任务草稿仍按任务 ID 保存。

为保护现有独立项目，当前不能把另一个已登记项目的任务目录设为本项目主目录，也不合并其任务和配置。还有待恢复的工作树草稿时拒绝更改主目录，保留原恢复入口。重叠项目身份与这类编辑行为仍需对照当前 Codex，不能据此称全部项目边界一致。

## 实际执行与恢复

普通新任务、项目选择器、深链接、弹出窗口和新自动化任务使用新主目录；直接发送尚未提交的草稿也会先准备新目录，保留输入、计划/目标状态与操作模式。初始化失败继续保留原内容。项目默认环境目录和技能列表按新主目录读取，实际请求的隐式技能发现仍按本任务的执行目录，附加目录不会自动进入该任务的技能目录。

任务选择、导航历史和应用启动恢复明确打开记录的物理目录，不套用最新项目默认值。旧 Core 任务继续原线程和历史；新任务建立独立线程。工作树来源和已开始的自动化发生记录也保持原目录，自动化结果恢复先处理记录回合，不因项目默认值变化重新执行或改写其任务目录。

已有任务的附加范围使用项目当前关联的文件夹，排除其自身执行目录；工作树替换来源检出后继承其余关联目录。原权限/只读政策保持不变。
