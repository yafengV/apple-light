## 参考与差异

当前公开客户端 26.930.51102、build 13100 的 `app-initial-f9b16fbf8fc7.js`，SHA-256 `22f3ea455585cfc0508e3d3627eac161c80c849c0aace3d76d09fdebaa0aeca3`，将普通聊天的 full／split 模式、当前聊天／内容选择和内容显示分别管理。第 692 篇已通过实际 `SHn`／`iVn`／`aC`／`swa` 夹具验证聊天回选不改变 full 模式及相邻内容选择。

本阶段继续读取 `thread-app-shell-chrome-6e13d1129e78.js` 的实际 `Du` 组件，SHA-256 `db5f01832c7d9c730407f6f4e4cdd699dd584393c206439fe12890d265dd3c4b`。它把有效布局映射到 `UnifiedTabStrip.mode`，full 模式使用统一标签表面；`Du` 还区分 workspace primary content 的分屏标题栏。因此不能把 ShipiOS 既有物理右侧面板当成参考 primary workspace 的完整实现。参考标签上下文菜单的关闭其他／右侧标签基于对应 controller 的有序内容集合。

ShipiOS 此前只修复了布局模式保存。其主标签栏、主内容选择和侧栏仍按物理左右位置过滤，造成 full 模式选到原右侧标签后，内容留在侧栏，主区继续显示旧标签或聊天；冷启动也会丢弃这个主选择。布局按钮按当前主选择是否为空显示文字，full＋聊天会显示错误动作并可能新建浏览器。

## 已接入的行为

| 状态／入口 | 本阶段行为与验证范围 |
| --- | --- |
| 主窗口与独立任务窗口 full 标签栏 | 合并当前任务的左／右内容，保持底部面板与分离标签的边界；主标签选中态、滚动目标和主内容使用同一显示集合 |
| full 选择原右侧内容 | 在主内容区显示，隐藏内容侧栏；不修改这个标签保存的物理位置，不重复挂载同一 WebView |
| full 返回聊天再切回内容 | 卸载网页显示，保持 full 模式与原位置；相邻导航重新选择后挂回原 WebView |
| 保存／冷启动 | full 主选择可引用原右侧标签；恢复主选择、焦点与模式，继续兼容缺少模式字段的旧布局 |
| 布局菜单与详情面板入口 | 按布局模式显示完整视图动作；full＋聊天可退出到已有内容；详情面板按钮能重新显示隐藏内容，主次交换仅对实际显示的面板启用 |
| 完整视图的关闭与拖动 | 关闭其他／右侧标签按统一有序列表执行；跨原左右位置拖动可排序，主窗口拒绝跨任务及跨显示面板排序 |
| 显式右侧浏览器／终端入口 | 新建或明确移到右侧进入 split；隐藏内容侧栏不会使终端切换按钮误判已经显示 |
| 网页焦点与命令 | full＋聊天不把缓存的隐藏右侧网页当成可见浏览器；split 文件检查器覆盖网页时不把浏览器命令送给被覆盖内容 |

非内容开发面板、文件检查器与运行检查器保留各自的显示逻辑。本阶段没有把这些 ShipiOS 专用面板列为 Codex 参考验收完成。
