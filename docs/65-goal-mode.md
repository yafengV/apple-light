# 持久目标模式

日期：2026-09-17。

OpenAI 在 2026-05-21 的[官方发布说明](https://help.openai.com/en/articles/6825453-chatgpt-release-notes)中将 Goal mode 描述为：定义结果和成功标准，让 Codex 持续朝目标工作。本轮按这一公开语义实现 ShipiOS 的兼容 API 目标模式；没有把它降级成一次性提示词。

## 用户交互

- 主窗口输入模式菜单和任务独立窗口均提供“目标模式…”。
- `/goal` 会打开目标编辑页，不会作为普通消息发给模型。
- 编辑页要求填写目标及至少一条成功标准；成功标准按行录入，可设置最多 1–10 个连续轮次。
- 目标卡片显示目标、成功标准、进行中/暂停/完成状态和当前轮次。
- 进行中的目标可以暂停或手动标记完成；暂停或已完成的目标可以继续，达到轮次上限后继续会从新一组轮次开始。
- 切换到标准、计划或本地操作会暂停当前目标。任务窗口和主窗口读取同一份任务目标状态。

目标状态随任务保存在 `workspace.json`。重启后仍保留目标、成功标准、轮次、状态和最后运行；若应用退出时目标请求仍在运行，恢复时会把它标为暂停。永久删除归档任务会同时删除目标状态。

## 模型请求与续轮

目标请求在运行元数据中保存：

- `mode = goal`
- `goal_objective`
- `goal_success_criteria`
- `goal_iteration`
- `goal_max_iterations`

system message 会明确给出目标、编号成功标准、当前轮次和完成判定规则。模型回复末尾使用 `SHIPIOS_GOAL_STATUS: continue` 或 `SHIPIOS_GOAL_STATUS: complete`；客户端在保存与显示前移除该协议行。

`continue` 会在没有用户队列消息时自动创建下一轮；已有队列消息优先执行，并继续携带目标上下文。`complete` 会结束目标。服务未返回明确状态、请求失败/取消、用户暂停或达到轮次上限时，目标会暂停，不会无限循环。自动续轮仍受全局单模型请求限制。

## 验证

本机 HTTP 夹具覆盖了实际请求内容、目标 system message、两轮自动继续、完成标记清理、服务遗漏状态后的暂停，以及最大轮次停止。模型解析、旧工作区迁移、持久化、斜杠入口和归档清理也有独立测试。

完整回归结果：

- 344 项 Swift 测试通过；
- 12 项 Rust 测试通过；
- Rust fmt、Clippy 与本机 IPC 冒烟通过；
- 日志：`.cache/goal-mode-full-tests.log`。

随后用原数据目录重新构建、签名并启动应用（PID 61192，日志 `.cache/goal-mode-native-restore.log`）。原生辅助功能树确认：

- 恢复的任务独立窗口模式菜单包含“目标模式…”；
- 点击后在当前窗口显示目标、成功标准和最多轮次编辑页，未创建第三个标准窗口；
- 单例主窗口的模式菜单也包含相同入口；
- `⌘,` 后设置页仍显示在 `ID: main` 的主窗口中；
- Esc 返回原任务后，标题“验证新输入框的真实构建”和草稿“这是一条待发送草稿，重跑后应保留”保持不变。

验收只打开并取消编辑页，没有保存目标或发送模型请求。`workspace.json` 最终包含空的 `goalSessions`，原任务和草稿未被改写。

这项实现补齐了公开 Goal mode 的核心状态和续轮语义。Codex Core 工具循环、工具审批、并行模型运行及当前 Codex 版本的逐像素视觉配对仍是独立差距。
