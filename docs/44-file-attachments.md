# 文件附件与输入区上下文

2026-09-17。补齐输入区只能添加图片、普通文件拖入后进入图片解码器的问题。

依据：[官方项目与会话文档](https://learn.chatgpt.com/docs/projects#bring-in-other-tools-and-context) 明确桌面会话可以直接添加文件或图片作为当前请求的上下文。该说明不是当前 Codex 附件菜单、标签和预览尺寸的配对证据。

## 当前实现

- 输入区加号提供“添加文件…”和“添加图片…”。系统文件面板属于当前主窗口，支持多选和取消。
- 文件标签显示名称和大小；点击在所属主窗口的弹层中预览实际内容，支持文本选择、Esc 关闭和移除。
- 文件 URL 拖入和粘贴按类型路由，普通文本粘贴继续交给输入框。异步导入捕获原草稿归属，不把附件转移到用户后来选择的任务。
- 支持只有文件的消息，也支持文件、图片和文字组合。环境诊断及构建操作不接受附件，避免附件被静默丢弃。
- 草稿、队列、历史及分叉持久化文件引用。发送失败可以重试；编辑队列把文件与文字一起放回空草稿。私有副本在最后一个引用被移除后清理。
- 发送时将验证后的文件内容纳入用户消息，普通兼容 API 可以读取文本；同时附图时继续生成 `text` 与 `image_url` 内容块。仅选择或预览不会发送网络请求。

## 格式和边界

当前支持 UTF-8 或带 BOM 的 UTF-16 文本（包括代码、Markdown、CSV、JSON），以及可提取文字的 PDF。PDF 只发送提取文字，标签、文件选择器和预览明确说明这一点；扫描 PDF、加密 PDF、Office 文档、压缩包和其他二进制格式仍未支持。不能据此宣称所有 Codex 文件格式已对齐。

每条消息最多 8 个普通文件，另保留原来的 8 张图片限制。单文件最多 5 MiB，提取文本最多 200 KB，PDF 最多 300 页，单次请求历史文件文本合计最多 1 MB；超限显示错误，不静默截断。这些是当前 ShipiOS 实现边界，并非 Codex 的产品限制。

原始文件复制到独立数据目录的 `FileAttachments/<UUID>.attachment`，目录 0700、文件 0600。保存名称、字节数、SHA-256 和 PDF 标记；预览与发送均核对内容，并拒绝附件或附件目录被符号链接替换。导入批次失败回滚该批次副本，写入失败保留原草稿，原文件不被修改。旧工作区、队列和消息缺少文件字段时仍可读取。

## 验证

新增测试覆盖私有副本、原文件删除、内容损坏、二进制/超限/符号链接拒绝、UTF-16 与 PDF 文字、混合图片请求、历史总量限制、异步草稿归属、批次回滚、持久化兼容、队列编辑、分叉、最后引用清理以及保存失败。

本机 HTTP 测试验证仅文件首条消息、队列自动续发、实际请求中的文件文字及历史、重启恢复和 HTTP 401 后重试保留附件。没有使用用户服务或外部 API 凭据。构造的文件 URL 粘贴测试不读取用户剪贴板；它不能替代 Finder 粘贴和拖放的原生验收。

全量 `./script/test.sh` 通过 263 项 Swift、12 项 Rust、fmt/Clippy 与真实 Agent IPC 冒烟（`.cache/file-attachments-full-tests.log`）。其后明确配置普通文件选择器的 `.data` 类型和文件选择权限，并为图片选择器显式启用文件选择；最终构建及 47 项相关回归通过（`.cache/file-attachments-final-tests.log`）。

## 原生验收

使用独立数据根目录 `/private/tmp/shipios-git-ui-t2l492o2/Data` 和本轮生成的 `NativeAttachment.txt`，实际验证：

- 加号显示文件/图片两个入口；文件入口打开属于主窗口的系统选择器。
- 选择文本文件并确认导入后，显示预览/移除标签，原草稿保持，焦点回到输入框；普通文字粘贴正常。
- 预览显示文件的中英文和复杂 emoji 内容；Esc 关闭，进入主窗口设置再返回时附件和草稿保留。
- 再次打开文件面板并取消，附件和草稿保持。
- 真实应用重启恢复同一任务、文件标签和文字草稿，预览仍读取正确内容（PID 48905，`.cache/file-attachments-native-restart.log`）。
- 切换其他任务时没有这张附件；切回所属任务后恢复。
- 点击移除后私有副本数为零、草稿引用为空，源文件逐字比对保持不变。测试草稿也已还原为空。

过程中自动化按键和粘贴曾异常，重连 UI 工具后恢复；文件面板初次选择时“打开”未启用，显式配置选择权限与文件类型后重新完成导入。未把这些中间失败记为通过。PDF 的提取由自动测试验证，本轮未进行 PDF 预览、Finder 文件粘贴、多文件拖放或不支持格式错误弹层的原生操作。当前 Codex 的附件菜单/预览外观与完整交互配对仍未取得。

最后以原开发数据根目录 `.shipios-local/desktop` 构建、签名并启动（PID 49450，`.cache/file-attachments-restore.log`）。原生界面确认原任务“验证新输入框的真实构建”和原草稿“这是一条待发送草稿，重跑后应保留”均保留，显示新版“添加附件”入口。
