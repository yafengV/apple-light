# 分离内容窗口恢复与工作区隔离

2026-09-25。修复分离标签窗口重启后依赖主窗口先选中原任务、以及恢复记录缺少数据目录归属的问题。

## 实现

`WorkspaceTabWindowRoute` 保存标签 ID、任务归属和规范化的数据目录。分离窗口入口统一使用此路由；其他数据目录保存的系统窗口直接关闭，不读取同名标签。旧版本仅有标签 ID 的记录，在当前工作区中能唯一解析任务时迁移；历史记录没有目录信息，无法追溯证明其原目录。

新增窗口恢复容器：等待路由和工作区加载；读取失败显示错误、重试和关闭入口；任务删除、标签已回主区或记录失效时关闭恢复窗口。后台任务的已保存网页、终端和审查可独立按需加载，不修改主窗口选择、项目、输入焦点及面板布局。

常规标签恢复与分离窗口共用资源创建逻辑，后续访问原任务时复用现有实例，避免重复启动终端。终端恢复只启动新 shell，不重放历史命令。沿用系统窗口恢复策略，没有新增强制恢复配置。

2. 同目录重新启动后，主窗口仍为 B，草稿保留。没有访问 A，最小化主窗口即可看到系统恢复的 A 审查：`review-a` 分支、`A.swift`、已暂存范围均正确。刷新完成后差异仍正常。
