# 设置完整循环后的反向 Tab

2026-09-18。修复 [第 120 篇](120-settings-action-keyboard.md) 记录的完整循环错位。

## 原因与修复

返回入口、搜索框与滚动导航原来共享一个 SwiftUI 焦点分区。从表单绕回返回入口后，反向 Tab 会重新进入导航列表，而不是回到表单末项。将顶部入口和滚动导航各自设为独立焦点分区，保留右侧表单分区及原生搜索交接，避免整块侧栏保留错误的导航锚点。页面布局、状态所有权及实际操作没有改变。

## 原生验收

通过项目脚本在原工作区构建运行，日志 `.cache/settings-focus-regions-build.log`。以下均为实际键盘检查：

- 从“个人资料”导航开始 Tab 24 次：其余导航 → 显示名称 → 用户名 → 选择头像 → 保存资料卡 → 返回应用；随后 Shift-Tab 正确回到保存资料卡，继续反向经过选择头像、用户名和显示名称。
- 正向再经过所有资料字段和按钮，返回应用 → 搜索，未漏掉入口。
- 当前资料页搜索 `sleep` 后：搜索 → 单条结果 → 资料字段及按钮 → 返回；Shift-Tab 回到资料卡。Tab 聚焦结果不切换页面。
- 无搜索结果时：搜索 → 资料字段及按钮 → 返回；反向仍回到资料卡，没有陷入空侧栏。
- 无表单控件的“运行时”页：运行时导航 → 返回 → 搜索；返回上的 Shift-Tab 回到运行时导航。
- 搜索清空、方向键切页、Shift-Down 不切页和 Esc 返回原任务均通过。
- 原任务与待发送草稿保持不变，工作区可交互。

设置布局、交互、通用偏好、导航及文本编辑器共 48 项回归通过，日志 `.cache/settings-focus-regions-tests.log`；严格签名检查通过。以上原生焦点路径由实机验证，自动化测试不能替代这些路径的证据。
