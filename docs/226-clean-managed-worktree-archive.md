# 托管工作树归档与恢复：干净检出

2026-09-26。归档一个托管工作树任务后，ShipiOS 会在确认没有活动回合或任务窗口占用后检查 Git 状态。若检出没有已跟踪修改、未跟踪文件或忽略文件，先在共享仓库中保护当前 HEAD 并持久化恢复提交，再由 `git worktree remove` 移除该检出。设置中的任务恢复操作会在原路径重建同一工作树，然后取消归档并清理保护引用。工作树中后来创建的提交同样由受保护的 HEAD 恢复；应用重启后流程仍可继续。

置顶任务和有任何未提交或忽略文件的工作树会保留整个目录，不做自动删除。Git 登记与目录不一致、路径被替换、仍有任务窗口使用、持久化失败或 Git 拒绝移除时也保留目录并显示状态。当前尚未实现**脏工作树的快照、删除与恢复**，所以这只是归档清理的第一阶段；删除归档任务时的托管目录清理、工作树数量限制和 Handoff 也待接入。

18 项 `WorktreeTests` 和 29 项归档、工作区记录、通知与项目导航回归通过，覆盖干净检出删除、含三类未保存文件及置顶任务时保留、保存失败不删除、重启恢复最新提交以及保护引用清理。原生 App 构建通过；Mac 锁屏时没有实际点击归档/恢复或与 Codex Mac 配对，不能计入完整 UI 验收。
