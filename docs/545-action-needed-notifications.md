# 等待批准与回答的独立通知

本机 Codex 安装包的 `notifications-settings-2d872075e9ec.js` 在任务结束提醒之外提供“需要权限时提醒”和“需要回答才能继续时提醒”两个独立开关，默认开启。ShipiOS 原来的“需要通知时询问系统权限”只管理 macOS 通知授权提示，不能替代这两个任务事件。本阶段保留该系统授权选项并将其移入“系统权限”区，新增两项真实事件提醒。

工具/MCP/Codex Core 审批进入等待状态时可发送批准通知；阻塞的 Codex 问题、MCP 表单及技能依赖提问可发送回答通知。自动化的无人值守拒绝路径不会发出等待用户操作的通知。两类通知按事件 ID 与任务/数据目录隔离，点击后沿用现有任务与运行轮次导航；偏好独立于“任务结束”的时机选择。旧通知配置没有这两个字段时默认开启；系统通知权限仍由 macOS 控制，未授权时不发布通知，也不会因新增开关擅自请求授权。

通知、审批、提问、MCP 表单和技能依赖等 57 项相关测试通过；注入式投递验证审批确实触发提醒，通知页离屏渲染确认两项开关及系统权限分组。非 `.app` 测试宿主会安全返回通知不可用，不调用会使 `xctest` 抛异常的系统通知中心。`script/build_and_run.sh --build-app` 正式构建及严格签名通过。前台通知横幅、点击导航、焦点与 Codex 双端交互还需在解锁 Mac 后实测；完整双端配对保持 **0/47**。
