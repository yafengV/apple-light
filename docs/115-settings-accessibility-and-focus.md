# 设置页面辅助功能与原生输入焦点

2026-09-18。接续启动恢复修复后的原生检查，设置继续使用主窗口 `ID: main`。

## 修复

- 为保留的工作区和各设置页建立明确的辅助功能容器，再应用可见性。此前透明、禁用的隐藏页仍暴露全部控件；现在只暴露当前设置页，保留原有页面实例和滚动状态。
- 非当前导航项显式移除“已选中”特征，修正“代码审查”在其他页面也被标为选中的情况。
- 主窗口键盘桥接移到工作区隐藏层之外，处理页面级裸 Esc。继续保护文本编辑、输入法组合、快捷键录制、确认弹层和 sheet；事件只作用于所属当前窗口。
- 原生任务输入框遵守 SwiftUI 的禁用状态，禁用时不能成为第一响应者、输入或粘贴。迟到的聚焦请求检查最新启用状态、请求身份、所属窗口和弹层；卸载后取消效力。
- 点击设置导航后，把原生编辑焦点明确交给窗口内容视图，避免 AppKit 再次回到搜索编辑器。

## 对照与诊断证据

重新读取本机 Codex 公开资源 `settings-page-1f095c82376f.js`：搜索 Esc 清空查询，页面级 Esc 排除编辑输入和对话框。因此“空搜索 Esc 仍留在设置”保留；不能把所有 Esc 都改成返回应用。

临时统一日志确认了两个实际焦点问题：隐藏的 `ComposerNativeTextView` 重新成为第一响应者；仅清空第一响应者后，搜索框的 `NSTextView` 又接管输入。日志只记录类型和布尔状态，未记录输入内容；诊断代码已移除。
