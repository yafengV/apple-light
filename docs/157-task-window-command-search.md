# 独立任务窗口命令菜单与任务搜索

2026-09-19。

## 问题与范围

此前独立窗口仅接管任务操作和文件搜索，`palette`、`palette-alternate`、`search` 会落到主窗口的 WorkspaceStore。结果是独立窗口按 ⌘K 时，后台主窗口出现菜单，后续命令可能作用于主窗口选中的另一任务。

本轮沿用第 149—153 篇依据公开静态资源建立的搜索组件、分组、排序和键盘规则，将其接入独立窗口。公开资源 `yAo/qwo` 可确认共用命令与任务结果、模式状态和分组键盘行为；本轮没有新增对 Codex 独立窗口的原生配对观察，因此不能将下面的隔离修复表述为该窗口已完全对齐。

## 实现

- ⌘K、⌘⇧P、可配置的任务搜索快捷键由当前任务窗口接管，加载/其他弹层期间禁用，不再回退到主窗口。
- 命令菜单与任务搜索共用原有视图，通过显式窗口上下文提供可用状态、执行、任务导航和关闭动作。主窗口默认行为保持原路径。
- 最近任务排除当前独立窗口的任务；搜索结果在同一独立窗口导航并进入其返回/前进历史，主窗口任务和项目选择不变。结果执行前再次验证模式、可用状态和任务存在性。
- 命令、任务、文件搜索共用互斥状态；菜单到任务/文件搜索的切换保留进入搜索前的焦点。独立窗口没有自己的浏览器标签时，不混入后台主窗口的浏览器结果或执行其浏览器命令。
- 置顶、重命名、查找、模型、分叉、文件和终端等已有任务命令使用窗口自身状态。设置、快捷键设置及项目等全局页面沿用主窗口路由；独立窗口尚未实现的命令保持不可用。
- 取消搜索恢复原草稿、查找栏或文件预览焦点；打开文件优先聚焦新文件。需要新焦点的命令和任务切换不会被旧输入框抢回焦点。

## 验证

- 39 项 Swift 相关测试通过，日志 `.cache/task-window-search-tests.log`。新增快捷键所有权及自定义绑定、窗口上下文执行、模式切换后的过期动作、消失任务、后台任务/草稿/菜单隔离测试。
- 项目脚本构建并运行原生 macOS 应用，在隔离数据根目录中保持主窗口任务 A、独立窗口任务 B。⌘K 和备用快捷键均在 B 打开菜单；菜单置顶只改变 B，A 仍未置顶。
- 菜单切换任务搜索，输入 A 并按 Ctrl+1 后，独立窗口导航到 A；⌘[ 返回 B，双方草稿完整。
- 首次原生验收发现菜单切换文件搜索后 Esc 丢失草稿焦点。修复为恢复 Composer 的绑定状态与 focus request；重新构建后原生复验通过。
- 从查找栏打开菜单后取消，焦点返回查找栏；文件搜索 `cpv` 返回 4 个候选，方向键和回车打开 `Sources/CommandPaletteView.swift` 并聚焦正文；从正文打开菜单再取消后，焦点仍回到正文。
- 搜索不可用的“新建浏览器标签”并按回车，菜单保持打开，没有触发主窗口浏览器。选择“设置”后在主窗口内显示设置页，返回仍为任务 A，草稿“主窗口草稿 A 保留”未变。
- 最终恢复原工作区并检查原草稿；严格应用签名检查通过。测试数据、构建产物和缓存不提交。
