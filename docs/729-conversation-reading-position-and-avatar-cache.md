# 阅读历史位置与有限头像缓存

日期：2026-10-09。属于第 726 篇 R5 的回复跟随和阅读位置，以及通用内置头像资源。排查第 725 篇固定广泛回归的两项失败，保留原失败终态。

## 实现

主聊天、独立任务窗口和浮窗统一使用原生滚动观察器及阅读状态。读者向上查看历史时，新回复不将页面拉回最新位置；位于底部时继续跟随，主动点击“返回底部”恢复跟随。任务窗口原来的每次回复更新无条件滚到底部改为同一逻辑，加入返回底部及新内容提示，并让查找／历史定位暂停跟随、关闭查找后按当前位置决定是否恢复。

原生观察器合并同一周期的布局通知，在异步交付时读取实际当前位置；开始滚动时丢弃更早的待交付布局通知，结束通知也使用当前位置。新模型内容和子任务卡片进入之前，视图同步读取原生位置，避免尚未交付的通知让旧“跟随底部”状态覆盖读者的历史跳转。布局缩短或窗口增高造成的正常位置钳制仍保持跟随，不把它们误判为读者操作。

观察器继续在 AppKit 布局／更新之外发布 SwiftUI 状态。同步快照只提供弱引用及只读位置，拆除时清空引用、丢弃旧回调，并恢复原生通知开关；没有改成在原生布局中直接写 SwiftUI 状态。

内置头像目录固定只有 56 个矢量资源，改用主线程中的有限字典保留已解码对象，避免机会式缓存逐出后重复行得到另一对象。资源选择、原始 SVG、主题、尺寸和绘制规则不变。本次没有单独复现导致旧广泛回归头像对象身份失败的具体逐出条件，不能把某种内存压力场景当作已证明根因。
