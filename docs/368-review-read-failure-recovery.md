# 仓库读取失败与审查重试

## 已复现的交互差异

第 367 篇已将子目录审查接入所属仓库，但仓库被发现不意味着其索引和历史可读。真实临时仓库中，损坏 `.git/index` 后，`rev-parse --show-toplevel` 仍成功，而 `git status` 失败。原审查状态把失败当成没有仓库，丢弃实际错误并启用创建；之前的批量快照和差异参数仍残留。

`.cache/git-review-recovery-before.log` 的单项复现测试有五个断言失败，分别覆盖创建可用性、修改权限、错误、快照和差异参数。没有修改用户仓库或个人配置。

当前[官方审查文档](https://developers.openai.com/codex/app/review)区分已有仓库的审查和无仓库的创建入口。本阶段纠正 ShipiOS 错误状态，文档没有证明读取错误的精确文案、布局或焦点与当前 Codex 相同；仍需双端配对。

## 实现

仓库状态读取失败保存在独立的 `gitReadError` 中。Git 已验证的仓库根目录仍保留；发现阶段失败不会将旧根目录或不可信元数据当成有效仓库。状态命令非零退出不再被吞掉。

无仓库页面区分检查中、确实无仓库和读取失败。检查期间显示进度；读取失败显示实际错误和重试入口，不显示创建按钮或要求关闭只读以创建的提示。修复后的成功刷新清除读取错误、恢复原审查范围和操作；如果元数据实际被移除，经成功检查后才回到创建入口。

失败清除文件变更、历史选择列表、差异、批量快照、撤销确认及旧差异请求；提交和 PR 弹层关闭，说明生成停止。任务项目、文件预览和提交草稿保持不变。刷新使之前的差异请求失效，旧请求不能在读取失败之后恢复过期内容。

逐文件、批量和差异块修改受读取失败状态约束，提交/推送不可启动。已捕获的审查和仓库授权在实际写入前也重新检查读取失败，包括分支或 PR 预检查。已经启动的操作可能完成，不承诺回滚既有外部写入。故障修复后须先刷新，旧操作不能绕过仍然存在的错误状态。

主窗口、独立任务窗口及分离审查共用上述实现，各自刷新原项目。损坏的最近 `.git` 文件不会退回父仓库，也不会被初始化覆盖。应用不删除索引、锁文件或修复仓库元数据，测试中的损坏和恢复仅在一次性夹具内进行。
