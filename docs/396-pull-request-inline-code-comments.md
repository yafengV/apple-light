# PR Code 单行与范围评论

Code 页现接入新建代码评论：行号区点击、拖选、Shift 点击、键盘扩选，范围末行下方的原生评论编辑器、取消与评论提交、独立草稿和错误恢复。评论绑定所选 PR 的源/目标版本和文件差异，不因后台刷新而静默迁移到新代码。

## 交互与草稿

- 同一文件内点击行号创建单行评论；拖动和 Shift 点击选择范围。同侧反向选择整理为起止行，跨侧保留两侧及相同数字的跨侧范围。
- 行号控件处理方向键焦点、Shift 上下扩选、Shift 左右跨侧、Return/Space 创建评论、Escape 清除选择和辅助功能按压。桥接仅限行号区，正文仍使用可选择文本。窗口本地弱引用注册表在 SwiftUI 销毁控件时注销，避免窗口之间路由事件。
- 草稿出现在范围末行之后；并排布局中同一草稿只出现一次。编辑器复用中文输入法保护、增长高度、撤销/重做、`@` 候选和 Cmd+Enter 提交，提供文字取消与评论按钮。
- 草稿按文件、末行和代码侧去重；重复选择聚焦已有草稿，不覆盖正文或范围。已有线程使用原回复入口。不同 PR 内容实例保留各自草稿。
- 同一个内容标签切换概览/Code 保留草稿；提交成功移除对应草稿，其他草稿不受影响。提交中和结果未确认时原草稿不可编辑或取消，避免确认对象变化。
- 源提交、目标提交、分支、文件数、路径、二进制类型或文件差异变化均使原草稿失效；失效正文仍可编辑、复制和取消，提交被禁用。文件移除时仍在 Code 差异列表下方显示旧草稿及路径。版本变化清除行号选择，不能将旧 Shift 扩选用于新版本。提交时发现版本变化后，当前旧代码禁用新建/发送并显示刷新差异入口；同源提交的目标分支单独变化也可以强制重新读取，不被请求缓存阻止。
- 新评论对重命名和删除文件使用显示的 PR 差异路径与旧侧行号，路径拒绝绝对路径、上级穿越、NUL 和不存在文件；无代码行的二进制文件不启用新评论。

## 提交与恢复

与既有评论共用 PR 修改互斥、权限资格、操作错误作用域及跨窗口刷新。提交前重新读取账户/PR 身份、源/目标提交和文件差异，并在写入前再次核对代码版本和写入资格。

正文通过 0700 临时目录中的 0600 JSON 文件传递，CLI 参数不包含正文，操作结束清理文件。HTTP 明确拒绝保留可编辑草稿，用户可修改后重试；网络中断、5xx 或无有效回执时保留待确认操作。重新读取只查唯一匹配结果，不重复发送。

结果匹配根评论的作者、正文、当前/原始提交和对应完整范围，排除基线已有 ID 及多个匹配。过时线程使用原始提交及位置确认；字段按 [GitHub 审查评论对象](https://docs.github.com/en/graphql/reference/pulls#pullrequestreviewcomment) 读取。成功 REST 回执也严格检查 PR、作者、提交、范围及非回复身份；有效回执遇到评论读取故障仍确认已接受并提供刷新提示。REST 评论 ID 不是 GraphQL 线程 ID，因此不伪造用于回复/解决的线程。

Code 页新增结果未确认的重新读取入口和已接受但刷新失败的提示/刷新入口，同样适用于 Code 中既有线程的操作。
