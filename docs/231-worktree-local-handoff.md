# 工作树与本地检出的往返移交

2026-09-26。依据 [OpenAI 工作树说明](https://learn.chatgpt.com/docs/environments/git-worktrees)，同一任务应能从托管工作树移回本地，之后返回原关联工作树。现有“移交”入口按任务当前执行位置切换方向；工作树到本地时先确认两个检出没有已暂存、未暂存或未跟踪修改，工作树仍是 detached HEAD，且 `.worktreeinclude` 指定的本地文件在两边内容与权限相同。随后按 Git 设置中的分支前缀（默认 `codex/`）为任务保留独立 `shipios-<任务 ID>` 分支，在来源本地检出创建或切换该分支；只做快进更新，分叉时不重写历史。分支名先存入任务工作树记录，以便中断后按同一分支重试。

移交回工作树时复用原目录，若本地分支有新提交且工作树提交是其祖先，工作树通过 detached HEAD 前进到该提交。主窗口及独立任务窗口继续显示同一任务与此前回合。真实 Codex Core + 本地假服务测试覆盖本地 → 工作树 → 本地 → 原工作树 → 本地、各阶段命令执行目录、双向提交同步与会话连续性；真实 Git 测试覆盖脏检出拒绝和分叉拒绝。

2026-09-26 后续阶段：已暂存、未暂存、未跟踪及 `.worktreeinclude` 指定的忽略文件现可随任务双向移交。两边必须属于同一仓库并位于同一提交，目标已跟踪文件须干净；已有本地文件须与来源快照相同，否则拒绝覆盖。Git stash commit 和本地文件副本先进入受保护的私有快照，持久化移交阶段后才应用到目标；目标内容与暂存区均校验通过后，才清理来源并移动任务归属。中断后重启可从持久化阶段继续，来源在快照后又发生变化时会保留原改动供检查。工作树存在未提交修改而本地任务分支提交更靠前时仍会拒绝，以免未经确认地合并两种状态。

最终 33 项工作树测试和 69 项模型传输测试通过；Codex Core 会话测试确认脏改动移交后，原任务历史保留，下一轮命令在目标目录运行。`script/build_and_run.sh --build-app` 及签名校验通过。Mac 仍锁屏，未完成本轮原生点击和当前 Codex Mac 的逐项配对。

后续启动交互修正：工作区先完成普通加载，再在后台续接未完成的移交，并以通知显示进度、成功或待处理错误。恢复期间只限制关联检出的任务运行与其他 Handoff，其他项目仍可操作；失败不会让“正在恢复工作区”遮罩常驻，修正来源后可用“继续移交”重试。成功与失败后重试的真实 Git 测试，以及 12 项工作区恢复和页面导航回归已通过。原生窗口因 Mac 锁屏仍待检查。

这仍不是完整 Codex Handoff：远程主机迁移、并行多检出冲突处理和当前 Codex Mac 的原生页面/键鼠配对尚缺。本地分支被其他工作树占用时仍由 Git 拒绝。
