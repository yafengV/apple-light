# 项目附加目录与真实 Core 工具范围

## 对照与本阶段范围

本轮检索并实际打开[官方项目文档](https://learn.chatgpt.com/docs/projects?surface=app)。项目菜单的 Edit project 可添加多个文件夹；主目录承担默认工作目录、Git 及自动指令/技能发现，其他目录可用于文件读写。工作树替换主检出后仍保留附加目录。

本阶段接入项目名称和附加文件夹编辑、独立持久化，以及每轮真实 Codex Core 工具范围。主目录切换、跨目录文件树/搜索和多仓库选择/汇总仍待后续实现，不能将本阶段称为完整多目录项目对齐。

## 用户入口与数据

侧栏和项目列表共用「编辑项目…」菜单，在主窗口的 sheet 内编辑名称，使用本地文件夹选择器添加多个目录，并可逐条移除附加目录。取消不保存；移除只解除项目关联，不删除实际文件。主目录目前显示为主目录，尚无 Make primary 动作。

保存统一校验目录、标准化路径及符号链接，并按实际路径去重，保留嵌套目录的独立条目。名称和目录一次性保存，失败保留原配置及编辑内容供重试；编辑目标以请求 ID 固定，旧回调或期间发生的外部配置变化不能覆盖新状态。项目身份、任务、草稿、当前执行目录保持原有归属。

`projectAdditionalFolders` 缺省为空，旧工作区仍为单目录项目。托管及永久工作树在没有独立覆盖时继承来源项目的附加目录，主检出仍是工作树本身；显式空覆盖可解除继承。

## 实际运行范围

发送前重新验证附加目录，目录消失时先报错，不建立新回合或消耗草稿。运行请求记录本轮 `additional_folders`，模型上下文包含目录位置；插件和技能发现仍以任务主目录为基准。基础 Chat Completions 只获得目录上下文与其已有工具，不因此增加自主文件工具。

Codex 私有 IPC 的 `codex.thread.start.additionalFolders` 将目录交给独立 Agent，再由适配器设置显式 `Config.workspace_roots`。工作目录仍为主目录，原沙箱政策、网络策略与只读模式保持生效。计划/审查没有因为附加目录获得写权限。

附加目录变化在下一轮生效：传输身份包含目录列表，空闲线程在下一轮提交前关闭并从原 rollout 恢复，以新范围继续同一线程，保留历史。已经开始的回合使用其捕获的目录快照；不假称编辑能立即撤销正在执行的工具权限。新范围与旧范围都记录在各自回合中。

## 验证记录

新增项目配置回归覆盖旧数据、持久化、别名去重、嵌套目录、无效路径、原任务/草稿保护、移除保留文件、保存失败重试、旧编辑请求、外部变化及工作树继承。
