# 多组快捷键与上下文分发

2026-09-17。补齐设置中多组绑定及工作区快捷键行为；尚无当前用户版本 Codex 的完整页面配对证据。

## 依据与实现

[官方命令文档](https://learn.chatgpt.com/docs/reference/commands)列出前后聊天/标签的三组 macOS 组合，以及文件树、审查面板的切换和显式打开审查标签。[官方设置文档](https://learn.chatgpt.com/docs/reference/settings)说明按名称/按键搜索、修改和恢复快捷键。

- 前后任务/标签支持 Ctrl+Tab / Ctrl+Shift+Tab、Cmd+Shift+] / Cmd+Shift+[、Cmd+Option+Right / Cmd+Option+Left。
- 设置显示一个命令的全部绑定，可逐个修改、添加或通过录制期间 Delete 移除。命令菜单中的移除操作清空该命令全部绑定，恢复默认则恢复整组。
- 按键搜索检查全部绑定；冲突检测、默认恢复和新增默认的迁移保护也检查全部绑定。原有 JSON 数组结构保持兼容，保存和重启不再丢弃第二组绑定。每命令最多六组；非法组合和重复绑定不会写入。
- 新增默认不能抢占已有自定义组合，包括用户已有数组中的第二组或之后的绑定。写入失败和格式错误文件仍保持原有保护。
- 额外组合通过主窗口内事件分发；录制、全局弹层、模型/分支弹层及启动恢复期间不处理。上下文仍由当前实际焦点决定：聊天区域切任务，文件原生预览切文件，浏览器区域切网页标签。
- Cmd+Shift+E 切换文件树、Cmd+Option+B 切换审查面板；Ctrl+Shift+G 始终打开审查。实机中遇到文件树菜单可用但快捷键未执行，补充窗口内面板按键分发后复测显示/隐藏通过。
- “跳转到行或浏览器地址栏”作为同一可配置命令，文件预览与浏览器均使用全部绑定；不再在文件视图硬编码 Cmd+L。

## 原生验收

使用隔离数据 `/private/tmp/shipios-git-ui-t2l492o2/Data`，未访问外部模型服务。浏览器仅录入 `.invalid` 地址草稿，没有提交网络导航。

实际确认：

1. 按键搜索录制 Cmd+Shift+]，结果只有“下一个任务或标签”；录制期间没有离开设置。
2. 为搜索任务录制上述组合，显示已占用且不保存；改用 Cmd+Shift+L、Cmd+Option+Shift+L 后，同一命令显示两组。
3. 第二组合实际打开任务搜索，Esc 回到原设置；重启到 PID 55572 后，第二组合仍能打开搜索。
4. 修改第二组合时按 Delete，只移除第二组合，第一组合保留。
5. 在聊天输入区域，Cmd+Shift+] 从“长列表验收 00”切到 01，Cmd+Option+Left 返回 00。
6. 在项目文件预览，Cmd+Shift+[ 从 B 切到 A，Cmd+Option+Right 回 B；任务仍为“搜索验收 Alpha”。
7. 两个浏览器标签分别填写 first.invalid、second.invalid；备用组合在标签间切换并保留各自地址草稿。
8. 文件树连续 Cmd+Shift+E 显示/隐藏通过；Ctrl+Shift+G 打开审查，Cmd+Option+B 隐藏。
9. 给行定位/地址命令增加 Ctrl+Option+L：浏览器中选中地址文本，文件中打开并聚焦行号输入。
10. 恢复全部默认的取消操作保留两个自定义命令；再次确认恢复后按钮禁用，测试设置恢复为默认。

最终隔离构建 PID 56022，日志 `.cache/shortcut-alias-native.log`。UI 检查出现一次 Computer Use 上下文失活，重新获取应用后继续；未以该工具错误作为应用失败证据。
