## 实现

新增页面拥有的 `VoiceShortcutPresentation`，保存当前录制模式／独立录制身份、临时修饰键和三行独立错误；绑定仍在原 `VoicePreferences` 中持久化。实际页面录制器收到可提交输入后，先结束本次录制，再做现有验证／冲突检查。失败保留原绑定、不重新注册；按住与单击相同绑定时使用参考含义的“请为单击听写选择不同的快捷键”。既有本地验证规则保留，不声称它与参考完整解码／注册策略相同。

键盘、修饰键和 blur 回调同时核对模式与本次录制身份，拒绝已经结束或旧录制的输入，旧回调也不能取消同模式的新录制。重复 keyDown 不消费录制。错误移入所属行的说明区域，使用共享说明字号／行高和行内间距；重新录制仅清该行，离开页面／设置时清临时状态。系统注册层现有错误仍由原 store 提供，本篇没有假造异步服务成功或改动 Carbon 注册策略。

## 前台补验

Mac 解锁后，在正式开发签名包中通过 ⌘, 进入设置，窗口仍为 `main`；语音页高级默认折叠，展开后显示单击行。分别在单击听写与语音聊天录制器按已有命令 ⌘K，录制器均退出，原“关闭”值不变，两个错误同时显示在各自行内。再次录制单击行只清除该行错误，语音聊天错误仍保留；Escape 取消后，再按 ⌘K 能正常打开命令菜单，证明此路径未遗留快捷键录制拦截。

离开语音再返回时，错误清空、高级恢复折叠；搜索“单击听写快捷键”并选择结果会展开高级行。清空搜索并返回应用后，原 `AGENTS.md` 文件标签与内容仍在同一主窗口中。没有保存新快捷键、修改 API 配置或启动录音／语音服务。两行具有相同“关闭”名称和错误说明时，CUA 元素重新定位曾报多项匹配；刷新截图后通过实际行坐标完成重新录制，进一步确认独立、明确命名的编辑控件仍需后续实现。这些是 ShipiOS 自身的有限前台验收，不是 Codex 双端配对或完整 VoiceOver 验收。
