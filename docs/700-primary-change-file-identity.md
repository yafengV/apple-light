# 项目主目录变更后的文件身份与恢复

日期：2026-10-09。推进 M02 和 M14，补齐第 699 篇记录的旧草稿相对文件标签问题。原范围仍为 47 页入口、29 项核心功能，未将本阶段专项通过当作完整 UI 对齐。

## 已复现的问题

文件标签原先只有 owner 和相对路径。项目主目录由 A 改成 B 后，关联或普通草稿仍使用稳定项目 owner，但视图会以 B 重新打开 `same.txt`。已挂载的编辑器因此显示 B 的同名文件，旧编辑内容没有写回 A；关闭后的固定项也会恢复到 B。仅保持标签字符串不变无法证明仍是原文件。

此阶段根据真实临时项目及原生视图复现修复数据归属，沿用第 698／699 篇的布局、返回和迁移要求；未提取新的 Codex 私有存储格式，也未声称下面的 `fileRoot` 字段来自 Codex。

## 已实现与覆盖

| 动作／状态 | 实现与验证范围 |
| --- | --- |
| 已打开文件 | 标签记录打开时的根目录；主目录变化不重置原文件编辑器。普通及关联草稿的实际隐藏视图均保留原文本，保存只写入 A，不改 B 的同名文件 |
| 新目录同名文件 | 新打开仍使用新默认目录 B；与旧相对 ID 冲突时使用实际绝对路径作为新 ID。按实际 URL 复用已有文件，A 和 B 的同名文件能同时存在 |
| 固定文件 | 保存原根目录；关闭、主目录改变、工作区记录重载后仍能打开原文件。冷恢复后先打开 B 的同名文件，再打开旧固定项，两个标签保持不同身份 |
| 关闭后重开 | 保留关闭项原根目录；即使先打开 B 的同名文件，重开仍返回 A，并保留原位置规则 |
| 旧工作区格式 | `SavedWorkspaceTab.fileRoot` 与 `PinnedWorkspaceTab.fileRoot` 为可选字段。更改默认目录前给已有冷布局／固定项补齐旧根目录，保持已有相对 ID 与独立窗口路由 |
| 项目保存失败 | 先准备候选记录，磁盘保存成功后才应用运行时根目录缓存；失败保留项目配置、布局和固定项原记录 |
| 独立内容窗口 | 冷布局校验与 materialize 使用保存根目录；真实 helper 切换默认目录、关闭并恢复后，同一路由仍能加载 A 的实际内容 |
| 旧文件树继续打开 | 主窗口与分离内容窗口的回调传入来源标签根目录；即使 A 已从当前默认文件夹配置移除，来源树打开另一文件仍对应 A |
| 跨任务迁移 | 源文件按保留根目录解析实际 URL，再校验目标根目录及关联文件夹；迁移后的固定项路径与根目录一起更新 |
| 迁移去重 | 目标使用旧相对 ID 或尚未访问的冷布局时，仍按实际 URL 拒绝重复迁入，不移除源标签 |
| 无效保存根目录 | 拒绝相对目录及 NUL，文件／固定项恢复失败时不回落到新目录同名文件 |

运行时缓存只保存根目录，不保存凭证、文件内容或 shell 输出。旧根目录固定的是已经打开的文件上下文；当前附加文件夹仍使用既有校验，未新增系统权限或修改 TCC。没有将所有跨窗口资源身份与权限生命周期描述为已完成。
