# 浏览器下载与保存位置

浏览器点击目标右键菜单的后续实现与验证见 [第 74 篇](74-browser-context-menu.md)。

2026-09-17。内置浏览器现已接入真实 `WKDownload`，并按 [OpenAI 浏览器文档](https://learn.chatgpt.com/docs/browser)补齐默认下载目录、自定义目录、“每次下载时询问保存位置”、下载状态和下载记录。设置继续作为 `ID: main` 主窗口内的页面存在，没有增加 `Settings` Scene 或独立设置窗口。

浏览器把带 `Content-Disposition: attachment` 或 WebKit 无法直接显示的响应明确转换为下载。每个下载由独立 UUID 跟踪准备、下载、完成、失败和取消状态；进度只更新内存中的视图状态，关键状态写入 ShipiOS 独立 `workspace.json`。WebKit 在导航转换为下载时产生的 code 102 正常中断不会显示成页面错误。

默认位置是系统 Downloads。用户可在“设置 → 浏览器 → 下载”选择其他可写目录、恢复系统默认，或开启每次询问。自动保存会清理路径字符并拒绝目录穿越；目标已存在时依次生成 `name 2.ext`、`name 3.ext`，不覆盖旧文件。询问模式使用附着在主窗口上的 `NSSavePanel`。下载列表显示最终文件名、进度、状态、大小和错误，可取消活动下载、打开文件或在 Finder 中显示。清除记录只移除元数据，不删除下载文件。

旧 `workspace.json` 自动迁移为空下载偏好和空记录。下载记录、最终路径与大小跨应用重启恢复；临时 WebKit Cookie 和网站存储仍维持既有的单次运行隔离策略。关闭拥有活动下载的标签会取消该下载，退出应用会关闭所有标签并取消剩余下载。

22 项浏览器定向测试使用真实 `WKWebView` 和回环 HTTP fixture，覆盖附件响应转换、精确文件内容、重复下载递增命名、活动下载取消、页面无伪错误、目录偏好持久化、旧数据迁移和清除记录不删文件，并重跑既有标签、历史、评论与截图行为。完整回归为 362 项 Swift、12 项 Rust、fmt/Clippy 和真实 IPC 冒烟全部通过，日志 `.cache/browser-downloads-full-tests.log`。

原生隔离实例在 `ID: main` 主窗口打开“设置 → 浏览器 → 下载”，选择仓库内隔离目录后访问回环页面。点击 Download 后面板显示 `fixture.txt / 已完成 / 25 bytes`，磁盘内容为 `shipios browser download\n`；完整重启后记录仍在。修复下载转换错误后再次点击，页面不再出现 `Frame load interrupted`，重复下载显示最终文件名 `fixture 4.txt`。开启“每次下载时询问”后，保存 sheet 附着在同一个主窗口，显示来源、目录与建议文件名；取消后记录明确变为“已取消”。原生过程没有使用 iOS Simulator，也没有向用户系统 Downloads 写测试文件。

验收后以原数据目录重启为 PID 94287。主窗口仍选中“验证新输入框的真实构建”，草稿“这是一条待发送草稿，重跑后应保留”保持不变；设置继续在同一个 `ID: main` 窗口呈现，Esc 返回原任务。

当前仍未实现持久浏览器资料、密码与自动填充、模型主动控制浏览器、站点授权弹窗、页面样式调整预览、完整 CDP，以及整页截图。Codex 本体无法由当前 CUA 工具读取，因此视觉尺寸、动画、焦点顺序和所有下载边界仍没有完成两侧实机配对。
