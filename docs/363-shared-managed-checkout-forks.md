# 同一托管工作树内的会话分叉

日期：2026-09-28。继续补齐普通侧栏、Activity、会话菜单及独立任务窗口中的「分叉到相同工作树」。旧本机 Codex 静态客户端的普通分叉向原生线程分叉传入来源 cwd；本阶段以此作为实现参考，不将旧静态代码当作当前版本的原生配对证据。

## 实现

已完成创建的托管任务可在同一检出分叉已结束的历史前缀，无需再创建工作树。分叉拥有独立任务、草稿、运行记录和 Core 子线程，实际执行目录保持相同；来源任务可以继续运行。创建、移交、清理或待恢复快照期间不允许普通分叉。新任务和共享关系在同一次工作区保存中提交，写入失败不发布任务或成员关系，也不消耗来源命令。

一个物理工作树保留一条托管记录。`taskID` 继续作为 Git 保护引用和私有文件快照的稳定键，新增 `sharedTaskIDs` 记录同目录分叉；旧记录默认只有原创建任务。来源任务删除后，不改写快照键，其他任务仍能查找原记录、在来源项目下展示并继续分叉。

普通归档仅在所有关联任务归档且无运行、置顶或任务窗口占用时清理；数量限制按物理检出计数，以所有关联任务的最近更新时间排序，并保护任一关联任务的运行、置顶或窗口。恢复任一任务共用同一快照，包括暂存、未暂存、未跟踪及忽略文件。最后一个任务删除才释放保护引用和私有快照；有效检出沿用原有规则转为永久项目，仍有共享任务时继续保持托管。

本地/工作树往返移交支持共享子任务。移交前检查两边任务均没有运行，避免清空仍被其他任务修改的目录。中断后的移交按 `HandoffGitSnapshot.taskID` 恢复真正移动的任务，保留工作树稳定身份；只为该任务显示继续移交入口，其他关联任务不能接管其恢复。

## 验证与发现

新测试使用真实 Git 检出、真实 Agent 和本机模型夹具。共享工作树测试覆盖嵌套分叉、来源运行及草稿保持、原子保存失败、来源删除与重启、暂存/未暂存及本地文件快照、最终成员清理、任意成员置顶/运行保护、双向移交、按子任务恢复中断移交、清理期间的删除与导航保护，以及主窗口入口与旧记录解码。

真实 Core 新增用例验证同目录工具历史、独立子线程、来源任务归档后的目录保留、重启后原子线程恢复、最后任务归档清理及重建后继续在原目录执行命令。

该用例发现归档当前任务的异步项目导航与清理存在竞态：清理遇到导航忙状态直接退出，目录未清理，随后恢复打开仍遇到未结束的导航。修复在清理前等待正在进行的项目准备结束，再重新检查共享任务资格；快照和移除阶段保留操作状态，防止删除或新窗口打开插入其中。失败证据 `.cache/shared-worktree-fork-native.log`；修复后的单项真实 Core 验证通过，`.cache/shared-worktree-fork-native-final.log`。

最终验证：

- 109 项工作树、共享分叉、归档、搜索、窗口及真实 Core 相关测试通过，`.cache/shared-worktree-fork-regressions.log`。包含 41 项既有工作树测试、10 项共享检出测试、7 项新检出分叉测试及 5 项真实 Core 用例。
- 另有 34 项删除、实际停止、任务菜单和窗口/项目导航回归通过，`.cache/shared-worktree-fork-actions.log`；两组没有重复用例，共 143 项不同测试通过。
- `./script/build_and_run.sh --build-app` 通过，`.cache/shared-worktree-fork-app-build.log`；`codesign --verify --deep --strict dist/ShipiOS.app` 与 `git diff --check` 通过。没有修改 Rust runtime，本阶段以真实 Agent/Core 集成用例验证交互。

上述构建及测试不包含原生鼠标、菜单、焦点、实际多窗口及当前 Codex 双端页面验收；既有首次模型响应偶发超时未在本阶段解决，完整配对保持 0/45。
