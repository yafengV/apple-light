# PR 监控与自动修复基础闭环

本篇记录基础阶段；保留分叉任务、连续轮次、提示刷新及来源未提交修改隔离的后续修正见[第 575 篇](575-pull-request-watch-retained-fork.md)。

Codex 当前公开分发代码中的 “Watch and fix PR” 会创建附着于独立任务的 10 分钟 heartbeat；它读取 PR、检查失败与冲突，在需要修改时使用隔离工作树。未开启自动合并时，PR 检查通过且无冲突会暂停；开启后继续至合并或关闭。自定义指令可以改变默认处理，不能绕过权限与安全限制。

ShipiOS 现在从 PR 摘要页启动、查看进度和暂停监控。Git 设置包含“准备好时自动合并”和独立的 PR 监控指令。监控以 PR URL 去重，保存 10 分钟日程，启动时立即运行一次；每轮先重新读取远端 PR，合并或关闭后停用，未启用自动合并且 PR 已通过检查、可合并、非草稿且没有额外指令时也停用。读取失败延后重试。每轮根据最新设置刷新提示，并限制到 Git 隔离工作树；工作树不可用时不会退回当前检出目录运行。

当前实现使用 ShipiOS 本地自动化任务，不是 Codex 附着于 fork 线程的 heartbeat。日程依赖 ShipiOS 进程运行；没有实现后台常驻服务，也尚未实测真实 GitHub PR 的拉取、修复、推送和合并闭环。准备阶段会创建隔离工作树，早于参考端“只有需要改代码才创建”的时机。自动暂停只对 GitHub 返回明确可合并且检查集合已读取的情况做保守判断；额外指令存在时交给任务判断。API 服务和 GitHub 凭据仍需用户在应用中配置。

定向测试验证创建与去重、偏好持久化、暂停恢复、关闭与绿色 PR 自动停止、读取失败重试及工作树不可用时不执行。自动化、PR 检查与合并、设置导航等相关回归 **109 项通过**；`script/build_and_run.sh --build-app` 构建和严格深度签名通过。桌面控制接口超时，未取得新包前台可交互工作区或双端逐页证据；完整配对仍为 **0/47**（主工作区 21 项、设置 26 项）。
