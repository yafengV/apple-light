# 文件选区审阅进入文本布局

选区操作和修改要求仍在选区旁显示。模型返回建议后，编辑器改为在选区结束行后预留空间，把原文、建议替换及“拒绝 / 编辑 / 接受”控件放在代码行之间；返回修改要求或关闭时移除这块空间。空间由 TextKit 布局管理器提供，不向文件文本插入占位符。原生文本编辑、选区、草稿、接受前一致性检查及撤销继续使用原有路径。

隐藏原生窗口测试确认审阅控件落在留出的行间空间、后续代码行下移、原文不变、关闭后行距恢复。文件选区、文件工作区及原生文本视图相关 30 项测试通过；语法高亮/WebKit 相关 20 项在正常 macOS 权限下通过，受限会话中相同测试因 WebKit 取消而失败。正式 macOS 应用构建和严格深度签名通过。`script/build_and_run.sh --verify` 完成构建与签名后，受当前受限会话的 Launch Services 影响，`open` 返回 `kLSNoExecutableErr`；提升启动权限后进程出现，但前台工具报告 Mac 已锁定，无法确认工作区可交互，也无法进行 Codex / ShipiOS 双端视觉、焦点及滚动对照。

审阅块尺寸、颜色、选区高亮、滚动到审阅块、键盘焦点与当前 Codex 的细节仍待真实前台配对。完整双端验收仍为 **0/45**。
