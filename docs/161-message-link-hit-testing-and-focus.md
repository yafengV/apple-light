# 可选择回复的链接命中与后台打开焦点

2026-09-19。

## 问题与修复

第 160 篇原生验收发现中键点击回复链接没有反应。进一步检查确认，在回复实际使用的 `.textSelection(.enabled)` 环境里，SwiftUI 没有执行链接测量所依赖的 `TextRenderer`，导致透明点击层的链接区域为空。右键也因此落到系统默认文字菜单。此前离屏测试没有启用文字选择，未覆盖实际呈现条件。

- 可见文字继续使用原生选择和链接语义；在其背景放置相同样式、不可选择的文字测量副本。测量 renderer 只计算字形区域，不绘制内容；副本不参与点击或辅助功能。链接命中和查找匹配位置因此都能在可选择正文中生成。
- 浏览器面板显式指定标签时，挂载不再主动选中或聚焦该标签。面板选择由布局拥有者响应用户动作完成，后台打开不会因为视图出现而变成前台打开。
- 输入框原先只通过开始/结束编辑通知同步焦点；点击已有草稿但没有打字时，焦点绑定仍为 false，无关视图更新会清除原生光标。现在同步真实 first-responder 变化，并把绑定写入延后到当前更新结束。回调读取最新响应者，避免快速切换重放旧状态；只有显式焦点状态变化才执行失焦，禁用保护仍保留。

## 自动化证据

三处问题均先由回归复现，再验证修复：

1. 可选择文字的渲染测试得到空链接区域；修复后在 240/420 点宽度均能测量独立链接、跨行区域和精确查找锚点，所有命中区域都位于点击层内部。
2. 真实 `NSHostingView` 挂载后台浏览器，原实现会发布 selection 并改变焦点请求；修复后，无当前选择及已有其他选择两种情况均不产生隐式激活。
3. 原生编辑器获得 first responder 但尚未打字时，原实现不更新绑定且视图刷新丢失焦点。修复后保持草稿和选区，快速进出焦点采用最后状态，显式失焦仍有效。

103 项输入框、链接、菜单、兼容文字、查找、浏览器及任务标签相关测试通过，日志 `.cache/message-pointer-composer-final-tests.log`。随后补充快速焦点切换及精确查找锚点断言，两个专项各 5 项再次通过，日志 `.cache/composer-focus-transitions-tests.log` 和 `.cache/message-pointer-anchor-tests.log`。这些专项包含在前述测试范围内，不累加为不同测试数量。
