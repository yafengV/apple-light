# 桌面交互对齐与验收

日期：2026-09-16。响应“UI 交互上至少要对齐 Codex mac app”的实现。本轮将原来的表单式工作台改成以任务为中心的原生桌面布局，延续已经确认的本地功能范围。

**验收含义修正：**本页验证的是 ShipiOS 已实现功能，不证明与 Codex 完全一致。后续逐项检查发现命令菜单、归档入口、设置、输入和开发面板等明显差距，见 [逐页交互差异审计](11-codex-ui-parity-audit.md)。

## 参考与范围

布局参考 OpenAI 的 [Codex app 官方介绍](https://openai.com/index/introducing-the-codex-app/) 中展示的项目与任务组织方式。当前环境的 UI 工具禁止读取 Codex 应用自身，因此未对用户安装的版本做像素级比对；不声称复刻其完整功能。

实现保持 SwiftUI + 少量 AppKit、独立 Rust Agent。中央会话显示用户填写的任务说明和真实执行结果，不生成虚构的模型答复。模型、代码编辑、Diff 审查、终端面板和 worktree 尚未接入。

## 已实现的交互

| 区域 | 行为 |
| --- | --- |
| 左侧栏 | 新任务、搜索、归档入口；置顶分组、当前项目的任务、最近项目；连接状态和设置入口 |
| 任务组织 | 右键重命名、置顶/取消置顶、归档/恢复；活跃任务禁止归档；归档保留运行记录 |
| 中央会话 | 多次执行归入同一任务；用户说明气泡、执行状态、可展开工具卡、结果摘要、复制/重跑/日志/诊断 |
| 空状态 | 项目名称、环境检查和构建建议，点击后填写输入区；无项目时提供打开与示例入口 |
| 输入框 | 多行输入、模式菜单、构建配置弹层、发送/停止；按任务保存草稿；重跑不会清空未发送草稿 |
| 本地指令 | `/doctor` 和 `/build`；普通文字为当前操作的说明；不支持的斜杠命令显示错误并保留输入 |
| 右侧详情 | 可显示/隐藏；诊断、标准输出/错误日志、产物、报告导出；窄窗口按可用宽度分配空间 |
| 搜索 | 按任务名称和说明检索当前项目，包括归档；方向键选择、回车打开、Esc 关闭 |
| 设置 | 跟随系统/浅色/深色、运行时状态与目录、快捷键说明 |

主要快捷键：`⌘N` 新任务、`⌘K` 搜索、`⌘O` 打开项目、`⌘↵` 执行、`⌘.` 停止、`⌘B` 切换侧栏、`⌘⇧I` 切换详情、`⌘,` 设置。换行保留给多行任务说明。

构建参数按项目保存。任务标题、置顶、归档、运行归组、说明与草稿存入 `<Desktop 数据根目录>/workspace.json`，原子写入并设置 0600 权限。旧执行历史首次加载时导入为任务；已有记录不会重复导入。损坏的工作区文件报告错误，不静默覆盖。Agent 数据库与原始产物继续保存真实执行证据。

## 当前边界

完成的是本地工作流对应的桌面交互。尚无模型会话、自动改代码、代码 Diff、实时逐行日志、任务队列或并行执行。每个项目一次执行一个操作；构建仍固定为 iOS Simulator SDK，Scheme 手动填写。任务搜索范围为当前项目，右面板宽度自动适配，暂不提供独立拖拽调宽。

后续接入 Codex Runtime 时，可保留任务侧栏和会话布局，将执行卡扩展为模型工具调用与审查记录；不能把本轮 UI 完成视为完整 AI 产品完成。
