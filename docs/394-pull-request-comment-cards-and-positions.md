## 页面与交互

- 根评论头像和作者区域可切换整张卡片；日期点击沿用头部折叠，菜单和外部链接使用各自操作。头部显示作者、已解决状态、非空回复数与相对时间；GitHub 链接和折叠箭头在悬停/控件焦点时显现，减少动态效果偏好关闭箭头旋转动画。作者控制与折叠文件名支持 Return，原生按钮保留 Space 激活。
- 同一线程的回复在原卡片内按顺序呈现各自头像、作者、日期、正文和编辑/删除菜单。回复不再各自套一张完整折叠评论卡片；空白回复不进入列表或回复数，原数据仍留在快照、结果确认和修复上下文中。
- Option 切换由被操作卡片的目标状态决定，应用于当前 Activity 页全部评论/审查/线程，提交组和事件保持自身行为。其他 PR 标签或窗口的折叠状态独立；普通后台内容更新保留手动折叠，条目移除清理状态。机器人/用户类型或解决状态改变时按新默认值重置。
- 编辑根评论或任何回复时，即使编辑内容为空也不能收起。非空回复（包括仅空白）也阻止收起；空回复可收起而保留草稿。批量收起跳过受保护卡片；从受保护卡片发起收起不会隐藏其他卡片。编辑/引用明确展开原卡片，解决状态变化也不能隐藏编辑器。
- 活跃修复附件、编辑或回复时隐藏新的评论菜单及回复/解决入口，原编辑器继续显示。Fix/说明和线程操作位于展开卡片的底部，折叠时隐藏；Activity 的整体 Fix/Remove 入口仍可处理所有有效附件。失败错误和原草稿继续由现有独立作用域管理，没有任何可用操作的根评论或回复不显示空菜单。
- 文件位置显示 basename 和完整路径帮助文字，折叠状态下点击文件名展开。展开后代码上下文按统一差异显示旧/新行号，沿用差异标记偏好，并按原始位置突出选中范围。进入完整 Code 页的文件跳转仍缺。
- 展示和引用去除正文首尾空白，编辑仍使用原始正文。审批/要求修改已由活动事件呈现，普通评论头部沿用作者与状态/回复元数据布局。

## 位置与修复附件

`line → originalLine → startLine → originalStartLine` 决定位置末行。当前行缺失而原始行存在时，范围起点优先原始起始行，再使用当前起始行；其他情况优先当前起始行。范围缺失时使用末行。L/R 代码侧和跨侧起点保留；仅单行时省略冗余起始字段。

保留原始线程的当前行、原始行、起始行、差异代码侧和全部评论，同时为 UI 与修复请求提供归一化 `position`。当前行号已失效但原位置有效的未解决线程仍可附加 Fix；没有位置、代码侧、非空正文，或位置/路径无效的线程继续禁用。原始 hunk 的选中行使用 `originalLine/originalStartLine`，避免当前文件移动后高亮错误的行。

修复正文拼接有效的去空白评论和回复；未知作者不生成虚假的 `@` 提及。原始评论快照不被过滤。归一化位置进入持久化、队列及两种协议的模型上下文；旧记录没有 `position` 时从原线程重新计算，外部修改保存的派生位置不能覆盖线程来源。
