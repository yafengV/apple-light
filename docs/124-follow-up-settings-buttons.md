# 追加消息选项的按钮组交互

2026-09-18。接续 [设置菜单接入范围](123-settings-menu-coverage.md)，修正通用设置中追加消息控件的顺序和键盘模型。

## 参考与实现

本机 Codex 26.908.70816 的公开 `general-settings` 资源将追加消息选项依次设置为 queue、steer。其 `segmented-toggle` 实现使用带 `aria-pressed` 的独立按钮和 group 容器，没有单选组的方向键选值逻辑。

ShipiOS 原来使用 SwiftUI segmented Picker，顺序为引导、排队。现改为 `SettingsSegmentedPicker`：等待下一轮在前，引导当前运行在后；每个按钮分别参与 Tab，空格或 Enter 执行选择，焦点移动不提交选择。选中态和键盘焦点分别呈现，辅助功能暴露选中按钮及组名。点击区域包含内边距；禁用后取消焦点及悬停状态。重复激活当前选项不重复写入绑定。

原偏好值、保存路径和运行中的消息处理逻辑没有变化。其他设置分段控件尚未迁移；不能假设所有页面共用同一种参考交互。
