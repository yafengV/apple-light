# 图片附件与会话上下文

2026-09-17。输入区此前只有文本，无法把 UI 截图等视觉资料真正发送给模型。本轮增加图片附件的数据、输入控件和会话流程。

依据：[Codex 桌面图片输入](https://learn.chatgpt.com/docs/image-inputs) 明确支持将图片拖入输入区作为上下文；[OpenAI 官方 Chat Completions 类型定义](https://github.com/openai/openai-python/blob/main/src/openai/types/chat/chat_completion_content_part_image_param.py) 规定 `image_url` 内容块及 URL/base64 图片数据。官方桌面文档并不证明当前版本预览弹层的尺寸、按钮和布局，相关外观仍待配对。

## 已实现

- 输入区添加图片按钮、文件选择器、本机图片 URL 拖入和图片粘贴处理。
- 草稿中的缩略图、文件名、移除按钮；点击缩略图打开主窗口所属的图片预览弹层，关闭后恢复输入焦点。
- 历史回合展示其图片；图片请求失败后附件仍保留，可重试。
- 支持仅图片消息与文字加图片消息。服务不支持视觉输入时显示实际请求错误，模型设置页说明需要服务与模型支持图片输入。
- 队列记录附件；编辑队列会一起移回文字和图片；排队、启动请求、保存历史之间的转换先保存成功再更新界面。
- 分叉复制历史图片引用，后续请求包含对应历史图片，不复制未发送草稿中的附件。
- 图片按草稿键归属；异步导入和粘贴捕获原草稿键，切换任务后不会将图片错误附到新任务。
- 普通文本请求继续使用原来的字符串 `content`；带图用户消息使用 `text` 和 `image_url` 内容数组，图片字节编码为 data URL。请求不使用本机文件路径作为图片 URL。

## 存储与边界

图片复制到独立数据目录下 `Attachments/<UUID>.<扩展名>`，不依赖原图之后仍存在。元数据包括名称、MIME、字节数和 SHA-256；发送和预览会检查文件内容与记录是否相符。目录权限为 0700，新文件为 0600。

当前支持 PNG、JPEG、WebP、静态 GIF。macOS 粘贴常用的 TIFF 转为 PNG，并处理图片方向。每条消息最多 8 张，每张不超过 10 MiB、4000 万像素，单次请求的全部历史图片原始字节合计最多 32 MiB。这些是 ShipiOS 当前实现的资源边界，不是声称与 Codex 或所有兼容 API 的限制一致。

`draftImages`、`runImages` 和队列的 `images` 字段可兼容缺少附件字段的旧工作区。草稿或队列移除最后一个引用时清理私有副本；历史和分叉仍有引用的图片不会被删除。导入批次或保存失败时回滚本批次新文件。

原图不会被修改；选图与预览不发送请求，用户发送消息时才向所配置的 API 服务发送图片。未读取个人 Codex 配置或认证，测试未使用用户 API Key。

## 验证

新增 10 项附件测试、2 项实际 HTTP 流式测试，覆盖：

- 原图删除后私有副本仍可读、权限、缩略图、内容损坏和符号链接拒绝；
- 请求含真实图片字节、文本/图片内容块且没有本机路径；
- 旧工作区/旧队列解码；
- 草稿归属、恢复、导入失败回滚、保存失败保留草稿；
- 队列编辑、分叉和删除最后一个引用的清理；
- 构造的 `NSItemProvider` 图片粘贴流程，未读取用户剪贴板；
- TIFF 图片转换；
- 仅图片首条消息、带图队列自动续发，以及实际 HTTP 中完整图片历史；
- 服务返回 HTTP 401 后保留图片并重试。
