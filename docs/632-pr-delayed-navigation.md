## 复现与修复

新增实际 NSWindow/NSScrollView/NSView 专项，不依赖模型固定回答：

| 场景 | 原行为及本阶段处理 |
| --- | --- |
| 目标 300 毫秒后才取得尺寸 | 旧 200 毫秒重试窗口已结束，目标始终不进入视口；现最多 200 次有界重试 |
| 文档尚未展开 | 目标已有正尺寸，但滚动被文档高度截在顶部，旧实现误报定位成功；现核验实际目标与垂直视口相交 |
| 首次滚动导致布局失效 | 首次定位后再等一个原生帧间隔并重新测量；失败继续剩余重试，不将首次结果视为最终结果 |
| 完成后手动滚动 | 成功后结束定位任务，后续 layout 不将用户拉回旧目标 |
| 横向隐藏行号 | 完成条件只核验垂直区间；行号在横向视口外也不持续重放已完成的垂直导航 |
| 取消、替换与卸载 | 等待和二次测量都核验原请求、取消状态及实际窗口；脱离窗口的目标不操作原文档 |

浏览器 requestAnimationFrame 在原生实现中以 16 毫秒等待和重新布局测量承接，不声称两种渲染器在所有刷新率下有相同帧时刻。仍仅操作垂直文档，现有横向偏移和顶部标题间距保持。

旧生产实现上的初次专项 3 项、1 个用例共 2 条失败断言；扩大后 4 项、2 个用例共 4 条失败断言。日志 `.cache/pr-anchor-before-632.log`、`.cache/pr-anchor-before-expanded-632.log`。两种延迟情况均有修复前失败证据。
